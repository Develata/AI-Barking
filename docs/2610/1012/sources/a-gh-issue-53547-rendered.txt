What issue are you seeing?

The codex daemon process is leaking environment variables across unrelated sessions. The daemon seems to pick up the environment variables of the first session that started the daemon. After that these environment variables are available to other unrelated sessions.

What steps can reproduce the bug?

Stop the codex daemon:

➜  /tmp codex app-server daemon stop
{"status":"stopped","backend":"pid","managedCodexPath":"/Users/alex/.codex/packages/app-server-daemon/current/bin/codex","managedCodexVersion":"0.162.1","socketPath":"/Users/alex/.codex/app-server-control/app-server-control.sock","cliVersion":"0.162.1"}


In one terminal window: mkdir a new directory, cd into it, export a unique env var, start codex with the daemon enabled, and ask it what env vars are available. It identifies the env var.

➜  /tmp mkdir codex-dir1
➜  /tmp cd codex-dir1
➜  codex-dir1 export CODEX_ISSUE=FOO123
➜  codex-dir1 printenv | grep CODEX_ISSUE
CODEX_ISSUE=FOO123
➜  codex-dir1 codex --enable daemon_auto_start
Disconnected from this task. Any running work continues.
To reconnect, run:
  codex resume 01a13364-e75b-7631-876c-d768cb33d9d9
Stop the current turn: run codex agents, select this task, and press x.
Token usage so far: total=6,194 input=6,116 (+ 31,872 cached) output=78

In a second terminal window: mkdir a new directory, cd into it, DO NOT export the env var, start codex with the daemon enabled, and ask it about the env var. It still shows the env var from the first window.

➜  /tmp mkdir codex-dir2
➜  /tmp cd codex-dir2
➜  codex-dir2 printenv | grep CODEX_ISSUE
➜  codex-dir2 codex --enable daemon_auto_start
Disconnected from this task. Any running work continues.
To reconnect, run:
  codex resume 01a13365-e8f6-78f2-aa20-5586bfdeef52
Stop the current turn: run codex agents, select this task, and press x.
Token usage so far: total=6,194 input=6,116 (+ 31,872 cached) output=78
What is the expected behavior?

The second session should not have environment variables from the first.

This is somewhere between a bug and a security issue. People often have sensitive project-specific env vars. Maybe it's not ideal, but that's the reality in many projects. These should not leak into the persistent server and should especially not leak across sessions.
