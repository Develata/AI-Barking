 copyberry[bot]

## What changed

Enable `instant_interrupt…

Old behavior

Mid turn messages went into pending_input, added to next sampling step.

New behavior:

When an interruption comes in a new undocumented:

{"type": "response.interrupt", "response_id": "...", "mode": "discard_partial_items"}

Is sent. Additionally, code mode has a clean way of yielding in long code mode blocks per: Enable code mode interruption by default by copyberry[bot] · Pull Request #51835 · openai/codex · GitHub

This is a nice feature, waiting on steering can be annoying, that said… there is a big piece of nuance here.

Got to use x-openai-internal-codex-responses-lite: true for this to work.

Now… the price you pay for this at least from source in codex.

Codex ties the fate of this feature with disabling of parallel tool calls.

For most harnesses this would be a disaster, but codex is moving more and more work into codemode so parallel tool calls are not needed as much.

Curious to see how this plays out, for image gen this is very nice, for other cases … it is a tricky compromise.
