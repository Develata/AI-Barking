 Codex CLI更新后启动守护进程实现自启动 有用户提议应当默认关闭可选开启

 [https://www.landian.news/archives/114184.html]

#人工智能 Codex CLI 更新后启动守护进程并实现开机自启动，有开发者提议应当默认关闭由用户手动开启。从 Codex CLI 0.157.0 版开始，Codex 开发团队为符合条件的交互式会话启用后台服务器自动启动功能。该功能会添加守护进程实现自启动，守护进程独立运行和更新。有开发者担心守护进程运行的版本与 NPM 管理的版本脱节，因此应当默认禁用才对。查看全文：https://ourl.co/127333

从 Codex CLI 0.157.0 版更新开始，Codex 开发团队已经为符合条件的交互式会话启用后台服务器自动启动功能。该功能会添加守护进程实现 Codex CLI 开机自启动，守护进程独立运行和更新，这种做法引起开发者不满，有开发者认为应该设置为默认关闭可选启用。

 [https://img.lancdn.com/landian/2026/10/127333.png]

 有开发者发现异常后提交讨论：

有开发者通过 npm 在 Linux WSL2 中安装 Codex CLI 0.157.0 版后，启动交互式会话后 Codex CLI 会创建后台守护进程，即便关闭 Codex 窗口该进程仍然会继续运行。Codex CLI 会将大约 374MB 的运行包复制到～/.codex 目录下并启动独立更新进程，该进程在启动约 5 分钟后首次检查更新，之后每小时检查一次更新。

这名开发者担心守护进程运行的版本可能与包管理器安装的 Codex CLI 版本脱节，也会沿用最初启动会话的环境变量例如代理设置。因此开发者认为 OpenAI 应该将其设置为默认关闭，有需要的开发者可以手动启用守护进程。
