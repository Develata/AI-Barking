Benchmark
The Legal Agent Benchmark is a benchmark recently [https://www.harvey.ai/blog/introducing-harveys-legal-agent-benchmark] released by Harvey to
test the ability of models to support legal work in an agentic setting. There are two datasets as of today: the public set and the held-out test set.
The results here are from the held-out set, and [https://www.harvey.ai/blog/legal-agent-benchmark-initial-results] initial results have already been released by Harvey.
Each task asks an agent to produce legal work against a set of task-specific criteria. The agent is provided with six tools:
Read File, Edit File, Write File, Glob, Bash, and Grep. It also has three skills: docx , pptx , and xlsx .
Reported results use the same methodology as Harvey’s initial [https://www.harvey.ai/blog/legal-agent-benchmark-initial-results] leaderboard .
Criteria pass rate is included to show how often models satisfy individual requirements, even when they do not fully resolve the task.

Methodology
We use Harvey’s generation and grading protocol in the same environment, with internet access disabled.
Harvey grades each submission with two LLM judges. Each judge computes a task pass rate. A task passes only if 100% of its criteria pass, and Harvey’s final score is the average of the two judge task pass rates.
The two judges were [https://www.vals.ai/models/openai_gpt-5.5] GPT 5.5 and [https://www.vals.ai/models/anthropic_claude-sonnet-4-6] Claude Sonnet 4.6 . [https://www.vals.ai/models/openai_gpt-5.5] GPT 5.5 used medium reasoning and [https://www.vals.ai/models/anthropic_claude-sonnet-4-6] Claude Sonnet 4.6 was not modified.
While running the benchmark, we found that redline criteria needed DOCX tracked changes preserved when reading submitted files so judges could see inserted and deleted text. We fixed that bug and merged it upstream in [https://github.com/harveyai/harvey-labs/pull/76] harveyai/harvey-labs#76 . The scoring rubric is unchanged.
The benchmark was modified to use our [https://github.com/vals-ai/model-library] model library , an abstraction over various LLM provider APIs, and to run on [https://github.com/vals-ai/Valkyrie] Valkyrie , our framework for running agentic benchmarks. These are infrastructure changes and do not impact model performance.
To improve judge performance and reduce cost, we split the instruction prompt provided to each judge so common elements could be cached. This did not modify prompt content outside of caching.
