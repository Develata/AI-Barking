# A 组取证：Claude Max 20x 改名 Ultra：取消 5 小时窗口、周限额不变

取证时刻：2026-10-31 16:48–17:25（北京时间，UTC+8）。执行方：claude-sonnet-5-5。
时间换算：北京时间 = UTC + 8；X 帖时刻取自 fxtwitter JSON 的 `created_at`（UTC），页面更新时刻取自帮助中心页面数据的 `lastUpdatedDate`（UTC）。

## 先读这里：关键结论（Claude 判断用）

1. **“20x 变 10x”不是降额，也不是同一口径的数字换了**。旧官方帮助页（Wayback 2026-10-24 快照）写的是“Max 20x includes 20 times the Pro plan's per-session usage allowance”，即 20x 是**每个 5 小时会话**相对 Pro 的倍数；旧页同时写 Max 有周限额，但**没写周限额是 Pro 的几倍**。新页（Ultra）写的 10x 是**每周**相对 Pro 的倍数。两个数字量的不是同一个东西。官方在 X 上说 “Weekly limits remain unchanged”。
2. “周限额一直是 Pro 的 10 倍”这件事，**官方页面（旧页与新页）都没有明文说过“旧 Max 20x 的周限额是 10x”**；唯一的明文是 Anthropic 员工（订阅产品负责人）10-30 的发言：“When we added weekly limits to Max 20x, we set them to 10x Pro's (the 5-hour limit stayed at 20x).”，L2。写正文要署“员工称”，不是“官方页面称”。
3. 被取消的恰是那个 20x 的 5 小时限制；周限额原样（“weekly limits remain unchanged”）。所以 Ultra 并没有比 Max 20x 多出总量，只是不再被每 5 小时的窗口卡住（仅限“已验证”账号）。
4. 集体诉讼存在（CourtListener 公开 docket 已核），Anthropic 在动议里的立场正是“5x/20x 指每会话（per session），不是每周”；听审排在 2026-11-06 10:00 PT。**但 CourtListener 上有一条 10-30 的“Order on Motion to Dismiss”记录，正文不可见，听审是否仍照常、动议是否已裁决，本组无法确认**（见 A5）。
5. WorkBuddy 的诉讼说法大体属实但有三处细节错（案由编号对、提起日对；“后与 Smith 案合并”对；“驳回动议”应为“动议驳回起诉（motion to dismiss）”，不是“驳回动议”；“xAI、Cursor 的 $200 档也叫 Ultra”本组未核，不在 A 组范围）。

## 可能的吠点（原文里有、线索摘要没提或说反的条件与限制）

1. “取消 5 小时限制”**仅限已验证的 Ultra 账号**，且是“starting today with most existing subscribers”分阶段推；新账号保留临时限制，官方没给解除时间或具体限制数值（@claudeai 帖；Ultra 帮助页）。
2. 验证标准不公布，不能申请，只能等（“factors like your account and payment history”）；结账手机号验证不算（Ultra 帮助页）。HN 评论称付费数月的账号也还没验证（见下 L6）。
3. 周限额不变：不是“不限量”。Ultra 仍有“weekly usage limit that applies across all models, and a separate weekly limit for Fable”，并且官方保留“weekly and monthly caps or model and feature usage”等其他限制、“We don't guarantee uninterrupted service”（Ultra 帮助页）。
4. 没有 5 小时限制意味着可以一周额度更快用完：媒体评论称“could use it up sooner”（The New Stack，L4，非官方）。
5. “20x→10x”不是同一口径（见关键结论 1、A3）。旧页面一直写“5x/20x”按“per-session”，而新页面写的 10x/5x 按“每周”；**旧页面没有写过周限额倍数**，所以“20x 变成 10x”这个说法既不能被官方页面坐实也不能被官方页面驳倒，只能靠员工帖（Overell，L2）说明“周限额从加入时就是 10x、5 小时限制是 20x”。官方没有解释这个命名为什么拖了这么久，Overell 帖自己承认“some new users assumed 20x applied to both limits”。
6. Max（原 5x）：新页面写 “5x Pro usage every 5 hours and every week”，旧页面只写 5x 的“per-session”。Max 的周限额旧页面同样没写倍数；Overell 帖只谈 Max 20x，没谈 Max 5x 的周限额。原告诉状主张 Max 5x 实际只有 Pro 的 3.5 倍（A5c，主张，未证）。
7. 定价页 Ultra 卡片的结账入口链接仍是 `?plan=max_20x`（`claude.ai/upgrade/max?plan=max_20x`，见 `a-pricing.html`），说明内部套餐 ID 沿用旧名；读者在账户内的升级弹窗仍可能看到旧文案——yeeyi 一篇文章称弹窗还挂着旧版“20x Pro 用量”（L5，二手，未核）。
8. 月度 API 额度须关联 Console 组织后领取，且“new subscribers can claim once they've been on an eligible plan for seven days”（API 额度页）；Ultra 的 $200 额度不是自动到账。
9. 同期背景（只作线索）：腾讯新闻 10-23 引述 SemiAnalysis 称 Anthropic 在对订阅额度做 A/B 灰测，周额度缩水约 20%（L5/L6，https://news.qq.com/rain/a/20261023A0EC5Q00）。**这是另一件事，与本次改名无直接证据关联**，不要混写；Claude Code 员工 Lydia Hallie 当时回应“额度没有任何调整”（同文转述，未取一手）。
10. 平台口径：Anthropic 在帖里用的是 X 平台，成稿须按“X 平台名不写进正文”处理。
