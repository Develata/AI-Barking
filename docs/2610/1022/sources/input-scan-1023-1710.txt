## 2. Claude生成约1.8亿行机器证明：239个软件入口得到限定范围内的安全保证

**事件：**Anthropic与Theorem合作，让Claude为真实开源软件的编译产物构造形式化证明。

**时间：**官方发表于**2026-10-22，仅给日期**。

**一手来源：**[Anthropic形式化验证研究全文](https://www.anthropic.com/research/formal-verification)。**已看原文、具体规格、证明规模和局限说明。**

**热度证据：**HN对应讨论由此前约**161分／75评论**，升至本轮**342分／199评论**。

**爆点：**过去通常需要形式化验证专家长期投入的工作，现在AI可以在数周内生成海量证明，再交给机器检查器验证。

**可能的吠点：**

- 研究覆盖**123个开源库、239个OSS-Fuzz测试入口**，不是完整证明123个项目所有功能正确。
- 使用Rocq证明检查器，检查的是**编译后的RISC-V程序及给定Linux语义模型**。
- 主要保证：在指定条件下，对**小于64MB的任意输入**，这些入口不会出现规定的崩溃、内存错误或断言失败。
- 假设包括**静态链接、单线程、固定内存预算及对应操作系统模型**；不能直接推广至所有x86、ARM、多线程生产部署。
- Claude在过程中发现并修复了部分错误，**证明结论针对修复后的代码**。
- 约1.8亿行是Rocq证明代码总量，不代表1.8亿个独立命题。
- **机器检查证明有效，不代表规格自动完整反映真实软件的全部安全需求**。模型语义、规格与实际二进制文件的一致性仍是可信计算基础的一部分。
- Anthropic公开部分证明和语义代码，但未完成全部成果由外部团队独立复现的公开报告。[Anthropic](https://www.anthropic.com/research/formal-verification)

**来源等级：L1官方研究与公开验证材料。核验难度：高。** 需要专业审查形式化语义、可信计算基础和证明目标。

**发布状态：**`unpublished`。  
**本轮状态：**`rising / machine-checked evidence / proof scope limited`。

**一手来源：**[Axios原始采访调查](https://www.axios.com/2026/10/22/ai-agents-banks-unauthorized-accounts-access)；[Reuters后续核对](https://www.reuters.com/legal/government/us-banks-detect-unauthorized-ai-agents-customer-accounts-axios-reports-2026-10-22/)。**均已看可读原文。**

**可能的吠点：**

- 银行正在探索只读授权等中间方案；**读取账户信息与转账、付款属于不同权限等级**。
- 当前尚无经确认的大规模资金被AI擅自转走的数字。
- 本轮1Password提出的凭据隔离方案，能缓解密码暴露问题，**却不能自动解决银行账户使用条款、操作授权与责任认定问题**。[Axios](https://www.axios.com/2026/10/22/ai-agents-banks-unauthorized-accounts-access)

# 八、本轮结论

**本轮选题有一个明显变化：新闻价值正在从AI模型“能做什么”，转向AI系统“实际影响了什么，以及由谁承担后果”。**

PHP事件最能说明这一点。AI辅助发现底层软件漏洞原本是技术新闻；当现实中的紧急灾害警报因此暂时停止，它就变成了公众直接感受到的基础设施安全问题。

美国银行限制AI Agent与1Password提供密码隔离，实际上在讨论同一个问题的两个层面：**用户允许Agent拿到什么凭据，以及Agent获得凭据之后究竟被授权做什么。** 安全设计不能只停留在密码是否泄露，还必须包含账户权限、操作审批和责任归属。

Claude的形式化验证研究则提供了另一种思路：与其事后发现错误，不如尝试给指定行为提供机器可检查的数学保证。但**形式化证明的强度取决于规格的强度、模型与真实系统的对应关系，以及可信计算基础是否成立**。

Canva Craft、Claude auto mode和Uber的公司级Agent部署，说明AI产品开始在普通用户和企业工作流中获得更深入的执行权限。此时，真实可用性、错误恢复、安全审计和成本边界，正在变得与基础模型跑分一样重要。

**本轮最终建议优先推进：① 日本软银因PHP安全维护暂停紧急灾害警报【跟进】；② Canva Craft；③ Claude大规模形式化验证。**

这一排序与上一轮不同：第一条优先级来自新增的现实公共安全影响，第二条来自新产品的普通读者价值，第三条来自强技术证据与持续升温的社区讨论，而非历史推荐结果。
