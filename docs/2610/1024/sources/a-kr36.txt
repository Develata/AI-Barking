Kimi K3.1 Pro刚发布，社区先炸了：比K3快、性能逼近Opus，但额度10分钟就烧光了

极客邦科技InfoQ [/user/323686438]·2026年10月24日 10:32

10 月 24 日，Kimi 正式发布 K3.1 系列首款模型 Kimi K3.1 Pro

10 月 24 日，Kimi 正式发布 K3.1 系列首款模型 Kimi K3.1 Pro。这是 Kimi 迄今能力最强的 3 万亿级参数模型，支持百万 Token 上下文，重点强化代码、3D 创作、金融研究以及长程 Agent 能力。与此同时，Kimi 还同步推出 K3.1 Pro Highspeed 高速版，在保持相同模型智能水平的情况下，输出速度提升约 2～3 倍。

按照 Kimi 公布的数据，K3.1 Pro 在代码、Agent 和知识类 Benchmark 上已经达到或接近当前最强闭源模型水平。相比 K3，K3.1 Pro 最明显的变化是进一步增加后训练计算量，并把强化学习（RL）扩展到数百个下游领域。为了支撑这套大规模联合训练，Kimi 对 RL 框架、长上下文推理、训练效率、沙箱基础设施、调度系统以及环境质量检查平台等进行了系统性改造。

K3.1 Pro 目前已经覆盖 Kimi 主要产品线。普通用户可以直接在 kimi.com 和 Kimi App 中使用；Kimi Work 桌面端面向 Windows 和 Apple 芯片 Mac 提供模型能力；Kimi Code 则可以在终端和桌面环境中使用 K3.1 Pro 进行编程。Kimi 表示，K3.1 Pro 完整模型权重将在 11 月 4 日前发布。

API 方面，Kimi K3.1 Pro 每百万 Token 缓存命中输入价格为 1.3 元，未命中缓存输入为 13 元，输出价格为 68 元。高速版 Kimi K3.1 Pro Highspeed 拥有相同模型能力，价格约为标准版 2 倍。

除了直接提供模型 API，Kimi 还推出 Hosted Agents 托管智能体服务，把支撑 Agent 长时间运行的 Harness 作为云端基础设施提供给企业和开发者，可以运行 7×24 小时长程任务，并支持多智能体协作。

这也进一步说明 K3.1 Pro 此次升级的主要方向，Kimi 开始把更多后训练算力投入真正能够持续工作的 Agent 环境，包括编程、金融研究、3D 工具调用以及长时间任务执行。

1 Coding 能力大涨，但“偏科”和冗长仍受关注 

代码和长程 Agent 是 K3.1 Pro 此次升级最明显的方向之一。

在 Terminal-Bench 4.0 中，K3.1 Pro 得分达到 65.7%。该 Benchmark 通过真实、资源受限的终端环境测试编程 Agent 完成复杂任务的能力，每项任务均设置专项测试。作为对比，Kimi 公布的成绩显示，GPT-6 Astra 得分 58.2%，Claude Opus 5.5 为 66.4%。这意味着 K3.1 Pro 在该测试中已经超过 GPT-6 Astra，与 Claude Opus 5.5 相差不到 1 个百分点。

在 Kimi 内部的 Kimi Code Bench 3.0 Long-horizon 长程代码测试中，K3.1 Pro 得分 61.2%，相比 K3 的 55.95% 进一步提高。该测试覆盖多种工程领域，重点评估模型的多步执行、工具调用以及端到端问题解决能力。

相比单纯生成代码，Kimi 此次更强调 K3.1 Pro 对完整软件工程任务的执行能力。模型不仅能够在真实代码库中定位和修复问题，也能从零构建完整项目，并自主调用 Unity、Unreal Engine、Godot、Blender 等外部专业工具。

例如，K3.1 Pro 使用 Unreal Engine 5.8 搭建一个云海之上的东方神话天宫游戏场景，调用 Blender 进行程序化建模，并结合 Nanite、Lumen 以及外部 8K 材质和 NASA 月球数据完成场景制作；另一个案例中，它使用 Godot 4.7.2 从零构建了一款包含 5 个探索区域、程序化地形、第三人称战斗、两阶段 Boss、昼夜循环和快速传送系统的 3D 动作冒险游戏。

Kimi 还测试了一个更长程的工程任务：让 K3.1 Pro 基于包含 296 个骨骼组件和 402 个肌肉组件的开源人体解剖模型，搭建人类行走动力学仿真系统。

整个过程中，模型进行了 167 项任务和 420 次独立评审，不断分析实验结果、定位问题和修改控制器，使仿真人体从最初几步就摔倒，逐渐进化至能够交替迈步并连续行走 11.2 秒。值得注意的是，当继续调整奖励函数已经无法改善手臂运动时，模型没有继续“死磕”参数，而是转向检查仿真器动力学，最终发现并修复肩部肌肉力臂计算中的 36 处错误，再重新训练控制器。

模型发布后，很多用户第一时间就自己测试了。有用户称自己用 Kimi 进行汇编和嵌入式逆向工程时获得了不错的结果，认为模型虽然比 Claude Opus 更啰嗦，但执行意愿较强。另一些用户则直接把 K3.1 Pro 视为当前少数真正能够与 Opus 5.5 正面比较的模型。

不过 K3.1 Pro 并不是所有领域都同步跃升。Artificial Analysis 数据显示，Humanity's Last Exam 从 47% 提升到 52%，CritPt 从 23% 升至 25%，SciCode 从 59% 升至 61%，提升幅度明显小于 Agent 相关指标。这也让部分社区用户认为，K3.1 Pro 目前仍存在比较明显的“偏科”：代码、Agent、前端和 3D 可能非常强，但并不能简单理解成所有能力都已经全面追平最强闭源模型。

2 3D 能力获得好评，但不太能“一句话出大片” 

3D 是 Kimi 此次宣传力度最大的能力之一，社区关注也较多。

在 BenchCAD 测试中，K3.1 Pro 借助工具取得 92.7% 的成绩，接近 Claude Opus 5.5 的 96.2% 和 GPT-6 Astra 的 95.9%。BenchCAD 主要测试模型从多个视角渲染图重建 3D 物体的能力。模型需要生成 CAD 代码，推断物体的形状、比例以及各组成部分之间的空间关系。

Kimi 表示，用户可以给 K3.1 Pro 提供文字描述、草图或参考图片，让模型重建成可继续编辑的 3D 模型。它也能够直接生成并运行 Blender、CAD 等软件脚本，并修改具体零件、几何结构、材质和场景布局，不必依赖额外的 MCP 连接器。

在官方的一个 FreeCAD 案例中，K3.1 Pro 通过 Python 构建了一个包含风扇、减速齿轮箱、压气机、燃烧室、涡轮以及外部管路的涡扇发动机，共包含 2100 个实体，并生成分步装配、内部爆炸图以及多个转子的旋转动画。另一项任务中，模型使用 trimesh 设计了一款由 5 个部件组成、可以直接 3D 打印的台灯，造型灵感来自福建土楼。

Kimi 也将这项能力直接做进了产品。目前 kimi.com 和 Kimi App 已经上线“3D Make”功能，用户可以在线预览和编辑模型，完成后可以下载用于 3D 打印，也可以导出视频或实况照片。

实际上，在正式发布前，代号“Kibitz”的疑似 K3.1 模型已经在 Arena 出现，一些测试者注意到它在 3D 场景、颜色选择、水面反射和整体构图上的表现较为突出。正式发布后，也开始有开发者把它放进真实 3D 工作流测试。

一名 AI 游戏开发者使用 K3.1 Pro 和 pi.dev Harness 生成“鹈鹕骑自行车”的高精度 3D 场景后认为，即将开放权重的模型已经可以做出相当不错的 3D 效果。不过他的测试也揭示了一个差距：K3.1 Pro 并没有靠一次 Prompt 直接得到最终结果，而是需要多轮“继续增强”的指令；相比之下，他此前测试 Claude Opus 5.5 时，用一次 Prompt 就得到了更完整的成品。

3 主动“砍掉”网络攻防能力，开放权重引发更多争论 

随着模型代码和 Agent 能力快速提高，Kimi 此次还用了相当篇幅解释 K3.1 Pro 的网络安全能力，以及为什么在发布开放权重前主动降低了部分攻击性安全能力。

Kimi 表示，在扩大后训练规模过程中，团队观察到模型的漏洞研究能力随之明显增强。进一步追踪后发现，一部分网络攻防数据混入了中期训练通用语料，同时强化学习环境中也包含相应任务。

内部实验显示，如果在中期训练和强化学习阶段都不删除这些网络攻防数据，模型的下游攻击能力会大幅增强。因此，在准备 K3.1 Pro 开放权重版本时，Kimi 从这两个训练阶段同时识别并删除相关网络攻防数据，同时尽量保留普通编程所需要的通用能力。

为了衡量效果，团队构建了 xdev-bench-hard 测试，其中包含基于源代码的漏洞发现和利用任务，覆盖 Linux 内核、Node.js、JavaScriptCore、Exim 和 VirGL 等软件近期公开漏洞。

测试中，Agent 需要读取存在漏洞的源代码、提示和二进制文件，自行开发漏洞利用程序，并在隔离沙箱中实现任意代码执行。如果不删除网络攻防训练数据，同一训练流程产生的模型在 xdev-bench-hard 上的 pass@3 可以达到 90.5%，最终发布版 K3.1 Pro 降低至 81.0%。

按照 Kimi 自身评估，目前 K3.1 Pro 的网络攻防能力仍落后于已经公开发布至少 3 个月的前沿闭源模型。这也直接影响了 Kimi 是否发布开放权重的判断。其原则之一是，不希望一个开放权重模型直接推进攻击性网络安全能力的最前沿；另一方面，Kimi 认为，只要控制能力扩散速度，让具备双用途能力的模型在用户自己的基础设施上运行，也可以帮助更多团队审查遗留系统和缺乏专业安全审计的代码。

对此，有开发者认为，这相当于 Kimi 承认自己内部能够训练出更强版本，只是选择不释放；也有人担忧，如果为了降低攻击能力而让模型减少安全知识，反而可能影响它发现漏洞和编写安全代码的能力。另一些人则认为，对于即将完整开放权重的 3 万亿级模型，这种渐进式释放是一种现实的安全折中做法。

这里也出现了一个此前开放模型很少需要面对的问题：随着开放权重模型越来越逼近闭源前沿，“究竟开放多少能力”本身开始成为模型设计的一部分。

4 金融研究能力提升，事实错误率从 23.4% 降至 8.3% 

除了代码和 3D，金融也是 K3.1 Pro 强化幅度较大的领域。

在 OfficeQA Pro v2 测试中，K3.1 Pro 得分 64.4，按照 Kimi 公布的数据取得当前最佳成绩。该 Benchmark 基于真实金融文件设计，重点测试模型的信息检索、跨文档核对以及多步数值推理能力。在衡量完整投资研究流程的 Frontier Finance 测试中，K3.1 Pro 相比 K3 同样有所提升。

Kimi 还公布了 3 项内部金融 Benchmark 结果。其中，K3.1 Pro 在 Financial Modelling 财务建模测试中较 K3 提高 14%，Financial Research 金融研究提高 20%；在模拟企业经营管理和决策的 Business Operation 测试中，得分达到 K3 的约 4.2 倍。

在实际案例中，K3.1 Pro 可以端到端生成英伟达财务模型，包括经营驱动因素、情景假设和估值敏感性分析；也可以围绕宁德时代制作投委会报告，分析市场一致预期与实际经营之间的差异，并结合财报、指引和潜在催化因素形成投资逻辑。

对于金融 Agent 而言，真正困难的并不只是计算，而是事实准确性。为此，Kimi 专门针对高难度金融和研究场景进行了事实准确性优化。

在内部 Kimi Hallu Bench Hard 压力测试中，K3 的单项事实陈述错误率为 23.4%，K3.1 Pro 下降到 8.3%；出现至少一处事实错误的回答比例，则下降到 K3 的约 42.4%。

不过 Kimi 也强调，这是一项专门选择模型容易出错样本的压力测试，上述错误率不能代表普通使用场景中的整体表现。

5 “额度几分钟就烧完”成最大槽点 

与能力上的好评形成鲜明反差的是 Kimi 订阅额度，这几乎成为讨论里最集中的负面反馈。

一名用户称，自己订阅了每月 99 美元的 Kimi 套餐，仅运行一个会话、没有启动 Agent 群组，大约 47 分钟就触发了 5 小时额度限制。另一名 19 美元套餐用户则称，一项任务就可能消耗完整的 5 小时额度，并明显侵蚀周额度。还有开发者直接表示，模型再强，如果 30 分钟左右就耗尽 5 小时预算，也很难把它真正用于持续开发。

Reddit 上甚至出现了更极端的个案。一名用户测试一个基础 3D 游戏 Demo 时称，没有使用子 Agent，模型运行约 10 分钟、任务尚未返回结果，就已经耗尽整个 5 小时额度；另一些 Plus 甚至更高等级订阅用户也报告了类似的快速消耗现象。这也让部分用户表示，直接按照 API 价格使用 DeepSeek 4.1 Flash 反而更加划算。

有用户认为，如果一个开放模型既因为参数规模过大难以在消费级硬件本地运行，又无法通过固定订阅获得足够长时间的使用，那么开放权重本身对普通开发者的价值也会受到限制。

从 API 价格看，K3.1 Pro 并不算昂贵，但固定订阅套餐里的可用量，却成为不少重度代码用户最明显的痛点。一些开发者甚至开始讨论“混合用模”：让 K3.1 Pro 负责规划和复杂决策，再让 DeepSeek 等更便宜的模型承担大量执行工作。

有意思的是，第三方数据确实能够解释一部分用户的额度焦虑。

Artificial Analysis 在完成整套 Intelligence Index 测试时，K3.1 Pro 累计输出约 1.5 亿 Token，而参与测试模型的中位数只有 8700 万 Token。也就是说，它在相同评测中输出的 Token 数量比中位水平高出约 72%。

Artificial Analysis 因此直接把 K3.1 Pro 评价为“非常冗长”。

速度也不是它的强项。Artificial Analysis 测得 K3.1 Pro 输出速度约 73.5 Token/s，低于 81.1 Token/s 的同类模型中位水平。不过不少用户反馈，K3.1 Pro 的实测速度“远快于 K3。”

但另一方面，因为 Token 单价下降，其整体任务成本仍具有竞争力。Artificial Analysis 估算，其 Intelligence Index 平均每项任务成本约 2.11 美元。另一项基于该数据的比较显示，Claude Opus 5.5 对应成本约 5.98 美元，GPT-6 Astra 约 3.26 美元。也就是说，K3.1 Pro 虽然“话多”、消耗 Token 多，但 API 场景下的单位任务成本并不差。

真正的矛盾更多出现在订阅制产品，用户对一项任务跑多久、花多少钱更为敏感。

这对于像 K3.1 Pro 这样定位长程 Agent 的尤其关键。模型越擅长持续搜索、调用工具、写代码和自我检查，一项任务持续时间越长，它就越容易吃掉大量推理预算。如果配套套餐没有同步提高使用上限，模型能力越强，反而可能越容易撞上“额度墙”。

不过，长程 Agent 的“额度焦虑”并非 Kimi 独有。

有 Claude 用户表示，自己使用 20 美元档套餐时，也遇到过一个复杂 Prompt 就几乎耗尽 5 小时额度的情况；另一名用户使用 Opus 5.5 处理已有代码库，大约 30 分钟后同样触发了使用限制。OpenAI 用户也报告了类似体验，一名用户称，在 20 美元套餐中使用高推理档位进行代码分析时，一次任务甚至还未完成便撞上额度限制。

因此，不同用户对“Kimi 额度是否特别少”的判断也出现分歧。一些开发者认为 Kimi 明显比 Claude、Gemini 和 ChatGPT 更加严格；但另一些人指出，模型选择、推理强度、工作流以及任务复杂度都会显著影响额度消耗，同一个订阅方案在不同用户手中的实际体验可能完全不同。
