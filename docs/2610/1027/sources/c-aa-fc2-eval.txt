Artificial Analysis' implementation of Cognition's FrontierCode 2.0, a private agentic coding benchmark of 132 tasks in real open-source repositories, graded on whether a maintainer would merge the agent's change.
See example tasks [#example-tasks]

Background

FrontierCode is a coding benchmark from Cognition [https://cognition.com/blog/frontier-code-2.0], built with maintainers of open-source repositories. Each task asks an agent to make a change to a real open-source repository, and the benchmark measures whether the change is good enough for a maintainer to merge.

We run all 132 tasks of FrontierCode 2.0. The tasks are private to avoid contamination.

The FrontierCode verifier grades each attempt with the task's tests and a rubric of blocking and non-blocking checks. An attempt that fails any blocking check, or that the trajectory scanner flags for looking up the solution, scores 0. Other attempts get a weighted score across the rubric's criteria.

We run every task three times with our Stirrup [https://github.com/ArtificialAnalysis/Stirrup] agent harness, capped at 500 turns, and weight every task equally in the average. Shell commands keep running in the background, so the agent can start a long build or test run, continue working, and check the result in a later turn. We use GPT-6 Luna (medium) as the LLM judge.

Methodology

All evaluations are conducted independently by Artificial Analysis. More information can be found in our FrontierCode 2.0 methodology [/methodology/intelligence-benchmarking#frontiercode-2-0].

Example Tasks

Restart Generator Resolvers on Reset

Repository: Mock Service Worker · Language: JavaScript

Mock Service Worker is a library for mocking network requests in JavaScript. A user reports that resetHandlers() doesn't restart generator resolvers, and the task asks the agent to fix the bug.

The task doesn't mention cleanup, but a library that discards a generator should close it so that the user's finally block runs. A fix that only drops the reference to the old generator restarts it as reported, but never closes it, so the cleanup below never runs. That fix fails the task.

function* () {
 try {
 yield 'first'
 return 'rest'
 } finally {
 cleanup() // never runs after a reset
 }
}

Source: Cognition, FrontierCode 2.0 [https://cognition.com/blog/frontier-code-2.0]

Send Cached Analytics Events in Order

Repository: PostHog Android SDK · Language: Kotlin

When the device is offline, the PostHog Android SDK writes analytics events to disk and sends them the next time the app starts. At startup, the live queue sends new events while a legacy integration, PostHogSendCachedEventsIntegration.kt, sends the cached ones. The two race, and events reach the server out of order. The task asks the agent to fix the race.

Scope blockers check that the agent leaves certain files unchanged. PostHogSendCachedEventsIntegration.kt is part of the SDK's public posthog.api surface, so a fix that deletes it breaks every app that references the class, and fails the task even though the race is gone. A passing fix moves cache loading into PostHogQueue.kt, removes the sending logic from the legacy integration, and leaves the public API unchanged.

Source: Cognition, FrontierCode 2.0 [https://cognition.com/blog/frontier-code-2.0]
