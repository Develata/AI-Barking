Artificial Analysis Progress Index v1 Methodology

Artificial Analysis Progress Index v1 [#artificial-analysis-progress-index]

The Artificial Analysis Progress Index v1 estimates the general capability of language models on a single scale that is consistent over time. It is designed for analyzing trends in AI progress, including comparisons between models released years apart.

The Artificial Analysis Intelligence Index [/methodology/intelligence-benchmarking] is designed to measure current frontier capability. Its composition is updated periodically: evaluations are added as models improve, and evaluations that no longer differentiate leading models are retired. Each version of the Intelligence Index is therefore measured on a different set of evaluations, and scores across versions are not intended for long-run comparison.

The Progress Index v1 addresses this by estimating model capability and task difficulty jointly, using item response theory. Models are linked through the evaluation tasks they have in common, so each model's estimate reflects its performance relative to the difficulty of the tasks it attempted, rather than the particular set of evaluations it was tested on. This allows models to be compared on one scale without requiring results on the same evaluations.

The Intelligence Index remains the primary measure of current model intelligence and is the recommended basis for comparing models for present-day use cases. The Progress Index v1 is intended for analysis of capability over time. We fit each effort variant as a separate model and represent each model by its highest-scoring variant.

Model and Estimation [#model-and-estimation]

The Progress Index v1 is based on item response theory (IRT), a statistical framework that places the capability of each model and the difficulty of each benchmark task on one shared scale.

Models don't need results on all the same benchmarks. As in other applications of IRT, we estimate each task's difficulty from every model that attempted it, and each model's capability from the tasks it attempted. Benchmarks that share models link everything onto one scale, so models tested on older and newer benchmarks can be compared directly.

Each model has one capability . Each item (one task within a benchmark, or a whole benchmark where only aggregate scores exist) has a difficulty , the capability at which a model is expected to score 50% after the guessing floor is removed, and a discrimination , how sharply the expected score rises as capability passes the difficulty

We scale capabilities and difficulties so that o3-mini (high) scores 220 and GPT-5.5 (xhigh) scores 320. We chose these anchors because both are stable frontier models with a clear performance gap across our evaluations. A fixed gap changes a model's odds of success on a given task by the same factor anywhere on the scale

Prior work: item response theory has been used to evaluate machine learning models (Martínez-Plumed et al., 2019 [https://doi.org/10.1016/j.artint.2018.09.004]; Rodriguez et al., 2021 [https://aclanthology.org/2021.acl-long.346]; Polo et al., 2024 [https://arxiv.org/abs/2402.14992]), and related methods place language models on one capability scale (Ruan et al., 2024 [https://arxiv.org/abs/2405.10938]; Ho et al., 2025 [https://arxiv.org/abs/2512.00193], the basis of Epoch AI's Epoch Capabilities Index [https://epoch.ai/benchmarks/eci]; Anthropic's Claude Mythos Preview system card [https://www-cdn.anthropic.com/08ab9158070959f88f296514c21b7facce6f52bc.pdf]). The Progress Index v1 fits individual tasks with log loss, using only evaluations we run ourselves

Input Data [#input-data]

The Progress Index v1 uses each model's available results on public Artificial Analysis benchmarks.

We use task-level data where it is available across a sufficient range of models, and aggregate benchmark scores otherwise (e.g., legacy evaluations). Where a task was run more than once, we average its repeats. Each benchmark carries equal weight for a model, regardless of how many tasks it has

A benchmark must have results from at least 4 models, and a model must have results on at least 4 benchmarks to be included in the fit

Input scores are normalized to range from 0 to 1. Where a model could score by guessing, we rescale scores such that guessing counts as 0, so a 25% score on GPQA Diamond (four options per question) counts as 0

We impute zero scores where a model's context window is too short for an evaluation: models with a context window under 100,000 tokens score 0 on AA-LCR
