MXC SDK v1.0.0 is the first stable release of the MXC SDK surface for Rust, .NET, and Node.js. It provides consistent APIs for creating and running containers, managing container lifecycles, selecting captured, piped, or terminal execution and discovering host support.

NPM: https://www.npmjs.com/package/@microsoft/mxc-sdk/v/1.0.0 [https://www.npmjs.com/package/@microsoft/mxc-sdk/v/1.0.0]

NuGet: https://www.nuget.org/packages/Microsoft.Mxc.Sdk [https://www.nuget.org/packages/Microsoft.Mxc.Sdk]

crates.io: https://crates.io/crates/mxc-sdk/1.0.0 [https://crates.io/crates/mxc-sdk/1.0.0]

See the Assets section for mxc-release-binaries.zip, which contains signed binaries that can be useful for testing.

What's New in v1.0.0

The V1 SDK is stable

The supported public SDK is now available through explicit V1 entrypoints:

Rust: mxc_sdk::v1

.NET: Microsoft.Mxc.Sdk.V1

Node.js: @microsoft/mxc-sdk/v1

The three SDKs share the same operation model and policy concepts while following the conventions of each language. V1 is the stable compatibility boundary for the 1.x release line. MXC will follow semver 2.0 [https://semver.org/] for future changes.

Direct execution supports captured output, live pipes, and PTYs

Callers can choose the execution model that fits their application:

Run to completion and receive captured stdout, stderr, warnings, metadata, and a typed outcome.

Spawn with pipes and interact with separate stdin, stdout, and stderr streams through an SDK-owned process handle.

Spawn with a PTY and interact through a caller-controlled terminal process, including initial terminal dimensions and runtime resize.

PTY support is available only when the selected backend can provide the requested terminal semantics.

Lifecycle managed APIs

The V1 lifecycle managed API supports:

Provisioning a container and receiving an opaque ContainerId.

Starting, stopping, and deprovisioning that container.

Running, spawning, or opening a PTY-backed process inside an existing

container when supported.

Backend discovery, filesystem policy, and telemetry APIs

V1 includes typed APIs for:

Discovering available backends and their capabilities.

Building filesystem policy from host tool, user profile, and temporary-directory discovery.

Querying and managing MXC telemetry consent.

Telemetry remains Windows-only, requires explicit user consent, and is subject to administrative restrictions.

Breaking Changes and Migration Notes

Import public APIs from the versioned V1 entrypoint for your language.

Replace legacy sandbox request and lifecycle types with ContainerRequest, ProvisionRequest, ExecutionRequest, ContainerId, and the corresponding operation-specific options.

Rebuild applications against the v1.0 SDK packages. Rust consumers must use the mxc_sdk::v1 module, .NET consumers must use the Microsoft.Mxc.Sdk.V1 namespace, and Node.js consumers must import from @microsoft/mxc-sdk/v1.

MXC v0.9.0 expands the stable sandbox surface with IsolationSession and WSL Container support, telemetry consent APIs, and new Windows ProcessContainer policy capabilities.

NPM release: https://www.npmjs.com/package/@microsoft/mxc-sdk/v/0.9.0 [https://www.npmjs.com/package/@microsoft/mxc-sdk/v/0.9.0]

See the Assets section for mxc-release-binaries.zip, which contains the signed production binaries and PDBs for the MXC project.

What's New in v0.9.0

Schema 0.9 is now stable

0.9.0-alpha is the current stable policy schema and the recommended version for new policies. Existing policies using schema 0.6, 0.7, or 0.8 remain supported. Schema 0.10.0-alpha is available for features that are still under development.

Schema 0.9 completes the directional networking transition. New 0.9 policies use network.egress, network.ingress, and, where applicable, runtimeConfig.networkProxy. Policies using earlier schema versions continue to use their existing network fields.

ProcessContainer is available on serviced Windows 11 builds

Windows 11 version 24H2 and 25H2 added Process Isolation for Microsoft Execution Containers in the August 2026 update KB5120998 [https://support.microsoft.com/en-us/servicing/os/windows-11/2026/08/kb5120998-windows-11-24h2-25h2-update].

The September 2026 update KB5124010 [https://support.microsoft.com/en-us/servicing/os/windows-11/2026/09/kb5124010-windows-11-24h2-25h2-update] adds the OS support MXC uses for:

Container-to-host loopback networking, represented by network.ingress.hostLoopback.

Enumerate-only filesystem access, represented by processContainer.filesystem.enumeratePaths. This permits directory queries and listing under the caller's existing access without granting file-content reads.

Install KB5124010 or a later cumulative update on Windows 11 24H2 and 25H2 to use these capabilities. On Windows 11 26H1, install the September 2026 update KB5124006 [https://support.microsoft.com/en-us/servicing/os/windows-11/2026/09/kb5124006-windows-11-26h1-update] or a later cumulative update.

IsolationSession and WSL Container join the stable surface

Schema 0.9 is the first stable schema release to include IsolationSession and WSL Container (wslc). Their one-shot and state-aware lifecycle APIs are included in the stable 0.9.0-alpha schema and no longer require experimental opt-in.

IsolationSession requires Windows build 26340.9212 [https://learn.microsoft.com/en-us/windows-insider/release-notes/experimental/preview-build-26340-9212] or later with the IsolationSession OS feature enabled.

Both backends support provision, start, exec, stop, and deprovision through the shared lifecycle model.

Windows Sandbox, MicroVM, and Hyperlight remain experimental and use the development 0.10.0-alpha contract.

Explicit environment inheritance

Schema 0.9 adds process.inheritDefaultEnv. Callers can now choose whether a supplied environment replaces the backend default or is layered over it.

Telemetry consent APIs

The Node.js SDK adds APIs to query, request, and withdraw MXC telemetry consent. Applications provide the consent presentation experience; MXC stores its own user decision and applies administrative policy only as an additional restriction.

Telemetry remains Windows-only, requires explicit user consent, and fails

closed.

Cross-platform enforcement and reliability

LXC directional networking now handles CIDR carve-outs more safely, waits for container addressing before execution, and fails closed when network initialization is incomplete.

Bubblewrap strengthens proxy and firewall enforcement, IPv6 handling, descendant cleanup, and network-provider failure detection.

Seatbelt enforces host-loopback policy, improves IPv6 loopback behavior, and fixes working-directory and listener behavior.

Learning Mode and denial capture add more actionable diagnostics and more robust stale-session recovery.

ProcessContainer selection and capability probing now avoid selecting an OS path that cannot enforce the complete requested policy.

Breaking Changes and Migration Notes

Node.js SDK

The minimum supported Node.js version is now 24.

Windows requires Node.js 24.21.0 or later within the Node.js 24 release line, or 26.8.0 or later. Node.js 26.8.0 or later is recommended.

MXC v0.8.0

MXC v0.8.0 is focused on a more consistent, fail-closed sandboxing experience across Windows, Linux, and macOS.

NPM release: https://www.npmjs.com/package/@microsoft/mxc-sdk/v/0.8.0 [https://www.npmjs.com/package/@microsoft/mxc-sdk/v/0.8.0]

See assets section for the mxc-release-binaries.zip file which contains all signed production binaries + pdbs for the MXC project.

What's New in v0.8.0

Schema 0.8 is now stable

0.8.0-alpha is now the current immutable stable policy schema and the recommended version for new policies. Existing 0.6 and 0.7 policies remain supported.

Stronger cross-platform networking

The new directional network policy separates:

Outbound traffic with IP/CIDR, protocol, and port rules

Inbound and host-loopback access

Container HTTP/S proxy configuration

Network permissions remain deny-by-default. ProcessContainer, Bubblewrap, LXC, and Seatbelt now validate the shared 0.8 contract and reject policies they cannot safely enforce instead of silently weakening them.

Safer proxy-only egress

Windows Process Container, Bubblewrap, LXC, and Seatbelt support schema 0.8 proxy-only egress on their enforcing paths. When platform prerequisites are met, MXC blocks direct network access and permits only the configured loopback HTTP/S proxy endpoint. Unsupported policy combinations are rejected rather than silently weakened.

Windows ProcessContainer proxy configurations have additional platform-specific requirements. See the ProcessContainer schema 0.8 proxy example [https://github.com/microsoft/mxc/blob/main/docs/process-container/examples/0.8.0-schema.md] for configuration and support details.

Windows ProcessContainer diagnostics

On Windows, ProcessContainer adds Learning Mode-powered denial capture. Applications can record resources blocked by a policy, use those results to refine the policy, and receive more actionable platform error details through the SDK. See the Learning Mode and denial-capture documentation [https://github.com/microsoft/mxc/blob/main/docs/learning-mode/capabilities.md].

Windows ProcessContainer availability

Important

To use the latest Windows ProcessContainer features today, use Windows Insider Preview Build 26340.9212 [https://learn.microsoft.com/en-us/windows-insider/release-notes/experimental/preview-build-26340-9212] or higher.

Windows 11 24H2 and 25H2 machines do not yet include all of the required OS-side changes, so ProcessContainer will not be fully featured on those builds. Updates bringing these changes to 24H2 and 25H2 are expected in the coming weeks.

Experimental backend progress

WSLc, IsolationSession, and Windows Sandbox gain major state-aware lifecycle improvements. These backends still require explicit experimental opt-in and are not part of the stable schema surface.
