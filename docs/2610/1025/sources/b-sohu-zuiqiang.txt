 最强Kimi上线，月之暗面致歉

ZAKER新闻

 2026-10-26 16:52

 [/media/120321309]

“问题出在我们，我们也本应更早修复。”

10月26日凌晨，月之暗面Kimi发布致歉信，为近期K3.1 Pro模型引发的限流和额度异常消耗向所有订阅会员认错。此时距离K3.1 Pro正式上线，才过去两天。

Kimi在致歉信中没有回避责任。

官方坦承，问题集中在两处：一是模型出现限流，高峰期响应被卡、任务推进受阻；二是用户的额度流失。补偿方案随之公布：所有有效期内的订阅会员，无论档位，统一获得月度总额25%的额度补偿，相当于一周的用量；如果当前消耗不足25%，则直接重置归零。调整结果在当天结束前同步到每位会员的用量页面，无需另行申请。官方同时表示已调整配置，正在减少不必要的子 Agent 调用和输出长度。

起因是10月24日，月之暗面发布K3.1 Pro，这是 K3.1 系列首个模型，3万亿级参数模型，支持 100 万 Token 上下文窗口，官方定位为公司迄今能力最强的产品。

第三方机构Artificial Analysis公布的首发评测中，K3.1 Pro取得55分，较K3提高11分，在当时的智能指数中排名第四。

但上线后，大量付费会员发现体验与预期严重不符：调用 K3.1 Pro 时频繁遭遇限流、响应变慢、任务中途中断，同时在未完成实际任务的情况下，额度被异常快速消耗。有开发者反映，模型在任务中自行启动了较多子智能体、输出冗长，是额度异常消耗的主要原因。

用户的反应并不一致。

有人在致歉声明下留言“把重置作为常规操作保留下去！”，认可补偿的到账速度；但更多付费用户的不满指向了更根本的问题：额度消耗的不透明。有用户吐槽“用token就用token表示呗，都用额度显示，一点不透明”，也有用户反映此前向客服申请售后时直接被告知“不行”，还有用户享受不到补偿“我下午就要切换周额度了，你上午重置，重置了个寂寞”。

这并非 Kimi 首次在新模型上线后调整服务。

今年7月，K3模型发布后，用户请求量在48小时内大幅超出预估、逼近集群承载极限，公司一度宣布暂停C端新用户订阅。两次情况的共同点，是新模型发布后的访问量集中上升，对算力调度和额度计算提出了更高要求。

K3.1 Pro的评测成绩并不差，在编程和3D建模基准上已接近国际头部模型。但评测分数和付费用户的实际体验之间，还存在一段距离。额度消耗是否透明、限流是否合理，才是订阅用户下一次续费时会重新评估的部分。
