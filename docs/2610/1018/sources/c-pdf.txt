1. Introduction
Frontier intelligence no longer scales through the model’s reasoning alone, but depends increasingly
on its ability to interact with the external world (Kwa et al., 2026; Sun et al., 2026; Team, 2026).
To solve a hard problem, an LLM agent must reach beyond the model itself by continually invoking
specialized tools, observing feedback from the environment, and adapting its next move (Feng et al.,
2026; Qu et al., 2025; Silver and Sutton, 2025). Beneath this expanding repertoire of agent harnesses
lies a single lingua franca: text, the common medium of both the agent’s autoregressive generation
and its environment interaction (Sumers et al., 2024; Zhang et al., 2026b). All intermediate reasoning
trajectories are generated token by token as text before the agent can act on the environment.
A separate line of work on latent reasoning points in a different direction (Chen et al., 2025; Zhu et al.,
2025b). By unfolding computation directly in continuous hidden space, latent models bypass the need
to decode and verbalize every intermediate step, providing more efficient internal reasoning within
the model’s “own language" (Hao et al., 2024; Wang et al., 2025; Yu et al., 2026). However, today’s
latent reasoners remain largely sealed behind the model boundary. Unlike decoded text, continuous
latent vectors (i) lack native pathways for tool invocation across multi-turn agentic reasoning (Chang
et al., 2026), and (ii) do not readily expose human-interpretable semantics, leaving them difficult to
supervise during training (Chen et al., 2026) and to audit or debug at inference (Korbak et al., 2025).
These constraints keep latent reasoning models from operating as capable agents in their own right.
Taken together, agentic interaction and efficient inner reasoning have so far required a different
medium each, leaving the two lines of work apart in the development of next-generation agents. We
believe this division can be closed by building a new type of agent that combines both strengths
to think beyond text while still acting through it. We call this unified design HybridAgent, one that
dynamically navigates between latent reasoning and text-based interaction within a single generation.
Building such an agent is hard, since it needs to handle both dense continuous vectors and sparse
discrete tokens as hybrid inputs, and determine when to transition between text and latent modes to
balance agentic actions and reasoning efficiency. To offset the hardness, we first revisit the model
architecture and extend its autoregressive generation interface to support hybrid inputs. At the heart
of this design is HybridLink, a lightweight residual adapter that bridges latent thoughts from the last-
layer hidden space back into the input embedding space and enables sequence-wise recurrence within
latent mode. Then, we realize multi-turn hybrid generation through the agent’s own working memory,
carrying complete hybrid trajectories of text, latent thoughts, and tool observations across turns.
Surprisingly, we find that HybridAgent can render its thoughts in latent mode as human-readable
pseudo-text, making latent reasoning transparent and directly inspectable rather than opaque.
To further unlock the potential of hybrid reasoning, we equip HybridAgent with dedicated post-
training algorithms. HybridSFT first stabilizes tool-integrated hybrid generation through activation
and self-conditioned training, which adapts the backbone to reason over latent thoughts produced by
its own HybridLink, enabling reliable coordination between the two components and closing the train-
inference mismatch. Then, HybridRL scales agentic reasoning capabilities by training HybridAgent
to adaptively balance latent reasoning and text-based interaction. To realize this, we enable policy
optimization over hybrid trajectories through hybrid policy factorization and exact rollout replay.
We provide theoretical grounding for HybridAgent through complementary analyses of multi-turn
context continuation and hybrid policy optimization. From an architectural standpoint, we show that
continuous working memory losslessly preserves the entire hybrid context across different turns. From
a learning perspective, the hybrid policy factorization and exact latent-context replay in HybridRL
provide a well-founded basis for policy updates over complete hybrid trajectories.
Empirically, we evaluate HybridAgent on 11 benchmarks spanning mathematics, science, medicine,

3. Building a Hybrid Reasoning Agent
We introduce HybridAgent, a hybrid framework that dynamically navigates between explicit text and
continuous latent reasoning within a single unified generation process. As illustrated in Figure 1, the
architecture preserves an LLM agent’s autoregressive generation and tool-calling interfaces while
accommodating both text and latent inputs. Below, we first present the hybrid interface for seamless
text-latent mode transition (Section 3.1), followed by multi-turn hybrid generation (Section 3.2).

3.1. Hybrid Mode Interface

Existing latent reasoning models typically feed the last-layer hidden state ℎ𝑡 directly back as the
next-step input 𝑒𝑡+1 . This design is not well suited to hybrid generation, as substituting ℎ𝑡 for a token
embedding creates a representation mismatch with the pretrained input space, making transitions
between continuous latent states and discrete tokens difficult. To support both latent and text modes
in a shared input interface, we add a lightweight adapter HybridLink to work alongside the backbone.
HybridLink as a Bridge. An LLM agent’s last-layer hidden states naturally encode the semantics of
its current generation, so the HybridLink R is designed to carry this information from the hidden
representation space back into the input embedding space. Formally, given any last-layer hidden
state ℎ𝑡 , HybridLink simulates its corresponding next-step input embedding as:

                                    𝑒𝑡+1 = R ( ℎ𝑡 ) = ℎ𝑡 + 𝑊2 𝜎 (𝑊1 ℎ𝑡 ) ,                            (4)

where 𝑊1 , 𝑊2 are standard linear projections, 𝜎 is an activation function (e.g., GELU). As the residual
connection largely preserves the original semantics of ℎ𝑡 , HybridLink only needs to align the distribu-
tional difference rather than learn the entire projection from scratch. Accordingly, the link module is
lightweight, with approximately 2𝑑ℎ2 parameters (e.g., ∼10M parameters for a 4B LLM).
Dynamic Text-Latent Mode Transition. Next, we describe how HybridAgent transitions between
text and latent modes during generation, together with the entry and exit decisions for each mode.
In text mode, HybridAgent behaves exactly as a standard LLM, sampling the next token from the
vocabulary at each step. The process continues until the agent generates one special token <latent>,
which serves as the entry anchor for the latent mode. For the next forward pass, the agent uses
HybridLink for latent reasoning in place of the LM head and token embedding layer.
In latent mode, each step’s last-layer hidden state is passed through HybridLink via Eq. 4, allowing
HybridAgent to continue its generation flow entirely in latent space without token decoding and
re-embedding. This sequence-wise recurrent computation over continuous representations extends the
agent’s effective reasoning depth, enabling more expressive internal reasoning. The latent reasoning
span terminates when the semantics of the last-layer hidden state ℎ𝑡 align with the exit anchor

3.2. Multi-Turn Hybrid Generation over Working Memory

In standard LLM agents, each turn’s generated content and tool outputs are appended to the textual
context and re-encoded as the next turn’s input prefix. Hybrid trajectories, however, interleave text
tokens with latent vectors and can’t be reconstructed through conventional tokenization alone. Instead,
HybridAgent carries the complete context across turns through its continuous working memory.
Cross-Turn Working Memory. Recall that a single-turn hybrid trajectory 𝜏 in Eq. 3 consists of
model-generated text, latent thoughts, and external tool interactions. During input construction,
all contents are mapped into the same input space through either the input embedding layer or
HybridLink. This shared space allows the Transformer to process all three components uniformly
and collect their KV entries throughout generation. We leverage these accumulated KV entries as the
HybridAgent’s continuous working memory to achieve multi-turn hybrid generation.

4. Learning to Perform Hybrid Reasoning
With the overall framework in place, we now turn to training. As HybridAgent leaves the backbone
architecture intact, no pre-training from scratch is required. Instead, we adapt the standard agentic
post-training pipeline of supervised fine-tuning and reinforcement learning to the hybrid setting. The
two training stages serve complementary roles: SFT teaches the agent to coordinate with HybridLink
and instantiate reliable tool use for stable hybrid generation (Section 4.1), while RL further scales
reasoning by learning when to think in latent space and when to act through text (Section 4.2).


4.1. Stabilize Generation via Hybrid Supervised Fine-tuning

As a first step toward stabilizing hybrid reasoning in HybridAgent, we design the entire HybridSFT
stage through a hybrid data curation pipeline and a staged training procedure.
Hybrid Data Recipe. To curate high-quality training data, we filter existing text-based agentic
SFT datasets from multiple sources and convert them into hybrid trajectories through automatic
annotation. We assign reasoning steps to latent mode based on both LLM Experts’ judgments and
target models’ own prediction entropy, while retaining a small set of key steps for tool interactions
and external debugging/auditing in text mode (see Appendix E for data curation details).

format and initialize the HybridLink. For format activation, we perform standard text SFT to teach
the backbone when to enter and exit latent mode by emitting the two special anchor tokens. We then

5. Empirical Evaluations
Tasks and Datasets. We conduct comprehensive evaluations of HybridAgent on 11 benchmarks
across various domains: (i) Mathematical Reasoning, including AIME 25 (math ai, 2025), AIME
26 (MathArena, 2026), and MATH500 (HuggingFaceH4, 2023); (ii) Knowledge-Intensive Reasoning,
including GPQA-Diamond (Rein et al., 2023), MedQA (Yang et al., 2024), and MuSiQue (Trivedi
et al., 2022); and (iii) Agentic Reasoning, including General AI Assistants (GAIA) (Mialon et al., 2024),
Humanity’s Last Exam (HLE) (Center for AI Safety et al., 2026), WebWalker (Wu et al., 2025),
SealQA (Pham et al., 2026), and DeepSearchQA (DSQA) (Gupta et al., 2026). We adopt the standard
evaluation metric for each dataset. Additional benchmark details are in Appendix H.1.
Baselines. For baseline comparisons, we evaluate HybridAgent against (i) Text-based Agentic Methods,
covering standard text SFT (with tools) and multi-turn tool-integrated RL methods such as GRPO (Shao
et al., 2024) and ARPO (Dong et al., 2025b); (ii) Latent Reasoning Methods, including SoftThinking
(Zhang et al., 2025), Coconut (Hao et al., 2024), and SoftCoT (Xu et al., 2025b); (iii) Frontier LLM
Agents, including GPT-5.6-Luna (OpenAI, 2026), Kimi-K3 (Team, 2026), GLM-5.3-Flash (GLM-5-Team
et al., 2026), DeepSeek-V4.1-Flash (DeepSeek-AI, 2026), QwQ-32B (Team, 2025); and (iv) Agentic
Frameworks, including ReAct (Yao et al., 2023), Search-o1 (Li et al., 2025a), and WebThinker (Li
et al., 2025b). Additional baseline details are provided in Appendix H.2.
Models and Training Setups. We instantiate HybridAgent with Qwen3-Base backbones (Yang et al.,
2025a) at three scales of 4B, 8B, and 14B. We then apply HybridSFT with 54K hybrid trajectories
curated through our automatic annotation pipeline, followed by HybridRL with 12K deep reasoning
examples (Yu et al., 2025) and 1K agentic search examples (Dong et al., 2025b). During RL, we set
rollout batches of 512 trajectories (64 × 8), followed by one optimization pass over 8 minibatches.
Implementation Details. HybridAgent interacts with external environments primarily through two
types of tools: a Python interpreter within sandbox environments and a live search engine (e.g., Tavily).
We cap tool usage at 10 calls per trajectory and retrieve the top 10 snippets for each search query.
As current serving engines do not support multi-turn hybrid generation, we extend the training and
inference infrastructure to enable text, latent, and tool-calling transitions and persistent KV working-
memory transfer. RL rollouts use a sampling temperature of 1.0, and evaluation uses temperature
0.6, top-p 0.95, and top-k 20. We conduct experiments on H100 GPUs using five independent seeds.
Additional training/inference details and hyperparameter setups are provided in Appendix H.3.

7. Related Work
Latent Reasoning Beyond Text. Recent works have explored applying intermediate reasoning
beyond discrete language tokens into continuous hidden spaces (Hao et al., 2024; Yu et al., 2026;
Zhu et al., 2025a), allowing models to perform internal computation without explicitly verbalizing
every reasoning step (Geiping et al., 2026; Shen et al., 2026; Zhu et al., 2025b). Existing approaches
broadly realize this idea by inputting last-layer hidden states (Saunshi et al., 2025; Tack et al., 2026),
compressing textual chains of thought into latent representations (Cheng and Van Durme, 2024;
Zhang et al., 2026a), or directly optimizing continuous reasoning trajectories (Chen et al., 2024; Tan
et al., 2026). These methods improve reasoning efficiency and depth but make direct inspection and
external interaction difficult (Chen et al., 2026; Korbak et al., 2025). HybridAgent builds on this
direction by integrating directly inspectable latent reasoning as a native built-in mode within the
agentic generation process, while preserving direct text-based auditing and tool interaction.
Agentic Reasoning and Tool Use. Frontier LLM agents (DeepSeek-AI, 2026; GLM-5-Team et al., 2026;
Team, 2026) extend reasoning beyond static generation by interacting with external environments
through tools (Qu et al., 2025; Shen, 2024), such as search engines (Jin et al., 2025; Zheng et al.,
2025b), code interpreters (Bianchi et al., 2026; Feng et al., 2026), and APIs (Patil et al., 2025; Qin
et al., 2024). A growing line of work further improves these capabilities through post-training over
multi-turn tool-use trajectories (Dong et al., 2025a; Qian et al., 2025), enabling agents to plan,
act, observe, and revise their reasoning (Li et al., 2025c; Su et al., 2025). Despite this progress,
existing agentic frameworks remain text-centric for both model-side reasoning and environment-side
interaction, incurring large generation overhead from verbalizing every intermediate step (Cuadron
et al., 2025; Xu et al., 2025a). HybridAgent decouples these roles by interleaving continuous thoughts
for internal reasoning and retaining text only where explicit interaction and monitoring are required.
We discuss additional related work and its relation to HybridAgent in Appendix D.


8. Discussion and Future Directions
Implications for Frontier Agent Safety and Secure Deployment. Frontier labs (e.g., OpenAI,
Anthropic) provide API-based access to reasoning models while hiding the chain-of-thought from
customers to protect intellectual property and limit information leakage, yet Panfilov et al. (2026)
show that the encrypted traces returned to clients can be replayed into a sibling model and transcribed
verbatim. HybridAgent places proprietary reasoning on a different footing. Latent thoughts exist
only as backbone hidden states that are readable solely through the provider-owned HybridLink
(Section 3), so no text exists to leak. The same property aids monitoring. Because the latent trace is
held by the provider rather than the client, providers can assess the safety of reasoning and actions
over the full readout, including the portion users never see, while the agent benefits from faster inner
thinking. Text mode is then reserved for what users legitimately need, such as tool calls, key decisions,
and the final answer, preserving an auditable trace without exposing the full reasoning.
Future Directions on Hybrid Agent Harness and Efficient Post-Training. Future work can build
a new type of agent harness around HybridAgent, where latent working memory is a first-class
component. Context management can then operate on KV entries directly, workflows can schedule
steps by mode, keeping tool calls and human-facing checkpoints in text while routine computation
stays latent, and one agent’s hybrid trajectory can serve as its message to another. Hybrid generation
can also make post-training more efficient. Because latent thoughts remain auditable during rollout, an
external critic can assign step-level credit to latent spans, branch promising trajectories, or terminate
ones whose latent reasoning has already gone wrong, before any text or tool call is produced.

9. Conclusion
We introduce HybridAgent, a unified hybrid reasoning framework that combines efficient latent
reasoning with text-based inspection and tool interaction. HybridAgent enables multi-turn hybrid
generation through both architectural designs and dedicated post-training algorithms on SFT and RL
stages. Across 11 benchmarks and 3 model scales, HybridAgent achieves strong performance against
advanced LLM agents and agentic frameworks spanning text-based and latent reasoning methods,
while substantially reducing inference time, token usage, and computational cost. Overall, HybridA-
gent provides a scalable and efficient framework for next-generation agents that can reason beyond
human language while retaining agentic interaction in environments and external inspectability.

The format and HybridLink activation provide a well-aligned initialization, but both are teacher-forced
(Figure 11, left). At every latent position, the backbone consumes the ground-truth embedding
Emb( 𝑦 ), and HybridLink is trained only to match its output R ( ℎ) to that target; the prediction itself
is never fed back as an input. At inference, the agent instead runs free (Figure 11, right). Once
it enters latent mode, every subsequent input is its own R ( ℎ), which neither the backbone nor
HybridLink has been conditioned on. This train-inference mismatch is akin to exposure bias (Bengio
et al., 2015; Ranzato et al., 2015), a standard issue in autoregressive sequence models that are trained
on ground-truth prefixes but consume their own predictions at inference.
It is worth noting that exposure bias is present in both text and latent modes, since both feed the
model’s own outputs back as inputs. In text mode (as in standard LLM SFT), each fed-back input
is sampled and re-embedded, and thus always corresponds to a token in the discrete vocabulary. A
prediction error, where the sampled token differs from the ground-truth target, only changes which
token is fed back; the input representation itself never leaves the set seen in training, so errors cannot
compound in the input space. Latent mode, in contrast, has no such projection. R ( ℎ) is continuous
and fed back unquantized, so even a small deviation from the target embedding becomes an input the
backbone has never seen in training. This deviation propagates to the next hidden state and hence
the next latent input, compounding over the tens to hundreds of steps in a latent span and gradually
eroding the semantic coherence of the latent trace.
Self-conditioned HybridSFT closes this gap by training both components on the model’s own generated
latent inputs. As in Figure 4, the teacher-forced first pass applies HybridLink to the last-layer hidden
state at each latent position, yielding the model’s own prediction of the next latent input. The second
pass then replaces the ground-truth latent embeddings with these predictions and trains the backbone

and HybridLink jointly, so both parts learn under the same latent inputs they encounter at inference.
Under this training scheme, the backbone learns to read, and HybridLink learns to produce, latent
inputs under the same conditions they encounter at inference. Thus, HybridAgent is trained as an
integrated whole rather than two separately activated components.


B.2. Learning When to Enter and Exit Latent Mode

As stated in Section 3, HybridAgent transitions between modes through two special tokens, the entry
anchor <latent> and the exit anchor </latent>. Within a latent span, these anchors are the only
positions supervised by LBackbone , while every other latent position is supervised by LHybridLink alone.
The two transitions are not symmetric, however. Entering latent mode is decided in text mode, where
the backbone samples the next token from the vocabulary as usual, whereas exiting must be decided
from a continuous latent state through the readout in Eq. 5. HybridSFT therefore treats the entry
anchor as an ordinary token and gives the exit anchor dedicated supervision.
Entry as a Text-Mode Decision. Since entering is a text mode decision, <latent> is simply a
cross-entropy target, and the backbone learns from the preceding context when to switch. The anchor
position then serves as the first latent step, with its last-layer hidden state passed through HybridLink
to produce the next latent input, so the span begins without any additional mechanism.
Exit as a Latent-Mode Decision. Exiting takes place in latent mode, where no token is sampled. By
Eq. 5, a span closes when the HybridLink’s output R ( ℎ) is nearest to Emb( </latent>), a decision
depending on both components, where the backbone produces a hidden state that encodes the exit
and HybridLink maps it onto the anchor embedding. HybridSFT therefore supervises the last latent
step of each span from both sides. On the HybridLink side, the regression target at this step is
Emb( </latent>), given slightly more weight than the span interior so that the single exit signal is
not diluted. On the backbone side, </latent> is also a cross-entropy target predicted from the same
hidden state, so the backbone itself learns to signal the exit.

D. Extended Related Work
Adaptive Reasoning on Text and Latent Space. Beyond fixed-length chains of thought, recent
work lets LLMs adapt how long and in which medium they reason (Bigverdi et al., 2024; Lv et al.,
2026; Yang et al., 2026; Ye et al., 2026), for example by learning when to stop latent reasoning or
deciding whether explicit deliberation is needed (Ning et al., 2025). Several methods interleave
latent reasoning with text decoding (Yue et al., 2025), using confidence or entropy signals (Xu et al.,
2026) to shift into continuous representations at uncertain steps and explore alternative reasoning
paths (Fu and Luo, 2026; Shi et al., 2026). However, existing methods largely operate within one
reasoning pass or switch modes only at single-turn granularity, and their latent states remain largely
opaque to inspect directly. Orthogonal to this line, HybridAgent uses latent mode for efficient deeper
reasoning, carries latent context across multiple turns through continuous working memory, keeps
latent thoughts directly readable, and preserves the agentic tool-use abilities for long-horizon tasks.
Hybrid Communication among Agents. A recent line of work in multi-agent systems (MAS) parallel
to HybridAgent studies hybrid-protocol communication, in which each inter-agent message combines
two media. A latent channel carries dense intermediate signals such as hidden states or KV entries,
while a text channel carries concise commitments that remain inspectable. Early instances augment
each natural-language message with the sender’s internal state trajectory (Tang et al., 2025), and later
work formalizes the dual-channel design by routing elaborate reasoning through latent vectors while
keeping answers and decisions in text (Dai et al., 2026; Mou et al., 2026). More recent works take
the same view from the deployment side, pairing every latent payload with a visible text commitment
wherever oversight is required (Liu, 2026) and evaluating the security of latent transfer alongside
visible text (Brito and Baquero, 2026). Complementary to these inter-agent protocols in the MAS
setting, HybridAgent decides the medium at the level of each generation step within a single agent,
switching between latent reasoning and text-based tool interaction over multi-turn trajectories.
KV-Cache Reuse. Reusing key–value (KV) entries across generation steps is standard practice for
efficient serving (Kwon et al., 2023; Zheng et al., 2024), and recent work extends it across requests,
caching shared prefixes and prompt modules (Gim et al., 2024; Juravsky et al., 2024; Ye et al., 2024)
and composing independently encoded caches so that repeated context need not be prefilled again
(Hu et al., 2025; Ma et al., 2025; Yang et al., 2025b). These methods treat the KV cache as an
optimization over a context that could in principle be re-encoded from text. HybridAgent likewise
builds on the backbone’s own KV entries, using them as a unified working memory that stores and
propagates both latent and text information across multi-turn hybrid generation.

H. Experiment Setups

H.1. Benchmark and Evaluation Details

We evaluate HybridAgent on 11 benchmarks spanning mathematical, knowledge-intensive, and agentic
reasoning. Together, these benchmarks assess complementary capabilities in multi-step problem
solving, specialized knowledge application, evidence integration, and tool-assisted information seeking.
We follow the setup of Dong et al. (2025b) and describe each benchmark in detail below.
(i) Mathematical Reasoning Tasks
AIME 25 (math ai, 2025): AIME 25 comprises 30 problems from the 2025 American Invitational
Mathematics Examination, covering algebra, geometry, number theory, and combinatorics. Its integer-
answer problems evaluate competition-level mathematical reasoning, requiring models to combine
mathematical insights with precise multi-step calculations.
AIME 26 (MathArena, 2026): AIME 26 contains 30 problems from the 2026 American Invitational
Mathematics Examination, following the same competition format as AIME 25. It provides a comple-
mentary assessment of mathematical problem solving across a separate annual problem set, testing
sustained reasoning and accurate numerical derivation.
MATH500 (HuggingFaceH4, 2023): MATH500 is a 500-problem subset of the MATH test set, spanning
7 mathematical subjects and 5 difficulty levels. It evaluates math reasoning across diverse problem
types, including symbolic manipulation, geometric deduction, and numerical computation.
(ii) Knowledge-Intensive Reasoning Tasks
GPQA-Diamond (Rein et al., 2023): GPQA-Diamond is a curated subset of 198 expert-written multiple-
choice questions in biology, physics, and chemistry. Selected through expert and non-expert validation,
these questions assess advanced scientific knowledge and reasoning that remain challenging for
non-experts even with web access.
MedQA (Yang et al., 2024): MedQA is a multiple-choice question-answering benchmark derived from
professional medical licensing examinations. The dataset contains 300 questions in total. Its questions
assess medical knowledge and clinical reasoning, requiring models to interpret patient information
and identify appropriate diagnoses, investigations, or treatments.
MuSiQue (Trivedi et al., 2022): MuSiQue is a multi-hop question-answering benchmark constructed
by composing single-hop questions into connected reasoning chains of two to four hops. It evaluates
the ability to combine evidence across multiple passages, with question construction designed to
reduce shortcuts that bypass intermediate reasoning steps. Following Dong et al. (2025b), we use
200 test-set questions for downstream evaluation across all methods.


                                                                                                     36
                                       Hybrid Reasoning Agents


(iii) Agentic Reasoning Tasks
General AI Assistants (GAIA) (Mialon et al., 2024): GAIA evaluates general-purpose assistants on
real-world questions involving reasoning, web browsing, information processing, and external tool
use. Its three difficulty levels reflect increasingly demanding combinations of reasoning steps and
tool interactions, assessing the ability to coordinate these capabilities toward a verifiable answer.
Humanity’s Last Exam (HLE) (Center for AI Safety et al., 2026): HLE comprises expert-authored
questions across a broad range of academic disciplines, including mathematics, natural sciences, and
the humanities. Its multiple-choice and short-answer problems assess advanced subject knowledge
and reasoning on questions designed to resist quick answers through direct web retrieval.
WebWalker (Wu et al., 2025): WebWalkerQA, referred to as WebWalker in our evaluations, is an
agentic search benchmark requiring exploration of website subpages and integration of information
from one or multiple sources. Its easy, medium, and hard categories reflect increasing traversal depth,
testing the ability to locate and synthesize evidence beyond surface-level search results.
SealQA (Pham et al., 2026): SealQA evaluates search-augmented question answering on factual
questions for which retrieved information may be noisy, conflicting, or unhelpful. We evaluate on Seal-
0 and Seal-Hard, which test factual accuracy and reasoning under challenging retrieval conditions.
Seal-0 targets questions selected for near-zero accuracy among the non-reasoning models used during
benchmark construction; Seal-Hard includes a broader collection of difficult questions.
DeepSearchQA (DSQA) (Gupta et al., 2026): DeepSearchQA evaluates multi-step web research through
tasks that require assembling complete answer sets from information distributed across sources. It
tests search planning, evidence aggregation, entity disambiguation, and the ability to determine
when sufficient information has been collected. We report both full-correct rate and F1 score to assess
complete task success and the balance between answer precision and coverage.


H.2. Baseline Details

To evaluate the effectiveness and efficiency of HybridAgent, we compare with 4 categories of methods,
including (i) Text-based Agentic Methods, (ii) Latent Reasoning Methods, (iii) Frontier LLM Agents,
and (iv) Agentic Frameworks. We describe the implementation details of each baseline below.
(i) Text-based Agentic Methods
Standard Text SFT: We apply standard SFT using the same training data and backbone models
as HybridAgent. During evaluation, the models can invoke tools and incorporate the returned
observations into subsequent reasoning. We use this baseline mostly to compare with the HybridSFT.
Agentic RL (GRPO/ARPO): We apply commonly adopted agentic RL methods after standard text
SFT to further train the text agent baselines. GRPO (Shao et al., 2024) optimizes the policy using
group-normalized rewards from sampled responses without requiring a separate critic. ARPO (Dong
et al., 2025b): ARPO combines entropy-guided adaptive rollouts with step-level advantage attribution
to improve multi-turn tool use. We train these methods using the same RL training data and backbone
models as HybridAgent, primarily to evaluate the effectiveness of HybridRL.
(ii) Latent Reasoning Methods
Coconut (Hao et al., 2024): Coconut performs continuous latent reasoning by directly feeding the
model’s last hidden state back as the next input embedding. A staged training curriculum progressively
replaces textual reasoning steps with latent thoughts, teaching the model to reason in continuous
space before generating a textual answer.


                                                                                                     37
                                       Hybrid Reasoning Agents


SoftCoT (Xu et al., 2025b): SoftCoT uses a lightweight frozen assistant model to generate question-
dependent soft thought representations, which a trainable projection maps into the target LLM’s
representation space. These representations guide subsequent generation, enabling latent reasoning
while keeping the assistant and target LLM frozen.
SoftThinking (Zhang et al., 2025): SoftThinking is a context-based method that represents interme-
diate reasoning as probability-weighted mixtures of vocabulary embeddings. Feeding these hidden
continuous representations back into the model preserves alternatives from the next-token distribution.
We implement all latent reasoning baselines using the same backbone models and, where applicable,
training settings and budgets as HybridAgent to ensure a fair comparison.
(iii) Frontier LLM Agents
To evaluate HybridAgent in a broader context, we compare it with current leading closed-source and
open-source LLM agents, including GPT-5.6-Luna (OpenAI, 2026), Kimi-K3 (Team, 2026), GLM-5.3-
Flash (GLM-5-Team et al., 2026), DeepSeek-V4.1-Flash (DeepSeek-AI, 2026), and QwQ-32B (Team,
2025), to assess both performance and inference efficiency of HybridAgent.
(iv) Agentic Frameworks
We further compare HybridAgent with established agentic frameworks that integrate multi-step
reasoning with external tool calling and environmental interactions. We apply Qwen3-14B as the
backbone for all these frameworks, with the same tool access and usage budgets as HybridAgent.
ReAct (Yao et al., 2023): ReAct interleaves natural-language reasoning with actions and observations
from an external environment. This interaction loop allows an agent to gather information, revise its
reasoning, and determine subsequent actions based on tool feedback.
Search-o1 (Li et al., 2025a): Search-o1 augments large reasoning models with adaptive search to
address knowledge gaps encountered during reasoning. Its Reason-in-Documents module analyzes
retrieved documents and extracts relevant evidence before incorporating it into ongoing reasoning.
WebThinker (Li et al., 2025b): WebThinker equips LLMs with a Deep Web Explorer that supports
iterative search, webpage navigation, and information extraction. Its Think-Search-and-Draft strategy
interleaves reasoning, evidence collection, and report generation to support complex research tasks.
Overall, these baseline methods provide complementary comparisons across training stages, text-based
and latent-space reasoning, and tool-integrated agentic settings.

Infrastructure and Configurations. As existing training and inference frameworks such as verl
(Sheng et al., 2025) and vLLM (Kwon et al., 2023) do not directly support multi-turn hybrid generation,
we extend their infrastructure to enable hybrid training and generation in HybridAgent. A shared
generation loop coordinates text mode, latent mode, and tool interaction while maintaining each
trajectory’s persistent KV cache as continuous working memory across turns. The agent enters latent
mode through the special entry anchor <latent>, feeds HybridLink-generated latent inputs back
into the backbone, and returns to text mode when the nearest-token readout matches the exit anchor
</latent>, as in Eq. 5. Tool observations are tokenized and processed against the existing working
memory, appending new KV entries without reconstructing or re-prefilling earlier context.
The engine also supports batched rollouts with per-sequence state tracking, allowing trajectories to
occupy different generation states within the same batch. Pending tool calls execute concurrently,
with waiting and completed sequences masked from further generation. Per-sequence attention masks
and position tracking preserve each trajectory’s causal context as generation proceeds. For HybridRL,
exact latent-context replay recomputes sampled text-token likelihoods in a single differentiable
forward pass while keeping recorded latent inputs unchanged. We check rollout–replay agreement of
log-probabilities at unchanged policy parameters. Multi-node data parallelism, sharded optimizer
states, mixed precision, gradient checkpointing, and resumable checkpoints support full-parameter
backbone optimization. Overall, the same engine supports RL rollouts, training-time validation, and
downstream evaluation, ensuring consistent mode transitions and working-memory handling across
configurable sampling settings, generation budgets, and tool-call setups.

   Always start and end the think block with plain text: open with a brief
