About the benchmarks

These benchmarks measure how well LLM coding agents implement and reason about programs in KillSwitch, a deliberately adversarial language whose source embeds real logic inside misleading prose.

Methodology

Each agent gets a task prompt, a copy of the spec, and a capped per-task budget and time limit. Success depends on producing a runnable program or correctly interpreting a provided one. Scores combine pass rate with cost and implementation size, so a model is rewarded for passing cheaply and concisely.

Benchmark runs have the following characteristics:

Deterministic evaluation. Each task used to evaluate an LLM model has a known correct answer. Evaluation is done programmatically, there is no grading using an LLM.
No internet access. Agents have no outbound network access beyond a scoped proxy to the model API, so solutions can't be fetched or looked up.
Isolated containers. Each run executes in its own container with a capped per-task budget of $5 and a hard 30 minute timeout.
Harnesses and models. Coding agents (OpenCode, Codex, Claude Code) are benchmarked together with the models driving them, so results reflect the combined system.
Repeated runs. Each model is tested at least twice on each task.
Complementary materials. For each task, models are supplied with the KillSwitch language's SPEC.md and AI_SPEC.md files. For some tasks, a KillSwitch script file implementing a program may also be included. Some, though not all tasks, also include a `killswitch` interpreter binary, which the agent can freely run and inspect.
