# 1018 期 C 组取证：HybridAgent 潜在空间推理（arXiv 2610.18861）

执行：Sonnet 5.5（claude-sonnet-5-5）。时区：北京时间（UTC+8），括号内为原时区。论文页码指 arXiv v1 PDF 页码（c-pdf.pdf，45 页）。存档读取时刻 2026-10-19 17:08–17:25（北京时间）。

核心结论（先读这里）：摘要里的四个数字不是同一个对象之间的比较。
- “10.4%”：摘要说是相对 frontier LLM agents 与 agentic frameworks；正文 5.1 节只在这一句里出现 10.4%：HybridSFT/HybridRL “improve over corresponding text/latent baselines by 18.5% at the SFT stage and 10.4% at the RL stage”，前提是 “under matched model sizes and training budgets”，即对象是同样 Qwen3 底座、同样数据训练的 GRPO/ARPO 等基线。相对 frontier LLM agents 的数字是另一句：14B “improving over the strongest agentic baseline by an average of 17.4%”。论文没有给出 10.4% 与 17.4% 的计算公式（相对/绝对、对哪些列平均），我用 Table 1/2/8 试了多种聚合，均未复现（见 C3 备注）。
- “token 减少 35.5%–54.7%”：图 6 的纵轴是 “Token/Step Usage”，对比 “Pure Text” 与 Hybrid，Hybrid 柱含潜在步（latent steps）；−35%/−52%/−54% 是总生成步数的降幅，不是文本 token 的降幅。文本 token 的降幅另算：图 6 标 “2.2x / 2.9x / 3.1x fewer tokens”，5.2 节写 “2.7× fewer text tokens”。
- “推理提速 1.8x–2.6x”：图 7，三个规模合并（pooled）的 wall-clock，文本基线 134 s/sample → Hybrid 63 s/sample（“2.1x faster”），“45%–61% less time” 对应 1.8x–2.6x；硬件、批量、是否含工具/搜索耗时、基线用哪个推理引擎，正文均未交代。
- “成本节省 2.7x–3.7x”：附录 G.2 表 9，是理论解码 FLOP 乘以一个假设单价估出的，不是实测账单；明确排除 prompt prefill、attention、外部工具执行；对照是同底座的纯文本 agent，不是 frontier 模型；不含训练成本。
- 三个效率指标的对照对象都是 “matched text-based LLM agents”（同底座 Qwen3-Base 的纯文本 agent），不是 GPT-5.6-Luna、Kimi-K3 等 frontier 模型。

## 二、可能的吠点

线索摘要（abs 摘要）没有写、但原文里有的条件与限制（每条注出处）：
1. 10.4% 的口径：摘要写成对 frontier agents 与 frameworks 的平均提升；正文唯一的出处句是“matched model sizes and training budgets”下、RL 阶段对“corresponding text/latent baselines”的提升（p10）。相对 frontier 行的另一数字是 14B 对“strongest agentic baseline”的 17.4%（p10）。论文未给计算公式，我无法复现（C3b）。
2. frontier 对比只在表 1 的 5 项 agentic 基准上出现；HLE 与 DSQA 上 HybridAgent 低于若干 frontier 行（表 1，p9）。表 2 的数学/GPQA/MedQA/MuSiQue 里只有同底座训练的基线。
3. “token reduction”含潜在步：图 6 把总步数（文本 token + 潜在步）与纯文本 token 数相比，文本模式部分另标 2.2x–3.1x；每个潜在步仍是一次完整前向（表 9 说明）。
4. 延迟只给了三规模合并的一组数（134 s 对 63 s），无硬件、批量、工具耗时、基线引擎说明（p11）；HybridAgent 跑在作者自扩展的推理引擎上（p8）。
5. 成本是理论估算：按 FLOP 乘假设单价，不含 prefill、attention、工具执行、训练成本（表 9 与 p36）；对照是同底座纯文本 agent。
6. 评测样本小：MedQA “The dataset contains 300 questions in total”，MuSiQue “we use 200 test-set questions”（附录 H.1，p36）；AIME25/26 各 30 题；作者自报 5 次独立运行平均标准差 ±0.014（表 1 说明）。
7. 用 GPT-5.6-Luna 同时当搜索页摘要器与评判：“We utilize GPT-5.6-Luna as both the search-page summarizer and LLM judge.”（p39）。GPT-5.6-Luna 也是表 1 的 frontier 基线之一。
8. 可读性证据是代理指标：readability 是余弦最近词嵌入，论文无单独 Limitations 节，没有直接的忠实性检验（C6）。README 真实示例读出文本不通顺（“Wait, I me the the speed of speed in air”）。
9. 只在 Qwen3-Base 4B/8B/14B 训练；“any standard pre-trained LLM” 是设计主张；公开权重只有 8B、14B，无 4B（C2、C7）。
10. ## 四、扫描说法勘误

- “开源仓库 https://github.com/togethercomputer/HybridAgent”：属实（MIT，213 星，创建 10-09，见 C7）。
- “基座为 4B、8B、14B 的 Qwen3-Base”：属实；但公开权重只有 8B、14B（无 4B）。
- “机构含斯坦福、UIUC、Together AI”：属实；另有 Meta（Yunzhe Qi 第二单位），扫描漏了。
- “用邻近 token 嵌入展示潜在状态的可读近似”：属实（nearest token embedding，Eq. 5，p4），论文称之为 “pseudo-text”。
- “HN 50145337 382 分 / 187 评，10/18 20:48 UTC”：读取时刻 17:16（北京）为 384 分 / 187 评，创建时刻属实。
- 已知情况里把摘要的“token reduction / faster inference / cost savings”默认当作三个指标：属实且口径各异（见开头核心结论）；“相对谁”的答案是同底座纯文本 agent，不是 frontier 模型。
