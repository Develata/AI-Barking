TL;DR

A Flamerix AI gist found Claude Code's agent_summary feature consumed 16.4% of one week's spend versus 15.7% for the main conversation.

Every ~30 seconds, Claude Code sends each background agent's full transcript to Opus to produce a 3-5 word status line, at ~9,000 input tokens per output token.

Anthropic's edwinarbus says typical cost is closer to 2% at API list price (6% in terminal) and a cache-miss fix shipped in 2.1.311+.

A GitHub gist by Flamerix AI [https://gist.github.com/flamerix-ai/c3905705cc4205e5de3011fa2e74efce] measured Claude Code's agent_summary feature consuming 16.4% of one week's spend, more than the 15.7% that went to the main conversation itself. The feature's job is to generate a 3-5 word status line.

Every ~30 seconds, for every background agent, Claude Code sends that agent's entire transcript to the agent's own model, usually Opus, and asks it to "describe your most recent action in 3-5 words". Flamerix writes: "The answer only updates the agent's status line in the agents panel; it never reaches the model or your conversation." In the same run, 19.7% of all API requests were summary calls, at roughly 9,000 input tokens per output token.

The feature has been on by default since version 2.1.232, which the gist dates to August 2026, with no documented setting to disable it. The author's workaround is a ~80-line Bun preload called no-agent-summary.js that wraps setTimeout and setInterval, matches the summarizer's callback by source text, and returns an inert handle instead of arming the timer. The gist says it has been verified across versions 2.1.257–2.1.312 on Linux.

The post landed on Hacker News [https://news.ycombinator.com/item?id=50284255] and drew a reply from edwinarbus of Anthropic's Claude Code team. His account differs: across users sending telemetry, agent_summary represents roughly 2% of API-list-price cost, 6% in the terminal specifically; the 16.4% figure, he said, reflects "a team running mostly background agents" and "doesn't seem like a typical session". He pointed to a cache-miss fix already shipped in version 2.1.311+ and said the team is working on "a much cheaper mode that sends short notes to a smaller model".

The thread fits a widening run of coverage about Opus-tier calls stacking up quietly inside agent loops on our Anthropic tracker [https://aiweekly.co/ai-news-today/anthropic-news]. Flamerix publishes the preload under MIT and warns the match depends on current implementation details.

 Editor's note

Opus-tier status-line pings are a real line item for background-agent teams; Anthropic now puts the typical share at 2% but confirms a cheaper small-model mode is in flight, so audit telemetry before scaling Claude Code agent fleets.

 Editor's take

If telemetry on 2.1.311+ still shows background-agent-heavy users above Anthropic's quoted 2% share, the small-model status mode moves from roadmap item to shipping priority.

Why does a client feature that routinely calls Opus still lack a documented off switch, three minor versions after default rollout?
