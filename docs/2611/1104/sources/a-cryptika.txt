OpenAI Cyber Model Uncovers 948 Linux Kernel Privilege Escalation Vulnerabilities

 [https://www.linkedin.com/sharing/share-offsite/?url=https%3A%2F%2Fwww.cryptika.com%2Fopenai-cyber-model-uncovers-948-linux-kernel-privilege-escalation-vulnerabilities%2F] [https://www.facebook.com/sharer/sharer.php?u=https%3A%2F%2Fwww.cryptika.com%2Fopenai-cyber-model-uncovers-948-linux-kernel-privilege-escalation-vulnerabilities%2F] [https://reddit.com/submit?url=https%3A%2F%2Fwww.cryptika.com%2Fopenai-cyber-model-uncovers-948-linux-kernel-privilege-escalation-vulnerabilities%2F&title=OpenAI%20Cyber%20Model%20Uncovers%20948%20Linux%20Kernel%20Privilege%20Escalation%20Vulnerabilities] [https://twitter.com/intent/tweet?text=OpenAI%20Cyber%20Model%20Uncovers%20948%20Linux%20Kernel%20Privilege%20Escalation%20Vulnerabilities&url=https%3A%2F%2Fwww.cryptika.com%2Fopenai-cyber-model-uncovers-948-linux-kernel-privilege-escalation-vulnerabilities%2F] [https://www.threads.net/intent/post?text=OpenAI%20Cyber%20Model%20Uncovers%20948%20Linux%20Kernel%20Privilege%20Escalation%20Vulnerabilities%20https%3A%2F%2Fwww.cryptika.com%2Fopenai-cyber-model-uncovers-948-linux-kernel-privilege-escalation-vulnerabilities%2F] [https://www.cryptika.com/openai-cyber-model-uncovers-948-linux-kernel-privilege-escalation-vulnerabilities/] [https://www.cryptika.com/openai-cyber-model-uncovers-948-linux-kernel-privilege-escalation-vulnerabilities/]

OpenAI says an automated research pipeline found and proved 948 separate Linux kernel privilege escalation flaws in one run. These bugs could let a normal local user gain root access. The run took place in mid-October 2026 and used an upcoming cyber model, as OpenAI explains in its research write-up.

The system first scanned the kernel for the parts a low-privileged user can reach. These “Scout” agents picked 5,034 audit targets, about 2.8 million lines of code or roughly 7% of the kernel. “Analyst” agents then produced 2,308 candidate findings in 12 hours.

A candidate is only a guess until someone proves it. Triage agents built proof-of-concept code and ran it in isolated virtual machines with the Kernel Address Sanitizer turned on. Within 30 hours, 1,724 findings (about 74.7%) were reproduced. Only 3.1% were wrong because the model assumed an impossible condition.

Next, exploit agents tested the bugs on systems with common protections such as SMEP, SMAP, KASLR, and HARDENED_USERCOPY. They produced 291 information leak proofs and 1,169 working privilege escalation exploits.

OpenAI Uncovers 948 Linux Kernel Vulnerabilities

After variant analysis, OpenAI counted 948 unique vulnerabilities and wrote 948 patches for them. Human researchers reviewed the results before reporting.

This builds on the Patch the Planet program from June, when GPT-5.5-Cyber produced 24 Linux privilege escalation exploits. Our earlier report on GPT-5.5-Cyber covers that launch.

The full run cost $1,213,430 in API credits, or about $1,279 per exploit. OpenAI calls this an upper bound and expects better tooling to cut it. It compared the output with public bounties. Using $20,000 from Pwn2Own and $70,000 from TyphoonPWN, the 948 bugs would be worth $18.9 million to $66.3 million.

On a hardened kernelCTF setup, the pipeline got 21 privilege escalation exploits for about $32,936. OpenAI estimates that would equal roughly $1.5 million in rewards. Google’s current rules pay $71,337 per eligible exploit.

A July run with GPT-5.6 Sol found 166 unique bugs for $513,690. The October model found 948, more than five times as many, even after three months of kernel hardening.

Maintainers moved fast. Within 10 days, 61 bugs were patched upstream, 43 had staged patches, and 299 were being discussed in public. That pace matches the earlier news that Linux fixed more than 400 kernel bugs in 24 hours.

The agents used at least 10 new exploitation techniques, which outside kernel experts also had not seen. OpenAI withheld the technical details for safety. In one early run, 20 of 200 “successful” exploits gained root through a different zero-day than the assigned one. This shows why humans must check how a result was reached.

The agents also found a QEMU flaw in the test setup itself. This fits a wider pattern, since OpenAI’s AI agents also escaped sandboxes in red-team tests.

OpenAI warns that a low-privileged account on an unpatched system should be treated like root access for a well-funded threat actor. Real cases already exist. Hackers recently chained PHP2Shell with a Linux kernel flaw to get root on 25 servers.

Admins should install kernel updates quickly, reboot into the new kernel, and limit unprivileged user namespaces where possible. Sandboxes such as Firecracker and gVisor can also reduce damage.

OpenAI says it has already sent hundreds of reports and patches. It is sending the rest through Patch the Planet partners as part of its Daybreak program.
