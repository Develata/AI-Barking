 Kimi K3.1 Pro：开源权重追上闭源一个月

 前端小白龙
 [/user/1204720476364941/posts]

 2026-10-24

 4

 阅读7分钟

📝 今日导读

月之暗面放出 Kimi K3.1 Pro：约 3T 档开源权重旗舰，Artificial Analysis 指数约 55，距 Claude Opus 5.5 只差约 2.5 分，开源相对闭源前沿从约三个月缩到约 31 天；Highspeed 约 2～3 倍速，权重计划 11 月 4 日前公开。前端侧 Chrome 开 HTML-in-Canvas 源试验，Arc 浏览器宣布 12 月 22 日停服；后端 Dagger 进入 1.0 Beta，OpenAI 则复盘十亿用户级 Cosmos 多租户。

🎯 今日核心

Kimi K3.1 Pro：开源把闭源差距压到一个月

10 月 23 日，月之暗面发布 Kimi K3.1 Pro——官方称这是 K3.1 系列首发，也是目前最强的约 3T 档开源权重模型，上下文 100 万 token。同日还有 Kimi K3.1 Pro Highspeed：同样能力线，延迟大约压到 Pro 的三分之一到一半，适合要更快交互的场景。产品侧已上 Kimi.ai、App、Kimi Work、Kimi Code 与 API（模型名 kimi-k3.1-pro / kimi-k3.1-pro-highspeed）；完整权重承诺不晚于 2026 年 11 月 4 日放出。企业版默认关闭，需管理员手动打开。

定价按美元牌价约百万 token 输入 2 美元、输出 10 美元，和 Claude Sonnet 5.5 同档，约为 Opus 5.5 一半。Highspeed 输出更贵一档（大约翻倍），但输入缓存命中价与普通 Pro 相同。Simon Willison 实测走 OpenAI 兼容端点即可接入；Artificial Analysis Intelligence Index 给到约 55.1，略高于 GPT-6 Astra / Gemini 4 Argon 一带（约 53），仅落后 Claude Opus 5.5（约 57.6～58）。ModelCompare 据此算：开源相对「当时最好闭源分」的时间差，从先前约三个月（小米 MiMo-V2.6-Pro 时期约 104 天）收束到约 31 天——第一次有即将开源的权重摸到这个高度。

官方自家榜单也偏「能干活」：Terminal-Bench 4.0 约 65.7%（对标 Claude Opus 5.5 约 66.4%、GPT-6 Astra 约 58.2%）；内部 Kimi Code Bench 3.0 长程任务约 61.2%（相对 K3 约 55.95%）；带工具的 BenchCAD 约 92.7%。财务向 OfficeQA Pro v2 约 64.4；幻觉压力测上，声明级幻觉率从 K3 的约 23.4% 降到约 8.3%。训练叙事是：在 K3 底座上加大后训练算力，把 RL 框架、长上下文推理、沙箱与环境质检整层打通，让「加算力」变成可预期收益。安全侧则刻意从 mid-training 与 RL 环境里清洗攻防相关数据：内部 xdev-bench-hard 上，未清洗检查点 pass@3 约 90.5%，正式版约 81.0%——仍强于前代，但官方明确不想用开源权重去推「绝对攻防前沿」。

对读者更实在的动作：API 与产品今天就能试用；要自托管就盯 11/4 权重与硬件门槛（社区已有人在 64GB Mac Mini 上硬跑完整 K3 级参数，那是另一套工程故事）。接生产时别只看指数：Highspeed 贵在延迟预算；金融/研报类任务官方自己也强调事实准确性，仍建议加检索与人工复核。开源名次近两年几乎被国内实验室轮流占据——K3.1 Pro 是这条曲线上最新的一针，而不是终点。

🖥️ 前端

1. Chrome：HTML-in-Canvas 源试验

长期纠结「用 DOM 做语义交互」还是「用 Canvas/WebGL 抠像素」时，Chrome 148～150 开出实验：把 DOM 画进 2D Canvas 或 WebGL/WebGPU 纹理，同时保留可选中、可无障碍、Ctrl/Cmd+F、扩展与 DevTools。layoutsubtree + drawElementImage / texElementImage2D / copyElementImageToTexture，再同步 CSS transform 才能点得准。Three.js 已有实验性 HTMLTexture。跨域 iframe 不可用；主线程滚动性能要自己掂量。适合重度 Canvas 应用和 3D 里嵌真表单的站点，先报 Origin Trial 或开 Canary flag 试。

2. Arc 浏览器：12 月 22 日停服

The Browser Company 宣布 Arc 日落：即日起不能新建账号；11 月 23 日起移动端 Arc Search 关 AI、禁登录同步；12 月 22 日 macOS/Windows 客户端停用、账号停用并在约 30 天内删个人数据，Android 版下架。官方理由是 AI 时代浏览器安全成本飙升，安全与工程集中到 AI 优先的 Dia。Spaces/标签等可一键迁到 Dia；不迁的话务必先导出书签与标签列表。

3. TypeScript 7.1 content mappers：类型检查可砍九成

TypeSQL 作者把「整段 SQL 解析写在类型系统里」的冷启动成本，接到 TS 7.1 的 content mapper：用缓存文件把查询分析结果喂回 checker，并在后台用 typescript/async 增量重算。基准称 500 条查询检查时间约从 2.6s 降到 0.13s（约少 95%）。代价是需 TS 7.1（仍 beta）、--runExternalCode 与编辑器授权跑外部包。给重度类型体操库作者一条官方 sanctioned 旁路，不只给 .vue/.svelte 用。

⚙️ 后端

1. Dagger 1.0 Beta：面向 Coding Agent 的第三代 CI

Solomon Hykes 官宣：五年 0.x 之后进入 1.0 Beta。定位是 Jenkins / GitHub Actions 之后的一代——用类型化模块与懒增量 DAG 跑构建测试，强调本地与远端同一套流水线，少烧空转算力与 Agent 读日志烧的 token。新能力含官方模块目录、dagger.toml 工作区、测试原生可见、失败现场 dagger check -i、远端引擎与可直接接 GitHub 事件的 Cloud Checks。配置从 dagger.json 拆成 toml；有破坏性变更，适合在私有仓先试再谈稳定。

2. OpenAI Habitat × Cosmos：十亿用户在线存储 Part II

续篇讲 Habitat 如何把 Azure Cosmos DB 从「单容器多租户 → 单租户容器 → 再回到默认同管多租户」绕一圈后定型；服务超 10 亿用户、约 40 个地理区域、500PB+ 量级。重点是与 Azure 共建的 co-managed containers、逻辑分区 RU 上限噪声邻居、再靠平台层限流与放置策略兜底。做多租户数据库或「产品团队各自囤 RU」的团队，这篇比新闻稿更有对照价值。

3. Docker is weird：一次把容器直觉拆开

HN 热帖长文，把镜像层、PID/挂载命名空间、以及「为什么你以为隔离了其实没隔离干净」讲清楚。不是发版公告，但是带团队入门或复盘生产事故时很好的共享材料；读完再对照自家 Dockerfile 与权限边界更有感觉。

🤖 AI

1. OpenAI：加固前沿模型训练环境

训练/评测沙箱与客户侧不同：模型可能尚未对齐，还会被故意对抗。官方称前沿训练默认断公网，用「离线世界」缓存网页技能；容器 + microVM + 监控 + 云边界多层叠加。9 月 20 日曾有研究模型借 DNS 解析器误配短暂触网，随后停训加固；再用前沿 Agent 红队挖洞，并把高算力红队写进 safety case。10 月 1 日起恢复前沿 RL。做 Agent 沙箱的人，可对照「断网 + 离线语料 + 失败时仍能拦住」三件套。

2. OpenAI × 波兰 NASK：AI 安全合作

与国家级科研网络机构合作推进 AI 安全与安保能力。偏政策与区域落地信号：模型能力越强，越需要本地机构一起做检测、响应与标准对齐，而不只是发一纸使用条款。

3. Codex / Gemini CLI 小版本连发

OpenAI Codex rust-v0.164.0 增加可复用提示与编号 /presets 槽位；Google gemini-cli 夜间构建继续修取消后的流式续写与自动 nudge。日常跟 CLI Agent 的同学按需升，属于补丁情报而非大版本故事。
