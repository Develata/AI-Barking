Kimi K3.1 Pro 完整权重开源：2.8 万亿参数、1.56TB、8 卡起步

 🕐 2026-11-05

 大模型与产品

 🔥 47 次点击

月之暗面把 Kimi K3.1 Pro 完整权重放上 Hugging Face 与魔搭，2.8 万亿总参数、约 1040 亿激活、100 万 token 上下文，以 MXFP4 量化发布，96 个分片合计 1.56TB，vLLM 基线要求 8 张数据中心 GPU。许可证基本沿用 MIT，但对 MaaS 转售与超大商业产品设了两条营收与月活门槛。

类别： 大模型与产品

主要来源： [P0] Hugging Face moonshotai/Kimi-K3.1-Pro 模型卡与 LICENSE；[P1] 凤凰网科技、新浪科技、PANews

证据强度： B（权重、模型卡、许可证可下载核对；参数量、上下文、量化格式为一手；第三方榜单 Vals AI 与 Agent Arena 提供部分交叉，但均为榜单方自述口径，未取得原始评测脚本）

本篇关键词： Kimi K3.1 Pro、开放权重、MXFP4、稀疏注意力、1.56TB、许可证门槛、Vals AI、Agent Arena、vLLM、自部署

月之暗面（Moonshot AI，全称北京月之暗面科技有限公司）——中国大模型公司，Kimi 系列模型开发者；Hugging Face（Hugging Face, Inc.）——美国开源模型托管平台，本次权重主要分发渠道之一。

上期日报把"权重是否在 11-04 前开放"列为到期观察项，答案是按期兑现：11-04 深夜至 11-05 凌晨，moonshotai/Kimi-K3.1-Pro 出现在 Hugging Face，模型卡与 96 个 safetensors 分片同时可下载，魔搭同步。

二、产品背景

Kimi K3.1 Pro 于 10 月 24 日发布，当时只开 API，并承诺 11-04 前放出完整权重。这个承诺在当下有特殊背景：开源阵营的分数与闭源前沿正在收窄，但"能下载"与"能跑"之间的距离在拉大。2.8 万亿参数的模型即使量化到 4 位，仍需上 TB 存储与多卡并行，这使开放权重的意义从"人人都能跑"变成"任何组织都能自己托管、自己微调、自己决定数据去向"。

月之暗面在模型卡与官方博客中的定位是"迄今能力最强的 3T 级开放权重模型"，并把 K3.1 Pro 描述为 K3 的大规模后训练版本：后训练算力显著增加，通过跨数百个下游领域的联合强化学习提升长程编码、3D 创作、金融长文与智能体链式任务s-AIDe★epThINk.cn。

三、采用的技术原理或方法

1. 长上下文改用稀疏注意力

据新浪科技对照 K3 的架构说明，K3.1 Pro 把原先使用全注意力的 24 层改为稀疏注意力：每个 token 只挑出最相关的约 2048 个 token 参与计算。这与 DeepSeek 此前公开的稀疏注意力路线同源，目的是在 100 万 token 上下文下把注意力计算量压下来。这一改动直接影响部署成本结构——长上下文的显存与算力开销不再随长度线性上升，但代价是检索精度依赖选择策略，官方未公布该策略的召回评估。

2. 后训练规模化与能力裁剪

官方把提升主要归因于后训练：跨数百个领域的联合强化学习。同一份材料也披露了一次主动的能力削减：中期训练语料与强化学习环境里原本混有网络攻防相关内容，开源版本把这两处数据移除，只保留通用编程任务。月之暗面给出的内部基准 xdev-bench-hard 上，未做该处理的检查点解题率 90.5%，实际发布的 K3.1 Pro 为 81.0%，差 9.5 个百分点。这是厂商自述的内部基准、未公开，第三方无法验证 81.0% 是否真实，也无法验证微调能否恢复被抑制的能力。

3. 量化发布与工程取舍

以 MXFP4 发布权重、激活用 MXFP8，是这次开源最实际的工程决策：它把 2.8T 模型压到 1.56TB，使"单机柜级别"的自建部署成为可能；代价是发布的是量化版本而非原始精度权重，下游若要做高质量继续预训练，起点已经被量化过。官方称采用了量化感知训练来补偿精度损失，但未公布与 BF16 版本的同任务对照。

四、解决的问题

它针对的不是"模型不够强"，而是三个具体的可获得性问题：

一是闭源前沿模型的调用成本与配额约束，官方 API 定价为输入 13 元、输出 68 元每百万 token，约为对标闭源模型的一个较低档位；

二是数据不能出内网的场景，权重可下载意味着可以完全离线部署；

三是研究可复现性，权重公开后，第三方可以在同一模型上做可比较的 harness 与微调实验。

七、定价或者使用策略

官方 API： 输入 13 元／百万 token、输出 68 元／百万 token；Highspeed 变体价格翻倍、速度约 2–3 倍。缓存命中价在第三方平台标为 0.20 美元／百万 token，官方人民币价未在同一页面给出。

第三方托管： OpenRouter 上输入 2 美元、输出 10 美元每百万 token；11-05 06:34 的 P50 数据显示，Modal 端点为 118 token/s、首字 0.73 秒，官方端点为 25 token/s、首字 5.45 秒，官方 Highspeed 为 59 token/s。这些是负载相关的分位数，不能当作稳定 SLA。

许可证两条门槛： 允许免费使用、修改与转售，公司内部使用不受限；但把推理或微调作为 MaaS 开放给第三方、且集团连续 12 个月收入超过 2000 万美元的，商用前需单独签约；商业产品月活超过 1 亿或月收入超过 2000 万美元的，界面须醒目标注 "Kimi K3.1-Pro"。本期未取得许可证全文的法律意见，条款解释以 LICENSE 原文为准。

自部署成本： 1.56TB 下载量、8 卡起步；官方提供 Kimi Vendor Verifier 供核对第三方端点是否保持原版能力（DeepSWE 上官方 0.755、Modal 0.764、Together 0.735）。

八、应用场景、方法或者案例

1. 需要数据不出域的行业部署

目标用户：金融、医疗、政务与大型制造企业的平台团队。

做法：以 8 卡节点为最小单元私有化部署，用官方 API 兼容层承接现有调用；对长文档（研报、合同、代码库）依赖 100 万 token 上下文一次装入。

当前状态：权重可下载、可部署，但本期未见具名企业私有化案例，也无第三方公布生产环境吞吐。

准入条件：存储 1.56TB 以上、至少 8 张数据中心 GPU、具备 vLLM 级别推理运维能力。

2. 第三方推理托管与价格竞争

目标用户：需要低成本长上下文调用的开发者。

做法：在 OpenRouter 等平台选择非官方端点，价格相同但吞吐差异可达四倍以上；上线前用 Vendor Verifier 跑一遍回归。

当前状态：已有多家端点在线（Together、Modal、Parasail、Nebius、阿里云百炼等），可用率从 80% 到 100% 不等。

已知失败条件：多轮工具调用需把 reasoning_content 原样回传，切端点时若不处理会破坏 agent 行为；最低价端点（Relace，输出 7.88 美元）可用率仅 80%，且未列 tools 参数。

九、局限与待验证事项

1. 适用范围

发布的是 MXFP4 量化权重，不是原始精度；用于继续预训练或高精度对齐研究时，起点已被量化。

100 万 token 上下文的能力边界未公开评测：官方只给出上下文长度，未给出长上下文检索准确率随长度的衰减曲线。

官方基准混用不同 harness，跨模型比较只能作方向参考。s-AIDe★epThINk.cn

2. 待验证指标

第三方在自有 8 卡节点上复现 65.7% 与 63.64% 的差距来源（harness、推理预算、评分器）。

AA 46.5 与 55 的口径差异究竟是版本更新还是子项不同。

许可证两条门槛的实际执行案例：是否已有 MaaS 厂商签约、是否有产品被要求加标注。

xdev-bench-hard 81.0% 的绝对水平：这个数字本身仍高，防守方应按"实际残余能力"自测，而不是按"已削弱"假设。

十、安全与伦理

1. 突破的边界s-AIDe★epThINk.cn

这次开源没有突破能力前沿，但突破了"开放权重的能力上限"这一惯例：此前开放权重模型少有在 3T 量级、且在后训练上对标闭源前沿的。月之暗面自己划的线是"不发布会扩展网络攻防绝对前沿的权重"，并用移除训练数据的方式把内部检查点从 90.5% 压到 81.0%。

2. 新增风险面与安全措施

新增风险面有三个：一是权重可被移除安全微调，厂商的"能力裁剪"在开放权重下不再是不可逆约束；二是攻击性能力虽有削减但绝对值仍高（内部基准 81.0%）；三是第三方托管端点的合规与数据留存政策不一致，企业代码出境风险上升。已有措施是数据移除、发布前内部审计与 Vendor Verifier 工具，覆盖范围限于官方端点与列入表中的托管商。

3. 硬性约束与价值争议

硬性约束来自两方面：许可证的营收与月活门槛属于合同约束，不是技术约束；出口管制与数据出境规则则因部署地而异，本期未逐国核对。价值争议在于"削减能力再开源"是否有效——移除训练数据降低的是模型自发倾向，不阻止下游用少量数据微调恢复；厂商选择公开这个差值（90.5% vs 81.0%），本身是把判断权交给使用方。
