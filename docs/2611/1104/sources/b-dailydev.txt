Kimi K3.1 Pro model weights are out [https://api.daily.dev/r/Fbrf3kpbp]

Kimi K3.1 Pro is an open-weight, natively multimodal agentic model and the first in its K3.1 series. It's a 2.8-trillion-parameter mixture-of-experts model with 104B activated parameters and a 1-million-token context window. It scores 65.7 on Terminal-Bench 4.0 and 92.1 on BrowseComp. The model uses a MoonViT-V2 vision encoder, Gated DeepSeek Sparse Attention layers, and MXFP4/MXFP8 quantization-aware training, and it's deployable via vLLM, SGLang, or Docker.

Questions this post answers

How many parameters does Kimi K3.1 Pro have and how many are active per token?

Kimi K3.1 Pro has 2.8 trillion total parameters in a mixture-of-experts architecture, with only 104 billion activated per token. It has 93 layers, 896 experts with 16 selected per token plus 2 shared experts, and a vocabulary size of 160K. Its context window extends to 1,048,576 tokens (1 million tokens). daily.dev helps engineers weighing MoE model trade-offs track specs like this across new releases.

What attention mechanism does Kimi K3.1 Pro use instead of full attention?

Kimi K3.1 Pro replaces the full-attention Gated MLA layers used in Kimi K3 with Gated DeepSeek Sparse Attention (Gated DSA) layers for more efficient long-context modeling. Its attention-layer composition is 69 KDA (kernel-based delta attention) layers plus 24 Gated DSA layers, with a DSA index top-K of 2048 and 32 index heads. anyone optimizing long-context inference can follow architecture shifts like this via daily.dev.

How do I run Kimi K3.1 Pro locally with vLLM or SGLang?

Install vLLM with 'pip install vllm' then run 'vllm serve "moonshotai/Kimi-K3.1-Pro"', or install SGLang with 'pip install sglang' and launch it via 'python3 -m sglang.launch_server --model-path "moonshotai/Kimi-K3.1-Pro" --host 0.0.0.0 --port 30000'. Both expose an OpenAI-compatible chat completions API callable with curl, and Docker images are also provided. developers standing up new model servers can keep deployment guides like this handy on daily.dev.
