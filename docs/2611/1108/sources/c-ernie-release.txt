1. 引言

一个 Base 模型的价值，既在于预训练建立了怎样的能力基础，也在于它为后续训练提供了怎样的起点。不同的领域、推理任务和 Agent 应用，需要不同的数据、训练目标与行为策略。开放预训练终点权重，让开发者能够在已有的通用能力之上，自行选择模型下一阶段的训练方向。

今天，我们发布 ERNIE-5.5-Flash-Base，向社区开放这一阶段的成果。它是一个稀疏 MoE 语言模型，总参数 280B，每 token 激活 14B，在 33.5T tokens 上从零完成预训练；最长训练上下文为 128K，微调与推理支持 1M tokens 上下文。本次发布的权重是预训练终点的 checkpoint，未经中训练与后训练，可作为领域适配、指令微调和强化学习研究的共同起点。

为了让这个起点具有长期使用的价值，我们从模型设计之初就把效率作为重要目标。后续训练中的反复采样，以及 Agent 应用中的多步交互和长上下文处理，都会持续累积计算与存储开销。因此，ERNIE 5.5 Flash 从注意力、残差连接到 MoE 层和输出头，逐个组件审视能力与效率的关系，将激活计算、KV cache 和长上下文处理开销纳入整体设计。

同样的长期视角也贯穿数据与训练系统。预训练数据决定了后续一切训练所依托的能力底座，因此语料着重加强那些事后难以补足的能力，如仓库级代码与长上下文理解；而架构上的效率设计，只有在大规模训练中同样高效才真正有意义，因此模型与训练系统是协同设计的。

我们希望，这次发布能让更多开发者复用大规模预训练的成果，将资源投入各自关心的能力、任务与训练方法。

核心亮点：

开放后续训练的起点。 提供未经中训练与后训练的 Base 权重，支持社区自行探索领域适配、推理强化和 Agent 训练路线。

面向持续训练与推理的效率设计。 结合稀疏 MoE 与混合稀疏注意力，在架构层面统筹模型容量、激活计算和长上下文开销。

全面的数据，高效的训练。 广覆盖、高质量的预训练数据为后续训练打下全面的能力底座；与模型结构协同设计的训练系统，保证大规模预训练高效进行。

阶段明确的研究基线。 以预训练终点的统一 checkpoint，支持不同训练方法的对照评估与增益分析。

2. 模型结构

 [/release/ernie-5-5-flash-base/architecture.png]

ERNIE 5.5 Flash 模型结构点击查看原图 ↗

ERNIE 5.5 Flash 共 43 层 Transformer，hidden size 4096，64 个注意力头。

2.1 Latent-Gated Sparse Attention

MLA + HCA 混合注意力： 大多数层只需要对远距离历史有一个粗粒度的视野，因此我们每七层中只保留一层对全上下文做 token 级访问，这些层采用多头潜在注意力（MLA）。其余各层采用重度压缩注意力（HCA）：每 128 个 token 压缩为一条缓存条目，对这些压缩条目以及最近一小段未压缩 token 构成的窗口做稠密注意力。这样，HCA 层只需全上下文层 KV cache 的一小部分，就能保留对整个序列的全局视野。

按层类型设置头维度： 头维度并非全模型统一，而是与各层的注意力计算量相匹配：计算量小的层用大头，计算量大的层用小头。HCA 层在 128 倍压缩后的序列上做注意力，计算量小，因此可以使用 512 维的宽头，额外计算很少；MLA 层逐 token 访问上下文，计算量更大，因此 query/key 与 value 均使用较窄的 256 维头。

KV cache 预算向 MLA 层倾斜： 绝大多数层采用 HCA 之后，关键的设计问题在于剩余的 KV cache 预算如何分配。一种做法是分给大量压缩稀疏注意力（CSA）层：这类层先将历史压缩 4 倍，再从中稀疏选取一部分做注意力。我们则将这部分预算集中用于少数保留全部 token 的 MLA 层。在 KV cache 预算相当的预训练对比中，HCA 搭配 MLA 优于搭配 CSA。

全上下文层采用稀疏注意力： 只有 MLA 层逐个访问远距离的历史 token。若做稠密注意力，长上下文下的注意力计算量会主要集中在这些层，因此它们采用稀疏注意力（DSA）：一个轻量级 indexer 为每个 query 给历史位置打分，核心注意力只在得分最高的 top-k 个位置上计算，每个 query 的核心注意力开销由此不再随上下文长度增长。采用 DSA 后，这些层的预训练 loss 与稠密注意力持平，训练速度显著提升。

注意力层内部还有两项改进：

低秩门控注意力（Low-Rank Gated Attention）： 门控注意力在注意力输出上施加一个可学习的输出门，已被证明能同时提升模型效果和训练稳定性。按照常规做法，门由该层的隐状态计算。我们改为用每个注意力层本来就会生成的低秩 query latent 来计算门。由于 query latent 的维度只有隐状态的四分之一，门投影的权重参数量在 ERNIE 5.5 Flash 中减少了 75%，同时在消融实验中效果也有所提升。ERNIE 5.5 Flash 的所有注意力层都采用了低秩门控注意力，MLA 层和 HCA 层均包括在内。

Virtual Head Attention（VHA） [https://arxiv.org/abs/2610.17959]：在注意力之后施加一个带恒等跳连的轻量跨头低秩混合，增强跨头信息融合，提升模型表达力与训练质量；推理时融合进注意力算子，开销几乎可忽略。

2.2 Multi-Router Latent MoE

传统 MoE 只用一个路由器给专家打分，再通过一次硬 top-k 选出专家。但我们发现，这个打分与专家的实际效用只是弱相关，中深层尤其明显；而落选的专家拿不到该 token 的梯度，一旦选错就很难纠正，错误会不断自我强化。

Multi-Router [https://arxiv.org/abs/2610.40577] 不再只靠一个路由器，而是让多个独立初始化的 sigmoid 路由器一起给专家打分。这些路由器的偏好会明显分化：一个专家只要被某个路由器强烈看好，或者被几个路由器同时看好，就有机会入选，选错后也更容易被纠正。这样，单个路由器打错分不会直接左右路由结果，路由对噪声特征和分布变化也更稳健；激活专家数、专家 FLOPs 和通信量则与单路由器完全相同。与单路由器相比，路由打分与专家实际效用的相关性明显提升，原本相关性最弱的中深层提升最大。

除第一层外，各层 FFN 均为 MoE 块：

512 个路由专家选 10，外加 1 个共享专家，负载均衡采用无辅助损失的 bias 修正方案。

隐空间专家。 每个 MoE 层先把 token 从 4096 维投影到 2048 维隐空间，专家（中间维 2048）在该空间内计算，最后经一次共享的上投影映射回原空间。相对全宽专家，dispatch/combine 通信量与专家 FLOPs 约减半。

Stable LatentMoE 设计与可学习标量。 MoE 块采用 Stable LatentMoE 的设计（上投影前的 RMSNorm 与 SiTU-GLU 专家激活），使专家输出在 43 层中保持合适的尺度，也让优化更稳定。在这一 RMSNorm 的基础上，每个路由专家的路由权重还会乘以该专家自己的可学习标量（learnable scalar）。

2.3 流形约束超连接（mHC）

模型采用 mHC 替代标准残差连接：每层通过受约束的混合矩阵读写 4 条并行残差流，以几乎可忽略的额外计算拓宽层间残差带宽。

2.4 MultiMax 输出头

单一的 softmax 温度难以兼顾两头：调低温度让分布变稀疏，但会把其他合理候选一起压掉；调高温度能保留多个候选，又会抬高不合理 token 的长尾。MultiMax 用可学习的分段温度打破这一取舍：在词表输出头上，它压制不合理 token 的长尾，同时保留合理候选 token 的多样性。logits 在分块、Triton 融合的交叉熵 kernel 内、softmax 之前逐元素调制，训练开销可以忽略、不增加显存，同时显著降低预训练 loss。

2.5 ECHO：取代 MTP 模块

传统多 token 预测（MTP）在主干上额外挂接专用模块来预测未来 token，多步损失主要监督这些模块，主干各层仍只为下一个 token 服务。ERNIE 5.5 Flash 用 ECHO [https://arxiv.org/abs/2610.24766] 取代 MTP 模块：直接复用主干自身的最后一层做未来预测，不再需要独立的 MTP Transformer 层，多步损失直接作用于生成下一个 token 的参数。让这些参数预测更远的 token，促使主干提前规划序列的后续展开，在推理与代码等任务上带来明显收益。ERNIE 5.5 Flash 以单步 ECHO 预训练；该层作为投机解码的草稿模型涌现外推特性：同样只训练一步，多步起草质量大幅优于辅助 MTP。

2.6 分词器

ERNIE 5.5 Flash 使用全新的 BPE 分词器，词表约 200K。数字采用从右到左（R2L）、最多三位一组的切分方式，使不同长度数字的数位对齐（如 1,234,567 → 1 234 567），有利于算术与数字密集文本。

3. 预训练

ERNIE-5.5-Flash-Base 在 33.5T tokens 上从零完成预训练，采用 Muon 优化器与 FP8 混合精度。训练上下文在预训练过程中逐步扩展至 128K tokens，微调与推理支持 1M tokens 上下文。本次发布的 checkpoint 为预训练终点的 Base 模型，未经过任何中训练与后训练。

3.1 数据

预训练语料覆盖广泛的领域与语言，兼顾知识广度与数据质量。在此基础上，我们在数据上重点建设了三个方向：

网页数据。 结合大规模多语言网页抓取、高保真文本抽取与模型驱动的多维质量过滤，获得知识覆盖广、有效学习信号密度高的网页语料。

代码数据。 来自代码仓库与网页的代码经过非代码过滤、面向召回的去重与多粒度质量分级。在静态代码之外，补充软件演化与执行验证类数据：commit、issue、pull request、代码评审、需求→PR 与多 commit 轨迹、自动生成的测试，以及经 CI 验证的修复，用于增强仓库级推理与 Agent 软件工程能力。

长文数据。 由三部分互补构成：经长程依赖筛选、基于 embedding 的去重、LLM 质量打分与规则清洗得到的天然长文档；将天然文本与检索到的语义相近干扰文本拼接构造的长序列；以及合成的 MRCR 式检索、基于引用的问答与多跳问答数据。

3.2 训练基建

本次训练配套了两项基建工作：在数千卡规模下保持高效的分布式 Muon 优化器，以及面向大 Head Dim 的注意力算子 FlashMask-4 [https://github.com/PaddlePaddle/FlashMask]。

分布式 Muon 优化器。 与 Adam 等逐元素优化器不同，Muon 采用逐张量（tensor-wise）的正交化更新，这同时改变了分布式训练的通信模式与显存分布。我们通过两项优化使 Muon 在数千卡规模下真正可用：

通信高效的 Muon 更新。 传统方案中，Dense 参数依赖跨机大环通信（千卡大环），跨机链路长、小消息多，链路利用率低，时延与抖动随集群规模显著上升；MoE 参数则走跨机同号卡通信。我们将 Dense 通信也统一改走跨机同号卡路径，并把 Dense 与 MoE 的同号卡通信融合为单次集合通信。有效 message size 因此大幅提升，带宽利用率随之提高；拓扑更规整，更契合专家并行通信；在不改变优化器语义的前提下，跨机时延与抖动显著降低。

面向显存均衡的切分优化。 Muon 的通信效率依赖足够大的 message size，朴素切分会把大量参数张量堆叠到靠前的卡上，造成节点间优化器状态存储严重失衡：少数节点显存压力过高、易触发 OOM，其 checkpoint 保存与远端上传/下载也会变慢，极大拉长故障恢复时间；卡数越多，影响越明显。我们提出节点间均衡切分方案，将相同的优化器状态向更靠后、更多的卡上摊开，在保持大 message size 以维持高效通信的同时，使各节点显存占用接近均衡。

FlashMask-4：面向大 Head Dim 的高效注意力。 FlashAttention 类算子的效率高度受制于 shared memory、tensor memory 等片上存储资源，大 Head Dim 下容易出现算力利用率不足，部分配置甚至难以实现。FlashMask-4 基于 CuTe-DSL 实现，同时支持 SM90 与 SM100 架构；在 SM100 上通过 2-CTA 分块并行计算与 Tensor Memory 双 Buffer 轮换实现大 Head Dim 下的高效计算，同时保留 O(N) 列式稀疏掩码表示与全掩码块跳过等原有优势。它支持高至 qk_head_dim = 576、v_head_dim = 512 的规模，这一规模 FlashAttention-4 并不支持。在 SM100 GPU 上，FlashMask-4 相比 FlashAttention-4 MaskMod 前向性能提升高至 175%，反向提升高至 74%。

ERNIE-5.5-Flash-Base 已在 Hugging Face [https://huggingface.co/baidu/ERNIE-5.5-Flash-Base] 以 ERNIE 5.5 Flash Base Model License Agreement v1.0 [https://huggingface.co/baidu/ERNIE-5.5-Flash-Base/blob/main/LICENSE] 发布，提供 FP8 与 BF16 两种 safetensors 权重（BF16 版本为 ERNIE-5.5-Flash-Base-BF16 [https://huggingface.co/baidu/ERNIE-5.5-Flash-Base-BF16]）。Base 模型要求每条输入以 BOS token 开头，分词时请保持 add_special_tokens=True。

Python · Transformers复制代码

from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_name = "baidu/ERNIE-5.5-Flash-Base-BF16"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name, torch_dtype=torch.bfloat16, device_map="auto")
model_inputs = tokenizer(["ERNIE 5.5 Flash 的混合注意力结构"], add_special_tokens=True, return_tensors="pt").to(model.device)
print(tokenizer.decode(model.generate(**model_inputs, max_new_tokens=256)[0], skip_special_tokens=True))

SGLang 与 vLLM 均可通过 completions API 提供服务，部署方法见模型卡。微调请参考 ERNIE 5.5 示例 [https://github.com/NVIDIA-NeMo/Megatron-Bridge/blob/main/examples/models/ernie55/]。

6. 总结与展望

ERNIE-5.5-Flash-Base 的出发点是：一个用于后续训练的 Base 模型，应当从设计上就是高效的。我们从注意力、残差连接到 MoE 层和输出头，逐个组件权衡能力与效率，并以广覆盖、高质量的预训练数据和与模型结构协同设计的训练系统作为支撑。每 token 仅激活 14B 参数，模型在各类能力维度和长上下文评测上都取得了不错的效果，同时保持了较小的 KV cache 占用。

Base 模型只是起点。经过后训练的 ERNIE 5.5 Flash 将随后推出，我们也期待社区在这一基座上探索领域适配、推理强化与 Agent 训练等方向。
