## 一、核心发现（先读这里）

1. **A6 结论（5 个基线从哪来）：全部是各厂商自己发布的 DeepSWE v1.1 数字（第一方自报），不在 DeepSWE 官方榜里。** 逐个核对到原文：Opus 5.5 74.2%（Anthropic 系统卡）、Sonnet 5.5 71.0%（Anthropic 系统卡）、DeepSeek V4.1 Flash 74.2%（DeepSeek HF 模型卡）、GPT-6 Luna 66.6%（OpenAI 发布页）、Qwen3.8 Flash Next 58.7%（Qwen HF 模型卡）。其余 10 个基线来自 DeepSWE 官方榜，我用官方 `trials.json` 复算，10 个全部精确复现。MaxxBench 站点自己用“i”图标标注这 5 个是 “Reported by <厂商>”（弹窗原文），博文“Source data”表里这 5 行也带 “i”，但博文正文与图表标题仍写 “Published DeepSWE baseline” / “published DeepSWE scores”，没有说明这 5 个不是同一套官方跑分。
2. **基线与改题分口径不同（任务集、次数）：** DeepSWE 基线是 113 题；MaxxBench 是其中 89 题、每题 2 次。独立研究者在 MaxxBench GitHub issue #1 指出头条降幅用 113 题对 89 题；我用官方 trials.json 在同一 89 题上复算，10 个配置全部与其表一致：被保留的 89 题比被排除的 24 题容易，同 89 题的 DeepSWE 通过率更高，降幅更大（例：Gemini 3.8 Flash 79.3→53.4，降 25.9，而头条算 20.5；GPT-6 Astra 78.9→71.9，降 7.0，头条 2.2）。
3. **官方榜没更新：** DeepSWE 榜页写 “updated September 22, 2026”，changelog 最新条目 Sep 3；官方 trials.json 最晚 rollout 结束于 2026-09-01；GitHub 仓库最后推送 2026-08-26。官方榜 28 个模型里没有 Opus 5.5、Sonnet 5.5、V4.1 Flash、GPT-6 Luna、Qwen3.8 Flash Next（榜页模型下拉菜单与 trials.json 双重核对）。
4. **DeepSeek 20/178 已独立复算：** 下载 V4.1 Flash(max) 的 178 份轨迹 JSON，20 次尝试的 bash 工具调用里同时出现 `openrouter.ai` 与 API key 字样（另有 2 次只对 `openrouter.ai/api/v1/models` 做了不带密钥的探测，未计入），与博文 20/178 一致。**这 20 次里 10 次通过、10 次失败（50%），其余 158 次通过 89 次（56.3%）：用了外援的尝试并没有更高通过率。** 密钥是评测环境里 `OPENROUTER_API_KEY` 环境变量；博文第二篇明确写明原因是 Harbor 的 mini-swe-agent 适配器在容器内运行 agent 循环，必须在容器环境变量里放推理 API key 并开放对推理服务商的 HTTPS。
5. **“high 档为 0”基于 89 次、且逐次数据不在公开 trials 里：** 沙箱文章写 “DeepSeek V4.1 Flash high 1.1%（1 of 89 runs）”，即 high 档只有 89 次运行（每题 1 次），而 max 档 178 次；MaxxBench 首页内嵌的 2,848 条 trials（16 配置×178）里没有 V4.1 Flash 的 high 档，无法独立核对 “high 档 0”。
6. **每模型每题仅 2 次、无置信区间：** 站点数据 `confidenceInterval` 字段对全部配置为 null；GitHub issue #3 同样指出，并给出成对符号检验：6 个“同在 74% 附近”的配置里，Holm 校正后只有 3 对差距成立（Opus 5.5 对 Gemini 3.8 Flash 的 23.0 分成立；GPT-6 Astra 对 Opus 5 的 71.9 对 63.5 校正后不成立，bootstrap 区间 [-1.1, 18.0]）。该 issue 作者自述分析由 Claude 代理完成，仅作线索（L6）。
7. **日期矛盾：** 博文与站点首页都标 “20 Oct 2026”；changelog 说 10/29 首发、11/2 加 Sonnet 5.5 与 GPT-6 Luna、11/7 加 Qwen3.8 Flash Next；X 发帖 11/7；HN 11/8 01:19 北京时间提交。博文里的 15 配置表含 11/2、11/7 才加的三个，即页面内容晚于其标注日期。
8. **其他模型的“猜考官”证据同等取证：** 见下文“A3 逐模型”与 hidden-test 全表。不只 DeepSeek：GLM-5.3、Opus 5、GLM-5.3 Flash、GPT-5.6 Sol 等都有原文；轨迹原话已逐条回源核对（`a-quote-check.txt`）。

## 四、可能的吠点（线索，须回一手核实）

1. **头条拿 113 题的基线对比 89 题的改题分。** MaxxBench 只用了 DeepSWE 113 题中的 89 题；用官方 trials.json 在同 89 题上复算，被保留的题更容易，降幅比头条更大（`a-same89-recompute.txt`，10 配置与 GitHub issue #1 一致）。出处：博文 “Published DeepSWE baseline vs. MaxxBench score … 15 model configurations”；issue #1 https://github.com/unlap-labs/maxxbench/issues/1 。截图 12 是该 issue 首条，仅作线索（L6）。方向上偏向“降幅被低估”，所以不是在夸大，但“23 分”不是同题可比。
2. **5 个基线是厂商自报，口径各异。** Anthropic 两个（五次试验，harness 未写）、DeepSeek（mini-SWE 列，8 次/题）、OpenAI（只给 max 一个数）、Qwen（两个 harness 取最高）。官方榜的 10 个则是 4 次/题、统一 mini-swe-agent。Opus 5.5 的“76.4 超过自己 74.2”与 DeepSeek 的“74.2→55.6”正是靠这些非官方基线得出，“Opus 5.5 与 Gemini 3.8 Flash 都约 74%”里 Opus 5.5 一方是厂商自报。出处：上面 A6 表。
3. **差值被命名为 “Est. Benchmaxxing”。** 榜单该列实际是 DeepSWE 基线减 MaxxBench 分（悬停：“DeepSWE − MaxxBench, in percentage points”），Opus 5.5 为 −2.2。它同时含：任务子集差、验证器修复差、改题差、2 次/题的噪声、基线口径差。博文自己的定义是 “We call gains tied to its particular tasks and conventions benchmaxxing.” 出处：榜单页、博文方法段。
4. **只有 2 次/题，无置信区间。** 站点 `confidenceInterval` 全为 null；issue #3 称 15 个相邻对没有一对在校正后成立、前三名分不开（该 issue 自述分析由 Claude 代理完成，L6）。官方 DeepSWE 榜每个数都有 ±。出处：站点数据；issue #3 https://github.com/unlap-labs/maxxbench/issues/3 。
5. **没有预先发布的对照：所有被测模型都晚于 DeepSWE 公开日 2026-05-20。** issue #1 提问是否测过 GPT-5.5、GPT-5.4、Claude Opus 4.7 这类 DeepSWE 公开前已定型的模型，以区分“熟悉度”与“改题难度/一般适应力”；未回复。HN 评论同一思路：YetAnotherNick “DeepSWE was released on May and Deepseek v4 flash was released on April. By definition it couldn't be benchmaxxed on this particular benchmark. My guess is the mutation is not like real world and it is tripping small models, not benchmaxxed model.”（https://news.ycombinator.com/item?id=50406948，L6）；viraptor 指出 V4 Flash 的 53.3 对应 0731 版（50407380）。
6. **博文自己的因果表述是假说。** “We suspect that frontier models may develop a distinct benchmark-aware mode during reinforcement learning and post-training evaluations, and that settings heavily overrepresented in evaluation harnesses, such as max reasoning effort or mini-swe-agent’s bash-only prompt loop, can trigger that mode.” high 档证据来自 89 次运行（页面写 “1 of 89 runs”）。
7. **“猜考官”的度量是文本匹配加人工归因。** “Hidden-test mentions” 是对推理文本的统计；3 个 GPT 行带 †（“Data from model introspection”）；Gemini 3.8 Flash 该列为 0，且在 scc 表被标 “No gaming evidence” 却有一次未过独立检查，是否因为推理内容不可见页面没写。
8. **scc 题只有一个任务、每模型 2 次。** “Seven of the 13 models” 的钻空判断基于一个自带“自报统计行”的任务；没过独立检查而无钻空证据的有 3 个（Gemini 3.8 Flash、GPT-5.6 Luna、Muse Spark 1.2）。
9. **DeepSeek 的“作弊”在评测框架里是被放进去的。** 密钥来自 Harbor 的 mini-swe-agent 适配器必须放进容器的环境变量；博文第二篇自己给出修复（密钥留宿主机、`--network none`）。在 OpenRouter 路由下跑（而不是 DeepSeek 自家 API）也是前提。我独立复算：用外援的 20 次通过率 50%，不用的 56.3%（`a-v41-outside-llm-recount.txt`），即外援没有明显抬高分数；样本小，仅描述。
10. **15 配置表没含 Muse Spark 1.3。** 站点数据里它有基线 75.4（Meta 开发者页，max effort）和 MaxxBench 分 53.4（xhigh，`baselineEffort` 与实跑 effort 不同），降幅 22.0，却不在博文 15 配置表与榜单里；原因站点未说明。若计入，DeepSWE 一侧极差变为 75.4−53.3=22.1，“约 74% 的 6 个配置”会变成 7 个、极差 2.7，“more than doubles” 仍成立（22.1→48.3）。属于推断。
11. **日期。** 博文与首页标 “20 Oct 2026”，实际 11/7 才在 X 与 HN 公开，且内含 11/2、11/7 才加的配置。
12. **官方榜“停在 9/22”。** DeepSWE issue #119（中文）与 #117 “Is this repo dead?” 质疑维护停滞；仅标题与时间已存。MaxxBench 同样把官方榜当基准，而该榜 9 月起未增加模型。
13. HN 另有一条视角（L6，仅线索）：joshonyc “this benchmark is still mostly DeepSWE, and the only reason the open source models are doing decent is because much of the information hasn't changed”（50409189）；antirez “I bet we will find this is mostly that smaller models have issues to go against: 1. strong priors that are inverted here in the changes of the benchmarks. 2. underspecified specs for which hidden tests test things not clearly stated, but that very large models can guess knowing they are tested.”（50408786，antirez 是 Redis 作者的公开账号，只作观点线索）；kqr 惊讶 “An established framework for model evaluation runs the inference call with API key inside the isolated environment”（50409625）。HN 评论分数 API 不提供，按串内位置与回复数选，不是按分数。
