Goldman Sachs 禁用 Claude Code 与 GitHub：3 个月终结前台全民编程

 商业
 2026年11月9日
 作者：Evan Neural
 版权所有：ic.work

 核心摘要
 Summary

高盛在 10 月更新内部指南，切断交易员与投行家对 Claude Code 和 GitHub 的访问权限，仅对 1.2 万名工程师及 Strats 团队豁免。

此时高盛正担任 Anthropic 11 月 IPO 的主承销商，前台收权与后台重注并存，说明无护栏的全民编程在强监管行业已被证伪。

2026 年 11 月的华尔街有一幕反差。高盛的投行家们正作为主承销商，向全球投资者路演推销 Anthropic 的 IPO 份额（代码 ANT，拟于 11 月底在纳斯达克上市）；但在他们自己的办公电脑上，Anthropic 旗下的编程智能体 Claude Code 与微软 GitHub，刚在 10 月被公司一刀切断了访问权限。

距离高盛首席信息官 Marco Argenti 在 7 月公开盛赞非技术人员靠氛围编程（Vibe Coding）快速搭原型，只过去了 3 个月。高盛发言人 Nick Carcaterra 给出的理由是实验阶段结束，出于生产力和风险管理考量收回权限。全行 4.7 万名员工里，这次收权与放行的边界切得很清楚：

被收回权限的前台业务岗包括交易员与投资银行家。他们此前数月一直在用这些工具监控客户实时资金流、制作图文材料，以及直接对市场走势和头寸建模。

获得豁免的正规军是约 12,000 名工程师，以及前台的 Strats（策略量化人员，兼具交易、量化研究与软件工程职能）。

继续全员开放的工具是高盛内部通用 AI 聊天助手（集成了 OpenAI、Anthropic 和 Alphabet 模型），同时高盛后台仍有 Anthropic 工程师驻场 6 个月，与工程团队共建交易会计和客户尽调开户的专属智能体。

为什么 3 个月就跑不通了

把生产力列为封禁理由，初看有些反常。AI 编程工具本来是用来提效的，怎么成了生产力的负资产？

粗糙的业务原型卡在严苛的工程合规关口前(示意图)

答案藏在 7 月份高盛 CIO 描绘的理想流水线里。按照当时的设想，交易员或资管人员有了点子，用 Claude Code、Codex 或 Devin 快速捏出一个能跑的原型，再交给背后的 12,000 名工程师去加固、扩展并推向生产环境。

这个设想忽略了一个基本的工程常识，写得出能跑的脚本，不等于写得出能进核心系统的工程代码。

AI 降低了写代码的门槛，却成倍抬高了审代码的代价。

真正被拔掉电源的，是像 Claude Code 这样能自己读写本地文件、编写并直接运行程序的编程智能体。在普通科技公司，产品经理用 AI 写个脚本跑挂了，大不了重启电脑；但在华尔街交易台上，放任业务人员直接运行这类工具，立刻撞上了三道现实墙。

第一道墙是本地权限继承与信息隔离墙（Chinese Wall）失守。Claude Code 运行时默认继承操作者的系统权限。投行家手握未公开的并购底牌，交易员盯着实时的客户资金流，银行必须在两者之间建立严密隔离。交易员用外部智能体随手拼凑的监控脚本，根本没有经过高盛内部平台的权限校验、密钥管理和许可证扫描。

第二道墙是绕过代码审计直接上生产环境。尝到快速生成的甜头后，交易员为了抢时间，直接把未经测试的脚本投入日常头寸建模，工程部门无从拦截。哪怕交回给工程团队，工程师去拆解黑箱逻辑、修补漏洞、重写架构的时间，往往比从头写一遍还要长。连以写代码为生的 Meta 工程师都在 10 月公开承认，自己现在经常上线无法完全解释清楚逻辑的 AI 代码；让不懂软件工程的交易员用自己看不懂的代码去测算市场头寸，直接踩中了金融机构最敏感的模型风险管理（MRM）红线。

第三道墙是失控的 Token 账单。编程智能体按 Token 消耗计费，一旦向缺乏工程训练的全员放开，算力成本会迅速膨胀。今年秋天，亚马逊不得不紧急关停了一个内部 AI 排行榜，因为员工为了刷榜冲排名，让智能体日夜不停地空跑无意义的任务；埃森哲则干脆将每位员工的 Claude 月度报销额度死死卡在 29 美元。高盛交易员拿昂贵的编程智能体去做图文材料、跑未经优化的监控脚本，在财务和 IT 部门眼里，纯粹是高风险且难以复用的散乱开支。

华尔街的真实 AI 账本怎么算

我更在意的是高盛这次对 Strats 团队的豁免，以及它在今年铺开的一整套治理动作。

如果高盛只是因为保守或者跟 Anthropic 有嫌隙，大可以一刀切禁掉所有前台部门，更不会去当 Anthropic 的 IPO 主承销商。单独放行 Strats，说明华尔街划分 AI 权限的标尺根本不是前后台之分，而是使用者具不具备工程治理与数学建模资质。

把高盛 2026 年的动作连起来看，这就是一张早就开始收网的二维治理图。早在今年 4 月，为了应对合同条款解释以及香港监管层对 Anthropic 旗下 Mythos 模型的风险评估要求，高盛就切断了香港投行家的 Claude 访问权限（摩根大通也在 6 月跟进移除了香港员工菜单里的 Claude）。4 月份画下的是地域与监管边界，10 月份画下的则是角色与工程纪律边界。

银行 / 机构核心 AI 编程动作与范围量化产出或管控措施工程与合规护栏

 高盛 (Goldman Sachs)收回交易员与银行家权限；后台与 Anthropic 驻场合作 6 个月仅豁免 1.2 万名工程师与 Strats；主承销 ANT 上市剥离前台代码执行权，开发权收归标准软件开发生命周期

 摩根大通 (JPMorgan)工程团队部署 GitHub Copilot；6 月移除香港员工 Claude 菜单工程生产力提升 10%-20%强制配合内部 AI 代码审查工具 PRBuddy

 摩根士丹利 (Morgan Stanley)聚焦遗留系统现代化改造截至 2025 年 6 月节省 28 万个工时专用内部工具 DevGen.AI 审查改造 900 万行遗留代码

 花旗集团 (Citigroup)开发人员使用 Copilot、Devin 与 Claude Code开发人员每周产能提升 10 万小时工程招聘硬性要求代码审查、安全与许可证扫描、密钥处理

 巴克莱 (Barclays)10 月宣布年底前让半数开发人员用上 Claude Code3 周后在 5,000 人裁员计划中剑指软件开发人员集中在专业开发团队内部推进工具替代

横向对比这五家大行就能看明白，金融业里所有能算出正账的 AI 提效，全部锁在受控的软件工程体系内。没有任何一家大行靠放任银行家自己写代码赚到生产力红利。甚至在同业对比中，高盛的做法还算温和——高盛用 AI 保护了那 1.2 万名工程师的权力边界，巴克莱则转头用 AI 开始裁撤工程师本身。

金融业的 AI 提效必须先卡死合规准绳(示意图)

1980 到 1990 年代华尔街曾经历过一轮极其相似的失控。当时 Excel 和 VBA 宏在交易台普及，每个交易员都能自己拉表格、写宏来做衍生品定价，摆脱了对 IT 部门的依赖。结果很快演变成电子表格风险（Spreadsheet Risk）——散落在个人电脑里的几千张表格没有版本控制、没有交叉审计，几个隐藏的公式错误就能让投行亏掉数亿美元，最终逼迫监管层出台了严苛的模型风险管理规范。

今天的氛围编程，不过是把当年的 VBA 宏换成了 Claude Code，而且编程智能体比当年的电子表格更具攻击性，它不仅计算数据，还能直接改写和执行系统指令。与当年不完全一样的是，今天的大行吃过上一代工具失控的亏，没有等酿成巨额交易事故才动手，而是在放开仅仅 3 个月后就提前完成了强行收权。

《韩非子》里讲，巧匠目意中绳，然必先以规矩为度。再聪明的工匠，动工前也得先卡死规矩和准绳。高盛这 3 个月的折返跑，给 Anthropic、微软 GitHub 以及 Cognition（Devin）等工具商敲了一记警钟，向非技术岗位无限扩张席位（Seat）的算盘，在金融、医疗、能源这类强监管行业根本打不响。

回到开头那个反差画面，高盛的投行家们虽然被剥夺了使用 Claude Code 的资格，但这并不妨碍他们把 Anthropic 的股票卖个好价钱。高盛用三个月的切身实验向全行业证明，正是因为 Claude Code 强到了能直接刺穿交易台防线的地步，企业的 IT 部门才不得不把它锁进专业工程师的保险柜里，改由后台工程团队集中采购和开发。接下来最值得盯紧的变量有两个，既然交易员监控客户资金流和实时建模的需求不会消失，高盛那 1.2 万名工程师和 Strats 能不能接住这些被强制收回的前台需求，以及 Claude Code 和 GitHub 会不会专为业务人员推出阉割掉底层执行权限、强制绑定企业合规沙盒的受限模式。
