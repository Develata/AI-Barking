重點摘要

Windows 11 元件會比對 7 種 AI 代理執行檔名

cmd.exe 改名 codex.exe 執行，也被記成 Codex

報告約每天一份，作者實測選用診斷資料開啟就排入上傳佇列

開發者 Xusheng Li 11 月 16 日在個人部落格 [https://xusheng.dev/posts/windows-coding-agent-telemetry/]發表逆向分析。他指出 Windows 11 的系統元件會比對 claude.exe、codex.exe、cursor.exe 等 AI 寫程式工具的執行檔名稱。比對結果會整理成約每天一份的診斷報告。在他測試的環境中，只要「選用診斷資料」開啟，報告就會排進上傳微軟的佇列。

作者把 Windows 內建的命令提示字元 cmd.exe 複製一份，改名為 codex.exe 後執行。元件隨即把它記成 Codex，作者表示光憑檔名就足以讓元件認定。這項功能在他的虛擬機上已經啟用，但他也寫明，證據不足以說每一台 Windows 都有啟用。

AI 代理分兩組比對，另有 12 類開發工具

作者表示，他最初是請 AI 協助檢視最新版 Windows 系統檔、尋找未公開的功能，才在系統元件 MissionControlAggregator.dll 裡看到這份名單。名單分成兩組。

命令列代理有 4 個欄位，檢查 copilot.exe、claude.exe、codex.exe 與 agy.exe。桌面代理有 5 個欄位，檢查 github.exe、claude.exe、codex.exe、cursor.exe 與 antigravity.exe。兩組合計檢查 7 個不同的執行檔名稱。

這些工具分屬微軟旗下的 GitHub、Anthropic、OpenAI、Anysphere 與 Google。控制這組檢查的功能名稱是 CLICodingAgentUsage，字面意思就是命令列寫程式代理的使用情況。

同一個元件也檢查 node.exe、python.exe、dotnet.exe、gcc.exe 與 VS Code 的 code.exe 等開發工具。這些工具總共歸成 12 個類別。報告以類別為單位記錄，例如 GCC 與 Clang 這類編譯器共用同一個欄位，不會分開記每個執行檔。其中 Node.js、Python、.NET 與 Visual Studio 的檢查會一併核對發行者名稱。

常見問題

Windows 11 會把 Claude Code 或 Codex 的對話內容傳給微軟嗎

依 Xusheng Li 11 月 16 日的分析，他沒有在報告中看到提示詞或原始碼，報告只標記是否偵測到 7 種 AI 代理。

每台 Windows 11 都有啟用 AI 寫程式工具檢查嗎

作者無法證實。他組建 26200.9974 的虛擬機測試前已啟用，但用官方 ISO 建立的乾淨虛擬機預設關閉這項檢查。
