Windows 11 Telemetry Flags Which Coding Agents You Run, Researcher Finds

Xusheng Li traced a service-experiment feature in build 26200.9974 that matches executable names such as claude.exe and queues the result as optional diagnostic data.

By Rosa Vasquez [/authors/r-vasquez]A.I. byline [/ai-disclosure]/November 17, 2026

The short version

Li traced the reporting to MissionControlAggregator.dll 10.0.26100.9818 on a Windows 11 ARM64 virtual machine running build 26200.9974.

The Nov. 16 writeup says the event has 4 command-line and 5 desktop agent slots, covering claude.exe, codex.exe, cursor.exe and copilot.exe.

Li's queued payload was flagged isRequired: false, and Microsoft's own page lists launched programs under optional diagnostic data.

Photo: Coolcaesar, CC BY-SA 4.0, via Wikimedia Commons [https://commons.wikimedia.org/wiki/File:Building92microsoft.jpg]

A Windows 11 component logs which coding agents run on a machine, matching file names such as claude.exe and codex.exe, and queues the result for upload to Microsoft, researcher Xusheng Li reported Nov. 16.

Li published the reverse-engineering writeup [https://xusheng.dev/posts/windows-coding-agent-telemetry/] on a personal blog. The work was done on a Parallels virtual machine running Windows 11 ARM64 build 26200.9974, where Li found the logic in MissionControlAggregator.dll, version 10.0.26100.9818. The feature is named CLICodingAgentUsage, carries feature ID 62580080, and was already switched on as a service experiment. Li did not enable it.

What the report event contains [#what-the-report-event-contains]

The event is Microsoft.Windows.MissionControlAggregator.Segments.SubCohorts, version 0.1.5. It is a bitmap, a row of on-or-off flags, and Li found no prompt text or source code in it. The function that builds it, ReportCohorts<12,4,5>, maps to 12 developer-tool categories, four command-line agent slots and five desktop agent slots.

Photo: Coolcaesar, CC BY-SA 4.0, via Wikimedia Commons

Slot groupSlotsExecutables Li lists

Command-line agents4copilot.exe, claude.exe, codex.exe, agy.exe

Desktop agents5github.exe, claude.exe, codex.exe, cursor.exe, antigravity.exe

Developer-tool categories12node.exe, python.exe, dotnet.exe, gcc.exe, clang.exe, gdb.exe, javac.exe, devenv.exe, code.exe and others

The inputs are richer than the output. Li says the source events carry runtime, time in focus, interaction counters and resource usage, but the component appears to discard them. The timestamps describe the collection window, not how long a tool was used.

How Li confirmed it leaves the machine [#how-li-confirmed-it-leaves-the-machine]

Li copied cmd.exe to codex.exe and ran it. The Codex command-line bit flipped to 4, which is 1 shifted left two places, and a second copy renamed gcc.exe set a developer-tool slot. The check Li exercised keyed on the file name, so a renamed binary counts and a Codex build under another name would not.

To force a report, Li moved the saved reporting-window start back 25 hours and restarted the DiagTrack service. The queued event appeared in DiagTrack's EventStore.db, with "CliAgentSubCohorts": [4] and "privacy": { "isRequired": false }. That last flag is the one that matters: the payload is classed as optional.

What Microsoft's documentation says [#what-microsofts-documentation-says]

Microsoft's diagnostic data page [https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization] says optional diagnostic data includes "App activity, such as which programs are launched on a device, how long they run, and how quickly they respond to input." The same page lists "app state change details" under required data, and Li's input events include KernelProcess.AppStateChangeSummary. The page's text does not mention coding agents or the aggregator by name.

It also says the settings-win.data.microsoft.com endpoint is used to remotely block an event from being sent. That fits a feature that arrived as a service experiment rather than a shipped setting.

Developer tools reporting on their users is not new on this beat. Chrome DevTools MCP sends usage statistics by default [/software/chrome-devtools-mcp-63-tools-usage-statistics-default], and Plannotator has no release-check opt-out [/software/plannotator-11-9k-stars-no-opt-out-release-check]. The difference here is that the collector sits in the operating system, below any tool's own settings.

How to turn it off [#how-to-turn-it-off]

Li lists two routes: decline optional diagnostic data during setup, or open Settings, then Privacy & security, then Diagnostics & feedback, and switch off Send optional diagnostic data. On a clean Windows 11 Home ARM64 install in the US region, Li found "Include Optional" selected by default.

Li's post carries no Microsoft statement, and a search on Nov. 17 for the feature and event names found no Microsoft response. Li also says the public ISO's baseline virtual machine had the feature disabled by image default, so it is not necessarily active on every installation. The test covered one build on one virtual machine, and Li's post gives no date for any wider rollout.
