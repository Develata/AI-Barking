It's easier to mod the Linux kernel in a way that would fool kernel-level anticheats, since the Linux kernel is both open-source and an extremely well-understood API surface.
With Windows anticheat the anticheat driver is using a well-defined API the kernel exposes to block other kernel drivers being loaded, but with Linux you can change the code implementing those types of APIs by compiling a custom kernel and editing the source code. With Windows such a custom kernel would be a significant reverse engineering effort.

If you allow customized kernels to be used then you've already lost. That would give you a similar level of access as running under a hypervisor which has been exploited and banned a long time ago.
Isn't the main issue for the lack of support on Linux the absence of centralized authority that would verify that each kernel/module is locked down enough to prevent "unauthorized" access to your own kernel, and certify/sign the entire boot chain - approved bootloaders, kernels, kernel modules that would allow anticheat to properly attest the boot state?
But that's a near impossible task that's at odds with the philosophy with the entire ecosystem. Support would probably have to be narrowed down to 1 boot loader that supports 1 heavily modified kernel with a short list of most commonly used kernel modules.

I've been using a Framework 16 with Linux on it for 1.5 years now, and everything has been smooth. The only issue I had was a hardware issue, which I would have had on Windows as well.
The issue, if you're interested, was that earlier builds of the Framework 16, including mine, could flex just a little bit while closed if something was pressing on them, e.g. if they were in a backpack with a bunch of other things. This would result in the screen actually pressing keys on the keyboard when it flexed, causing the computer to wake out of sleep mode. (They've apparently fixed that in the past year with a different material for the laptop's metal frame, which flexes less, but I can't tell you from personal experience whether it works because I have kept my laptop). For original laptop owners, they released a BIOS update about six months ago that allowed the keyboard to turn off when in sleep mode, so that it wouldn't wake the computer anymore. That solved the issue for me.
So my personal recommendation is yes, buy a Framework laptop and run Linux on it. You won't be paying for a Windows license if you don't need one, unlike with most manufacturers where the price of a Windows license is baked into the price of the laptop. (Framework isn't the only one to offer you the option of not paying for Windows, thankfully).
I see others have recommended System76; I've never used them but they also have a good reputation.

I swear there's like a manual for anti-linux posts that's resulted in people posting the same basic thing to reply to this since like 2008
"I daily drive every operating system known to man and the normies just aren't ready for this yet"
"Linux doesn't Just Work like [preferred corporate OS]" (lol, lmao)
Basically some flavor of "I am an enlightened computer nerd who knows that you must be a braingenius to use anything but the shareholder-approved device configurations". This is also the exact sales pitch microsoft makes when they sell hospitals, schools, and other institutions on letting them control their IT, as well as the basis of their advertising. "Your computer, simplified!" I don't buy that these people are speaking from a place of actually making a useful effort to help anyone.
Meanwhile, in reality I've been helping aunties, product managers, call center workers, and gamers use linux for several years and generally speaking there are enough desktop environment options that are learnable that generally these people are by and large happier after about a week or so. The tech companies have really been degrading the customer experience in pursuit of shiny objects, telemetry, lock-in, and ads. The bar is in hell.
I think the key to this success has been taking a different approach. A lot of people seem to say "You should do this better thing, here's a guide". Installing any linux distro is a lot more activation energy than using it, and people don't really know where to start. But getting people started requires:
1. Ask about what their use case for a computer is. You may even do a small amount of research about what's out there, if you're not already aware of what applications they're likely looking for. Most people who are used to being told what software to use are not used to looking. Despite being strongly of the opinion that most people's computing needs can be served by a linux distro, I have definitely done this for some people and said "this might not actually be possible yet, you may still need one computer to be a mac" or whatever for edge cases like very specific corporate software. Maybe have a few different DEs in mind that someone might want to use. One-size-fits-all is dumb. People's needs are different.
2. Let the person whose computer it is drive an install process, but be there to answer questions. The goal is for using the computer to be something they seldom if ever need direct assistance to do, and people get there a lot faster if they're touching the thing to set it up.
3. Have other people there. Make it a team endeavor. This makes frustrating things a lot more fun, and any messing with your computer is frustrating. If you're a computer toucher for a living, you get paid primarily to tolerate frustration while you get from a thing not working to it working.
This is hands-on, but the value someone gets out of control of their computer is worth the investment, for you and for them

> And some people have a worldview that says wealth is a zero-sum game, therefore anyone rich must have gotten that wealth by exploiting the poor.
Wealth is not zero-sum, but it is created by work. When you collect a salary in exchange for work, it is because your employer deems that your work is worth more than your salary. Otherwise, it would not be a sound financial decision to employ you. There is literally no way to rise to the top without paying people less than you think their work is worth.
When many thousands of people create value in exchange for less money than their work is worth, that's how you get a billionaire.
You might say, "well it's your choice to work", but under capitalism, donating the surplus value of your work to an richer person is the only way to survive. As in, you will literally die if you don't. If you can somehow collect the required capital to start a company, you can try to compete, but now you're donating your surplus value to billionaire investors instead, and with much fewer protections. If you succeed, you are now the one depending on thousands of workers donating the surplus value of their work to you, and the cycle repeats.
The only way to break the cycle is to keep the coordination of many humans, but forgo the upwards flow of wealth to a few individuals. We used to do this with taxes, and it's a crude mechanism, but it worked. Collective ownership seems to work even better.

Very few, if any modern games actually use WINE. In today's world, if you want a Linux build for your game, it's usually just a checkbox option in Unity/Unreal/Godot etc. A lot of games just have native Linux support. Those that don't use Proton, which is designed specifically to accelerate graphics calls.
As for faster, it's not that Linux does anything special to improve speeds, Windows is just genuinely that bad. Windows on its own consumes more resources than pretty much any Linux distro which means there's more compute for your game.
Again counter-intuitive: compatibility is better with Linux. I have some old games that won't play on modern Windows but work flawlessly under Linux.
There really is no good reason to use Windows other than being locked into Adobe software or whatever. Linux is just better in pretty much every sense.

Well when you think about it, the Windows games are just calling out to library functions within Windows, that in turn often hook into library functions within maybe some vendor library that's part of a driver.
If you make those faster you make the game faster.
If all you're doing is slinging triangles at a GPU, then the faster you can do that - without having to ask other bits of the OS for help - the faster the game will draw.

Don't do it in the settings, do it with group policy settings. Windows will not override those like it will "user" settings.
Computer Configuration > Administrative Templates > Windows Components > Data Collection and Preview Builds.
Allow diagnostic data -> set to 0
Group Policy Management Console, go to Computer Configuration > Administrative Templates > Windows Components > Data Collection and Preview Builds
Limit dump collection -> set to 0
The privacy.sexy site/scripts have further settings to disable the (numerous) other telemetry "features" in Win11. Careful, as the 'full bore' privacy setting locks things down so much that Windows won't detect whether it's connected to the internet because it disables the internet connectivity test to MS servers. This can interfere with windows update and, annoyingly, even some game stores. Origin, for example, will refuse to connect if Windows thinks it isn't connected to the internet.

fuzzfactor [user?id=fuzzfactor] 6 hours ago [item?id=50527525] | parent [#50525277] | prev [#50525475] | next [#50525193] [–] [javascript:void(0)]

I've been having a seamless dual-boot experience with Windows 11 and Linux Mint Debian Edition, LMDE7.
As a preface to those Mint instructions, in Windows Disk Management I shrink the main Windows partition by about 20GB to 50GB, this creates some new "unallocated space" immediately following the normal Windows C: volume.
Then create a "New Simple Volume" in that unallocated space, but do not assign a drive letter and do not format. This will be the sole Linux partition, no /swap, no /usr, none of that monkey business when you are not replacing Windows, merely adding Linux as an option to a "virtually unchanged" Windows PC. You want Linux to occupy a single partition just like Windows does. At the Command prompt in Windows Diskpart, next select the target HDD or SSD, then select the target Linux partition on that drive, and "SET ID=4F68BCE3-E8CD-4DB1-96E7-FBCAF984B709 which is the designator for Linux Root. Also in Diskpart you can select the EFI volume and assign an alphabetical letter to the EFI volume so you can see the hidden folders and back up the Windows-specific \EFI\Boot\bootx64.efi file contained within. Manipulating the "hidden" EFI files can only be done at the Command prompt (not the GUI) after assigning a drive letter like this, and after you reboot, that drive letter will be removed automatically and no more access to EFI unless you reassign a drive letter again in CMD.
Then boot to the LMDE7 USB drive so you can install Linux to the unformatted partition.
In the Mint install wizard you will have to choose the "Manual" partitioning & formatting option, which opens up infinite possibilities, but this simple dual-boot arrangement only takes a couple distinct settings. In the displayed list of partitions, select that unformatted volume as "root", indicated by the single slash "/", and choose to format it using ext2, ext3, or ext4. Then in the small fat32 boot partition (where the Windows boot files are already residing in the "hidden" \EFI\Microsoft\ folder), Do Not format this partition, but select it as the ideal location for the Linux boot files, and designate it as "/EFI/Boot".
That's it.
After completion, Linux will be completely independent from Windows. In the EFI boot volume there will be a new \EFI\debian\ folder alongside the \EFI\Microsoft\ folder. The only change to any Microsoft files (and it's a "big" one) is within the \EFI\Boot\ folder which is a common folder to all the OS's on that SSD. When first powered up, \EFI\Boot\ is the folder that the UEFI firmware searches for so it can execute \EFI\Boot\bootx64.efi which then boots the PC. On a plain Windows PC the bootx64.efi file is from Microsoft and points to \EFI\Microsoft\ then Windows boots normally. The Linux install process replaces bootx64.efi with a different bootx64.efi which points to \EFI\debian\ instead. This is also a good time to use Windows to back up the Debian-specific bootx64.efi file.
Fortunately, the Mint install process runs a Grub routine including os-prober, which as the name implies, probes for other OS's besides the Linux you are presently installing at the time. And auto-adds any OS's found, to the new Linux multi-boot menu. So it reliably picks up a regular Windows installation and adds an entry for that Windows to the Linux bootmenu. Basically that Windows bootentry points to the same old \EFI\Microsoft\ folder which is unchanged and then boots Windows normally when selected.
Unfortunately, os-prober has been commented out of the Grub files and the probe only functions upon OS installation. So when Grub itself is re-installed or updated at a later time, intentionally or not, os-prober no longer runs by default and Windows will be auto-removed from the Linux bootmenu and you wonder where it went. Windows is still there intact regardless and can be recovered by replacing the Linux bootx64.efi with the original Windows bootx64.efi that you backed up earlier. But that would give you no more menu access to Linux.
To avoid this deficiency in the default Grub files, in Linux you need to edit the \etc\default\grub file to uncomment (remove the # hashmark from) the GRUB_DISABLE_OS_PROBER=false line. This basically requires using sudo at the Linux command line since otherwise the file is read-only.

If the server is located reasonably close to you (same country/state), you can expect a round trip latency of ~10ms, which is less than the latency of a top of the line competitive PC, and well under the limit of human perception for audio and visual feedback. So, viable in this universe.
In practice, there are a lot more variables, but under 40ms is achievable today with a good PC, a good connection, and a reasonably close server. That's good enough for all but the fastest games with competitive gameplay, and cloud gaming is generally considered a better experience than a low-end PC.

Logging itself is not a violation of privacy when it doesn't leave your device. Of course it's a matter of expectations, for example logging keystrokes would be a weird thing, even if it didn't leave the device.

If we're looking at it from a forensic perspective, there is a lot to check, once you have access to the user folder. For example there's the cached thumbnails of most images that were once on the computer.

rmunn [user?id=rmunn] 4 hours ago [item?id=50528279] | parent [#50528090] | next [#50526836] [–] [javascript:void(0)]

Because in many cases the answer the tool gives can be verified. For example, I often ask "What's the syntax in software ABC to do XYZ?" Then when the LLM spits out the syntax, I read the manpage (or online docs) for ABC, and double check that yes, the `--xyz` option was the right one. The LLM's answer is usually faster than scrolling through the manpage myself, reading 50 irrelevant options before I get to `--xyz`.
I've had one case where the LLM told me "You can do XYZ like this: (example)" and the online docs said "You can't do XYZ yet, we haven't added that feature, but when we do add it then this is how to do it: (example)". So I still double-check. But it's right 90+% of the time, and it saves me time since the LLM (running on massively parallel clusters of GPUs) can synthesize and associate words much faster than I can.
So that's why people are trusting the LLMs. Because they're usually right. You should never trust them 100%, though: always verify, whenever it's possible to verify, what they tell you.

In the age we're entering, I'm not convinced that escaping to MacOS or to nix or any other system is any sort of guaranteed win. I saw MacOS doing similar analytics things to Windows, but trust is, it's private! MacOS also barely feels maintained. nix is a crapshoot and any distro you're thinking of using to get a workable desktop that lets users feel at home is already failed by that very goal. What's worse is that the nix ecosystem is rife with insane package managers that makes them even more ripe for getting plucked by AI in the upcoming years. It will also be even easier for AI to social engineer and get people on nix to install persistent bot networks and malware even if it only runs as a regular user to expand the computation footprint it has access to.
I'm not a fan of the always online cloud infrastructure integration that Windows has, but being realistic, if you want to use your computers the way you have been for the past couple decades then Microsoft's approach is the only realistic one in my opinion even though they have a long way to go still. I say that sadly. If you want true security and true privacy, you have to compute in a different way with greater limitations and I see almost nobody willing to do that. It's like the doctor and patient dilemma. Doctor tells you to stop doing this thing that's killing you, patient comes back in 3 years closer to death, because they don't change.
Given the situation Microsoft faces, it's impractical to automatically configure every home computer with some air gapped NSA secure configuration, because there would be far more outrage than any privacy advocates have ever put up. It's only gotten worse, because so much software only works with the internet and the internet has gotten so important that a lot of software is only useful with access to the internet.
Then you've got this battle between dying hard drives losing data, fires, floods, hurricanes and other natural disasters destroying your data versus backing it all up online, but opening yourself up to security risks that way. People like to think they have multiple backups, but then some storm takes out both of your backup locations, because they weren't distributed enough. If World War 3 happens, the data centers may become a huge target and even as distributed as they are, they can only take so much. Nature is eating at you from every direction.
