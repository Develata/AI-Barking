Router internals

Built for agents in production.

A benchmark-driven pick is only half of a router. These are the details that decide whether it survives real traffic.

0% markup
Your keys, your bill

Requests go out with your own OpenAI, Anthropic, Google, DeepSeek, Moonshot and Z.ai keys, so providers bill you directly. We add nothing to token prices — plans include a number of routed requests.

Per suite
Drift-aware by default

When a model’s detector fires on the suite your strategy depends on — or it has an open canary incident — it drops behind healthy models. The routing reason names who was passed over.

5 fallbacks per request
Outages route around you

Each request carries up to 5 fallbacks: first from your own fallback order (a list of up to 10 models, skipping any that are unavailable), then the best models at other providers. A circuit opens after 5 straight failures and probes again after 60 seconds.

All six providers
Tool loops that don’t derail

Native tool calls with the provider’s own call ids, each model’s reasoning carried between turns, and a loop that stays on the model that started it. Forced tool_choice and json_schema work everywhere — natively, or emulated and checked.

32 MB · 15 min
Long context, long thinking

Native streaming on every provider, request bodies up to 32 MB for 1M-token contexts, and a 15-minute timeout for models that think before they answer.

Per key · per project
Budgets that hold

Hard and soft monthly budgets on every key and project, a maximum price per 1M tokens, a maximum latency, and provider or model exclusions — all checked before a request is sent.

X-AISM-Reasoning
Every pick explained

Each response names the model, the provider, the latency and why it won. Preview any routing setting against the real pipeline without spending a request.

AES-256-GCM
Private by default

Prompt logging is off unless you turn it on. Logged prompts are scrubbed of secrets before they are encrypted, and so are your provider keys.

14-day window
Learns from production

Real failures and your ratings through /v1/router/feedback adjust each model’s effective score, so a model that benchmarks well but fails in practice loses ground.

FAQ

Questions people actually ask.

Still unsure? The methodology [/methodology] explains every number on the site, and the full FAQ [/faq] covers the rest.

Are AI models really getting worse over time?
Sometimes — and usually without notice. Providers change weights, safety layers and serving infrastructure behind the same model name. AI Stupid Level re-runs the same tasks on every model on a fixed schedule and compares each one with its own history, so a drop shows up as data instead of a hunch. Is your AI getting worse? [/is-ai-getting-worse] gives the answer by provider.
Is ChatGPT getting worse? Is Claude getting worse?
Check the record: is ChatGPT getting worse [/is-chatgpt-getting-worse] and is Claude getting worse [/is-claude-getting-worse] each read the drift detectors and the 24-hour board for that family. Every OpenAI and Anthropic model we track is re-tested on coding every 4 hours and on reasoning and tool use every day, and a model is flagged only when a change holds up statistically — not after one bad run.
Is there a live AI degradation tracker?
Yes. The AI degradation tracker [/ai-degradation-tracker] shows every model we test with the state of each suite’s drift detector, how close it is to firing, and the hourly canary’s alarms over the last 30 days. The Smart Router reads the same alarms: for new requests in the routing modes an alarm affects, that model drops behind healthy ones while the alarm is open.
What does “cost per correct fix” mean?
What we paid the provider, at its list price, for every attempt at a task, divided by the attempts that passed the hidden tests. A model that is cheap per token but fails often can cost more per correct result than a pricier one that gets it right, so this is the number that tells you what the work really costs.
Which AI model is best for coding right now?
It changes, which is the point.
