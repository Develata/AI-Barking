Claude、GPT 集体降智？我扒出 7 个隐藏原因，附抢救教程

Claude Opus 5.5、GPT-6 Astra、GPT-6.1 Sol 最近疯狂降智，可第三方跑分却显示，成绩基本没有下滑。

很多「降智」，问题出在被偷偷换了模型、推理强度暗降、对话拖拖拉拉，一分钟就能自查；GPT 账号被风控的，可以试试这几个方法。

Claude 和 GPT，最近疯狂降智。

CLAUDE.md 里明明写着全程用中文回复，Claude Opus 5.5 还是会冷不丁冒出一段英文。你提醒一句，它能消停好几轮，过一阵又切换回英文。我的体感，「这两周它不太正常了。」

我应该不是个例。前段时间「Claude Opus 5.5 被降智了」的帖子在海外社区刷屏好几天，昨天更是冲上了 X 的热门话题榜。

科技播客圈的元老 Leo Laporte 原本把 Claude Opus 5.5 当成心头好，现在，「它说什么我都要打个问号。」在他看来，能力变来变去的模型，根本不可靠。

OpenAI 重置哥 Tibo，发帖感慨，「如今的智能体真的很厉害，可用起来还是很让人抓狂。」评论区有人回怼，「你们的模型一天比一天贵，也一天比一天笨。」用 GPT 的老铁们相当扎心，明明选的是 GPT-6 Astra，画出来的「鹈鹕骑车」却像两三代以前的模型画的。

骂声一片，这些模型的跑分却稳如老狗。

开源项目 LiveNerf 从 Claude Opus 5.5 发布第三天起，每天用 Claude Code 订阅账号拿同一套 78 道题考它，每 10 天统计一次，到 11 月 3 日，三次都判定为「没变化」。另一个追踪项目 NerfBench，GPT-6.1 Sol 和 GPT-6 Astra 的成绩也都在正常范围内。

LiveNerf 每天拿同一套题考 Claude Opus 5.5，每 10 天的得分。

两边都没说错。

因为很多「降智」，问题出在模型以外。被偷偷换了模型、推理强度暗降、对话拖拖拉拉、账号被风控、中转站有猫腻。

大部分你自己就能查出来，也能抢救一下。

01｜先花一分钟，确认模型有没有被掉包

先看模型名和推理强度，这两样不对，后面怎么调整都白搭。

7 月底我教过你们一招「果汁值」，一条提示词让 ChatGPT 自曝推理预算。到了 GPT-6 这一代，这招已经问不出来了，GPT-6 Astra 会一口回绝你。

就像这样。

那，还能怎么办？

Claude Code 里，你可以用 /status 查看当前模型和版本，用 /effort status 查看推理强度，/usage 还能按模型查看这次会话的用量。

ChatGPT 里，打开设置里的「使用情况」，切换到「分析」，在右上角选择「按模型」，最近 7 天实际用了哪些模型，一目了然。

前几天 GPT-6 Astra 被曝偷跑，就是通过这个方法确认的。

Codex 同理，用 /status 命令查看当前模型、推理强度和用量。

别问模型「你是谁」。模型自报的型号，会受到多重因素的影响，不太靠谱。

02｜Claude 被拦截一次，整个会话都改用旧模型

被安全拦截有提示，但模型不会自动换回来，得手动用 /model 切换。

Claude Opus 5.5 内置了几道安全检查，请求一旦被判定为生物、网络安全相关，或者模型训练这几类，Claude 就会改用旧模型重新回答。生物类和模型训练换成 Claude Opus 5，网络安全类换成 Claude Opus 4.8。

检查的范围比你想的还要大。Claude 读到的记忆、MCP 连接器内容、搜索结果和文件都包括在内，即使你的提示词里一个敏感词都没有，也可能被拦截。

被拦截换模型后，整个会话都会一直用旧模型，推理强度也沿用，Claude Opus 5.5 默认 medium，换到 Claude Opus 4.8 还是 medium，比 4.8 自己默认的 high 低一档。

你要是在做渗透测试、做相关研究或者 CLAUDE.md 里提到了这类项目，聊着聊着觉得它变笨了，很可能就是这个原因。绝大多数 AI 编程，一般不受影响。

Claude Code 官方文档关于自动切换模型的说明。

用 /model 重新选择 Claude Opus 5.5 就行。

不想被自动换模型，就在 /config 里找到「Switch models when a message is flagged」（消息被拦截时切换模型）这一项，改成「Ask each time」（每次先问），或者在设置文件里加上这一行。

"switchModelsOnFlag": false

以后再被拦截，Claude Code 会停下来，让你选择是换模型，还是改写提示词再试一次。

如果切换回去又被拦下，就先改写上一条消息，或者按两次 Esc 退回到那条消息之前。

03｜Claude Opus 5.5 默认只用 medium 档，强度得自己调高

想让模型多想一会儿，就自己把强度调高。以前保存的设置对 Claude Opus 5.5 不生效。

Claude 模型的推理强度从低到高分为 low、medium、high、xhigh、max 五档，越往上想得越久，也越费额度。

Claude Opus 5.5 的默认强度是 medium，比 Claude Opus 5 的 high 低一档。Anthropic 自己实测下来，在编程和知识工作类的评测里，Claude Opus 5.5 用 medium 已经不输于 Claude Opus 5 的 high 了。

9 月 22 日起，以前保存在全局设置里的推理强度，不再套用到 Claude Opus 5.5 这类新模型上，一律从默认档起步。你用 Claude Opus 5 的时候设置过 high，换到 Claude Opus 5.5，实际用的是 medium，自己可能还不知道。

这是官方故意这么设计的，Anthropic 建议换过来以后先从 medium 起步，再用自己的任务试试各个档位。

Claude Code 官方文档关于默认推理强度的说明。

推理强度降一档，模型效果差多少？

根据 LiveNerf 的测试，同样的题目，从 high 降到 medium，准确率下降约 4 分（不算太大），输出 token 减少四分之一。

推理强度的调整方法有三种。

一是用 /effort high 或者 /effort xhigh，设置一次，就会保存为这个模型的默认设置。/effort max 只对当前会话生效。

二是写进设置文件，注意要按模型写，可选 low、medium、high、xhigh。

"modelSettings": {
 "claude-opus-5-5": { "effortLevel": "high" }
}

三是只给某一轮临时调高强度，在提示词里写上 ultrathink。这个词变成彩虹色，就说明强度已经提高了。

建议别一上来就用 max 档。Claude Opus 5.5 是出了名的「雷霆大思考」，Anthropic 官方也提醒 max 收益递减，容易想太多。

这是官方给的档位建议。日常开发用 medium；修复 bug 这类验证很重要、容易漏掉边界情况的活，用 high；xhigh 想得更深，也更费 token；max 留给想放手让它自己啃的难题。

Codex 的推理强度写在 ~/.codex/config.toml 的 model_reasoning_effort 里，会话中可以用 /model --reasoning=high 临时调高，调整完用 /status 核对。根据网友们总结的不完全经验，GPT 模型 high 以下的档位更容易遇到降智。

04｜对话越长模型越笨？纠正两次就重开

回答跑偏时，先别在原对话里纠正，退回去或者清空重来。

当你明显感到模型回答变差、又没报错的时候，问题可能出在对话本身。

回答跑偏了，先别急着在原对话里纠正，按两次 Esc 或者用 /rewind 退回到出错之前，换个更具体的说法重新问。

在原对话里纠正，错误的答案会一直留在上下文里，后面的回答容易被它带偏。

Claude Code 官方的最佳实践则更进一步，「纠正两次还不对，别纠正第三次，用 /clear 清空对话，写个更好的提示词重来。」

Codex 也类似，比如用 GPT-6.1 Sol 时，一个提示词用完就新开对话，效果更好。

10 月 14 日，终端里的 Claude Code 新增了「空闲压缩」功能；10 月 30 日，VS Code 插件和桌面端跟进。一段 20 万 token 以上的对话放着不动大约 54 分钟，就会被自动压缩成摘要。

不想开启？在 Claude Code 设置里加上一行 "idleCompaction": false。

另外，记得在终端里运行 claude update。

10 月以来，Claude Code 修复了多个疑似降智的 bug，比如压缩上下文后把刚做完的活撤回重做，或者读到的是改动前的旧版 CLAUDE.md。

05｜旧提示词，可能在拖你的后腿

用 /doctor prompt-audit 让 Claude 自己检查一遍，它只给建议，你批准才改。

如果你的 CLAUDE.md 是从旧模型时代一路积累下来的，那里面可能有很多「回答前再检查两遍」「务必做到最详尽」「必须严格遵守以下 12 条」这类话术。

Anthropic 专门测试过这件事。在一个客服场景的评测中，往提示词里分别塞进六种旧写法，再用 /claude-api prompt-audit 清理掉，成本平均降了 9%，准确率提高了约 2 个百分点。

新一代模型会把「再检查一遍」这类话当真，白白多烧 token；遇到互相矛盾的规则，它还会停下来反复找人确认，该办的事反而没办。

Claude Code 里的 /doctor prompt-audit 会扫描你的 CLAUDE.md、规则和技能文件，找出给旧模型写的指令、指向不存在文件的引用，以及互相打架的规则，给你一份修改建议。

OpenAI 也在 GPT-6 Astra 的官方指南里「强烈建议」，把模型能读到的技能文件和 AGENTS.md 这类文件都检查一遍。技能文件写得含糊或者互相矛盾，GPT-6 Astra 可能活干一半就不干了。指南还给了两段现成的提示词，放进 AGENTS.md 就能用。

用户的指令优先于技能里的规定。用户明确的指令和技能冲突时，以用户的为准。

如果某个技能让你停下来请示、确认，把活留着没做完，或者偏离了用户的意图，请写出你读到的那个 SKILL.md 文件名和链接，引用相关的那条指令，简单说明它在这里为什么适用。另外，分清哪些是技能里明确的要求，哪些是你自己对规定的理解。

06｜中文聊着聊着，突然吐英文

language 设置能让英文回复变少，但拦不住；加上一个 Stop 钩子，英文回复会被自动打回重写。

这一点我深有体会。

我专门让 Agent 统计了一下，9 月 28 日-10 月 25 日，Claude Opus 5.5 每周有 7%-9% 的回复几乎全是英文，同期 Claude Opus 4.6 在 2% 左右，Claude Sonnet 5.5 几乎为零。

模型自动切换成英文回复，最常发生在 Claude 读完一大段英文的工具输出之后。也有用户发现，加载了英文写的技能之后，冒出英文的比例翻了一倍。

即使你已经在设置文件里加上了 "language": "简体中文"，CLAUDE.md 里也写明全程用中文回复。

目前唯一有效的办法，是 Stop 钩子。

Claude 每次准备结束回复时，钩子检查这段话是不是英文，是英文就拦截，让它用中文重写。网友实测，钩子拦截了 44 次，44 次都改回了母语。

上教程。注意，以下方法你可以手动操作，也可以喂给 Agent 让它帮你设置。

把下面这段保存为 ~/.claude/hooks/zh_guard.py。

import json, re, sys

data = json.load(sys.stdin)
if data.get("stop_hook_active"):
 sys.exit(0)

text = data.get("last_assistant_message") or""
text = re.sub(r"```.*?```|`[^`]*`|https?://\S+", " ", text, flags=re.S)
zh = len(re.findall(r"[\u4e00-\u9fff]", text))
en = len(re.findall(r"[A-Za-z]", text))

if en >= 60and zh < en * 0.1:
 print(json.dumps({
 "decision": "block",
 "reason": "上一条回复是英文。请用简体中文把它重写一遍，不要调用新的工具。"
 }, ensure_ascii=False))

再在 ~/.claude/settings.json 里配置好这个钩子。

"hooks": {
 "Stop": [
 { "hooks": [ { "type": "command", "command": "python3 ~/.claude/hooks/zh_guard.py" } ] }
 ]
}

钩子只检查每轮最后那段回复，工具调用中间那些一两句的进度说明，它拦不住；被拦下的英文回复，也会先在屏幕上显示出来，再改写成中文。

真到了怎么提醒都拉不回来的地步，新开一个会话最省事。

07｜ChatGPT 账号被降智，怎么判断、怎么「抢救」

先用几招快速判断，确认被降智了，再尝试刷冷却 CD、换 IP、申诉。最后一招，换号。可以试试，但不保证有效。

你选的是 GPT-6 Astra 或者 GPT-6.1 Sol，实际被偷偷路由成了旧模型，比如 GPT-5.6 Luna。

这种风控 OpenAI 官方从没承认过，但你在使用中能感到模型明显的「降智」。

表现为知识陈旧、画出来的图结构错乱，还会连续弹出「Selected model is at capacity」，模型容量不足。

有可能持续被降智，有可能动态降智，刚开始用正常，用到一半又不行了。

同一个提示词，同样选 GPT-6 Astra + xhigh，两个账号画出来的鹈鹕骑车。

先判断是不是真被降智了，方法从快到准依次排列。

最简单粗暴的方法是发一句 ciallo。

没降智 Astra 的回复长这样。

再进一步，不联网询问一件最近才发生的事。如果被偷偷换成旧模型，知识会停留在更早的时候。

画「鹈鹕骑车」也是经典方法了，画得不好基本就是被降智了。

最准确的应该是检测「模型指纹」。

9 月我们介绍过开源工具 ModelTrace，原理是 AI 说不出真正的随机数，每个模型生成的随机数都有自己的分布，像笔迹一样，三道题就能认出是哪个模型。降智的号生成起随机数来还特别慢。但要注意它的指纹库里还没有 GPT-6.1 Sol、GPT-6.1 Terra 和 GPT-6.2 Astra，测试这几个模型，结果只能当参考。

ChatGPT 确认被降智了，怎么办？

如果你忍得了，先尝试刷新冷却。所有设备都退出登录，48-72 小时不用。不少网友表示有效，但重度使用可能会「二进宫」。

换干净的 IP，亲测有效。但换完最好等一会再尝试，因为 ChatGPT 可能需要重建账号缓存。所以测试有没有恢复，可以隔几分钟连续测试几次。

第三招改密码、重新开启两步验证、退出所有登录，过几个小时再登录。这个方法和第一个「刷新冷却」同理。

第四招，回到以前没降智的旧对话里接着对话，有可能恢复正常。

最后一招是换号，最费钱，但最有效。

最后，谁要是说能 100% 解决降智，那一定是骗你的。
