We introduce the Multimodal Knowledge Agent (MKA) benchmark, which measures how well autonomous
agents perform end-to-end professional knowledge work that depends on visual understanding. Each
task requires an agent to extract and combine information from multiple visually dense files, such as CAD
blueprints, electronics schematics, radiographs, complex charts and geospatial maps, and to produce
a standalone deliverable in .xlsx, .pptx, .pdf, .docx, .html or .png format. Existing benchmarks
leave this capability largely untested: removing image-viewing tools leaves Gemini 4 Carbon’s score
on GDPval (Patwardhan et al., 2025) unchanged (Section 4.3), and single-format evaluations such as
GDP.pdf (Garre et al., 2026) and GDP.xlsx (Surge AI, 2026) do not require reasoning across files or
modalities. MKA contains 200 tasks across 10 economic sectors. Deliverables are graded against expert-
weighted rubrics by a sandboxed agentic autorater that agrees with human domain experts on 96.2% of
criterion judgments in our expert-graded study (Cohen’s 𝜅 = 0.91), scored by weighted satisfaction rate
(WSR) overall and on frontier criteria unsaturated by prior-generation models (Climb-WSR). Across the
frontier models we evaluate (Gemini 4 Carbon, Claude Fable 5.2, Claude Opus 5.5, and GPT-6 Astra),
Claude Fable 5.2 (56.6% Climb-WSR, 73.3% Overall WSR) and Gemini 4 Carbon (54.3% Climb-WSR,
71.9% Overall WSR) achieve the highest scores, while Carbon uses 5.7× fewer tokens. Even for the
strongest models, Climb-WSR remains below 57%, leaving substantial headroom for multimodal agents.


1. Introduction
    Real-world knowledge work is deeply visual. Professionals routinely read technical diagrams
and schematics, interpret complex charts (Wang et al., 2024c), and work with messy scanned
documents (Ma et al., 2024a)—all while visually verifying the formatting and layout of their own
work products. Yet today’s frontier agents, shaped by coding-centric training (Jimenez et al., 2024;
Merrill et al., 2026; Wang et al., 2024a), exhibit a surprising degree of text-and-code bias rather than
using vision as a tool. Given a workspace of files, they instinctively convert documents to plain text,
Markdown, or CSVs, and often rely heavily on brittle OCR engines or traditional computer-vision
scripts despite possessing far stronger native visual capabilities (Anthropic, 2026; Bai et al., 2025;
Google DeepMind, 2025, 2026; Meta AI, 2025, 2026; OpenAI, 2025, 2026; Zhu et al., 2025)—
and even when looking at images directly, models remain prone to geometric blindness and strong
text-prior bias (Rahmanzadehgervi et al., 2024; Vo et al., 2025).
     Existing agentic benchmarks fail to expose this blind spot (Table 1; Section 5). Multi-file workplace
evaluations such as GDPval (Patwardhan et al., 2025) and APEX-Agents (Vidgen et al., 2026), either
allow task-critical signal to be extracted via scripts with negligible score loss, or focus on text- and
spreadsheet-heavy domains. Meanwhile, visual QA suites (Chen et al., 2024b; Fu et al., 2024; Garre
et al., 2026; Wang et al., 2024c; Yue et al., 2024b) test single-turn text responses without tool use,

2. The MKA Dataset
    MKA consists of 200 real-world tasks written and verified by vetted domain professionals. The
tasks are split evenly across 10 sectors (20 tasks each) and cover 83 occupations, including financial
analysts, licensed architects, electrical and mechanical engineers, GIS surveyors, data scientists,
attorneys and physicians. Each author has at least five years of professional experience, and every
task was reviewed for realism and accuracy by a second expert with the same job profile.
     Each task has a single prompt that specifies the user scenario, the requirements and the target
deliverable. An expert spent 3 to 8 hours on each task: assembling a realistic multi-file input bundle,
solving the task to produce golden reference deliverables, and writing a grading rubric with a golden
justification for every criterion.


Input files. Each task includes 2 to 45 input files (1,459 in total; mean 7.30, median 6.0), and
solving it requires combining information across visual, tabular, document and geospatial formats.

     To support independent evaluation while preventing benchmark contamination, MKA is accompa-
nied by two disjoint task sets. MKA (200 tasks) is the private evaluation suite reported in this paper,
hosted and graded independently on a public leaderboard by Artificial Analysis using the open-source
Stirrup framework (Section 3.1). MKA-Showcase (10 tasks) is a separate, publicly downloadable
release of one task per sector with full prompts, input files, and grading rubrics.

3. Evaluation Setup

3.1. Agentic Harness

     We evaluate every model in Stirrup (v0.2.1) (Artificial Analysis, 2025), an open-source,
lightweight agent framework maintained by Artificial Analysis. The harness gives the agent the task
prompt and the paths of the input files as text, so the agent must open and inspect each file and build
the final deliverables through tool calls. All models use the same harness, system instructions, tool set,
container image and resource budgets; only the model endpoint changes. An externally maintained,
minimal harness avoids model-specific scaffolding, so deliverable quality and token efficiency are
directly comparable across model families.


Agent loop. Stirrup runs without human intervention until the agent calls finish or reaches the
limit of 250 turns, with up to a 1M-token context window if available, and an 8-hour wall-clock limit
per task. At 70% of the model’s context length, compaction is triggered. If the model replies without
a tool call, the harness prompts it to continue. In the final 20 turns, the harness appends a warning
with the number of remaining turns so the agent can finish and submit its deliverables.


Sandbox. Each task runs in a fresh, isolated Linux container (4 vCPUs; 128 MB base RAM dynami-
cally bursting up to 16 GB) based on a Debian container with Python 3.13 (python:3.13-slim-
trixie), with working directory /workspace and input files staged under /workspace/input.
The sandbox has internet access. The image includes common document, PDF, OCR and rendering
tools, including LibreOffice, Tesseract, pymupdf, weasyprint and Python Office libraries, so agents

can parse inputs and build deliverables without installing software.


Tools. Stirrup exposes four tools: code_exec, view_image, web_search and finish. code_exec
runs bash commands and Python scripts (300 s per-command timeout), and web_search issues
web queries (180 s timeout). view_image loads a raster image (.png, .jpg, .webp, .gif, .bmp
or .tiff) into the model’s visual context. To inspect a document or slide deck visually, the agent
renders pages to .png with code_exec using command-line tools such as LibreOffice and pdftoppm,
and views the pages it needs with view_image. view_image is designed to respect the native image
resolution of the output file. At the end of a trajectory, finish checks that every declared deliverable
exists and ends the session.


3.2. Agentic Autorater

    Most MKA tasks (88.0%; 91.3% of rubric criteria) require standalone files such as spreadsheets
(.xlsx), slide decks (.pptx), documents (.docx), PDFs or images. MKA rubrics check both visual
layout and underlying file internals such as spreadsheet formulas. Static text extraction omits charts
and formatting, while static page renders hide cell formulas and can clip wide sheets. To give the
grader direct access to both, we use an agentic, multimodal judge that can inspect rendered pages
and run code to query file contents.


Grading harness. The Agentic Autorater is also a Stirrup agent. It runs in its own fresh container
with code_exec, view_image and a structured submit_verdicts finish tool, and without web
access. Its /workspace contains only the candidate’s deliverable files and final text response. The
autorater does not receive the task’s input files: MKA rubrics are self-contained, with each criterion
stating the expected value, tolerance or property directly, so grading checks the deliverable against
the rubric without re-solving the task. In a single session, the autorater checks these outputs against
the verbatim task prompt and rubric and returns, for each criterion, a pass/fail verdict, a justification
and the files it cited (prompt in Appendix A). We use OpenAI GPT-6 Luna as the autorater model.
Using a judge from outside the Google model family avoids favoring Gemini; we also see no sign of
same-family preference, as GPT-6 Astra ranks last among the evaluated models.

3.4. Quality and Efficiency Metrics

    We evaluate each model on deliverable quality and token efficiency across all 200 tasks. All metrics
are task-level means with tasks weighted equally. Rollouts that fail due to transient infrastructure or
API errors are re-run. Sessions that hit the turn or wall-clock limit are not re-run and are graded on
any outputs produced before termination; rollouts that produce no output (such as safety refusals)
score zero on all criteria.

WSR scores each criterion directly from 𝑤𝑖 𝑗 and 𝑠𝑖 𝑗 without gating on the primary/secondary labels or
prerequisite DAGs from Section 2; those annotations structure rubric authoring and quality control,

Climb and regression splits. Domain experts author rubrics covering every task requirement,
including basic formatting checks that current models pass routinely. Using a fixed panel of four
prior-generation models (Gemini 3.8 Flash, Gemini 3.6 Flash, Claude Sonnet 5.5 and GPT-6.1 Sol),
we label a criterion regression if every model in the panel passes it in at least 2 of 3 runs (6,396 criteria
across 180 tasks), and climb otherwise (7,888 criteria across all 200 tasks). Tasks that consistently
run out of context for the model panel are labeled all-climb. Because this split is derived from
autorater verdicts, a small fraction of criteria the panel satisfies may also be labeled climb due to
judge false fails (Section 3.3); the 2-of-3 rule dampens single-run flips, and the frozen split applies
equally to all evaluated models. Computing Eq. (2) over each subset yields three task-level scores:
Climb-WSR (headline; frontier capability), Regression-WSR (retention of skills that prior-generation
models already have, averaged over the 180 tasks with regression criteria) and Overall WSR (overall
deliverable quality).

5. Related Work
    MKA builds on a long tradition of benchmarks that have driven progress across two largely
separate tracks: static multimodal perception over documents, charts, and diagrams, and autonomous
tool use in coding, web, and office environments. Below, we situate MKA alongside prior work
across workplace deliverables, spreadsheet workflows, multimodal question answering, active visual
reasoning, agentic search, and computer-use grounding (summarized in Table 1).


Workplace Deliverables. Building on repository-level coding and CLI benchmarks (Jimenez et al.,
2024; Merrill et al., 2026; Yang et al., 2025), multi-application office and simulated company environ-
ments (Wang et al., 2024b; Xu et al., 2024), and domain-expert rubric evaluations (Arora et al., 2025;
Starace et al., 2025; Vidgen et al., 2025), recent suites evaluate agents on realistic project deliverables.
APEX-Agents (Vidgen et al., 2026) places agents in multi-file worlds across banking, consulting, and
law, grading outputs via per-criterion LLM-judge calls (Pass@1). GDPval (Patwardhan et al., 2025)
spans 44 occupations and grades deliverables primarily via blinded pairwise preference. Although
its workspaces include PDFs and slide decks, task-critical signal can largely be extracted via Python
scripts and OCR without visual inspection.


Tabular and Spreadsheet Workflows. Dedicated spreadsheet benchmarks isolate multi-step code
execution over complex workbooks without requiring visual perception or non-tabular deliverables.
GDP.xlsx (Surge AI, 2026) equips agents with sandboxed Python tools over a single workbook to
produce a text answer, while SpreadsheetBench 2 (Ma et al., 2024b; Zhu et al., 2026) evaluates
.xlsx modeling, debugging, and chart creation without cross-modal inputs.

Multimodal and Document Question Answering. Foundational document and chart QA bench-
marks (Ma et al., 2024a; Masry et al., 2022; Mathew et al., 2021) and harder frontier suites such
as MMMU (Yue et al., 2024a), CharXiv (Wang et al., 2024c), and MMMU-Pro (Yue et al., 2024b)
require strong visual perception, but present pre-selected images or pages in a single, tool-free turn
and grade multiple-choice or short text answers. Diagnostic suites including MMStar (Chen et al.,
2024b), BLINK (Fu et al., 2024), VLMs Are Blind (Rahmanzadehgervi et al., 2024), and VLMs Are
Biased (Vo et al., 2025) further show that VLMs often bypass pixels via linguistic priors or fail at
basic 2D geometric tracing. Extending document QA to enterprise files, Surge AI’s GDP.pdf (Garre
et al., 2026) evaluates atomic criterion rubrics over dense, multi-document professional PDFs, yet
still pre-attaches source PDFs in a single-turn prompt and grades a text response via a text-only
judge—omitting iterative tool use, cross-format synthesis, and binary deliverable verification.


Frontier VLMs and Active Visual Tool Use. Frontier multimodal models across proprietary (An-
thropic, 2026; Google DeepMind, 2025; Meta AI, 2026; OpenAI, 2026) and open-weight (Bai et al.,
2025; Meta AI, 2025; Zhu et al., 2025) families pair native visual perception with code-driven agent
scaffolds (Wang et al., 2024a), and recent models across labs—from Google’s Agentic Vision (Google
DeepMind, 2026) to Claude (Anthropic, 2026), Meta Muse (Meta AI, 2026), Qwen (Bai et al., 2025),
and OpenAI o3 (OpenAI, 2025)—actively inspect visual inputs by cropping, zooming, and transform-
ing images inside chain-of-thought. MKA tests whether these active perceptual capabilities transfer

                                                                                                         14
                     MKA: Evaluating Multimodal Knowledge Agents on end-to-end professional tasks



to multi-file enterprise workspaces where agents must choose when to write code versus when to
inspect pixels.


Agentic Search and Retrieval. Following general tool-use assistants such as GAIA (Mialon et al.,
2024), deep-research benchmarks evaluate multi-step web search over text (BrowseComp; Wei
et al. 2025) and visual web content (MM-BrowseComp; Li et al. 2025b). By design, however, these
benchmarks constrain outputs to a single short string or number to permit exact-match grading,
leaving open-ended multi-file synthesis untested.


GUI and Computer-Use Environments. Browser and desktop benchmarks (Li et al., 2025a; Xie
et al., 2024) evaluate agents acting through low-level pixel coordinates (mouse_move, click(x,
y)) or DOM actions, verifying completion via deterministic post-hoc scripts that check exact file
diffs, DOM states, or database records. While effective for closed-form UI tasks, model failures are
dominated by brittle interface grounding, and deterministic state scripts cannot evaluate open-ended
reports, executive slide decks, or valid layout trade-offs. Building on LLM-as-a-judge (Zheng et al.,
2023), MLLM-as-a-Judge (Chen et al., 2024a), and Agent-as-a-Judge (Zhuge et al., 2025) paradigms
alongside classical inter-rater agreement (Cohen, 1960; Fleiss, 1971), MKA decouples domain-level
multimodal reasoning from GUI clicking while grading binary deliverables with a sandboxed visual
and programmatic autorater.


6. Limitations
    Each model runs once per task and is graded in a single autorater pass, so our confidence intervals
capture task sampling but not run-to-run agent or grader variance. The human agreement study
covers 50 tasks and focuses on high-weight criteria (weights 3–5) with a balanced pass/fail mix, so
the 96.2% agreement may not transfer exactly to low-weight formatting checks. The vision ablation is
run on Gemini 4 Carbon only; other models may rely on vision to different degrees. The sandbox has
internet access, which mirrors real deployments but may let agents retrieve some information online
instead of extracting it visually. The climb/regression panel includes two earlier Gemini models, so
the split reflects what that panel already solves. Finally, API costs use provider list prices at the time
of writing and will change.


7. Conclusion
     Real-world knowledge work is inherently visual, requiring professionals to reason over blueprints,
schematics, maps, charts, and scanned documents while verifying the layout of the files they produce.
MKA brings this reality into agent evaluation across 200 multi-file workflows and 10 sectors, paired
with an Agentic Autorater that matches human domain experts on 96.2% of criterion judgments
in our expert study (𝜅 = 0.91). Our findings show that native visual perception drives not only
deliverable quality, but also compute efficiency: removing image-viewing tools degrades Climb-WSR
while inflating turns (1.28×) and output tokens (1.40×) as agents fall back on brittle scripting
workarounds, and frontier models exhibit an over 16× spread in total token usage across multimodal
trajectories (from 2.43M to 40.48M tokens per task), with Gemini 4 Carbon matching top deliverable
quality at 5.74× lower token usage (6.26× lower API cost) than Claude Fable 5.2 and 2.83× lower
token usage than Claude Opus 5.5. Yet while evaluated models exceed 95% on routine regression
checks, top Climb-WSR reaches just 56.6%—leaving substantial headroom for agents that natively
coordinate visual inspection, code execution, and visual self-verification.

A. Agentic Autorater Prompt
    Listing 1 shows the verbatim prompt template used by the Agentic Autorater (Section 3.2). At
runtime, the grading harness populates five placeholders:

   • {deliverables_line}: Comma-separated list of harvested deliverable filenames staged in
     /workspace (or (none - the agent submitted no files)).
   • {chat_line}: Path to the staged transcript of the candidate’s final text response when non-
     empty (or (none - the agent said nothing in its final message)).
   • {task_prompt_section}: The verbatim task prompt given to the candidate agent, prefixed
     by TASK PROMPT GIVEN TO THE AGENT:.
   • {rubrics_content}: The task’s rubric JSON mapping each "criterion N" key to its
     description and integer weight.
   • {output_warning_section}: Empty when the candidate submitted at least one deliverable
     file, or Listing 2 when the candidate responded only in chat.

Calling submit_verdicts validates that every rubric criterion has a structured verdict and terminates
the grading session.
Listing 1 | Agentic Autorater prompt template.
You are grading an agent’s work on a task. You are given two kinds of evidence:
the files the agent submitted, and the agent’s final chat message. Your task is to
verify whether the agent’s work satisfies the criteria
provided below.

The files have been written to the directory /workspace in your environment.
Use the code_exec tool for shell commands (Python scripts, LibreOffice,
pdftoppm, ...) and the view_image tool to look at images or rendered pages.
To inspect a PDF or Office file visually, render its pages to PNG first (e.g.
pdftoppm -png -r 150 <file>.pdf <prefix>) and view the PNGs.
IMPORTANT: When viewing several images, view them one at a time, never output
multiple view_image calls in a single response.

STRATEGY GUIDE FOR OFFICE DOCUMENTS:
When an output artifact is a Microsoft Office file (.docx, .pptx, .xlsx), choose
the most effective evaluation strategy (or a combination) based on the specific
rubric criteria. In most cases, START by rendering the document (Option A): the
extraction libraries in Option B routinely fail to "see" content that a human
grader sees (computed cell values, theme colors, text inside tables), which is a
common cause of FALSE NEGATIVES.
Option A (Rendered Evaluation - PREFER THIS for content presence, values,
  colors, and visual layout): Convert the document to PDF, render its pages to PNG,
  and inspect them with the view_image tool. The rendered PDF shows computed cell
values, theme/fill colors,
  text inside tables, charts, and the visual layout that programmatic extraction
  often misses. Use the code_exec tool to run LibreOffice:
    soffice --headless --norestore --nolockcheck --convert-to pdf <filename> --outdir
/workspace
  Then render the PDF to PNG (pdftoppm -png -r 150 <file>.pdf <prefix>) and use
  the view_image tool on the pages.
