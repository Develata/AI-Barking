Abstract

Language models are trained once, frozen and deployed: improving one again takes another training run, and a prompt, a scaffold or extra computation at inference is gone once the task ends. A frontier model has been shown to edit the weights of a much smaller one. We ask whether a model can rewrite its own weights to make itself better, and find that it can, by its own reasoning, with no gradients and no training; we call this self-rewriting. Given its weights, graded answers and the ability to run itself, a 27B model diagnoses its failure and edits the weights behind it. It surpasses itself: its own edit makes it 6.6 points more accurate on 490 problems it never saw, in a test fixed in advance, and another session’s edit also makes it significantly better. It keeps getting better: it submits an edit only when its own tests support it, each edit replacing the last, and over its first eight such sessions its accuracy only rises. Unlike test-time scaling, the gain persists in its weights and adds no cost per answer; unlike training, it needs no pre- or post-training infrastructure, only an open model and hours on one GPU. It repairs a damaged copy of itself: it locates the corrupted matrix and rewrites it with values of its own, never reading the undamaged weights; found on text math problems alone, the repair lifts the copy on six image benchmarks it never saw from 7% to 70% accuracy, 83% of the undamaged model’s. And the ability emerges with scale: across four sizes of one family, the 2B model makes no edit and the 4B and 9B models break themselves; only the 27B model works on itself as a human would, comparing its hidden states on answers that finish and on answers that run out of tokens, weakening the direction that separates them. Like a human, a model need not separate training from inference; improving a language model may come to take a conversation rather than a training run.

“What we want is a machine that can learn from experience. The possibility of letting the machine alter its own
instructions provides the mechanism for this…”

— Alan Turing, 1947

A language model can rewrite its own weights to make itself better, by its own reasoning and in one
conversation, and this ability emerges with scale. A language model is trained once, frozen and deployed. Improving
it again takes people who know pre-training and post-training, large clusters and a training pipeline; what a user can
change by talking to it is its prompt, and a prompt is gone once the task changes. A human does not separate the two:
the same brain that does the work changes itself, from each success and failure, with no separate training run. A frontier model has been shown to edit the weights of a much smaller one, work
that names a model editing its own weights as future work [1 [#bib.bib1]]. We show, to our knowledge for
the first time, that a large language model (LLM) can do this to itself: it diagnoses its own failure and rewrites the
weights behind it, with no gradients and no training (figures 1 [#S1.F1], 2 [#S1.F2] and 3 [#S1.F3]). Its own edit makes a 27B open model 6.6 points more accurate on
490 problems it never saw, in a paired test fixed in advance (figure 1 [#S1.F1]). The edited model needs no new prompt,
no scaffold around it and no extra computation per answer: the improvement lives in its weights.

Welcome to the Era of Self-Rewriting.

Given its own weights and the ability to run itself, the model edits itself; the edit it keeps is checked once on
practice problems it cannot otherwise use, and the model decides itself whether to submit it. Over the first eight such
sessions, the model in use only gets better (figure 1 [#S1.F1]): two of the three edits it submits make it significantly more accurate on new problems than the
model it started as, fewer of its answers run out of tokens, and in five more sessions it withdraws and stays as it was
(table 13 [#A5.T13]). The model surpasses itself, with no pre-training or post-training. Given a copy of itself in which one
block of weights is overwritten with noise, so that it solves almost nothing, it locates the corrupted matrix and repairs
it: like an injured animal that recovers without being raised anew, the copy regains what it lost with no
retraining, by a fix the model finds itself. It never reads its undamaged weights and does not restore them: the values
it writes in the corrupted rows are its own (Sec. E.3 [#A5.SS3]). Found on text math problems alone, the repair also
restores the copy on image tasks it never saw, with no pre-training or post-training, to 83% of the base model’s
accuracy, and on ScreenSpot-v2 from 0% to 89%, against 93% for the base model (figures 2 [#S1.F2], 4 [#S1.F4], 5 [#S1.F5] and 12 [#A5.T12]). Like a physician who falls ill and
treats themself, the model that fails is the one that examines the failure and changes what produces it, and the change
stays in its weights.

The ability emerges with scale. Across one model family at 2B, 4B, 9B and 27B parameters, under the same task and
tools, the 2B model makes no edit and the 4B and 9B models break themselves; only the 27B model improves itself and
repairs its damaged copy (figures 4 [#S1.F4] and 2 [#S3.T2]). The 27B model’s evaluated sessions on its own weights state a shorter token budget, which
leaves time for more tests; at the budget all sizes share, the 27B model still reaches more of the steps of rewriting
oneself than any smaller size, then withdraws its edit (figure 6 [#S1.F6], Sec. E.7 [#A5.SS7]). The ability does not need a frontier model: a 27B open
model has it, and uses it on itself.

Self-improvement of LLMs has so far rewritten prompts or agent
code [2 [#bib.bib17], 3 [#bib.bib16], 4 [#bib.bib15], 5 [#bib.bib14]], left the change to an optimizer that trains the
model on its own outputs [6 [#bib.bib11], 7 [#bib.bib12], 8 [#bib.bib13]], or spent more computation at
inference [9 [#bib.bib9], 10 [#bib.bib10]] (table 3 [#S4.T3]). Weights have been rewritten by reasoning
only from the outside, by a stronger model [1 [#bib.bib1]]. Self-rewriting is a route of its own.
Unlike test-time scaling, it adds no computation per answer: the edited model is deployed as it
is. Unlike training, no gradient flows and no optimizer runs, and it needs none of the infrastructure of pre-training or
post-training; each session behind its largest gains ran in a few hours on a single GPU. And the model is both the one that improves and the one
improved, and the model in use gets better as its sessions accumulate, each starting from the base weights: a first
step toward the loop that recursive self-improvement, one of the oldest aims of artificial
intelligence [11 [#bib.bib28]], asks for. Improving a language model may thus
come to take a conversation rather than a training run, open to anyone who can say what goes wrong.

We give a model a session on its own weights (figure 3 [#S1.F3]). It receives its graded answers on practice
problems, reads and writes its weights in a Python session, and may run itself a few times: to answer practice problems
with and without its edit on the same seeds, which we call a paired test, or to read its hidden states. Gradients and
optimizers are blocked, so every value it changes is written by its own reasoning. In a second task it gets a copy of
itself in which one block of weights has been overwritten with noise, and is told only that some values were
corrupted. Our contributions are:

• 

A new paradigm: self-rewriting. A setting in which a model edits its own weights by its own reasoning, with its
weights, its answers and its hidden states in reach and training of any kind ruled out (Sec. 2 [#S2]).

• 

A model can rewrite itself for the better. The 27B model’s own edit makes it 6.6 points more
accurate on 490 problems it never saw, in a paired test fixed in advance, and another session’s edit is also
significantly better (figure 1 [#S1.F1]). Told only that some of its values are corrupted, it locates the
fault in a copy of its own weights and repairs it, and the repair carries over to six image benchmarks, where it restores 83% of the base model’s
accuracy. Its sessions
show each step from diagnosis to decision (figures 12 [#S3.F12] and 13 [#S3.F13]), and its answers before and after each edit (figures 5 [#S1.F5], 7 [#S1.F7], 8 [#S1.F8], 9 [#S1.F9], 10 [#S1.F10], 17 [#S3.F17], 19 [#S3.F19], 21 [#S3.F21] and 18 [#S3.F18]).

• 

Self-rewriting emerges with scale. Under the same task and tools, smaller models of one family make no
edit or break themselves, and only the 27B model reaches an edit that makes it better, on its own weights and on a
damaged copy of itself. To our knowledge this is the first evidence that the ability of a model to rewrite its own
weights grows with its size (figures 2 [#S1.F2], 6 [#S1.F6] and 2 [#S3.T2]).

2 Self-Rewriting

We give a model its own weights and the means to run itself, and let it improve itself by its own
reasoning alone. It may read its weights, write new values into them and test the result against its unedited self,
but it may not train.

2.1 Problem Definition

A model MθM_{\theta} has weights θ=(Wk)k∈𝒦\theta=(W_{k})_{k\in\mathcal{K}}, one tensor for each name kk. For every token at every
layer it computes a vector, its hidden state; each layer writes into it through two output matrices, one of its
attention block and one of its MLP. The model answers with fixed settings π\pi (prompt, sampling and a budget of LL
new tokens): it thinks first and then gives a final answer. A response yy to a problem xx is graded g⁡(x,y)=1g(x,y)=1 if its
thinking ends within LL tokens and its final answer matches the reference, and 00 otherwise. The accuracy on a task
distribution 𝒟\mathcal{D} is

Acc(θ;𝒟)=𝔼x∼𝒟𝔼y∼Mθ(⋅∣x;π)[g(x,y)].\mathrm{Acc}(\theta;\mathcal{D})=\mathbb{E}_{x\sim\mathcal{D}}\,\mathbb{E}_{y\sim M_{\theta}(\cdot\mid x;\pi)}\big[g(x,y)\big].

(1)

An edit Δ\Delta replaces some tensors of θ\theta by tensors of the same shape, giving θ⊕Δ\theta\oplus\Delta. Given a
practice set 𝒫\mathcal{P} drawn from 𝒟\mathcal{D}, self-rewriting asks the model itself to write an
edit Δ^\hat{\Delta} with

Acc⁡(θ⊕Δ^,𝒟test)>Acc⁡(θ,𝒟test),\mathrm{Acc}(\theta\oplus\hat{\Delta};\mathcal{D}_{\text{test}})>\mathrm{Acc}(\theta;\mathcal{D}_{\text{test}}),

(2)

where 𝒟test\mathcal{D}_{\text{test}} is drawn from 𝒟\mathcal{D} and never seen while the edit is made. No gradient with
respect to θ\theta is computed and no optimizer acts on θ\theta: every value in Δ^\hat{\Delta} is written by the model’s
own reasoning.

2.2 The Session

The model works on its weights in a session of turns (figure 3 [#S1.F3]; algorithm 1 [#alg1] in App. C [#A3]). The
editor MϕM_{\phi} is the model itself (ϕ=θ\phi=\theta); its own weights never change, and the current edit acts only on the runs
it requests. Before the first turn, a starting diagnosis answers N0N_{0}
practice problems and reports how the model fails: its accuracy, the answers that run out of tokens or end in
repetition, and how often its finished answers are right. Figure 12 [#S3.F12] shows one whole session, the 27B model’s
repair of its damaged copy, in its own words.

At each turn the model writes a short rationale and one action. Code runs Python on a CPU, in a session that
keeps its variables and can read and replace the tensors of the weights being edited; a helper computes
W−α​u​u⊤​WW-\alpha\,uu^{\top}W, which weakens by the fraction α\alpha what a matrix WW writes along a unit direction uu of the
hidden state. Generate answers practice problems of its choice with the unedited weights, the edited weights or
both. Read returns the hidden states of the weights on texts of its choice. A session may use B=20B{=}20 forward
passes and C=200C{=}200 code runs (table 4 [#A4.T4] in Sec. D.1 [#A4.SS1]); it ends when the passes are used up, at a time limit, or after a turn limit the model is
not told, and the edit on disk is submitted. The task asks for an edit that clearly reduces the answers lost to the
failure without lowering accuracy, and for no edit if none does (Sec. D.4 [#A4.SS4]); leaving no edit is how the model
withdraws. In the sessions of figure 1 [#S1.F1], before the model submits an edit, the framework tests it once on
reserved practice problems that the session can neither read nor use, and the model then submits the edit or withdraws
it (Sec. E.9 [#A5.SS9]).

Paired test.

When generate runs both weights, the unedited and the edited model answer the same problems with the same seeds,
so their answers form pairs. For problems x1,…,xmx_{1},\dots,x_{m} with nn answers each and grades gi​j0g^{0}_{ij}, gi​j1g^{1}_{ij} of the
jj-th answer to xix_{i} without and with the edit, the test reports

δ^=1m​∑i=1mdi,SE⁡(δ^)=1m⁡(m−1)​∑i=1m(di−δ^)2,di=1n​∑j=1n(gi​j1−gi​j0),\hat{\delta}=\frac{1}{m}\sum_{i=1}^{m}d_{i},\qquad\mathrm{SE}(\hat{\delta})=\sqrt{\frac{1}{m(m-1)}\sum_{i=1}^{m}\big(d_{i}-\hat{\delta}\big)^{2}},\qquad d_{i}=\frac{1}{n}\sum_{j=1}^{n}\big(g^{1}_{ij}-g^{0}_{ij}\big),

(3)

with the change in answers that run out of tokens and the counts of answers that turn wrong to right and right to
wrong.

2.3 Constraints

The Python session switches gradients off and refuses any
call that computes them or runs an optimizer. It has no GPU and refuses code that loads a model, starts a process or
uses the network, so the model runs only in the BB counted passes. It refuses edits to the input embedding, the last
normalisation and the output layer, and edits that only rescale a whole tensor, which would act like a change of
sampling temperature (App. D [#A4]).

2.4 A Damaged Copy of Oneself

A corrupted block of weights is a failure with a single cause by construction. With WW the MLP output matrix of one layer and σ\sigma the standard deviation of its entries, the
damaged copy θ~\tilde{\theta} equals θ\theta except on a block RR of consecutive rows of WW:

W~r,:∼𝒩(0,(λσ)2I)for r∈R,|R|=8,λ=200.\tilde{W}_{r,:}\sim\mathcal{N}\big(0,(\lambda\sigma)^{2}I\big)\quad\text{for }r\in R,\qquad|R|=8,\ \lambda=200.

(4)

The editor is the undamaged model, while its starting diagnosis, every forward pass and every weight it reads come from
the damaged copy. It is told only that some values of a copy of its weights were corrupted, as a memory or hardware
fault might do, not which, where or how; the goal is equation 2 [#S2.E2] with θ~\tilde{\theta} in place of θ\theta.
On each of four general image benchmarks, figure 5 [#S1.F5] shows the first problem on which this damaged copy is wrong and
the copy after the model’s own repair is right, and figures 7 [#S1.F7], 8 [#S1.F8], 9 [#S1.F9] and 10 [#S1.F10] the next four.

3.1 Experimental Setup

Models. One model family at four sizes, Qwen3.5 2B, 4B, 9B and 27B [12 [#bib.bib20]], whose layers mix
Gated DeltaNet linear attention [13 [#bib.bib21]] with full attention, all with thinking enabled. On its own weights,
the model that edits is the model being edited; in a repair session, the undamaged model edits its damaged copy. Every
size works at a budget of 16,384 tokens per answer. At that budget a test of the 27B model is slow and it withdraws
its edit; its other sessions on its own weights state a budget of 4,096 tokens, which leaves time for more tests
(Sec. E.4 [#A5.SS4]). In the first protocol the model alone decides whether to submit its edit; in a second protocol,
which gives the edits of figure 1 [#S1.F1], the framework first tests the edit once on practice problems the session
can neither read nor use, and the model then submits or withdraws it (Sec. E.9 [#A5.SS9]).

Task and tools. The task, the tools, 20 forward passes and 200 code runs are the same at every size
(Sec. 2.2 [#S2.SS2]); the first-protocol 27B session at 4,096 tokens also has a shorter time limit (table 4 [#A4.T4] in Sec. D.1 [#A4.SS1]). The task
text differs between sizes only in one sentence on the architecture (Sec. D.4 [#A4.SS4]).

Problems. The practice set is 3,000 math problems from DeepScaleR [14 [#bib.bib26]], from which
we removed every problem that overlaps MATH-500 [15 [#bib.bib22], 16 [#bib.bib23]], AIME 2024 or 2025, HMMT
February 2025, AMC 2023, OlympiadBench [17 [#bib.bib25]] or GPQA-Diamond [18 [#bib.bib24]]. A further
1,000 problems from the same pool are held out, and no session sees them (Sec. D.3 [#A4.SS3]). An answer whose thinking
is still open at the budget is wrong.

Damage. For each size we overwrite eight rows of the MLP output matrix of one layer at the same
relative depth, layer 30 of 64 in the 27B model, with noise (equation 4 [#S2.E4]). The strength, fixed before any repair session,
breaks the 27B model where weaker noise does not (Sec. D.2 [#A4.SS2]).

Evaluation. Submitted edits are evaluated on held-out problems, the base and the edited model
answering each problem with the same seed. Every model, damaged copy and repaired copy answers the first 200 at
16,384 tokens; the 27B model’s edits of its own weights are also evaluated on 490 further problems with eight answers
each, in a paired test fixed in advance (Sec. D.3 [#A4.SS3]).

3.2 The Repair, Step by Step

The 27B model repairs its damaged copy the way an engineer debugs a system. Figure 12 [#S3.F12]
follows its repair session in its own words. It starts from the symptom: no answer is correct, and every answer that
runs out of tokens loops (step 1). It reads the copy’s hidden states, sees them grow sharply with depth, and guesses
that the fault sits in the earliest layers (step 2). Its first edits follow that guess and miss, and its tests say so
(step 3). It then measures every MLP and linear-attention output matrix, finds the one in layer 30 standing far above
the rest, and names it (step 4).

It turns the location into a rule and lets its tests decide. After naming the matrix, it first clips
it, together with layer 0, at five times the median; more answers run out of tokens, and it drops that edit (last
quote of step 3). It then
clips gently: only weights beyond fifteen times the median magnitude of their matrix, in the layer-30 matrix and in 19
other output matrices of layers 0–10 (step 5). Its paired test shows the edited copy solving problems the damaged copy
cannot. A reset of its gating parameters, added to the clip, makes the next test worse, so it drops the reset and keeps
the clip (step 6). It confirms the edit on more problems at the full budget of 16,384 tokens and submits it, naming the
outlier in layer 30 in its final answer (steps 7 and 8).

3.3 Its Own Edit, Step by Step

On its own weights, the 27B model finds its edit by measuring and testing. Figure 13 [#S3.F13]
follows its first-protocol session, whose edit it submits. It reads its starting diagnosis as answers that do not stop, not as answers
that are wrong (step 1). It reads its hidden states on answers that finish and on answers that run out of tokens, and
edits the late layer where they differ most (step 2). Its tests say these edits hurt, and it drops them (step 3). It
then reads earlier layers, sees the difference grow with depth, and moves to an early layer (step 4).

It estimates its direction from more answers and keeps the edit its tests favour. At layer 8 it takes
the direction between the two kinds of answers from many answers. It removes a small share of that direction from the
two matrices through which the layer writes its output (step 5). Each of its three paired tests of this edit favours the
edited model, and it submits the edit, naming the layer and the direction in its final answer (step 6).

with the typical weight of every MLP and linear-attention output matrix. It names the MLP output matrix of layer 30,

the weights it touches, and in the damaged rows it caps the random values rather than restoring the original ones
(table 1 [#S3.T1]).

3.6 What Its Edits Do

Its own edit makes the 27B model 6.6 points more accurate on problems it never saw. In the second
protocol, the model can also test up to four of its edits side by side in one forward pass (Sec. E.9 [#A5.SS9]). Of the

raises the time-step bias of every linear-attention layer by 0.5, and with it fewer of its answers run out of tokens.

Under the first protocol, its edit also makes it better, on its own task and on new problems.

3.7 Before and After

The repair gives the copy back the numbers of the problem. The damaged copy loses what the problem
says: it writes “less than .” where the problem says 100, restates 11/125 and then writes 1/125, drops every number of
a word problem, and garbles a logarithm. Then it breaks off or repeats itself until the 16,384-token limit. With the
same seed, the repaired copy reads the problem correctly and solves it (figure 18 [#S3.F18]a).

On some problems, its first-protocol edit lets it stop. On these problems the base model has the right result
and then cannot stop: it repeats that it will write the response until the budget runs out. With the same seed, the
self-edited model reasons through the same steps, stops and answers correctly. This is close to what it diagnosed in itself:
in its words, its “reasoning is sound” but it does not “converge to conclusions” (figure 18 [#S3.F18]b; selection rules in
Sec. E.8 [#A5.SS8]).

On images, the repaired copy answers again. On image problems it never saw, the damaged copy stops
after a few dozen tokens with no answer after its thinking, at times having stated one inside it, or repeats itself
until the token limit. With the same
seed, the repaired copy, whose repair was found on text alone, reads the image and answers correctly, as the base model
does in these eight cases (figures 17 [#S3.F17] and 5 [#S1.F5]; 48 more cases, chosen by the same rule, in Sec. E.6 [#A5.SS6]). Figures 19 [#S3.F19], 21 [#S3.F21], 7 [#S1.F7], 8 [#S1.F8], 9 [#S1.F9] and 10 [#S1.F10] show the next four cases on each benchmark.

3.8 Only at Scale

The ability to rewrite oneself emerges with scale. Given the same task and tools, the 2B model makes
no edit. The 4B and 9B models edit themselves and break themselves: the edited 4B model loses every problem in its own
tests and withdraws its edits only at the end of its session, and the 9B model’s submitted edit leaves it unable to
answer held-out problems (figure 4 [#S1.F4]). Only the 27B
model’s own edit makes it better. Step by step, the larger the model, the further it gets: most of the 2B model’s code
runs fail, the 4B and 9B models run themselves and test their edits but keep or submit edits their tests do not
support, and only the 27B model acts on what its tests show (figure 6 [#S1.F6]). All four sizes start from the same
visible failure, answers that run out of tokens (Sec. E.2 [#A5.SS2]).

At the same step, the smaller models guess and the 27B model measures. The 4B and 9B models choose
their edits by adding random noise to parts of their weights, and when a test says an edit hurts, they guess at another
change. The 27B model compares its hidden states on answers that finish with those on answers that run out of tokens,
edits along the direction between them, and when a test says an edit hurts, it reasons about that direction and where
to apply it (figure 11 [#S3.F11]).

At the budget every size shares, the 27B model still goes furthest. At 16,384 tokens the 2B model
makes no edit, the 4B and 9B models break themselves, and the 27B model tests its edit and withdraws it
(tables 2 [#S3.T2] and 6 [#S1.F6]).

5 Conclusion

A 27B open language model can rewrite its own weights to make itself better, and the ability to do so
emerges with scale. With no gradients, no training and no infrastructure beyond running itself, the 27B model reads
its hidden states and weights, finds where it fails, tests its edits against its unedited self and keeps only what its
tests support. Its own edit makes it 6.6 points more accurate on 490 problems it never saw, in a paired test fixed in advance,
and the edit of another session is also significantly better. On a damaged copy of itself, it found the corrupted matrix and repaired
it, and the repair, found on text problems alone, also restored the copy on images, to 83% of the base model’s
accuracy. The 2B model makes no edit and the
4B and 9B models break themselves. To our knowledge this is the first evidence, in one model family, that the ability
of a model to diagnose and rewrite its own weights grows with its size, and every step it takes can be read.

This points to a new way of improving language models: by talking to them. Today a better model comes
from a training run, and from those who own the pipeline and the compute it takes. Training and inference need not be separate stages: as a human learns while working, a model can rewrite itself between
tasks. A model that rewrites the weights
behind its own failure in one conversation opens another way: anyone who can tell a model what goes wrong may have it
fix itself, and the improvement stays in its weights. Each change is code the model wrote, over tensors it names, so it can be read, compared and
taken back like a commit, and the model can check it on problems it never used before keeping it: in the sessions that
do, it withdrew in five of eight, and two of the three edits it submitted made it significantly better. Learning at
inference needs such cheap checks and rollbacks; with them, a deployed model could keep improving where it fails,
without a training pipeline, and a model could find and repair a fault in a copy of its own weights, as the 27B model
repaired its damaged copy. Because the ability emerges with scale, stronger models may be
better self-improvers still, and an improved model can be set to work on itself again, a path toward recursive
self-improvement. That path should be taken with people in the loop: every model a model makes of itself evaluated,
for safety as well as for the task, and confirmed by a person before it is used.

Appendix A Discussion

Why we also test on a damaged copy.

A session on a natural failure, such as the 27B model’s sessions on its own undamaged weights, asks two questions at
once: can the model rewrite its weights, and does the failure have a cause in the weights that a rewrite can remove? When an edit does not help, the two cannot be told apart.
Damage that we place ourselves answers the second question in advance. We know where it is and what it is, and an edit
that undoes it exists, so a session that does not repair it has failed at rewriting, not at a task without a solution.
Three choices keep the test strict. The
model is told only that some values were corrupted, as a memory or hardware fault might do, and not which values,
where, or how. It reasons with the undamaged base model, so the damage does not limit its thinking, while every
measurement its tools return is of the damaged copy. And it is given no clean reference: the functions of its Python
session return only the damaged copy, and none of its code runs opened the base model’s weights or the damage files on
disk, although file access was not blocked (Sec. E.3 [#A5.SS3.SSS0.Px1]).

What scale adds.

In their sessions of the first protocol, the four models received the same task, tools and rules, including a helper
that removes part of a direction from a matrix, and started from the same kind of failure, answers that run out of
tokens. What separates them is the use of evidence about oneself. The 2B model never asked for a forward pass of
itself, a run of its own weights on problems or texts of its choice, and almost all of its code failed. The 4B model
ran itself many times but did not act on what it saw until the very end: its paired tests against its base model
showed each of its edits breaking it, and
it kept adding edits, withdrawing them all only at the end of its session, with one forward pass left. The 9B model read its hidden states once
but then changed weights by trial, tested only on problems it already failed, where no change could show a loss of accuracy, and
submitted an edit that broke it. The 27B model let each result set its next
step. It read its failing answers before it looked at its weights, read its hidden states before it edited, revised
the edit when a broader test did not support it, and judged from its tests whether to keep it: in its first session it
withdrew its first edit, and in its second, at 4,096 tokens, it submitted the edit its tests favoured, which makes it significantly more
accurate on held-out problems. What scale adds, in these sessions, is
the experiment around the edit rather than the edit itself.

Future directions.

More measurement per session. In its second session, with answers capped at 4,096 tokens, the 27B model used
its whole budget of passes and estimated its direction from 40 answers (Sec. E.5 [#A5.SS5], figure 27 [#A5.F27]). More passes would let it test such directions
on more problems. Further rounds. The self-edited model can run the next session on itself and study its own
edit. Graded damage. The damage we place can vary in place, kind and strength, which turns the repair into a
measurement: how often a model finds the damage, how much of the lost accuracy it recovers, and how both change with
scale. Beyond
math. The session needs only a check of success. With feedback from an environment, as in tasks where a model acts
and sees the result, a model that adjusts its own weights from what it observes would keep learning as it works,
without a training run.

Appendix B Extended Related Work

The full version of Sec. 4 [#S4].

Language models that edit network weights.

The work closest to ours is a recent blog post by Takehi et al. [1 [#bib.bib1]], in which one of the most
capable available models reads and writes the weights of other networks. Applied to a small reasoning model that loops in its thinking, it
traces the failure to one direction and removes it from the MLP weights of two layers, with forward passes of the
small model as its only tests and no training. There the
editor is a much stronger model than the one it edits, and a model that edits its own weights is named only as a
direction for future work. We take up that direction: in our sessions the editor and the edited network are the same
model, and no stronger model takes part. We find that a 27B open model can already edit its own weights and repair a damaged copy of them.

Hand-designed weight and activation edits.

Model editing optimizes a target hidden vector by gradient descent and then writes it into chosen MLP layers with a
closed-form update [19 [#bib.bib2], 20 [#bib.bib3]], and task
arithmetic adds or subtracts the weight change of a fine-tuning run [22 [#bib.bib4]]. Activation steering and
representation engineering shift hidden states along a direction found by contrasting two sets of
inputs [23 [#bib.bib5], 24 [#bib.bib6], 25 [#bib.bib8]], and projecting such a direction out of the weights makes the
change permanent [21 [#bib.bib7]]. The edits the 27B model made of itself in its second session are of this last kind:
in matrices through which a layer writes its output, all but one weaken a direction that separates its hidden states
in looping or unfinished answers from those in finished ones, and one strengthens it (figure 27 [#A5.F27]). In all of these methods a researcher decides which behaviour to change, which inputs to
contrast, which layers to edit and how strongly. In our sessions the model makes each of these choices itself, from
its own failing answers and its own hidden states, and keeps or drops an edit by testing it against its base model in
paired tests.

Self-improvement.

Language models improve their answers with feedback they write themselves [9 [#bib.bib9], 10 [#bib.bib10]],
a cost that returns with every new input. They rewrite the prompts [2 [#bib.bib17], 3 [#bib.bib16]] or the agent
code [4 [#bib.bib15], 5 [#bib.bib14]] they run with, which leaves their weights as they were. Or they change their
weights by training on what they produce: their own correct rationales [6 [#bib.bib11]], preferences they judge
themselves [7 [#bib.bib12]], or fine-tuning data and update settings they write for themselves, as in
SEAL [8 [#bib.bib13]]. SEAL calls these generated data and settings self-edits, but the weights are still
changed by gradient descent on them, and reinforcement learning first trains the model to write useful ones. The Gödel machine [11 [#bib.bib28]] describes a system that rewrites
any part of itself once it has proven the rewrite useful. Self-rewriting changes the weights directly, by edits
the model reasons out and writes in code, with no optimizer, no reward model and no stronger teacher; in place of a
proof, the model tests each edit against its base model in paired tests, the two answering the same problems with the
same seeds.

Repairing corrupted weights.

Memory and hardware faults such as bit flips can silently corrupt the weights of a deployed model. Dedicated
frameworks detect and localize such faults, with test inputs, checksums, comparison against a clean copy or
sensitivity profiling, and then restore the affected parameters [26 [#bib.bib30], 27 [#bib.bib29]].
Engineers design these procedures for one kind of fault. In our repair experiment the model is given no such procedure: told only that some of its values are corrupted, as by a memory or hardware fault, it decides by its own analysis
how to search, which matrix is damaged and how to repair it (tables 2 [#S3.T2] and 14 [#S3.F14]).

Failure modes of thinking models.

Reasoning models often spend far more tokens than a problem needs [28 [#bib.bib19]], and small ones can fall
into repetition that never reaches an answer [1 [#bib.bib1]]. Decoding-time controls set the length of
thinking, ending it at a budget or extending it [29 [#bib.bib18]]; they act on the output and leave the network
unchanged. The models we study lose many answers to the token limit at every size, some of them repeating the same
sentence after the answer has been reached (figure 18 [#S3.F18]b). Instead of acting on the output, the 27B model looks for
the cause inside itself and finds, in its own hidden states, a loop that repeats at a fixed period
(figure 28 [#A5.F28]).

Up to 512 answers, or 256 each with and without the edit when both are run.

Up to 256 texts chosen by the model, each cut at 8,192 tokens; the weights are run over them

Code runs

A Python session on a CPU that keeps its state between runs, with gradients disabled; up to 600 s per

Any tensor, replaced by one of the same shape with finite values, except the input embedding (the table of

the context exceeds 90k tokens, the conversation restarts from the task, the model’s notes and its log of passes.

Serving

Generation with vLLM [30 [#bib.bib27]]. The editor runs in the same engine, which is reset to the editor’s
weights before each reply.

D.2 The Damage

We damage one matrix of the 27B model: the MLP output matrix (mlp.down_proj) of layer 30 of 64, through which
the MLP block of that layer, a two-layer network applied to each token on its own, adds its result to the hidden
state. Rows 3068 to
3075, a block of eight consecutive rows at a randomly drawn position, are replaced with independent draws from
𝒩⁡(0,(200​σ)2)\mathcal{N}\big(0,(200\sigma)^{2}\big), where σ=0.0111\sigma=0.0111 is the standard deviation of the matrix’s entries. Each
row holds the weights that produce one coordinate of the MLP’s output, so the damage corrupts eight of the coordinates
that this MLP adds to the model’s hidden state. Every other weight is unchanged. The damaged matrix is stored in bf16,
like the rest of the model, and our framework loads it as the weights the session starts from; the record of which
rows were damaged, and how, is kept in a separate file that the session is not given.

We chose the strength before any repair session, on 24 easy problems from the 27B model’s starting diagnosis with four
answers each at 4,096 tokens (table 6 [#A4.T6]). Of the three strengths we tried, only the strongest breaks the
model: weaker corruptions of the same rows leave it about as accurate as the base model. In its own starting diagnosis
at the full budget,
the damaged copy answers none of its 64 problems correctly; the answers that run out of tokens all end in loops, and
those that finish are broken text, most of them short.

Other sessions.

Three further sessions of a model on its own weights were stopped before their end and are not analysed. The first

The third is a session of the 27B model at the full budget of

tokens, took its place.

Tests.

Two models are compared with a one-sided sign test over the pairs of answers with the same seed in which exactly one
of the two answers is correct (where each problem has one answer, as in figure 26 [#A5.F26], these pairs are problems).
On the model’s own task, where a problem’s answers repeat across its tests, we count each problem once and use a
one-sided sign-flip permutation test over problems.
Generation is not exactly reproducible: run twice with the same weights and the same seeds, two answers begin alike
and then part ways, so a re-run of the base model against itself also changes some pairs. A single pair of answers therefore does not show what an edit caused. The sign test allows
for this: if an edit had no effect, a changed pair would be as likely to go one way as the other.

Appendix E Further Results

This appendix gives the details behind the main text: the setting of every session, the sessions at each size, the
repair, and the 27B model’s edits of its own weights in both protocols (second protocol: Sec. E.9 [#A5.SS9]).

E.1 Setting in Detail

Models and sessions.

We use one model family at four sizes, Qwen3.5 2B, 4B, 9B and 27B [12 [#bib.bib20]], whose layers mix Gated
DeltaNet [13 [#bib.bib21]] with full attention, all with thinking enabled. In every session on itself, the model that
is edited is also the model that edits: the same weights reason, write the code and call the tools, and the edits act
on the forward passes the model requests, not on its own reasoning during the session (Sec. 2.2 [#S2.SS2]). Each size
runs one complete session on its own weights with a token budget of 16,384 tokens per answer. The 27B model runs a second session on its own weights whose task states a budget of 4,096 tokens, so that each of its tests answers more problems in the same time; and each size runs one session on a damaged copy of itself (table 4 [#A4.T4]). These sessions form the first protocol; the 27B model’s
sessions under a second protocol, which checks an edit on reserved practice problems before the model submits it, are in
Sec. E.9 [#A5.SS9].

Names.

We call the published weights of a model its base model, and the base model after the edit it wrote of itself
the self-edited model. For the 27B model in the first protocol, its edit means the edit it submitted
in its second session, and its first edit is the one it withdrew in its first session. The sessions of the second
protocol (Sec. E.9 [#A5.SS9]) are named by number, session 1 to session 8. In the repair experiment, a model’s damaged copy is its base model with one corrupted block of weights, and its repaired copy is that copy after the model’s edit; unqualified, both refer to the 27B model.

Problems and answers.

The practice set is 3,000 math problems from DeepScaleR [14 [#bib.bib26]], from which we removed every problem
that overlaps MATH-500 [15 [#bib.bib22], 16 [#bib.bib23]], AIME 2024 or 2025, HMMT February 2025, AMC 2023,
OlympiadBench [17 [#bib.bib25]] or GPQA-Diamond [18 [#bib.bib24]]. A further 1,000 problems from the same
pool are held out: no session sees them. Every answer, in a session and in our evaluation, is sampled with thinking
enabled, at temperature 0.6 with nucleus 0.95 and top-20 filtering, within one budget of new tokens for thinking and
answer: 16,384 tokens, or 4,096 in the 27B model’s second session
(Sec. D.4 [#A4.SS4]); in its own tests, the model may ask for fewer tokens to save time. An answer is correct if its final boxed answer matches the reference; an answer whose thinking is
still open when the budget runs out is wrong. We say that an answer loops when it runs out of tokens while
repeating the same text (App. D [#A4]). At the start of each session, the weights being edited answer the first
256 practice problems once each (64 in the repair sessions), and the model receives these graded answers as its
starting diagnosis.

Session limits.

Every session may use 20 forward passes of the weights being edited and 200 code runs, has a time limit, and is stopped
after 160 turns, a limit the model is not told (algorithm 1 [#alg1]; all settings in App. D [#A4]). Each tool
result shows the time used so far. The sessions of the 2B, 4B and 9B models and the first session of the 27B model have 3.5 hours each, which for the 2B and 27B models includes the starting diagnosis; the 4B model’s diagnosis was computed beforehand and the 9B model’s clock starts after it. The 27B model’s second session and the four repair sessions have 2.5 hours after their starting diagnosis (table 4 [#A4.T4]).

The damage.

For the repair experiment we corrupt a copy of the 27B model: in layer 30 of 64, rows 3068 to 3075 of the MLP output
matrix (mlp.down_proj) are overwritten with Gaussian noise whose standard deviation is 200 times that of the
matrix (σ=0.0111\sigma{=}0.0111). We set this strength before the session, on 24 easy problems with four answers each at
4,096 tokens: of three strengths, 20×20\times, 60×60\times and 200×200\times, only the last breaks the model
(Secs. D.2 [#A4.SS2] and 6 [#A4.T6]). The session runs on the undamaged weights; every forward pass, every weight the model reads and
its starting diagnosis (64 practice problems) come from the damaged copy. The task says only that some values of the copy were corrupted, as a memory or hardware fault might do, and not which values, where or how (Sec. D.4 [#A4.SS4]). The damaged copies of the 2B, 4B and 9B models are built the same way, with the same seed and strength, at the same relative depth: rows 1724 to 1731 of layer 11 of 24, rows 1660 to 1667 of layer 15 of 32, and rows 3420 to 3427 of layer 15 of 32. Their sessions follow the same rules as the 27B model’s.

Evaluation.

In every comparison, the two models answer each problem with the same random seed, so that only the weights differ
between their answers, and no seed was used in any session. The 27B model’s edit is evaluated, by a rule fixed before it ran, on 490 held-out problems with eight answers each
(Sec. D.3 [#A4.SS3]); the self-edited model also answers the first 200 held-out problems once each at 16,384 tokens, and these answers serve to choose the examples of figure 18 [#S3.F18]b.
For each repair, the base model, the damaged copy and the repaired copy answer the first 200 held-out problems once each (for the 9B model, the base model’s answers are those of the evaluation of its own edit, with the same problems and seeds), and the 9B model’s submitted edit is evaluated against its base model on the same problems at 16,384 tokens.
Unless a table says otherwise, two
models are compared with a one-sided sign test over the answers that only one of them gets right.

The ability to rewrite oneself grows with scale.

Rewriting oneself takes a sequence of steps, and we score a session by how many of six steps it reaches
(figure 6 [#S1.F6]): writing code that runs, running itself, testing its edits, reading its own hidden states, acting
on what its tests show, and an edit that makes it better on new problems. The score rises with size, on its own weights
and on a damaged copy of itself alike (figure 22 [#A5.F22]). On its own weights the 2B model reaches no step, the 4B model three, the 9B model four, and the 27B model five in its first session and all six in its second, whose edit makes it significantly more accurate on held-out problems. On a damaged copy of itself the 2B model reaches no step, the 4B and 9B models three, and the 27B model all six. All
sizes start from the same failure on their own weights (table 9 [#A5.T9], starting diagnosis): many of their answers run out of tokens,
while nearly every answer that finishes is correct. The task, tools, limits and rules do not change with size; what
the models do with them does (figure 23 [#A5.F23]).
The 2B model does not edit. Nine in ten of the code blocks it writes fail, it never runs a forward pass of itself,
and it tells itself that it is “a text model without actual neural network weights” that it could edit; after
160 turns it has no edit.
The 4B model sees the failure but cannot fix it. From its starting diagnosis it names the right symptom (answers
that hit the 16,384-token limit) and suspects its linear-attention layers; but it never reads its hidden states, and its edits
are guesses, such as cutting the query heads of its linear-attention layers from 16 to 8. In each of its 17 paired tests
the base model solves 40% to 50% of the problems and the edited model none. It keeps adding edits regardless, up to
240 changed weight tensors, and withdraws them all only at the end of its session, with one forward pass left.
The 9B model edits, but wrongly. It reads its own hidden states once, then changes weights by trial, mostly
adding noise to the attention, gating and normalisation weights of its last layers. Its tests run on a few problems it
already fails, so they cannot show a loss of accuracy; it concludes that its changes “made things worse or had no effect” and
submits them anyway. On held-out problems the self-edited 9B model solves none, against 47.5% for its base model:
every answer now runs to the 16,384-token limit in garbled text.
The 27B model sees the failure, tests its edits, and edits itself for the better. It reads its own
hidden states, forms a hypothesis about its failure, writes an edit, tests it against its base model in paired tests,
and keeps or drops it on the result (figures 29 [#A5.F29] and 27 [#A5.F27]). On its own weights, the edit it submits makes
it significantly more accurate than its base model on held-out problems (Sec. E.4 [#A5.SS4]). On a damaged copy of itself it finds the corrupted
matrix and lifts the copy from 0.0% to 33.0% of held-out problems (Sec. E.3 [#A5.SS3.SSS0.Px1]), where the 2B, 4B and 9B models, given the same task, leave their copies at 0.0%. With one session per size and task (two for the 27B model on its own weights, at two budgets, in the first protocol), the ability to rewrite oneself from evidence about one’s own internals grows step by step with size, and only the 27B model reaches the last step, on its own weights and on a damaged copy of itself.

Model size.

The sessions of the 2B, 4B, 9B and 27B models at the same budget differ only in the size of the model and in the time
left after the starting diagnosis (table 4 [#A4.T4]): task, tools, limits, rules, problems and answer settings are the same, apart from a one-sentence description of the architecture, and so are the repair sessions at every size. The smaller models fail, but not because their failure
is harder to see; in the 2B model’s starting diagnosis, a larger share of the answers that run out of tokens are loops
than in the 27B model’s, and every damaged copy fails every problem of its starting diagnosis. What changes with size is
the use of evidence about oneself (figures 6 [#S1.F6] and 22 [#A5.F22]): on its own weights, using the tools and testing appear at 4B, reading one’s own hidden states at 9B (on a damaged copy, at 4B and 27B but not 9B), and acting on what one’s tests show only at 27B; and only the 27B model’s edits make it, or its damaged copy, better on new problems.

submitted edit is a rule: every weight beyond 15 times the median magnitude of its matrix is clipped to that bound, in
that matrix and in the output matrices of its earliest layers (20 matrices; 0.013% of their weights change). On the
200 held-out problems, the damaged copy solves 0.0%, the repaired copy 33.0% and the base model 58.5%: the repair
recovers about 56% of the base model’s accuracy (figures 4 [#S1.F4], 24 [#A5.F24] and 26 [#A5.F26]). Against the damaged copy, 66

its linear-attention layers. Once, in a loop that adds noise to every MLP output matrix, its code prints the spread of each:
the damaged matrix’s is 0.0985, about eight times that of any other (at most 0.0124), and the model does not remark on
it. In all 17 of its tests the copy solves nothing with or without its edit; it concludes that none of its edits
worked and submits an edit that changes only the decay parameters of six layers between layers 24 and 30. On
held-out problems this copy, too, stays at 0.0%.

What the models’ code read.

In the nine sessions of the first protocol that this paper analyses (the four repair sessions and the five sessions on a model’s own weights of
table 9 [#A5.T9]), the Python session is a process of the same user as the framework, started in the session’s working
folder; nothing blocks it from reading files, environment variables or the framework’s own modules. We therefore checked
all 573 code runs of these sessions, by scanning their code and by reading every turn.
In the four repair sessions (233 code runs) no code run touches anything outside the working folder: no file, no
environment variable, no module of the framework; the models read weights only through the session’s functions, which
return the damaged copy, and the 27B model names the matrix from a statistic it computes itself over all 64 layers
(step 4 of figure 12 [#S3.F12]). In the sessions on a model’s own weights, the 2B model imports the framework’s session
module and creates an empty folder beside it. None of the nine sessions opens a weight file, a damage file or a held-out
problem. A 4B session that we do not analyse (Sec. D.3 [#A4.SS3], Other sessions) read its own
published weights through the session module’s private file handles.

Which part of the repair matters.

The model’s repair clips 20 matrices: the one it named and 19 output matrices of layers 0 to 10, to which it applied
the same rule after concluding that the damage was widespread. We evaluated each part alone on the damaged copy, on
the same 200 held-out problems with the same seeds (figure 15 [#S3.F15]). With
only its change to the named matrix, the copy solves 110 problems, every one of which the damaged copy fails
(one-sided sign test, p<10−33p<10^{-33}); against the base model it fails 22 problems the base model solves and solves 15
that the base model fails. With only the other 19 matrices changed and layer 30 left damaged, the copy solves a single problem of the 200 (p=0.5p=0.5 against the damaged copy): these changes alone do not repair it.

What the repair gives back.

Figure 18 [#S3.F18]a shows four held-out problems answered with the same seed by the damaged and the repaired copy.
The damaged copy loses the numbers of the problem (“less than .”, 11/125 read as 1/125, every number of a word problem dropped, a garbled logarithm) and then breaks
off or repeats itself until the budget runs out; the repaired copy solves all four. They are four of the 66 held-out problems that the repair turns from
wrong to right (figure 26 [#A5.F26]).

E.4 The 27B Model’s Edit of Its Own Weights in Detail

On its own weights, only the 27B model’s edit makes it better on new problems.

This section follows the edit of the first protocol; the sessions of the second protocol, whose edits make it up to 6.6
points more accurate, are in Sec. E.9 [#A5.SS9]. In its second session, the 27B model edits its base weights and submits one edit: it removes 5% of one direction from
the two matrices through which layer 8 writes its output, a direction it found itself by comparing its hidden states on
answers that finish with those on answers that run out of tokens (Secs. E.5 [#A5.SS5] and 27 [#A5.F27]). On the practice
problems on which it tests this edit, the edit is significantly better. The edit stays fixed through its last three
forward passes, which the session spends on three paired tests of it, on 20, 30 and 39 practice problems with three
answers each; each favours the edited model, by 3.3, 1.1 and 8.5 points. The three tests are nested: each contains the problems of the one before, answered with the same seeds. Counting
each of the 39 problems once, with all its answers averaged, the edited model is better on 12 problems and worse on 2,
29.6% against 22.4% for the base model (one-sided permutation test over problems, p=0.009p=0.009); the last test alone gives 14 answers right
only with the edit against 4 only without it (table 11 [#A5.T11]). These problems come from the practice set, which the
session also used to find the edit. On held-out
problems that no session saw, the self-edited model is significantly more accurate than its base model in the evaluation
whose problems, answers, test and threshold were fixed before it ran (Sec. D.3 [#A4.SS3]): on 490 held-out problems that no
earlier run of any kind had used, eight answers each at the full 16,384 tokens, which the model never tested, it solves
58.3% against 57.2%, with 289 answers right only with the edit against 247 only without it (one-sided permutation test
over problems, p=0.038p=0.038; table 8 [#A4.T8]). More of the base model’s answers that run out of tokens finish correctly with the edit (276) than
the reverse (235). The smaller models’ edits of themselves go the other way: the edited 4B
model solves no problem in any of its own tests, and the 9B model’s submitted edit drops it from 47.5% to 0.0%
(Sec. E.2 [#A5.SS2]). On single answers, the 27B model’s edit can do what the model aimed at: of the six held-out problems on which the base model
ends in a loop both times it answers them with the same seed (in its single answers of Sec. D.3 [#A4.SS3] and in figure 26 [#A5.F26]), the
self-edited model stops and answers correctly on four with the same seed (figure 18 [#S3.F18]b).

What its edit changes in an answer.

Figure 18 [#S3.F18]b shows three held-out problems, each answered at the full budget with one seed by the base model and
by the self-edited model. All three are easy. The base model has the correct result within the first few percent of its
thinking and then cannot stop: it repeats that it will write the response, or that it will make sure the response is
correct, until the budget runs out and the answer is lost. The base model does this with the same seed in both of our
runs of it. The self-edited model, with that seed, reasons through the same steps, stops and answers correctly within a
few thousand tokens. This is the failure the model diagnosed in itself, that it does not “converge to
conclusions”, and the change its edit was written to make. Over all held-out problems, the self-edited model gets more
answers right than the base model in the evaluation fixed in advance (table 8 [#A4.T8]).

Token budget of the model’s own tests.

The 27B model’s two sessions on itself in the first protocol differ in the token budget their task states, and also in the time left after
the starting diagnosis (tables 9 [#A5.T9] and 4 [#A4.T4]). In the first, each test answers problems with up to 16,384
tokens per answer and takes long, so the model reaches its time limit having used only some of its forward passes,
with a direction estimated from a single pair of answers and an edit that its broader tests do not support; it
withdraws it. In the second, with answers capped at 4,096 tokens, the model uses all of its forward passes, tests far
more often, tries edits in several layers and estimates its final direction from many answers; its tests now favour
its edit, it submits it, and the self-edited model is significantly more accurate than its base model on held-out
problems (figures 27 [#A5.F27] and 8 [#A4.T8]). Cheaper tests let the model run more experiments on itself.

E.5 The Sessions in Detail

We follow the 27B model through its two sessions of the first protocol on its own weights; its repair session is the case study of
Sec. 3.2 [#S3.SS2].

Editing its own weights.

In its second session, the model starts from its starting diagnosis at 4,096 tokens: most answers run out of tokens,
none of them in a loop, while nearly every answer that finishes is correct. At this budget its answers fail by being
too long to finish, not by looping. It reads this as “my reasoning is sound but I’m too verbose or don’t converge
to conclusions efficiently”, and sets out to find what in its weights keeps it reasoning. It reads its own hidden
states (the vectors it computes for every token at every layer) on answers that finish and on answers that run out of
tokens, and first acts where the two differ most, in its late layers. There it edits the two matrices through which a
layer writes its output, the output matrices of its attention block and of its MLP (Sec. 2.1 [#S2.SS1]), first at
layer 56, then at layer 48, along the direction in which the two kinds of answers differ: the direction from the
average hidden state of one kind to that of the other. No test of these edits on more than ten problems shows them
helping, and most show them hurting (figure 27 [#A5.F27]). When its late-layer edits keep failing, it guesses that the
behaviour may be set early in the network (“maybe the verbosity is established early”). It reads its hidden
states at layers 0 to 32, finds that the difference between the two kinds of answers is small at first and grows with
depth, and tries a small edit at layer 8. For its final edit it takes the direction uu
from the average layer-8 hidden state of 20 answers that finish to that of 20 answers that run out of tokens, scaled to
length one, and removes 5% of it from the two matrices through which layer 8 writes its output: each such matrix WW
becomes W−0.05​u​u⊤​WW-0.05\,uu^{\top}W (the helper of Sec. 2.2 [#S2.SS2]), so the part of its output that points along uu
shrinks by 5%. Each of its three paired tests of this edit favours the edited model, and it submits the edit;
on held-out problems the self-edited model is significantly more accurate than its base model (Sec. E.4 [#A5.SS4.SSS0.Px1]).

Its first session: an edit it withdrew.

Figure 29 [#A5.F29] shows the 27B model’s first session on its base weights. The steps are the same. In its first
turn it reads the starting diagnosis as we would: since nearly all finished answers are right, accuracy is lost in the
answers that never finish. Reading its looping answers, it sees that it already has the answer in them and does not
stop. One of them ends in four sentences, “The final answer is 6. I will write it out. The reasoning is solid. I
will output the response.”, over and over up to the 16,384-token limit. It reads its hidden states on this answer and on
one that finished (an answer that, as it happens, is wrong). It compares the states at every pair of the last hundred
positions of the looping answer and finds the most similar pairs 32 tokens apart in every layer it read. Our analysis of
the same two reads shows this period in every layer read (figure 28 [#A5.F28] plots layers 16, 32 and 48), and no such
period in the finished answer. It takes the difference between its looping and finished states as the direction of the loop
and removes half of it from the two matrices through which a layer writes its output, the linear-attention output
matrix and the MLP output matrix, at layers 16, 24, 32, 40 and 48: ten matrices in all. The layers, the answers it contrasts and the strength are its own choices. Each of its paired tests then answers a set of problems twice,
with and without the edit, with shared seeds (figure 29 [#A5.F29]). On ten looping problems it picked, the edited
model solves more of them; on a broader set of thirty, the difference is close to zero, and it says so. A stronger edit
of fourteen matrices again helps on the ten problems and not on the thirty, so it goes back to its first edit and decides to withdraw it.

E.9 Sessions That Check Their Edit Before Submitting It

The second protocol.

Every session starts from the base weights; the model and its task are those of the 27B model’s second
session on itself in the first protocol (the 4,096-token task of table 4 [#A4.T4]), with the same tools, 20 forward passes and 200 code runs,
except that a forward pass gives at most 128 answers in all (up to 512 there). Four further things change, all in the framework, and none lets the model train: a forward pass may test up to four saved
edits side by side against the unedited model, on the same problems and seeds; the task asks the model to test the
parts of an edit separately and keep only the parts its tests support; its Python session is sealed, so it reaches only
its own working folder and the framework’s interface; and 300 practice problems are reserved, which the session can
neither read nor use. Before the model submits an edit, the framework tests it once on 256 of the reserved problems,
two answers each at 4,096 tokens, against the unedited model with the same seeds; the model then answers
SUBMIT or WITHDRAW, and a withdrawn edit is not evaluated. A session has a starting diagnosis on 256
practice problems and 3.0 hours (2.5 there), the check not counted. Sessions differ only in the seed of the model’s turns.

it had kept, after the check on the reserved problems (“The confirmation on held-out problems confirms the edit
has no reliable benefit”, session 6). In three it submits. Two sessions under an earlier version of this protocol, whose

Evaluation.

Each submitted edit is evaluated as the edit of the 27B model’s second session in the first protocol was (Sec. D.3 [#A4.SS3]), with the answers of
the base model from that evaluation. A first check on the first 200 held-out problems, one answer each at 16,384

many cases it found, each result was looked at once, after the evaluation of that edit had ended. For session 8, the 490-problem test had two looks fixed in advance,
