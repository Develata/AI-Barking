## 二、可能的吠点（说法 vs 证据；L1 来源为主，社区评论仅作线索 L6）

1. 标题“10 GB file”vs 实际：模型卡文件表 3.0bpw = 10.12 GB，视觉投影 mmproj-BF16 另 0.93 GB（“for all three”）；24 GB 卡上 3-bit 仅放得下约 135K 上下文，满 262K 需约 30 GB 显存（模型卡显存表）。“10 GB 文件”不等于 10 GB 显存。
2. “match BF16” vs 逐项：现行模型卡表里 3-bit 在 MGSM 93.1 < BF16 94.0；2.5-bit 在 Terminal-Bench 60.2 < 62.6、AIME 96.5 < 97.7、MGSM 91.8 < 94.0、RealWorldQA 81.3 < 82.4；DeepSWE 两档高于 BF16 约 1.2–2.1 分（41.0 / 41.9 vs 39.8）。论文自称“within noise”（配对差 s.e. 3.2–3.6 分，论文 §4.1）。
3. 对照口径：Unsloth 点不是作者跑的，是读自其图表（≈，mini-swe-agent，至少三轮）；NariQ 与自家 BF16 用 Claude Code。论文自述“this normalization does not remove harness differences”。GSQ-RCO IQ3_XXS 在自家 harness 为 36、在 Unsloth harness 约 29（图 19），HN 评论（WithinReason，hugmynutus）质疑“gains due to harness”（L6；作者回复自家 BF16 每轮 45.0 vs Unsloth 报告 45.65）。
4. 版本漂移：论文 v1（11-19）与 fork README 用一轮数（BF16 44 / 3-bit 47 / 2.5-bit 46 / 2-bit 33），11-22 的模型卡改成三轮平均（45.0 / 46.3 / 47.3 / 32.3）；3-bit 与 2.5-bit 的 DeepSWE 高低因此互换（一轮 41.6 vs 40.7，三轮 41.0 vs 41.9）。
5. 自家评测，无独立复现：全部分数来自 Nari Labs；BF16 一次 verifier 超时记 0（338/339）；单人项目（模型卡：“this has been a solo effort”）；论文致谢“AI tools assisted with writing, literature search, implementation, and research analysis.”
6. 只有一个运行时：模型卡“Run them on our llama.cpp fork (required)”；fork 对上游领先 18 提交、落后 275；上游 llama.cpp 无 NariQ 相关 issue/PR；GGUF 类型 id 44–49 上游未分配。HF 页面自带的“Use this model / Local Apps”按钮（llama.cpp、LM Studio、Jan、vLLM，命令为 `llama serve -hf …:BF16`）是平台自动生成的通用片段，按模型卡这些在现在都不能加载（存档 b-hf-community.html，该页 11-24 22:58 取）。
7. 速度只在 RTX PRO 6000（SM120）上给：同卡 4K 上下文 NariQ 3.0bpw 88.9 tok/s vs Unsloth UD-IQ3_XXS 94.7；Ampere、Ada、Hopper、Apple“are slower than comparable GGUFs for now”；M3 Pro 18 GB 3.8 tok/s（Metal 文档：“too slow for long agent sessions”）；GeForce 唯一一次记录：RTX 5060 Ti 16 GB，2.5bpw，Windows，约 38 tok/s，“not qualified”，仅在 fork README，模型卡与 qualification 页仍写未测。
8. 16 GB 卡：模型卡把“fit long contexts on 16 GB consumer GPUs”放在“next”（KV 与激活量化尚未做）；今天 KV cache 与激活为 BF16。fork README：5060 Ti 16 GB Windows 约 47K 上下文。
9. 系统要求：Linux x86-64 + NVIDIA 驱动 ≥570（Windows ≥572，实验，二进制未签名，Smart App Control 开启时被 Windows 11 拦截，关闭后“on many Windows 11 versions it cannot be turned back on without resetting Windows”）；AMD、Intel“No NariQ kernels”；老于 Ampere“fall back to slow CPU execution”。
10. 预编译与下载量：Linux 包 257 MB + cudart 594 MB，模型本地缓存“about 13 GB with the 3.0bpw file”（fork README）；HF 下载量 8,795（“Downloads last month”，11-24 22:58 取）。
11. 社区线索（L6，HN）：mmastrac（exl3/exlr8 作者之一，自述）质疑未说明与 exl3 mul1 码本的关系，称 NariQ“appears to be a derivative of exl3's mul1”，作者回复“we ... did internally run against MUL1 ... similar results”，称贡献在“loss counting only the tokens the model writes”（HN 50617252、50622379，无分数显示）。jedbrooke/vorticalbox：3.8 t/s“a 1000 token reply is around 4 minutes”（HN 50617744，按其算术）。作者自述“It does run on my Mac alright, but ... pretty slow atm.”（HN 50622057）。均无第三方 GeForce 实测。

## 五、对读者（已核实事实，注出处）

- 要跑只能用 nari-labs 的 llama.cpp 分支；原版 llama.cpp、Ollama、LM Studio 现在不能加载（模型卡限制段；fork README 首段）。
- 一键脚本：Linux（Ubuntu 22.04 或 Debian 12 及以上）+ NVIDIA 驱动 570 以上，`bash run.sh 3.0`；Windows 为实验版，驱动 572 以上，二进制未代码签名，Smart App Control 开启时被拦（fork README）。
- 显存：24 GB 卡 3-bit 可放约 135K 上下文，满 262K 需约 30 GB（模型卡显存表）。16 GB 卡没有官方上下文数字；作者自测 RTX 5060 Ti 16 GB 的 2.5bpw 约 47K 上下文、约 38 tok/s（fork README，一次，未合格）。
- 不受益或受限：AMD、Intel 无内核；早于 Ampere 的 NVIDIA 卡回退 CPU，慢；Mac 仅 M3 Pro 18 GB 跑过，约 3.8 tok/s（3.0bpw）、4.9 tok/s（2.0bpw），需从源码编译（模型卡；Metal 文档）。
- 价格与许可：免费下载；权重 Apache-2.0，fork 代码 MIT（HF NOTICE；fork README）。
- GeForce 实测：作者只有一张 5060 Ti 的记录；其他 GeForce（含 RTX 4070 等）无官方数据；Ada 架构“slower than comparable GGUFs for now”（模型卡）。
- 作者计划：向上游 llama.cpp 提交支持（“we hope to merge support into upstream”，未提交）；KV cache 与激活量化“next”（模型卡）。
