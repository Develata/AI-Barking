Codex 用量扣減出錯　OpenAI 預告 Sol/Astra 修正後額度將更快用完

2026年11月25日週三 上午6:34

 [https://www.facebook.com/dialog/feed?app_id=458584288257241&link=https%3A%2F%2Fhk.news.yahoo.com%2Fshare%2F2c20313e-8aa7-322d-9e49-fdf13235d097%3Fsoc_src%3Dsocial-sh%26soc_trk%3Dfb%26tsrc%3Dfb] [https://api.whatsapp.com/send?text=https%3A%2F%2Fhk.news.yahoo.com%2Fshare%2F2c20313e-8aa7-322d-9e49-fdf13235d097%3Fsoc_src%3Dsocial-sh%26soc_trk%3Dwa]

OpenAI 已向 Codex 訂閱用戶發出題為「An update to Codex usage」的電郵，承認部分請求扣減的用量額度少於原意，並表示已作出修正。這封電郵是一項用量更正通知，並非公佈新功能。修正後，用戶可能會發現自己比之前更早觸及用量上限，而訂閱價格維持不變。

用量扣少的範圍

根據 OpenAI 發出的電郵，受影響的是 Codex 內部分 GPT-6.2 Astra 及 Sol 請求，這些請求扣減的用量額度少於原意。電郵亦明確指出，受影響範圍包括 Ultrafast 模式，因此更正並不限於未使用該模式的請求。官方沒有在電郵中交代額度少扣的實際比例，也沒有列出受影響的時間範圍。

廣告

廣告

為何之前覺得額度耐用

部分用戶早前可能覺得 Codex 的用量突然較耐用，或留意到額度消耗較慢。按 OpenAI 的通知，部分請求扣減額度少於原意，這種感覺並非由 GPT-6.2 Astra 或 Sol 的效能優化，或新模型帶來的效果所解釋，而與用量計數偏差有關。官方現已更正這項扣減問題。

在扣減方式更正後，受影響的請求會按修正後的方式計入用量，因此用戶處理同一批工作時，額度會較先前更快耗用。若工作流程長期依賴 Codex 處理大量請求，觸及上限的時間亦可能明顯提前。換言之，先前被視為化算的額度使用方式，在更正後未必再成立；實際情況仍以用戶自己的剩餘用量為準。

修正後要留意什麼

OpenAI 提醒用戶，更正後可能會更早觸及用量上限。用戶可前往 Settings → Usage，查看剩餘用量及重置時間，以掌握目前的額度情況；訂閱價格則不會改變。官方電郵沒有交代受影響的時間範圍、少扣比例或補償安排。用戶宜重新估算自己每日可用額度，避免再按先前「耐用」的印象安排工作量。
