黎曼猜想那份1740万行的证明，被砍掉了99.5%！

2026-11-26 10:45发布于北京科技领域创作者

问AI · 若验证通过却无人能懂，这算人类证明吗？

1740万行，砍到了7.6万行！

还记得上周那份让整个数学圈看傻眼的黎曼猜想证明吗，它被重写了。

今天早上，Anthropic 研究员 Luke Sernau 在 GitHub 放出新版本，最短的一版只剩7.6万行代码。

链接：https://github.com/lsernau/grh-lean

Sernau 的仓库叫 grh-lean，里面放了两版。

可读版：约30万行代码、801个文件，带导读、目录和术语表，写给想读的人。

紧凑版：约7.6万行代码、792个文件。作者在说明里写，这一版只求短，读起来不会轻松。

比较有趣的是，上周数学家 Levent Alpöge 写出黎曼猜想1740万行证明的是 Claude，这周把它压到两百分之一的，还是 Claude。

◈1740万行，没人读得动

这份证明有多让人头疼，得倒回一周看。

11月20日，Anthropic 数学家 Levent Alpöge 宣布，他和 Claude 花了大约六周，证明了悬了167年的黎曼猜想。

那会儿交出来的不是论文，是一份 Lean 代码。

Lean 是让电脑检查数学证明的语言：每一步推理写成代码，程序逐行核对，错一步就编译不过。

第二天，Lean 社区就确认：对的。

可是，17.5万个文件，1740万行，太大了。

是 Lean 整个数学库的七倍。这么大一份东西，全篇只有一处写给人看的注释。

就连陶哲轩看完说，消化它需要时间。

机器能从头查到尾，人连从哪里开始读都找不到。

于是社区决定先把文件删小点。

◈上百人删了五天

创业者 Rohan Arun 把原版拆成一个个模块，用 GitHub 机器人分派，谁认领哪块谁来修，很快拉来了上百位贡献者。

第一天，他们就删掉了1.1万多个压根没被引用的文件。

可到11月25日，Lean 社区公共仓库里的代码，也才比原版少了大约24%。

另一个项目 rh-trim 更狠，直接上程序自动删。

它先给证明画了张地图，结果发现，真正收尾的论证只占6.6%，其余全在搭工具，光一个步骤就占了全部代码的38%。

然后开删：删一批，编译一次，看报错，把删错的放回去，再删。

38个小时，71轮。

最好的一轮，还剩17个错误。

始终没能清零。就算全删干净，最多也只能少大约8%。

连数学家 Alpöge 自己都绷不住了。

11月24日，他在 X 上发长帖认错：代码里明显有很多垃圾，大家的批评都合理；本该整理好再发，只是整理起来比想象的难得多。

◈Anthropic 研究员 Luke Sernau 换了条路：重写

Luke Sernau 没去碰原来那17万个文件，而是带着 Claude 和几位 Anthropic 同事，把证明从头重写了一遍。

整体思路沿用 Alpöge 的方法，但很多步骤换成了别的论证，从原版搬来的背景材料也都重写过。

具体怎么做的，他在 Lean 社区的讨论区只透了个大概。

先把一层层嵌套的定义全部展开，铺成一条很长的扁平证明。

在这条长链里找能合并、能化简的地方。

再重新折回成定义。

这样一来，原来隔着好几个文件、互相看不见的重复，就能摆在一起处理了。

有些地方光这样还不够，只能换一条全新的论证。原版依赖 Vandiver 猜想的那一大块，被他整个拿掉了。

不过，Sernau 在仓库首页写得很清楚：这份证明只通过了机器检查，没有数学家完整读过，也没有论文。

◈下周会剩一页吗

消息一出，X 上很快刷屏了。

数学家 Robin Houston 的发文调侃：照这个速度，下周就只剩一页了。

算一下这一周：证明是 AI 写的，压缩是 AI 做的，检查是机器跑的。

那问题来了。

如果哪天它真被压到一页，每一步都对，机器也认了，却还是没人说得清它为什么成立。

这算不算，人类证明了黎曼猜想？
