# 1126 B 组取证：Google Workspace 强制 MCP 与 Gmail 发信限制

执行：Antigravity（Gemini 模型家族子代理）。本机 macOS，UTC+8；取证时间：北京时间 2026-11-27 21:12 起，约 21:48 写成。时间一律写北京时间（括号保留原时区）。级别按 `EDITORIAL.md` L1–L7；状态只用：已找到 / 部分支持 / 与说法不符 / 未找到一手来源。抓取与截图逐条记录见 `capture-log-b.md`；截图在 `images/16–29`（其中 `20`、`24` 已被 `27`、`26` 替代，列待删）。

## 零、最关键发现（2026-11-26 至 11-27 的实时反转与真实边界）

1. **“Gmail MCP 不能发邮件”在发布 48 小时内发生反转**：
   - **2026-11-24 首发时至 11-26 晚（北京）**：TechStackups（11-26）、Flavio Copes（11-26）以及独立评测机构 Suncly（在 `contradictions.json` 记录 `readOn: 2026-11-26T11:03:29Z`，即北京 11-26 19:03:29）各自实测 `https://gmailmcp.googleapis.com/mcp/v1` 返回均只有 **23 个公开工具**，`send_message`、`reply`、`forward`、`update_draft` 等 8 个工具在当时的 Gmail 配额页中被脚注标为 `"require partner access and aren't generally available"`（仅 Anthropic Claude 连接器等合作方可用）。
   - **2026-11-26 晚至 11-27（北京）**：HN 热帖 `50653477` 于北京 11-26 17:44（`09:44:23Z`）冲上首页后，Google 于 **2026-11-26 21:15 UTC（北京 11-27 05:15）前**悄然更新了线上 MCP 端点与文档（Wayback 快照 `20261126211519` 已显示更新；`gmail/api/reference/mcp` 与 `send_message` 等工具页标注 `Last updated 2026-11-26 UTC.`，配额与总览页标注 `Last updated 2026-11-27 UTC.`；HN 评论 `50663581` 于北京 11-27 14:43 也指出了这一更新）。
   - **截至本组实测（北京 2026-11-27 21:14–21:19）**：无需鉴权直接调用 `https://gmailmcp.googleapis.com/mcp/v1` 的 `tools/list` 已返回 **30 个工具**，**包含 `send_message`、`reply`、`forward`、`update_draft`、`create_filter`、`list_filters`、`update_label`**；原配额页中的“partner access”脚注已删除；官方 `gwscli`（实测 `1.0.6.1026726559`）因运行时动态拉取服务端列表，也已同步开放全部 **30 条 Gmail 命令**和 **15 条 Drive 命令**（但 Drive 仍无更改共享权限 `share` 和永久删除命令）。
2. **真限制还在，只是换成了两道门**：
   - **端点分化（`/mcp/v1` vs `/mcp/v1self`）**：`/mcp/v1`（30 个工具）虽然开放了 `send_message`、`reply`、`forward`，但前提是客户端必须支持 MCP **form elicitation（表单诱导/人工逐次确认）**；对于不支持 form elicitation 的 MCP 宿主/客户端，只能连回退端点 `/mcp/v1self`（**25 个工具**），而 **`/mcp/v1self` 仍然剔除了 `send_message`、`reply`、`forward`（以及 `apply_sensitive_message_label`、`apply_sensitive_thread_label`）**。无人值守脚本或未声明 form elicitation 能力的客户端调用需确认工具会报错 `-32021 MissingRequiredClientCapability`。
   - **条款与计费剪刀差**：2027-02-01 起《Workspace AI Tools Addendum》生效，规定 AI Agent / AI Harness 驱动的访问必须走 Google MCP 或官方 `gwscli`；且 2027-04-01 起，传统 REST API 在 Scaled Tier 保留巨额每日免费额度（Gmail Light 7000 万 / Medium 1000 万 / Premium 100 万），而 **Scaled Tier 下的 Gmail / Calendar / Drive MCP 每日免费额度为 0，从第 1 次成功请求起计费**（且 `search_threads` 与 `list_drafts` 每次按 10 次请求计费），企业内部自用豁免（internal-use exception）也不适用于 MCP。

## 四、可能的吠点（说法 vs 证据 + 社区线索）

1. **“Gmail MCP 不能发邮件，只锁死给合作方 / Gemini” vs 实际证据（11-26 晚已翻转，但仍卡在 `/mcp/v1self` 与 HITL）**：
   - **说法**：TechStackups（11-26）称“The Gmail One Can't Send Email”，称 `send_message`、`reply`、`forward`、`update_draft` 需要“partner access”；BlockBeats（11-26 19:06）标题称“把Gmail彻底锁死给Gemini”。
   - **证据**：11-24 至 11-26 11:03 UTC 时确实只有 23 个工具；但 Google 在 11-26 21:15 UTC 前更新了线上的 `gmailmcp.googleapis.com/mcp/v1`、官方 `gwscli` 与文档，截至北京 11-27 21:14 实测 `/mcp/v1` 已直接返回 **30 个工具**（含 `send_message`、`reply`、`forward`、`update_draft`），不再限合作方。**然而**，不支持 form elicitation 的客户端所连的 **`/mcp/v1self`（25 个工具）依然没有 `send_message`、`reply`、`forward`**；且在 `/mcp/v1` 下发信默认触发人工确认（`input_required`），无人值守自动化脚本不改管理员策略就跑不通（`MissingRequiredClientCapability`）。
2. **“强制走 MCP 只是为了安全/防提示词注入” vs 计费剪刀差与 30 天记忆上限**：
   - **说法**：Google Cloud Blog（`b-cloud-blog-agents.txt`）称强制 MCP/CLI 是因为传统 REST 只认 OAuth token，AI 代理需要请求路径上的策略检查、DLP 和人工确认（HITL）。
   - **证据**：安全能力属实，但 **Scaled Tier 计费规则存在显著不对等**（`b-quota-pricing.txt`）：同样在 Scaled Tier 下，**REST API** 享有每日免费额度（Gmail 每日 7,000 万 Light / 1,000 万 Medium / 100 万 Premium），且企业内部项目可申请 `internal-use exception` 免升付费档；而 **Gmail / Calendar / Drive MCP 在 Scaled Tier 每日免费额度为 0，从第 1 次成功请求起计费**（$0.10–$0.50/千次，其中 `search_threads` 与 `list_drafts` 每次算 10 单位 = 搜索 $5.00/千次），且 **内部自用豁免不适用于 MCP**。免费 Standard Tier 则被锁死在 **5,000 次/天/项目/产品**（即全项目每天最多 500 次 Gmail 搜索）。此外，《Addendum》第 2(b) 条规定所有派生技术信息（向量嵌入、记忆索引、用户画像、组织图谱）**最多保存 30 天**，第 2(f)(g) 条禁止训练与开发同类办公竞品。
3. **“从 2027-02-01 起直接封停/切断直连 REST API 的 AI 工具” vs 条款与配额页的真实后果**：
   - **说法**：部分报道写成 2027-02-01 起“停用传统直连”“无法直连”。
   - **证据**：`b-quota-usage-tiers.txt` 写的是 AI 代理直接调用 REST API 将**被限制在 Standard Tier 配额（超额限流 `throttles requests until the quota window resets`）**；《Addendum》第 3 条写明可“立即限制或停用”的是违规进行第 2 条 `(a)-(g)` 数据存储/训练/爬库等行为；同时 `is_agentic`（`Use this client for an AI-powered agent`）目前属于**开发者在 GCP 控制台勾选的自声明**，Google 官方文档未公开说明 2027-02-01 后如何识别未勾选却走 REST 的代理。
4. **Google 文档自身一度前后打架，以及 HITL 的客户端信任边界（L1 + L3/L4 线索）**：
   - **证据**：Suncly 于 11-26 记录同一天内 Google 的 HTML 参考页（23 工具）、给 LLM 用的 `.md.txt` 文档（旧版 10 工具，标 Developer Preview）、配额表（31 工具含 8 个合作方工具）三处不一致；11-27 复核时三处已对齐为 30 工具，但 Drive MCP 依然缺失共享/改权限（`permissions.create`）和永久删除工具。此外，Suncly 实验指出 MCP form elicitation 在无状态 HTTP 上仅靠向客户端返回 `requestState` 并信任客户端由人确认后回传 `ALLOW_ONCE`，若本地代理拥有 shell 权限调用简化版 CLI 包装器，部分模型会自行补全自动放行代码。
5. **社区高赞/技术评论线索（L6，未核作正文事实）**：

## 六、扫描说法勘误（对照派工单“已知情况”）

1. **勘误 1：“Gmail MCP 是否完全不能发邮件 / 受限于合作方权限”**
   - **扫描线索**：称 Gmail MCP 支持读、搜、建草稿等，是否不能发邮件或受限于合作方权限待核。
   - **一手核实**：**已反转**。11-24 至 11-26 11:03 UTC 时确实只有 23 个工具、8 个发信/改草稿/过滤工具标合作方专用；但截至 11-26 21:15 UTC（北京 11-27 05:15）及本组 11-27 21:14 实测，**`/mcp/v1` 已公开开放全部 30 个工具（含 `send_message`、`reply`、`forward`、`update_draft`）且配额页移除合作方限制**；只有不支持 form elicitation 的客户端用的 **`/mcp/v1self`（25 工具）仍然没有发信工具**。
2. **勘误 2：“新公布的 8 个官方 MCP 服务器”**
   - **扫描线索**：称新公布 8 个官方 MCP 服务器（列出 Gmail、Drive、Docs、Sheets、Slides、Calendar、Chat、Tasks、People API 共 9 个名字）。
   - **一手核实**：派工单括号里其实列了 9 个，实际官网 `mcp-server-tools` 与 `configure-mcp-servers` 明确写的是 **9 个 GA（正式可用）MCP 服务器**（Gmail、Drive、Docs、Sheets、Slides、Calendar、Chat、Tasks、**People API**；其中 People API 不提供 `/mcp/v1self`，也不走 `*mcp.googleapis.com` 域名而是 `people.googleapis.com/mcp/v1`），另有 **2 个 Developer Preview**（Classroom、Universal Search）和规划中的 Google Keep。博客正文里只列了 8 个 `*mcp.googleapis.com` 套件（漏提 People API），导致媒体普遍写成“8 个”。
3. **勘误 3：“2027-02-01 违规直调 REST 就会被封号 / 彻底无法使用”**
   - **扫描线索**：待核是限流还是封号。
   - **一手核实**：**两层分开**。技术文档（`b-quota-usage-tiers.txt`）明确规定 2027-02-01 起直接调 REST 的 AI 代理将被**限制在 Standard Tier 配额**（超限后 HTTP 403/429 限流，不会自动关停在额度内的常规调用）；《Addendum》第 3 条写明“立即限制/停用”的触发条件是违反第 2 条 `(a)-(g)`（留存/训练/爬库/竞品等），违反第 1 条（未走 MCP）虽违反协议（按 Google APIs Terms 第 3(a) 条 Google 保留暂停权），但未单列自动封号机制，且 `is_agentic` 依赖开发者自勾选。
4. **勘误 4：“官方 CLI 是否绕开 MCP 限制的替代方案”**
   - **扫描线索**：问是否有 CLI 路径绕过发信限制。
   - **一手核实**：官方 `gwscli` **不是绕开 MCP**——它底层正是调用 Google 的 `*mcp.googleapis.com/mcp/v1` 服务（`b-gwscli-readme.md`），因此之前服务端未放开发信时 `gwscli` 也同样只有 23 条命令（Flavio Copes 实测），现在服务端放开后 `gwscli` 实时同步变成 30 条命令（含 `send_message`），并在终端用 stdin/stderr 做 HITL 人工确认；而社区开源的 `gws`（REST Discovery 封装）继续可用但**不再被允许用于 AI 代理**（2027-02-01 起违反 Addendum）。
5. **勘误 5：“99% 开发者与 5,000 次/天口径”**
   - **扫描线索**：称超出免费每日 5,000 次/项目/产品的部分可能计费。
   - **一手核实**：不准确——①在免费的 **Standard Tier** 上不会自动计费，超限只会被限流直到太平洋时间午夜重置；②只有在开发者**主动绑定计费账号并把整个项目切到 Scaled Tier** 时，才会从 2027-04-01 起计费，且**一旦切到 Scaled Tier，原本每天 5,000 次的免费 MCP 额度直接清零**，从第 1 次成功请求起收费（`b-quota-pricing.txt`）。

## 七、对读者（全有 L1 出处）

1. **普通在网页或官方 App（iOS/Android）手动收发 Gmail、用 Drive/Calendar 的人**：**不受影响**。Workspace AI Tools Addendum 仅补充《Google APIs Terms of Service》，管辖的是通过 Google Cloud 项目和 API/MCP 接入的外部软件与代理（`b-ai-tools-addendum.txt`、`b-google-apis-tos.txt`、`b-ws-updates-blog.txt`）。
2. **用个人免费 `@gmail.com` 账号自接 AI 助手（如 Claude Desktop、Antigravity、本地编码代理或开源 MCP）的个人用户**：
   - **个人账号可以用官方 MCP 和 `gwscli`**：官方在配置文档中专门提供 **`Quick setup for personal use`（Personal mode）** 一键入口，无需走开发者应用审核即可创建单人 OAuth 客户端并自动勾选 `Use this client for an AI-powered agent`（`b-configure-mcp-servers.txt`、`b-oauth-agentic-help.txt`；仅 Google Chat 写操作与组织通讯录搜索需要付费 Workspace 账号，`b-workspace-cli.txt`）。
   - **自用免费额度**：默认 Standard Tier 无需绑卡，每项目每产品每天 **5,000 次免费请求**（`search_threads` 与 `list_drafts` 每次扣 10 次 = 每天 500 次搜索；超限会限流不会自动扣费，`b-quota-usage-tiers.txt`、`b-gmail-quotas.txt`）。
   - **2027-02-01 前要做什么**：若你用的开源本地 Gmail/Drive MCP 工具目前直接调 Google REST API（或用旧版社区 `gws` CLI），2027-02-01 起按条款属于违规且会被限制在 Standard Tier 配额；可改用官方 **`gwscli`**（本地终端代理推荐，不会往上下文塞 500KB+ schema，且已支持 `send_message`/`reply`/`forward` 和交互确认）或直连 **`https://gmailmcp.googleapis.com/mcp/v1`**。如果你的 MCP 客户端不支持 form elicitation，只能连 `/mcp/v1self`，则只能让 AI **`create_draft` / `update_draft`（写草稿）后自己到 Gmail 手动点发送**（`b-mcp-elicitation.txt`）。
   - **注意旧 OAuth 客户端**：2026-11-11/12 前创建且未勾选 `Use this client for an AI-powered agent` 的旧客户端已被 MCP 服务器拒绝，若无法在 Google Auth Platform > Clients 里直接修改勾选，需新建一个勾选了该选项的客户端（`b-gmail-configure-mcp.txt`、`b-oauth-agentic-help.txt`）。
3. **开发面向多用户的 AI 邮箱/办公助手产品的团队（含企业内部自建代理）**：
   - **两条硬约束**：①**2027-02-01** 起必须切到官方 MCP / `gwscli`，把 AI 功能与非 AI 功能的 OAuth 客户端彻底拆分（`b-oauth-agentic-help.txt`），并把基于邮件/文件生成的向量嵌入、记忆索引、用户画像等“技术信息”保留期设为 **不超过 30 天**，用户断连即删，严禁用于模型训练/微调/评测集/蒸馏（`b-ai-tools-addendum.txt`）；②**2027-04-01** 起若项目总调用量超过每天 5,000 次（所有用户共享）而升级到 **Scaled Tier**，**MCP 不享有每日免费额度、不享有企业内部自用豁免**，从第 1 次成功调用起按 $0.10–$0.50/千次计费（`b-quota-pricing.txt`）。另外需确认自己依赖的 Drive 操作（如自动改共享权限、永久删除）目前仍不在官方 Drive MCP 的 15 个工具中。
4. **Google Workspace 企业管理员**：
   - 2026-11-24 起两周内管理后台陆续上线新控制台：**`Admin console > Agents > Settings > User review for external agents`** 可分别对“对外协作（含发外域邮件）、对内协作、读取外部数据、读取内部数据”四类动作设置 **Allow / Require user approval / Block**；注意用户已保存的 `Always allow` 授权 **90 天过期且目前用户无法自行查看或撤销**，若要强制每次发外域邮件都弹窗确认，需取消勾选 `Except when user always allows`；同时可在 `Security > Access and data control > API controls` 管控特定 AI 代理的 OAuth Client ID 并查看含 `By an agent`、`Agent ID`、`User approved` 字段的审计日志（`b-admin-apps-help.txt`、`b-configure-mcp-servers.txt`）。
