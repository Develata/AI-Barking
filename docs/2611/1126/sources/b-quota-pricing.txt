 Understand Google Workspace API and MCP server pricing and billing tiers

 Stay organized with collections

 Save and categorize content based on your preferences.

Google Workspace APIs and Model Context Protocol (MCP) servers provide flexible
access to Google Workspace services, enabling developers, integrations, and AI
agents to automate workflows and manage organizational data. As AI agents
generate growing demand and data risks, Google Workspace uses a
standardized tiering and pricing model to meet our performance, safety,
security, and privacy commitments while providing enhanced visibility and
control over how AI agents access and use Google Workspace data.

This document introduces the Google Workspace API pricing model, explains how
daily no-charge allowances and billing tier buckets work, and illustrates how
monthly costs are computed for apps enrolled in the Scaled Tier.

Pricing model overview

The standardized model defines certain usage tiers for Google Cloud projects:

Standard Tier: Enforces published usage limits on projects and is
available at no cost across Google Workspace APIs and MCP servers, with
no Google Cloud Billing account or credit card required at enablement or to
get started. This tier is enabled by default for any new Google Cloud project
and is the default tier for all existing projects unless a developer opts in
to the Scaled Tier.

Across generally available (GA) Google Workspace MCP servers
(Gmail, Google Calendar, Google Drive, Google Docs,
Google Sheets, Google Slides, Google Chat, and Google Tasks), the
Standard Tier is capped at 5,000 requests per day, per project, per
product. Submitting additional quota requests isn't possible on the
Standard Tier—requesting higher MCP quotas requires enrolling in the Scaled
Tier with a linked Google Cloud Billing account, and requesting higher
per-project REST API quotas requires enrolling in the Scaled Tier or
attesting to the internal-use exception. Usage on the Standard Tier never
produces a charge on a Google Cloud bill, and daily billing thresholds
aren't relevant.

Standard Tier with internal-use exception: Allows
Google Workspace organizations to request higher per-project
REST API quotas without switching to the Scaled Tier (MCP server
quotas aren't eligible for increases under this exception), provided
the Cloud project is used exclusively by internal
organizational users and doesn't share API or MCP access externally.

Scaled Tier: This tier provides faster, scaled access for developers,
production apps, and AI agents (using MCP) that require large-scale,
high-volume data processing beyond Standard Tier quotas. Available for the
Gmail API, Google Calendar API, and Google Drive API and for GA
Google Workspace MCP servers (Scaled Tier MCP billing applies to the
Gmail, Calendar, and Drive MCP
servers).

Under this tier:

Developers can request higher rate quotas (enrolling unlocks quota
requests; you must submit a request if higher limits are required).

MCP is required when AI agents or similar access tools obtain data from
Google Workspace APIs—starting February 1, 2027, AI agents calling
Google Workspace REST APIs directly are limited to Standard
Tier quotas regardless of tier.

You must configure it for the whole Cloud project, not on a
per-API or per-MCP basis.

REST APIs include daily no-charge allowances (billing thresholds) for
each API and billing tier bucket. Starting April 1, 2027, charges
apply only to successful (2xx) REST API requests consumed after
exceeding the daily allowance for a billing entity (the linked
Google Cloud Billing account).

MCP servers have no daily no-charge allowance on the Scaled Tier.
Switching from the Standard Tier to the Scaled Tier removes free MCP
allowances, so starting April 1, 2027, charges apply from the first
successful (2xx) request on billed MCP servers (Gmail,
Calendar, and Drive).

Unlike single REST API calls, some MCP tools count as multiple requests
(billing units) because they make multiple API calls.

HTTP 3xx, 4xx, and 5xx responses aren't counted toward billing
usage. Failed MCP tools/call requests that return HTTP 200 with
isError: true also don't count toward Scaled Tier billing. This
exclusion covers tool execution and argument-translation errors such as
invalid arguments, missing resources, permission denials, and declined
user confirmations. Failed calls still count toward 1-minute rate-limit
quotas and the Standard Tier daily MCP limit of 5,000 requests per day,
per project, per product.

For more information, see Usage
tiers [/workspace/guides/quota-usage-tiers#usage-tiers].

Billing tier buckets and unit pricing

A billing tier bucket is a pricing category (Light, Medium, Plus, or Premium)
that groups API methods and MCP operations based on their resource intensity,
operational complexity, and payload size.

Under the Scaled Tier, REST API operations within a bucket only begin
counting as billable requests after daily traffic exceeds that bucket's
independent daily no-charge allowance. By contrast, billed Scaled Tier MCP
servers (Gmail, Calendar, and
Drive) have no daily no-charge allowance, so every successful MCP
operation is billed from the first request at its bucket's unit price per 1,000
billable requests (billing units).

Unlike single REST API calls, some composite MCP tools count as multiple
requests (billing units) because a single tool call makes multiple underlying
API calls.

The Drive API and its MCP server use all four buckets, whereas the
Gmail API and its MCP server use Light, Medium, and Premium. All
requests to the Calendar API and its MCP server use the Plus bucket.

Daily no-charge allowances for REST APIs

Each day, your linked Google Cloud Billing account receives an included
daily no-charge allowance (billing threshold) for each REST API service and
billing tier bucket. Daily allowances reset every day at midnight Pacific Time
(PT).

Important: Daily no-charge allowances apply only to REST APIs. On the
Standard Tier, GA Google Workspace MCP servers require no billing
account and are capped at 5,000 no-cost requests per day, per project, per
product. Switching a project to the Scaled Tier removes free MCP allowances,
so Gmail, Calendar, and Drive MCP
usage is billed from the first request with 0 daily no-charge allowance.

How daily no-charge allowances work

When building with REST APIs on the Scaled Tier, daily no-charge allowances
operate according to the following principles:

Allowances are independent per bucket: Each REST API service and billing
tier bucket has its own separate daily no-charge allowance. Making calls to
a method in one bucket (for example, Bucket A: Gmail API Medium)
consumes only the allowance for that specific bucket. It doesn't affect or
consume the daily no-charge allowance of other buckets (such as Bucket B:
Gmail API Premium).

Requests within the allowance are unbilled (no charge): For any REST API
method in a given bucket, the initial requests up to that bucket's daily
allowance threshold are free of charge. They're excluded from billing
calculations.

Billing begins only after exceeding the threshold: For REST APIs,
charges begin applying only after your billing account's daily request count
for that specific bucket exceeds its included allowance. You're billed only
for the incremental calls in that bucket beyond the daily no-charge
allowance, at that bucket's unit price.

No retroactive billing: Exceeding the daily no-charge allowance for a
REST API bucket never triggers retroactive charges for the calls included in
the allowance. Those initial requests remain free of charge.

Daily resets protect against sporadic or seasonal spikes: Daily
no-charge allowances reset every day at midnight Pacific Time (PT). If your
REST API app experiences sporadic or periodic traffic surges—such as annual
retail sales events (like Black Friday) or seasonal school events (such as
semester course enrollment)—you're only billed for overages on the specific
days that exceed your daily allowance. On all other days when REST API
traffic remains within the daily allowance, you incur $0 in REST API
charges.

automatically applies programmatic spend-based discounts. Discounts are
evaluated on separate cumulative monthly spend tracks for
Google Workspace REST APIs and MCP servers across all projects sharing
the same billing account.

Monitor and estimate your costs

The Google Cloud console provides tools to track your API usage and estimate
monthly costs before enrolling in the Scaled Tier:

Dashboard tab [/workspace/guides/quota-dashboard]: Review average

Project billing usage
tab [/workspace/guides/quota-project-billing-usage]: Inspect your
Cloud project's 30-day API request and MCP tool call volume
categorized by API or MCP service and billing tier bucket.

Pricing calculation examples

The following REST API examples illustrate how daily no-charge allowances and
volume discounts determine your monthly bill on the Scaled Tier (note that
Scaled Tier MCP server usage has no daily no-charge allowance and is
evaluated on a separate volume discount track).

Example 1: REST API usage within daily no-charge allowances

A project operates an integration that makes 5,000,000 Gmail API Light
requests and 500,000 Gmail API Premium requests each day.

Daily Gmail API Light usage: 5,000,000 requests (below the
70,000,000 daily allowance) = 0 billable requests.

Daily Gmail API Premium usage: 500,000 requests (below the
1,000,000 daily allowance) = 0 billable requests.

Total billable cost: $0.00.

Because REST API usage remains within daily no-charge allowances, you incur $0
in charges.

Example 2: REST API app exceeding daily allowances

A productivity tool makes 10,000,000 Gmail API Light requests (Bucket
A) and 2,000,000 Gmail API Premium requests (Bucket B) each day
consistently over a 30-day month.

Evaluate Gmail API Light (Bucket A):

Daily requests: 10,000,000

Daily no-charge allowance: 70,000,000

Daily billable requests: 0 (usage remains within the 70,000,000
allowance; requests are ignored for billing)

Daily cost: $0.00

Evaluate Gmail API Premium (Bucket B):

Daily requests: 2,000,000

Daily no-charge allowance: 1,000,000

Daily billable requests: 2,000,000 - 1,000,000 = 1,000,000 (the first
1,000,000 requests are free of charge; charges apply only to the
excess)

Daily cost: (1,000,000 / 1,000) × $0.50 = 1,000 × $0.50 = $500.00

Calculate 30-day gross cost:

30-day gross total: 30 × $500.00 = $15,000.00

Apply volume discounts:

Monthly spend of $15,000 falls within the $0–$20,000 bracket (0%
discount).

Total monthly bill: $15,000.00.

Example 3: High-volume REST API enterprise service

An enterprise data sync service processes high volumes across the
Gmail API and Drive API, generating $60,000 in gross
billable REST API usage during a 30-day month.

Calculate marginal discount brackets:

First $20,000 (at 0% discount): $20,000.00

Next $30,000 ($20,000 to $50,000 at 17% discount): $30,000 × (1 - 0.17)
= $30,000 × 0.83 = $24,900.00

Remaining $10,000 ($50,000 to $60,000 at 30% discount): $10,000 × (1 -
0.30) = $10,000 × 0.70 = $7,000.00

Calculate net billed total:

Net monthly bill: $20,000.00 + $24,900.00 + $7,000.00 = $51,900.00

Total savings from volume discount: $8,100.00 (~13.5% overall
effective discount).
