Google Workspace terms now require AI agents to use its MCP servers

 Nov 27, 2026
 ·
 9:48 AM
 ·
 By MLQ.ai Newsroom [/about/editorial-standards/] · Edited by Peter Foy [/about/peter-foy/]
 ·
 3 min read

Key points

Agent-driven tools that pull Workspace user data must use a Google MCP server, under an addendum last modified Nov. 24 [1] [https://workspace.google.com/terms/ai-tools].

The addendum bans using Workspace data for model training, fine-tuning, evaluation datasets or distillation [1] [https://workspace.google.com/terms/ai-tools].

Google's developer guide lists nine Workspace MCP servers as generally available, with Classroom and Universal Search still in developer preview [2] [https://developers.google.com/workspace/guides/configure-mcp-servers].

Google has added an AI Tools Addendum to its Google Workspace API terms that requires AI agents to reach Gmail, Drive and other Workspace data through Google's own Model Context Protocol (MCP) servers. The page shows a last-modified date of Nov. 24, 2026 [1] [https://workspace.google.com/terms/ai-tools].

The core rule is short. A "GWS Access Tool" that is, or is driven by, an AI agent, AI harness or AI model must use a Google MCP, and "You may not obfuscate or otherwise allow any GWS Access Tool to avoid classification as a GWS Access Tool," the addendum says [1] [https://workspace.google.com/terms/ai-tools]. It defines an access tool as any AI agent, harness, model or other tool that obtains user data through a Workspace access point, and an AI harness as the software layer that deploys agents, invokes tools or APIs, or orchestrates tasks [1] [https://workspace.google.com/terms/ai-tools].

What agents can and cannot do with the data

The addendum lists seven prohibited activities. Tools may not process user data beyond active, user-authorized tasks, store Google technical information for more than 30 days, keep user data or technical information after access is revoked, or scrape and systematically probe Workspace access points, Google MCP servers or their documentation beyond what a task needs [1] [https://workspace.google.com/terms/ai-tools].

Two bans go to the business models of AI companies: user data and Google technical information cannot be used for model training, fine-tuning, evaluation datasets or distillation, or to build a product similar to a Workspace service [1] [https://workspace.google.com/terms/ai-tools]. If Google reasonably believes a tool has done any of these things, it may immediately restrict or remove the tool's access or suspend the customer's access to the affected services [1] [https://workspace.google.com/terms/ai-tools]. The addendum controls where it conflicts with the existing API terms [1] [https://workspace.google.com/terms/ai-tools].

The terms page does not state a separate effective date, quota or rate limit, and does not mention direct REST API access [1] [https://workspace.google.com/terms/ai-tools]. MLQ.ai also found no effective date in Google's MCP developer documentation [2] [https://developers.google.com/workspace/guides/configure-mcp-servers].

The MCP servers agents are being steered to

Google's developer guide lists remote MCP servers for Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, Tasks and the People API as generally available, and Classroom and a Universal Search server as developer previews [2] [https://developers.google.com/workspace/guides/configure-mcp-servers]. Google opened the first Workspace MCP server as a public developer preview on May 1, 2026, alongside a standardized usage-tier model for agent tools and Workspace APIs [3] [https://workspaceupdates.googleblog.com/2026/05/agent-tools-and-security-updates-for-workspace-developers.html].

The guide sets several conditions. OAuth clients used by agents must have "Use this client for an AI-powered agent" selected or requests are rejected, sensitive calls can trigger approval prompts, saved approvals expire after 90 days, and Chat write actions need a configured Chat app [2] [https://developers.google.com/workspace/guides/configure-mcp-servers]. It says using the servers with Claude requires a Claude Enterprise, Pro, Max or Team plan [2] [https://developers.google.com/workspace/guides/configure-mcp-servers].

For developers of assistants that read inboxes and files, including Anthropic's Claude and open-source agent frameworks, the addendum means Workspace access by an agent is expected to run through Google's endpoints and its approval and attribution controls. Anthropic said on Nov. 24 that MCP SDKs now see more than 700 million monthly downloads (MLQ.ai coverage [/news/anthropic-says-mcp-sdks-top-700-million-monthly-downloads-as-background-tasks-reach-general-availability-in-claude/]).

Disclosure: MLQ.ai's newsroom uses AI tools, including Anthropic's Claude, to help produce its coverage.
