 Configure the Gmail MCP server

 Stay organized with collections

 Save and categorize content based on your preferences.

Gmail offers a remote
Model Context Protocol (MCP) [https://modelcontextprotocol.io/introduction]
server that allows AI agents to securely interact with Gmail
data. By configuring the Gmail MCP server, you enable AI
applications like Google Antigravity and Claude to perform actions in
Gmail.

The Gmail MCP server provides a standardized way for AI agents
to:

Read data: Search threads, retrieve messages and drafts, and list labels
and filters.

Take action: Send, reply to, and forward emails, create and update
drafts, manage labels and filters, and move messages or threads to and from
Trash or Spam.

Respect security: Inherit the same permissions and data governance
controls as the user.

Note: You can also connect AI agents and interactive terminals to
Gmail with the
Google Workspace command-line interface (CLI) [/workspace/guides/workspace-cli], gwscli.

Prerequisites

A Google Cloud project. You can create or select a project during
Quick setup for personal use [#quick-setup], or see
Create a project [/workspace/guides/create-project].

An MCP host, which is an AI application like
Google Antigravity [https://antigravity.google/] or Claude. The AI
application creates an MCP client connection for each MCP server.

To run the gcloud commands for manual setup on this page, set up the
gcloud CLI in a local development environment by following these steps:

Install the Google Cloud CLI [https://cloud.google.com/sdk/docs/install].
 If you installed the gcloud CLI previously, make sure you have the
 latest version by running gcloud components update.

If you're using an external identity provider (IdP), sign in to the
 gcloud CLI with your federated identity. For more information, see
 Sign in to the gcloud CLI with your federated identity [https://docs.cloud.google.com/iam/docs/workforce-log-in-gcloud].

Initialize the gcloud CLI [https://docs.cloud.google.com/sdk/docs/initializing].

Configure the Gmail MCP server

To use the Gmail MCP server, set up a Google Cloud project
with an AI-agent OAuth 2.0 client and configure your AI application to connect
to it:

Personal use: If you're connecting an AI application for your own
Google Account, use Quick setup for personal use [#quick-setup] to
configure a project, enable the APIs and MCP services, and create an OAuth
client on a single page.

Multi-user or custom setup: If multiple users will sign in with your
OAuth client, or if you want to enable only specific APIs, MCP services,
and OAuth scopes, start at Enable the APIs [#enable-apis].

Quick setup for personal use

Use Personal mode onboarding in the Google Cloud console to create
an OAuth 2.0 client that works only for your Google Account and doesn't require
app verification or separate OAuth consent screen setup:

Open Personal mode onboarding in the Google Cloud console. The
button pre-selects a Web application client, which Google Antigravity
and Claude require:

Set up personal mode [https://console.cloud.google.com/auth/overview/personal?apis=ws,wsmcp,tasksmcp&clientType=web&isAgent=true] 

If your MCP client uses a desktop or mobile OAuth flow instead of a web
redirect URI, open personal mode setup for a Desktop app [https://console.cloud.google.com/auth/overview/personal?apis=ws,wsmcp,tasksmcp&clientType=desktop&isAgent=true],
Android [https://console.cloud.google.com/auth/overview/personal?apis=ws,wsmcp,tasksmcp&clientType=android&isAgent=true], or iOS [https://console.cloud.google.com/auth/overview/personal?apis=ws,wsmcp,tasksmcp&clientType=ios&isAgent=true] client, or change Application
type on the page.

In Select Project, select an existing personal-mode project or click
Create a new project. If prompted, complete the project creation form.

Configure your OAuth client details:

Enter a Name for the client.

If Application type is Web application, in Authorized
redirect URIs, click + Add URI and add your MCP client's callback
URI:

For Antigravity: https://antigravity.google/oauth-callback

For Claude: https://claude.ai/api/mcp/auth_callback

Verify that Use this client for an AI-powered agent is selected.

Review the Google API Services User Data Policy [https://developers.google.com/terms/api-services-user-data-policy],
select I agree to the Google API Services: User Data Policy., and click
Continue.

The console enables core Google Workspace APIs and MCP services in
your project and creates your OAuth client.

Copy your Client ID and Client Secret, and then connect your client
to the MCP server [#configure-mcp-client], skipping step 1 since you already
have your OAuth client ID and secret.

Enable the APIs

Skip this step if you used Quick setup for personal use [#quick-setup].

To use the Gmail MCP server, enable the following API in your
Google Cloud project:

Gmail API

CLI

gcloud services enable gmail.googleapis.com --project=PROJECT_ID

Replace PROJECT_ID
with your Google Cloud project ID.

Console

Enable the APIs in the Google Cloud console:

Enable the APIs [https://console.cloud.google.com/flows/enableapi?apiid=gmail.googleapis.com] 

Enable the MCP services

Skip this step if you used Quick setup for personal use [#quick-setup].

To enable the MCP components for Gmail, enable the following
service in your Google Cloud project:

Gmail MCP API

CLI

gcloud services enable gmailmcp.googleapis.com --project=PROJECT_ID

Replace PROJECT_ID
with your Google Cloud project ID.

Console

Enable the MCP services in the Google Cloud console:

Enable the MCP services [https://console.cloud.google.com/flows/enableapi?apiid=gmailmcp.googleapis.com] 

Set up the OAuth consent screen

Skip this step if you used Quick setup for personal use [#quick-setup].

The Gmail MCP server uses OAuth 2.0 for authentication and
authorization. You must configure the OAuth consent screen before you can
create an OAuth client ID.

In the Google Cloud console, go to Google Auth Platform
> Branding.

Go to Branding [https://console.cloud.google.com/auth/branding] 

If you have already configured the Google Auth Platform, you can
configure the following OAuth Consent Screen settings in
Branding [https://console.cloud.google.com/auth/branding],
Audience [https://console.cloud.google.com/auth/audience],
and Data Access [https://console.cloud.google.com/auth/scopes].
If you see a message that says Google Auth Platform not configured
yet, click Get Started:

Under App Information, in App name, type Gmail MCP Server.

In User support email, select your email address or an appropriate
Google Group.

Click Next.

Under Audience, select Internal. If you can't select
Internal, select External.

Click Next.

Under Contact Information, enter an Email address where you can
be notified about any changes to your project.

Click Next.

Under Finish, review the
Google API Services User Data Policy [https://developers.google.com/terms/api-services-user-data-policy] and if you
agree, select I agree to the Google API Services: User Data Policy.

Click Continue.

Click Create.

If you selected External for user type, add test users:

Click Audience.

Under Test users, click Add users.

Enter your email address and any other authorized test users, then
click Save.

Click Data Access >
Add or Remove Scopes. A panel appears with a list of scopes for each
API that you've enabled in your Google Cloud project.

Under Manually add scopes, paste the scopes for the
Gmail MCP server:

https://www.googleapis.com/auth/gmail.readonly

https://www.googleapis.com/auth/gmail.compose

https://www.googleapis.com/auth/gmail.modify

https://www.googleapis.com/auth/gmail.settings.basic
(required only when calling create_filter [/workspace/gmail/api/reference/mcp/tools_list/create_filter])

Click Add to Table.

Click Update.

After selecting the scopes required by your app, on the Data Access
page, click Save.

Configure your AI application

To add the Gmail remote MCP server to your AI application, follow
the instructions for your application.

User-delegated OAuth 2.0 client IDs that call the Gmail MCP
server must have Use this client for an AI-powered agent selected in
Google Auth Platform > Clients. To
update an existing OAuth 2.0 client ID, select this setting in
Google Auth Platform > Clients, as
described in
Manage OAuth Clients [https://support.google.com/cloud/answer/15549257].
If you can't change this setting on an existing client, or if the client also
supports non-agent features, create a new OAuth 2.0 client ID for your AI
agent. For rejected requests, service accounts with domain-wide delegation, or
Google Apps Script, see Troubleshooting [#troubleshooting].

Antigravity

To add the Gmail remote MCP server to Antigravity,
add the server configuration to your mcp_config.json file. These
instructions support Antigravity 2.0, Antigravity IDE, and Antigravity CLI.

Create an OAuth 2.0 client ID and secret, or skip to the next step
if you already created one in
Quick setup for personal use [#quick-setup]:

In the Google Cloud console, go to Google Auth Platform
> Clients
> Create Client.

Go to Create Client [https://console.cloud.google.com/auth/clients/create] 

Select Web application as the application type.

Enter a Name.

In the Authorized redirect URIs section, click + Add URI,
and then add https://antigravity.google/oauth-callback in the
URIs field.

Select Use this client for an AI-powered agent.

Click Create and copy your Client ID and Client Secret.

Open or create the configuration file
~/.gemini/config/mcp_config.json.

Add the mcpServers configuration to mcp_config.json:

{
 "mcpServers": {
 "gmail": {
 "serverUrl": "https://gmailmcp.googleapis.com/mcp/v1",
 "oauth": {
 "clientId": "OAUTH_CLIENT_ID",
 "clientSecret": "OAUTH_CLIENT_SECRET"
 }
 }
 }
}

Replace the following:

OAUTH_CLIENT_ID: The
client ID you created.

OAUTH_CLIENT_SECRET:
The client secret you created.

Save mcp_config.json.

Authenticate the MCP server. You can authenticate using either the
GUI settings or the CLI:

For Antigravity IDE or GUI (Antigravity 2.0):

Open your settings screen (e.g., click Settings at the
bottom-left or open Antigravity User Settings).

Navigate to Customizations.

Under Installed MCP Servers, click Refresh.

Find gmail in the list, click Authenticate,
sign in to your Google Account, copy the authorization code,
paste it into the input dialog, and click Submit.

For Antigravity CLI:

Start Antigravity CLI:

agy

Open the interactive MCP management panel by running:

/mcp

Use the arrow keys to select gmail, move to the
Authenticate action, and press Enter. Complete the
sign-in flow in your browser, copy the authorization code, paste
it into the terminal prompt, and press Enter.

Verify that the server is correctly configured and running:

For Antigravity IDE or GUI: A Sign out button appears
next to the server under Customizations
> Installed MCP Servers.

For Antigravity CLI: Open the /mcp panel to view your
configured MCP servers. Verified and authenticated servers display
Authed next to their names inside the interactive TUI panel.
You can select any server under the dashboard view to inspect its
status and list all of its available tools.

The remote MCP server is ready to use in Antigravity.

Claude

To use the Gmail remote MCP server with Claude.ai or Claude
Desktop, you must have the Claude Enterprise, Pro, Max, or Team plan.

To add the Gmail remote MCP server to Claude, configure a
custom connector with an OAuth client ID and secret.

Create an OAuth 2.0 client ID and secret, or skip to the next step
if you already created one in
Quick setup for personal use [#quick-setup]:

In the Google Cloud console, go to Google Auth Platform
> Clients
> Create Client.

Go to Create Client [https://console.cloud.google.com/auth/clients/create] 

Select Web application as the application type.

Enter a Name.

In the Authorized redirect URIs section, click + Add URI,
and then add https://claude.ai/api/mcp/auth_callback in the
URIs field.

Select Use this client for an AI-powered agent.

Click Create and copy your Client ID and Client Secret.

Configure the MCP server in Claude:

In Claude.ai or Claude Desktop, go to Settings
> Connectors or
Admin settings >
Connectors.

Click Add custom connector.

Enter the connection details for Gmail:

Server name: Gmail.

Remote MCP server URL:
https://gmailmcp.googleapis.com/mcp/v1

In Advanced settings, enter your OAuth client ID and
OAuth client secret.

Click Add.

Others

Many AI applications have ways to connect to a remote MCP server. You
typically need to enter details about the server, like its name, endpoints,
transport protocol, and authentication method. For the Gmail
remote MCP server, enter the following:

Server name: gmail

Server URL: https://gmailmcp.googleapis.com/mcp/v1

Transport: Streamable HTTP [https://modelcontextprotocol.io/specification/latest/basic/transports/streamable-http]

Authentication: The Gmail remote MCP server uses
OAuth 2.0. When creating your OAuth 2.0 client, select
Use this client for an AI-powered agent. For single-user personal
setups, you can create a web, desktop, Android, or iOS client using
Quick setup for personal use [#quick-setup]. For details, see
Learn about authentication and authorization [/workspace/guides/auth-overview].

To avoid hourly sign-in prompts with a Web application OAuth client,
configure your MCP client to request offline access using
access_type=offline or the offline_access scope. For details, see
Repeated hourly sign-in prompts [#hourly-sign-in].

For more details on connecting different types of AI applications, see
Configure MCP in an AI application [https://docs.cloud.google.com/mcp/configure-mcp-ai-application].

Test the Gmail MCP server

After you configure your AI application, you can verify the connection by
running some test prompts.

Try asking your AI application the following questions:

"What did Ariel say in her last email about our marketing plan?"

The client filters for emails from Ariel using gmail.search_threads,
retrieves the latest thread's content with gmail.get_thread, and then
summarizes it for you.

"Draft an email to ariel@example.com saying that I approve the marketing
plan."

The client uses gmail.create_draft to create an email in your drafts
folder, which lets you review and send it from Gmail.

If the tools execute successfully and you receive relevant responses, your
Gmail MCP server is configured accurately.

Troubleshooting

Use the following sections to resolve common authentication and connection
issues with the Gmail MCP server.

Check OAuth log events

If you encounter issues connecting to the MCP server, check for errors in the
OAuth logs. Ask your Google Workspace administrator to review the
OAuth log events in the security investigation
tool [https://knowledge.workspace.google.com/admin/security/about-the-security-investigation-tool].

Rejected requests from user-delegated OAuth clients

If your requests to the MCP server are rejected, verify that the
user-delegated OAuth 2.0 client ID for your 3-legged OAuth flow has Use this
client for an AI-powered agent selected in Google Auth Platform
> Clients:

Existing client supports the setting: Select Use this client for an
AI-powered agent on your existing OAuth client.

Existing client can't be updated: Create a new OAuth client with Use
this client for an AI-powered agent selected and update your app to use
it.

Existing client also supports non-agent features: Create a separate
OAuth client for the AI agent and keep the existing client for your
non-agent features.

For instructions, see
Configure your AI application [#configure-mcp-client] and
Manage OAuth Clients [https://support.google.com/cloud/answer/15549257].

Service accounts with domain-wide delegation

If your app uses a service account with domain-wide delegation for 2-legged
OAuth, you can't select Use this client for an AI-powered agent because
service accounts aren't managed in Google Auth Platform
> Clients:

Access control: Requests to the MCP server from these service accounts
aren't rejected for missing the agent setting. Instead, access is governed
by the domain-wide delegation settings that your Google Workspace
administrator manages. For details on administrator settings, see Control
API access with domain-wide
delegation [https://knowledge.workspace.google.com/admin/apps/control-api-access-with-domain-wide-delegation].

Sensitive actions: Google Workspace MCP servers still return
form elicitation prompts for human-in-the-loop confirmation on sensitive
tool calls made through domain-wide delegation user impersonation.

Requests from Apps Script

If you call the MCP server from Apps Script, you can't select
Use this client for an AI-powered agent on the default OAuth client that
Apps Script creates and manages for your script. This applies
even if your script uses a standard Google Cloud
project [/apps-script/guides/cloud-platform-projects#standard_cloud_platform_projects].

To call the MCP server from Apps Script, do the following:

In the Google Cloud console, go to Google Auth Platform
> Clients, create an OAuth client,
and select Use this client for an AI-powered agent.

In your script, use the OAuth2 for Apps Script
library [https://github.com/googleworkspace/apps-script-oauth2] to
authorize users with that OAuth client.

When you call the MCP server, send the access token that the library
returns instead of the token from ScriptApp.getOAuthToken.

Apps Script projects that don't call Google Workspace
MCP servers aren't affected.

Repeated hourly sign-in prompts

If you're prompted to sign in again about every hour, your MCP client isn't
receiving or using a refresh token. This typically happens in the following
situations:

Missing offline access on a Web application OAuth client: Unlike
Desktop app OAuth clients, Web application OAuth clients default to
online access. To request a refresh token, include access_type=offline or
include the OpenID Connect (OIDC) offline_access scope alongside at least
one API scope, and don't set access_type=online.

Re-authorizing an already-consented app: Google's OAuth 2.0 server
issues a refresh token the first time a user grants offline access. If a
user already authorized your OAuth client without offline access, or if
your MCP client lost its stored refresh token, subsequent sign-ins might
not return a new refresh token. Include prompt=consent in the
authorization request, or remove the app's access in
Google Account connections [https://myaccount.google.com/connections] and sign in again.

Static bearer token: If you pass a raw access token in an
Authorization header, such as output from
gcloud auth print-access-token, the token expires after one hour unless
your client refreshes it.

For details, see Refresh an access token [/identity/protocols/oauth2/web-server#offline].

Important security consideration: Indirect prompt injection

When you expose a language model to untrusted data, there is a risk of an
indirect prompt injection attack. Because AI applications like Google
Antigravity have access to powerful tools and APIs through the
Gmail MCP server, they can read, modify, and delete data in your
Google Account.

To mitigate these risks, you must screen prompts and responses for malicious
content or prompt injection attacks. You can use the Google-provided
Model Armor, or you can use your own solution if you document it so
users can accept that risk. For instructions, see
Configure security for Google Workspace MCP servers [/workspace/guides/configure-mcp-security].

Follow these best practices:

Only use trusted tools. Never connect the Gmail MCP
server to untrusted or unverified applications.

Be cautious with untrusted inputs. Avoid asking your AI application to
process emails or other resources from unverified sources. These inputs
might contain hidden instructions that can hijack your session and let an
attacker modify, steal, or delete your data.

Review all actions. Always carefully review the actions taken by your AI
application on your behalf to make sure they are accurate and match your
intentions.

Handle user approvals with form elicitation

Google Workspace MCP servers use server-driven human-in-the-loop
approvals through MCP form elicitation [/workspace/guides/mcp-elicitation] to protect user
data before an AI agent performs sensitive actions, such as sending emails,
modifying shared calendar events, sharing or trashing files, or accessing shared
data.

Choose the endpoint that matches your MCP host's capabilities:

/mcp/v1: Recommended primary endpoint for MCP hosts and clients that
support form elicitation. Exposes all tools and full result sets for each
server. If your MCP host includes built-in local tool confirmation prompts,
set them to Always allow for Google Workspace MCP servers on
/mcp/v1 to avoid duplicate prompts.

/mcp/v1self: Fallback endpoint for MCP hosts that don't support form
elicitation, such as https://gmailmcp.googleapis.com/mcp/v1self. Exposes
only tools and results that work without form elicitation under default
policy, although specific calls might still require approval depending on
policy and target resources. The People API and Google Classroom MCP
servers don't use form elicitation or provide /mcp/v1self.

For endpoint details, approval UI recommendations, and client implementation
steps, see Handle user approvals with form elicitation [/workspace/guides/mcp-elicitation].

Administrator controls and governance

Google Workspace administrators can apply controls and governance to AI
agents that connect to Google Workspace MCP servers or the
Google Workspace command-line interface [/workspace/guides/workspace-cli], including
OAuth app access settings, user review policies for external agents, agent
attribution, data loss prevention, and audit logging. For details, see
Manage AI agent access & user review [https://knowledge.workspace.google.com/admin/apps/control-which-apps-access-google-workspace-data#ai-agents] in
Google Workspace Admin Help and
Administrator user review policies [/workspace/guides/mcp-elicitation#admin-policies].
