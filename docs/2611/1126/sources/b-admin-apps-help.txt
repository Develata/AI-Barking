If your users sign in to apps through their Google accounts, you can control how
these apps access your organization's data. Using OAuth 2.0 settings in the
Google Admin console, you can manage 3 types of apps:

Google-owned—Apps developed by Google

Internal—Apps that your organization develops

Third-party—Apps not created or owned by Google or your organization

Some apps use OAuth 2.0 scopes—a mechanism to limit access to a user's account.
You can also customize the message that users see when they try to install an
unauthorized app.

Note: For Google Workspace for Education, additional restrictions might
prevent users in primary and secondary institutions from accessing certain apps.

Restrict or unrestrict Google services

You can restrict, or leave unrestricted, internal and third-party app access to
most Google Workspace services, including Google Cloud services like Machine
Learning. Here's what each option means:

Restricted—Only internal and third-party apps configured with a Trusted
or Specific Google data access setting can access data.

Unrestricted—Only internal and third-party apps configured with a
Trusted, Limited, or Specific Google data access setting can access the
scopes configured by an admin, regardless of whether the scope has
restricted or unrestricted data access.

For example, if you set Calendar access as Restricted, only internal and
third-party apps configured with a Trusted or Specific Google data access
setting can access Calendar data. Internal and third-party apps with a Limited
access setting can't access Calendar data.

Note: For Gmail, Google Drive, and Google Chat, you can specifically
restrict access to high-risk scopes (for example, sending mail or deleting files
in Drive).

Manage app access to Google services & add apps

You can manage access to certain apps by blocking those apps or marking them as
Trusted, Specific Google data, Limited, or Blocked:

Trusted—App has access to all Google Workspace services (OAuth scopes),
including restricted services. You can allowlist apps configured using OAuth
client IDs to maintain Application Programming Interface (API) access to
Google Workspace services even when those services have Context-Aware Access
policies that apply to API access.

Specific Google data—Can request data access only to scopes that you
specify when configuring the app.

Limited—App can only access unrestricted services. You can change an
app's data access setting from the apps list or from the app information
page.

Blocked–App can't access any Google data.

Google-owned apps that aren't Workspace apps can be Trusted, Blocked, or
Exempted. By default, most Google-owned apps are Trusted. However, when both
third-party and Google-owned apps are selected, access options are limited to
Trusted and Blocked.

When configuring or changing an app's access level, the list of OAuth scopes
includes all scopes that the app has ever requested. This list might not reflect
your organization's current configuration. To view the exact scopes configured
for an app, point to the app and click View details.

Unconfigured app settings

Custom user message

This is a custom message to show to users when they can't access a blocked app. To create a custom message, select On and enter a message.

If the custom message is off or can't be shown, users see a default message instead.

Unconfigured third-party apps

This setting controls what happens when users try to sign in to unconfigured apps with their Google Account. Users can still access apps that are configured with Trusted, Limited, or Specific Google data access, regardless of this setting.

Choose an option:

Allow users to access any third-party apps (default)—Users can sign in with Google to any third-party app. Accessed apps can request unrestricted Google data for that user.

Allow users to access third-party apps that only request basic info needed for Sign in with Google—Users can sign in with Google to third-party apps that request only basic profile information: the user's Google Account name, email address, and profile picture.

Don't allow users to access any third-party apps—Users can't sign in with Google to any third-party apps and websites until you configure those apps and sites with an access setting. For details, go to Manage third-party app access to Google services & add apps [#trustorlimit].

Google Workspace for Education editions: You can choose different settings for users who are over and under 18 years old. If you use this setting to block third-party apps, you can allow users who are under 18 years old to request access to blocked apps with the User requests to access unconfigured apps setting.

Internal apps

This allows internal apps built by your organization to access restricted Google Workspace APIs.

To allow API access for all internal apps, check the Trust internal apps box.

User requests to access unconfigured apps

These settings allow users to request access to unconfigured third-party apps, which admins can then review and approve or dismiss. The options available depend on your Workspace edition.

Google Workspace for Education editions

Settings for users over 18 years of age—These settings allow educators and users who are over 18 years of age to request access to apps for themselves or on behalf of others (proxy requests). For example, a teacher can make proxy requests on behalf of students. You can review these requests and grant or refuse access.

When requests are made, you're notified. You can configure access for users who requested access for themselves. For proxy requests, you can configure access for users on behalf of whom the request was made.

To allow users to request access for themselves, check the Allow users to request access to apps for themselves box.

To allow users to make a proxy request, check the Allow users to make requests on behalf of other users (proxy requests) box.

Note: Share this link [https://access.workspace.google.com/apprequests] with educators to enable them to make proxy requests on behalf of others.

Settings for users under 18 years of age—This allows users who are under 18 years of age to request access to apps for themselves.

To allow users to request access to apps for themselves, check the Allow users to request access to apps for themselves box.

To access these settings, go to Find the settings [#settings].

All other Google Workspace editions

If you or another admin restricts access to unconfigured apps, users can request access to these apps. To allow users to request access to unconfigured apps, check the Allow users to request access to unconfigured third-party apps box.

When a user requests access, a new entry is added to the Apps pending review list on the App access control page in the Admin console. After reviewing the list, you can choose whether to allow or dismiss the request. Note that your choice applies to all the users in an organizational unit. For details, go to Review & manage third-party app access requests [/admin/apps/review-and-manage-third-party-app-access-requests].

Note: This request flow is only triggered by apps that haven't been assigned an access setting by an admin. If a configured app tries to access a Google service it doesn't have permission for, the user is blocked and won't be able to request access through this flow.

Manage AI agent access & user review

You can control how external and internal AI agents access your organization's
data when they connect through Google Workspace Model Context Protocol (MCP)
tools or the Google Workspace command-line interface (CLI). These AI agents
sign in using OAuth 2.0 client IDs. Use the API controls settings earlier on
this page to trust, limit, or block an agent's client ID and control which
services it can access.

Require user review for external agent actions

You can decide when external AI agents must ask users for permission before
acting on Google Workspace data. These user review rules apply only to
external agents that use Google Workspace MCP tools or the
Google Workspace CLI. Standard app connections don't use these user review
rules.

Private actions that affect only the signed-in user run without a confirmation
prompt. For example, creating an email draft or editing a private file doesn't
require user approval. Moving items to the trash always requires user
confirmation for each request, and external agents can't permanently delete
items.

Note: Service accounts that impersonate users through domain-wide
delegation [/admin/apps/control-api-access-with-domain-wide-delegation] still
trigger user review prompts on Google Workspace MCP tools when approval is
required. Unattended workflows must either run actions set to Allow or use
standard Google Workspace APIs.

In the Google Admin console, go to Menu 
Agents Settings.

Requires having the Security administrator
privilege [/admin/users/administrator-privilege-definitions#user_security].

(Optional) To apply the setting only to some users, at the side, select an
organizational unit or configuration group.

Click User review for external agents to expand the section.

Review the four external agent activity categories:

External collaboration: Controls creating, editing, and sharing data
with accounts outside your organization, such as sending external emails
or inviting external guests. By default, this is set to Require user
approval.

Internal collaboration: Controls creating, editing, and sharing data
with accounts inside your organization. By default, this is set to
Require user approval.

External data access: Controls reading files, messages, or events
owned or shared by accounts outside your organization. By default, this
is set to Require user approval.

Internal data access: Controls reading files, messages, or events
shared by accounts inside your organization. By default, this is set to
Allow.

For each category, select an option:

Allow: Lets external agents complete the action without prompting
the user.

Require user approval: Prompts the user to review and approve the
action before the agent runs it. Leave the Except when user always
allows box checked to let users save an Always allow choice for up
to 90 days for a tool, recipient, resource, or owner. Uncheck the
Except when user always allows box to require confirmation every
time.

Block: Stops external agents from completing the action. To block an
external agent from all Google Workspace services, block its client
ID in Manage app access to Google services & add apps [#trustorlimit].

Click Save.

Changes can take up to 24 hours but typically happen more quickly. Learn more [/admin/support/troubleshooting/how-changes-propagate-to-google-services]

Known limitations

In App access control lists, iOS apps added using Apple App Store bundle
IDs currently show Unknown in the Ownership column.

OAuth scope information isn't shown for Google-owned apps. This is expected
because Google-owned apps can request scopes that are internal to Google.
