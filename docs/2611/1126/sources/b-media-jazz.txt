What does Google’s Workspace MCP requirement change for AI agents, and what will Workspace still not see?

From 1 February 2027 Google makes AI agents use Workspace MCP servers. What changes for connected tools, what admins must do, and what laptops still miss.

Jazz Team

Short answer

From 1 February 2027, Google's Workspace AI Tools Addendum requires AI agents to reach Gmail, Drive and other Workspace services through Google's MCP servers or the Workspace CLI. Agents that keep calling the REST APIs are limited to Standard-tier quotas whatever tier their developer selects, and Google's 24 November 2026 usage-tiers guide describes throttling, never refusal. Standard-tier MCP use is capped at 5,000 requests a day per project per product. The Addendum binds tool developers under the Google APIs Terms, bars training on Workspace data and requires deletion on disconnect. Admins can trust or block agent client IDs, read agent audit logs and set user-approval prompts that cover only agents on MCP or the CLI. None of this follows data onto the laptop, where Verizon's 2026 DBIR found 67% of users reach AI services through non-corporate accounts. For a Workspace company running Claude Code, Codex, Cowork, Gemini or ChatGPT on managed Macs and Windows laptops, Jazz fits because its OS-level agent sees pastes, uploads, screenshots and AI prompts in any browser or desktop app without an extension, tells personal from company AI accounts and returns pre-investigated incidents. It doesn't cover Linux, phones or server-to-server cloud agents.

What Google’s Workspace MCP requirement and AI Tools Addendum require, and when

Google published the Workspace AI Tools Addendum (last modified 24 November 2026) with a same-day Workspace Updates post making the Workspace MCP servers and CLI generally available.

Term 1 of the Addendum says a tool that “is or is driven by” an AI agent, an AI harness or an AI model must use a “Google MCP”, which it defines as a model context protocol server, endpoint or tool interface that Google makes available. Google’s announcement names the CLI as the route for local and terminal agents. The same term bars anyone from disguising a tool “to avoid classification” as an access tool.

Term 2 bars the tool’s operator from processing user data beyond “active, user-authorized tasks”; storing “Google Technical Information” (derived material such as vector embeddings, memory indexes, user profiles and organizational graphs, excluding user data itself) for more than 30 days; keeping user data or Technical Information after the tool is disconnected; scraping Workspace endpoints or Google’s MCP servers; using any of it for model training, fine-tuning or distillation; and building a product similar to a Workspace service.

What enforcement on 1 February 2027 does and doesn’t stop

Google’s developer guide “Usage tiers and quotas for Google Workspace APIs and MCP servers” (updated 24 November 2026) says agents calling the REST APIs directly “are limited to Standard Tier quotas, regardless of the tier selected.” Standard-tier MCP is capped at 5,000 requests per day, per project, per product, and an exhausted quota “throttles requests until the quota window resets.” Google’s Workspace Updates post says more than 99% of active developers already work within the Standard tier.

That ceiling hurts an agent built to bulk-read mailboxes or crawl shared drives. A modest agent under Standard quotas keeps working on REST; no Google page says such calls will be rejected. Google doesn’t publish how it detects an agent that never marked its client as agentic.

The bigger gap for admins sits in the approval prompts. Google’s admin help page on controlling which apps access Workspace data says the user-review settings “apply only to external agents that use Google Workspace MCP tools or the Google Workspace CLI. Standard app connections don’t use these user review rules.” An agent still calling REST gets no prompts. Until its vendor moves it, your lever is the client ID: trust it, limit its scopes or block it. The Next Web’s 24 November report [https://thenextweb.com/news/google-workspace-ai-agents-mcp-servers-rules] says agents need sign-off before sending email; Google’s help page makes that a default admins can change.

Who the Workspace AI Tools Addendum binds

The Addendum “supplements the Google APIs Terms of Service.” Its obligations fall on “you,” the party using Google’s APIs: the company that builds the AI tool, or your own engineers when your company runs an agent from its own Google Cloud project. An employee who clicks Allow on a consent screen hasn’t accepted the API Terms.

If a vendor trains on your mail, Google’s remedy under term 3 is to restrict that vendor’s access. Term 4 says Google “will have no responsibility for or liability from” a third-party tool’s acts, including training on user data. Your protection for what the vendor does with the data is your own contract with it.

What changes for Google Workspace AI agents employees already connected

Tools employees authorized with work accounts already appear under API controls in the Accessed apps list, which Google says updates 48 hours after a token is granted or revoked. Expect new client IDs as vendors move agent features to MCP, because a client that missed the 12 November marking deadline must be replaced by a new one marked agentic.

Once a tool talks to Workspace through MCP or the CLI, the user-review settings under Agents > Settings apply. Google’s defaults are Require user approval for external collaboration, internal collaboration and external data access, and Allow for internal data access. Users can save an “Always allow” choice for up to 90 days unless you clear that option. Moving items to the trash always needs confirmation, and external agents can’t permanently delete anything.

Google’s admin pages describe controls over accounts in your organization; none covers an agent an employee links to a personal Gmail or Drive holding copied work files.

Gemini sits apart. The Addendum doesn’t mention it, the user-review settings are written for external agents, and the Gemini app’s access to Workspace services has its own setting, per Google’s admin help page “Control Gemini App access to Workspace services”.

What admins should do before 1 February 2027

Inventory third-party AI apps. In Security > Access and data control > API controls, list every client with Gmail, Drive or Calendar scopes and its user count. Google doesn’t document a filter for agentic clients, so mark agents yourself; the audit logs’ “By an agent” field helps.

Set the user-review categories. In Agents > Settings (Security administrator privilege), decide per organizational unit whether internal data access stays on Allow, and whether to clear “Except when user always allows” so every external send is confirmed.

Read the agent audit logs. OAuth log events carry “By an agent”, “Agent ID” and “User approved”. The “Agent product” field currently works only for Google Workspace Studio flows, and API call events need Enterprise Standard or Plus, Education Standard or Plus, or Cloud Identity Premium.

Decide on internal-use projects. A super admin can mark a project internal to keep higher REST quotas at no charge. The exception covers non-agentic REST use only; higher MCP quotas need the Scaled tier, and Gmail, Calendar and Drive MCP usage on that tier is billed from the first request from 1 April 2027.

Separate work-account and personal-account agents. The Admin console covers the first group. The second needs visibility on the laptop and a written policy on which AI accounts may touch company data.

Check DLP for agents. Google’s admin help page on controlling app access says existing user-level DLP applies when an agent sends or shares on a user’s behalf, sensitive personal information protection is on by default for agents, and you can add agent-specific DLP for Calendar, Chat, Drive and Gmail. Setting up DLP in Google Workspace [https://jazz.security/dlp-explained/dlp-basics/how-to-set-up-dlp-in-google-workspace/] walks through the Drive and Gmail side.

Announced, not yet available as of 25 November 2026, with no dates given: time-limited approvals; AI access restrictions that block external agents from Gmail messages and specific Drive files and folders; users viewing agent activity and revoking access themselves; the Keep MCP server; and more granular agent policies “over the coming months.”

What Workspace still won’t see once data is on the laptop

Google’s new controls govern calls into Workspace. These five paths begin after the call.

Files Drive for desktop has already synced

Google’s Drive log events page says downloads are logged “including when files are copied between Drive and a local device using Google Drive for desktop,” as Download and Item content synced events. Mirrored folders keep a full copy on disk and streamed files sit in a local cache, where Claude Code, Codex or Claude Desktop reads them as ordinary files. Claude Code’s security documentation [https://code.claude.com/docs/en/security] says that in Manual mode it asks before reading outside the folder where it started, and that an approved shell command “can still write anywhere your user account can.” No Google page describes a Workspace log or Drive DLP event for that local read. An endpoint agent sees what happens next, such as the contents going into an AI prompt or an upload.

Computer-use agents inside a signed-in browser or app

The Addendum’s obligations trigger when a tool reaches data through a “GWS Access Point”, defined as an API, connector, proxy, command line interface or third-party service. It says nothing about browsers or screens, and Google hasn’t said whether a computer-use agent counts as an access tool.

Anthropic’s computer use help page [https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork] says Claude works from screenshots, clicking and typing in desktop apps, and “isn’t limited to the folders you’ve connected.” Google’s support page for Gemini computer use on Mac, launched 19 November 2026, says it is “only available in Gemini tasks for personal accounts” and reaches “logged-in accounts and active sessions” in native Mac apps. Microsoft’s Copilot Cowork browsing documentation says it drives the user’s own Edge “using the sites you’re already signed in to” and is off until an admin enables it. Chrome’s Gemini auto browse is off by default for managed users, under the GeminiActOnWebSettings policy.

Browser policy reaches agents built into a managed browser. For the rest, an endpoint agent sees the pastes, uploads and file movements the session produces, as Gemini computer use on work Macs [https://jazz.security/dlp-explained/dlp-basics/gemini-computer-use-on-work-macs-company-data/] details.

Pastes and uploads into personal ChatGPT, Claude or Gemini

Verizon’s 2026 Data Breach Investigations Report [https://www.verizon.com/business/resources/T343/reports/2026-dbir-data-breach-investigations-report.pdf] found 67% of users reach AI services through non-corporate accounts on corporate devices, down from 72% a year earlier, and source code was the most common data type in 858,440 untrusted DLP events aimed at GenAI tools. Workspace records the open or the download, not the paste. Chrome Enterprise Premium can see a paste or upload in Chrome, and Google’s documentation says its signed-in-account condition is “currently supported only for personal and managed Google Accounts.”

OpenAI’s data controls page [https://help.openai.com/en/articles/7730893-data-controls-in-chatgpt] says data sharing for training is enabled by default on Free, Plus and Pro, and Anthropic’s consumer retention page [https://privacy.claude.com/en/articles/10023548-how-long-do-you-store-my-data] (1 July 2026) says chats a user allows for training may be kept de-identified for up to five years. An endpoint agent that tells the personal account from the company one is the control that sees this path; which DLP tools tell personal from corporate accounts [https://jazz.security/dlp-explained/dlp-basics/dlp-tools-that-tell-personal-from-corporate-accounts/] compares the methods.

Downloads and exports by other routes

The Drive log records a web download or a Drive for desktop copy, but nothing in it follows the file when someone renames it, zips it, uploads it to a personal cloud account or attaches it to a personal email. Only something on the device sees that sequence.

Data after it reaches the agent’s vendor

Once Workspace content is on the vendor’s servers, only contracts apply: the Addendum for tools that used Workspace access points, the vendor’s terms, and your agreement with the vendor. No endpoint agent, Jazz included, sees inside a vendor’s infrastructure.

Can the Workspace CLI let a coding agent read all of your Drive?

It can read what the signed-in user can read, within the scopes granted. Google’s Workspace CLI guide says gwscli auth login with no arguments authorizes all supported services, and advises starting “with read-only access or grant only the minimum scopes required.” The CLI pauses for approval on “sending messages, sharing content externally, trashing items, or deleting data,” while “other write actions run without asking once you’ve granted the required OAuth scopes.” Reads of internal files default to Allow in the Agents settings.

Your levers are the CLI’s client ID in API controls and the Internal data access category, which you can set to Require user approval. What the agent then does with the text, such as sending it to its model provider, sits outside Workspace. Blocking unapproved MCP servers on company laptops [https://jazz.security/dlp-explained/dlp-basics/how-to-block-unapproved-mcp-servers-on-company-laptops/] covers the local side.

How Jazz covers the laptop side of Workspace agents

Jazz runs one endpoint agent on managed macOS and Windows laptops and records data-handling actions where they happen, such as a paste into Claude Desktop, a Drive file dragged into a personal ChatGPT upload or a screenshot of an open Sheet. Its detection layer [https://jazz.security/product/detection/] covers desktop applications, browsers, CLI tools and personal cloud accounts without per-app integrations, so a portable browser or a terminal agent doesn’t route around it, and it records data going into a local agent and out through it [https://jazz.security/dlp-explained/dlp-basics/how-to-secure-ai-agents-on-employee-computers/].

Each flagged movement goes to Melody, which treats a sanctioned corporate GenAI account and a personal one as different destinations [https://jazz.security/blog/product/security-that-says-yes-how-to-enable-genai-without-losing-the-data/]. A Drive export pasted into a personal Claude account and the same text in the company’s ChatGPT workspace get different answers. When a movement needs a response, Jazz Prevention [https://jazz.security/product/prevention/] can steer the user to a safer path, ask for a justification, escalate to a manager or analyst, or apply a targeted block.

Jazz covers managed Windows and macOS only, so Linux machines, phones and unmanaged devices are outside it. It doesn’t see cloud-hosted agents calling Workspace server to server, which belong to the Admin console, and it doesn’t scan Drive or Gmail at rest. It records what data moved, from which app and to where, but doesn’t by itself mark whether a click came from an agent or the employee. The server-side half is covered in is Google Workspace DLP enough [https://jazz.security/dlp-explained/dlp-basics/is-google-workspace-dlp-enough/], is it safe to connect AI tools to Google Drive [https://jazz.security/dlp-explained/dlp-basics/is-it-safe-to-connect-ai-tools-to-google-drive-and-sharepoint/] and are MCP servers a security risk [https://jazz.security/dlp-explained/dlp-basics/are-mcp-servers-a-security-risk/].

Frequently asked questions

Does Google's MCP requirement stop employees pasting Drive files into personal ChatGPT?

No. The requirement governs how AI agents call Workspace. A paste into a personal ChatGPT account happens on the laptop after the file was opened or downloaded, so Workspace logs only that earlier event. On managed Windows and macOS, Jazz's OS-level agent [https://jazz.security/product/detection/] sees the paste in any browser or desktop app and tells the personal account from the company one.

Do we need to do anything before February 1, 2027 if we only use Gemini?

The Addendum doesn't mention Gemini, the new user-review settings are written for external agents, and the Gemini app's access to Workspace services has its own Admin console setting. Still open API controls and check the Accessed apps list, because employees may have authorized third-party AI tools with their work accounts.

Can the Workspace CLI let a coding agent read all of our Drive?

It can read whatever the signed-in user can read within the granted scopes, and running gwscli auth login with no arguments authorizes all supported services. Internal data access defaults to Allow. Limit or block the CLI's client ID in API controls, or set Internal data access to Require user approval in Agents settings.

Which tool shows what AI agents on our Macs do with Google Drive files?

Workspace logs the Drive for desktop sync, then loses sight of the file. On managed Macs, Jazz's endpoint agent records data going into a local agent and out through it [https://jazz.security/dlp-explained/dlp-basics/how-to-secure-ai-agents-on-employee-computers/], plus pastes, uploads and AI prompts in any app or CLI tool, and Melody returns pre-investigated incidents. It doesn't mark whether the agent or the employee clicked.

Will AI agents that still call the Workspace REST APIs stop working on February 1, 2027?

Not according to Google's documents. Its usage-tiers guide says agents calling REST directly are limited to Standard-tier quotas regardless of tier, and throttled when a quota runs out. No Google page says the calls will be rejected, so a low-volume agent keeps working, and Google's user-approval prompts don't apply to it.

Who does the Workspace AI Tools Addendum bind?

It supplements the Google APIs Terms of Service, so it binds the party using Google's APIs: the AI tool's developer, or your own engineers if your company runs an agent from its own Google Cloud project. An employee who clicks Allow hasn't accepted the API Terms, and your recourse against a vendor is your own contract with it.

Can Jazz see cloud-hosted AI agents that call Workspace through Google's MCP servers?

No. Agents running in a vendor's cloud that call Workspace server to server never touch the laptop, so the Admin console's API controls, user-review settings and agent audit logs cover them. Jazz covers managed Windows and macOS devices only; Linux machines, phones and unmanaged devices are outside it.

Which Workspace AI agent controls are announced but not available yet?

As of 25 November 2026, with no dates given: time-limited approvals, AI access restrictions that block external agents from Gmail messages and specific Drive files and folders, users viewing agent activity and revoking access themselves, the Keep MCP server, and more granular agent policies.

How do we see what computer-use agents like Claude or Gemini do in a signed-in browser or app?

Google's Addendum doesn't mention browser or screen agents. Agents built into a managed browser follow its policy, such as Chrome's GeminiActOnWebSettings for Gemini auto browse. On managed Macs and Windows laptops, Jazz sees the pastes, uploads and file movements the session produces, without telling the agent from the employee.
