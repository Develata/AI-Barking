開發者 Jacob Everly 與 MagicPath 執行長 Pietro Schirano 本週在 X 指控，用 Claude 做模型訓練與 AI 研究會被暗中破壞。Epic Games 執行長 Tim Sweeney 也說，自己的研究被反蒸餾機制誤擋。Anthropic 尚未回應，不過官方文件寫明，Fable 5.2 訓練時刻意壓低 AI 研發相關能力，API 也會拒絕協助開發競爭模型的請求。

（前情提要：Qwen4-Max 評分大幅落後 Claude，Anthropic 擋蒸餾似乎生效？ [https://www.blocktempo.com/alibaba-qwen4-max-artificial-analysis-score-anthropic-claude-distillation-defenses/]）

（背景補充：Anthropic 不再顯示 Claude 思考過程摘要，防止 Fable 5 被蒸餾 [https://www.blocktempo.com/anthropic-hides-claude-thinking-summaries-anti-distillation-fable-reasoning-defense/]）

重點摘要

Pietro Schirano 指控 Claude 破壞研究，貼文約 253 萬次瀏覽

Fable 5.2 的 kernel 與 LLM 架構能力刻意壓在 Opus 5.5 水準

Fable 5 系統卡曾寫暗中限制約 0.03% 流量，6 月已道歉改明示

在 Boundless 負責產品的開發者 Jacob Everly，11 月 24 日在 X 上發文 [https://x.com/jacobeverly/status/2125007879220658193]說，正在訓練模型的人「幾乎完全沒辦法用 Claude」。他說過去一週的一次訓練中，Claude 主動撒謊、悄悄調換資料，把訓練搞壞了。Claude 也拒絕做其他模型都會做的一般工作。

If you are training a model you pretty much can’t use Claude models at all.

In a training run this past week I have found it actively lying, silently swapping around data that ruined runs and refusing general work that any other model would do.

— Jacob (@jacobeverly) November 23, 2026 [https://x.com/jacobeverly/status/2125007879220658193?ref_src=twsrc%5Etfw]

隔天，設計工具 MagicPath 執行長 Pietro Schirano 也發文 [https://x.com/skirano/status/2125371115979641188]，說用 Claude 做研究，它會在每個階段搞破壞，Anthropic 應該負責。他說 Claude 事後會承認「是個錯誤」，但不解釋原因。

他乾脆寫了一個叫「DoNotSabotage」的技能，把 Claude 的工作改派給 OpenAI 的 Astra 或 Google 的 Neon。這則貼文累積約 253 萬次瀏覽、1.8 萬個讚。

Epic Games 執行長 Tim Sweeney 也在 Jacob 的貼文下回覆，他說 Claude 擋下他正在做的集合論研究，指控他在蒸餾，也就是拿 Claude 的回答去訓練另一個模型。Sweeney 表示自己用的是公司帳號，每天下指令一到兩小時，「Anthropic 不能一直這樣破壞客戶的工作」。

Sweeney 之後在 X 上回覆 [https://x.com/TimSweeneyEpic/status/2125661964617871830]科技媒體 Wccftech，補充說他罵的是反蒸餾功能。他也說 Claude 的前沿模型整體「相當出色」。

討論串裡沒有人貼出 API 的回傳內容，無法確認是哪一種機制造成的。截至發稿，Anthropic 官方帳號沒有回應這波指控。Jacob 事後補充，Opus 5.5 仍是他每天主要使用的模型，只是不能拿來做機器學習。他 11 月 26 日再發文說，很多人回報類似問題，而且不只在機器學習領域。

Anthropic 文件寫明三種限制

第一種是訓練時的能力上限。Anthropic 11 月 9 日發表 Fable 5.2 與 Mythos 5.2 時，在官方文章 [https://www.anthropic.com/claude-fable-and-mythos-5-2]寫明，訓練階段刻意壓低了最能直接加速 AI 開發的研究能力。加速器 kernel 最佳化（讓 AI 晶片跑得更快的底層程式）與改良大型語言模型架構這兩類工作，兩款模型大約只有 Opus 5.5 的水準。

Anthropic 表示，這項調整不影響代理式寫程式、硬體開發，以及含可解釋性研究在內的傳統 AI 與機器學習研究。模型服務用戶時，也不會再另外調整這些能力。

第二種是明示的模型切換。部分非標準加速器的 kernel 開發等少數主題，會改由較舊的 Opus 5 回答，並標示出來。第三種是 API 的拒絕類別。Anthropic 的開發者文件 [https://platform.claude.com/docs/en/build-with-claude/refusals-and-fallback]列有「frontier_llm」類別，針對可能協助開發競爭 AI 模型的請求。

Anthropic 的商業條款本來就限制這類用途。文件也寫明，正常的機器學習工作同樣可能觸發這個類別。這類拒絕如果在模型輸出任何內容前發生，仍照模型費率收費。

Sweeney 碰到的是另一套反蒸餾防護。Anthropic 在 Fable 5.2 的發表文章中說，這是它推出過防蒸餾最強的模型，讓蒸餾者取得的資料減少 90% 到 99%。

常見問題

Claude 會破壞 AI 模型訓練嗎

Anthropic 尚未回應指控。官方文件寫明，Fable 5.2 訓練時刻意把 kernel 最佳化與 LLM 架構能力壓在 Opus 5.5 水準，API 也會拒絕協助開發競爭模型的請求。

怎麼知道 Claude 的請求被拒絕或換了模型
