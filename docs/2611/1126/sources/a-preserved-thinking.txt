Preserved thinking

Copy page



On Claude models that run the prefix check, preserved thinking determines whether the model can use a thinking block you send back from an earlier turn.

Claude can build on its reasoning from earlier turns when your code sends the thinking blocks back. Preserved thinking determines which of those blocks it can use. On models with preserved thinking [/docs/en/build-with-claude/preserved-thinking/prefix-checks#outcomes], usable blocks stay in context and are billed as input. Send assistant turns back exactly [/docs/en/build-with-claude/preserved-thinking/change-tools-or-instructions#append-assistant-turns-exactly-as-returned] as the API returned them.

If a request already failed with The block is bound to a different conversation, start at Fix a thinking block bound to a different conversation [/docs/en/build-with-claude/preserved-thinking/fix-bound-to-a-different-conversation].

What a thinking block is tied to

On these models, a thinking block is tied to the following:

What came before it: system, tools, and every earlier message. If any of them changes, the block fails the prefix check [/docs/en/build-with-claude/preserved-thinking/prefix-checks#prefix-check], and the request can get a 400 error. So only add to a conversation (see Change tools or instructions without failing the prefix check [/docs/en/build-with-claude/preserved-thinking/change-tools-or-instructions]).

The model: a model reads only some other models’ thinking blocks (see Which model switches keep the reasoning on the Claude API [#which-model-switches-keep-reasoning]).

The account: blocks from some models are tied to an account (see Accounts and cloud platforms [#account-bound-thinking]).

prefix_mismatch_behavior [/docs/en/build-with-claude/preserved-thinking/prefix-checks#preserved-thinking-controls] chooses whether a request that fails the prefix check gets a 400 error or the API drops the failing blocks. The response’s input_transformations [/docs/en/build-with-claude/preserved-thinking/fix-bound-to-a-different-conversation#input-transformations] lists thinking blocks the API dropped or let through. Dropping thinking has a cost (see What dropping thinking costs [/docs/en/build-with-claude/preserved-thinking/fix-bound-to-a-different-conversation#drop-block-cost]).

Switch models and back

Change model and keep sending the whole conversation. A thinking block that the new model or account can’t use never causes an error. The API drops it for that request and doesn’t bill it, and Claude answers without that reasoning.

On a model with preserved thinking [/docs/en/build-with-claude/preserved-thinking/prefix-checks#outcomes], thinking: {"type": "enabled"} [#thinking-type-on-switch] is a 400 error, and a request that fails the prefix check [/docs/en/build-with-claude/preserved-thinking/prefix-checks#prefix-check] can get one.

Claude Opus 5.5 can’t read Claude Fable 5.1’s blocks, so the API drops them for its request. Back on Claude Fable 5.1, they’re read again, because the API never changes your messages. On a switch, reasoning is lost permanently only if your code removes it. So don’t remove thinking, and don’t keep a separate history for each model.

A dropped block doesn’t count as a change to the conversation, so both models’ blocks stay valid.

Switches your code doesn’t make

A router, a fallback after a refusal [#after-a-refusal], or a server-side fallback can switch models for you, and another provider’s model can take a turn [#other-provider-turns]. Keep sending the whole conversation. A turn that holds a fallback block has its own rule. For which blocks to leave out, see Continuing the conversation [/docs/en/build-with-claude/refusals-and-fallback#continuing-the-conversation].

Any switch can pick a model that doesn’t accept system messages. See When a model doesn’t accept system messages [#unchosen-switches-details].

Accounts and cloud platforms

A move to another account or cloud platform works the same way: keep sending the full history.

Thinking blocks from Claude Fable 5.2, Claude Mythos 5.2, Claude Sonnet 5.5, and Claude Haiku 5.5 work only in the account that produced them or a linked one. In any other account, the API drops them, with no error.

What counts as your account [#accounts-by-platform] depends on the platform.

Secrets and untrusted text

Send a file your user wouldn’t expect Claude to trust [/docs/en/build-with-claude/preserved-thinking/change-tools-or-instructions#untrusted-text] only in a tool_result block. When you remove secrets, personal data, or injected text [/docs/en/build-with-claude/preserved-thinking/change-tools-or-instructions#remove-sensitive-content] from your history, also remove every thinking block after the first place they appear. Claude then works without that reasoning.

Thinking settings on the new model

Models with preserved thinking [/docs/en/build-with-claude/preserved-thinking/prefix-checks#outcomes] reject thinking: {"type": "enabled"} with a 400 error. When you move a conversation to one of them from a model whose requests set "enabled", send "adaptive" instead. Leaving thinking out gives adaptive thinking on these models too.

When a model doesn’t accept system messages

If a model isn’t on the list of models that accept system messages [/docs/en/build-with-claude/mid-conversation-system-messages], leave system messages out of its requests only. Keep them in your stored history. Back on a model that accepts them, send the full stored history again. Coming back without them is a change, and the request can get the 400 error.

After a refusal

None of the permitted fallback models [/docs/en/build-with-claude/refusals-and-fallback#naming-your-own-fallback-models] can read the refusing model’s thinking, so the fallback model answers without it. Back on the model you asked for, Claude reads both models’ thinking.

A turn from another provider’s model

A turn from another provider’s model goes at the end, as text and tool_use content. Claude’s earlier thinking stays valid.

What counts as your account on each platform

Claude Models on Google Cloud (Google managed)Your Google Cloud project

The API can also leave out a thinking block that another account produced, if that account is no longer in good standing. This applies to requests to Claude Fable and Claude Mythos models, Claude Opus 5, Claude Opus 5.5, Claude Sonnet 5.5, and Claude Haiku 5.5. The request still succeeds, and the model answers without that block’s reasoning.
