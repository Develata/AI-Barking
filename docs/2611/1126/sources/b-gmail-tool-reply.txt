Tool: reply

Replies to a specific email message in the authenticated user's Gmail account. Supports replying to only the sender or to all recipients (reply-all) via the replyAll parameter.

Requires the messageId of the message to reply to. Plain text body content can be provided in body (do NOT format body with Markdown), and rich-text HTML content in htmlBody (use valid HTML tags). If htmlBody is not provided, then body is required. If body is not provided, then htmlBody is required. Attachments can be included via the attachments field, but the combined size cannot exceed 25MB. Set includeSignature to true to append the user's configured Gmail web signature to the reply. To reply to an existing thread, retrieve the thread via get_thread first to find the messageId of the latest message in that thread.

Returns a Message object with the id, threadId, and viewUrl (if available) fields populated.

 The following code sample shows how to use curl to call the reply MCP tool.

 Curl Request

curl --location 'https://gmailmcp.googleapis.com/mcp/v1' \
--header 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
--header 'content-type: application/json' \
--header 'accept: application/json, text/event-stream' \
--data '{
 "method": "tools/call",
 "params": {
 "name": "reply",
 "arguments": {
 // Provide these details according to the MCP tool specification.
 }
 },
 "jsonrpc": "2.0",
 "id": 1
}'

Input Schema

Request message for Reply RPC.

ReplyRequest

 JSON representation

{
 "messageId": string,
 "body": string,
 "htmlBody": string,
 "replyAll": boolean,
 "to": [
 string
 ],
 "cc": [
 string
 ],
 "bcc": [
 string
 ],
 "attachments": [
 {
 object (Attachment [/workspace/gmail/api/reference/mcp/tools_list/create_draft#Input.Schema.Attachment])
 }
 ],
 "includeSignature": boolean
}

 Fields

 messageId

string

Required. The unique identifier of the message to reply to. If you want to reply to an existing thread, first retrieve the thread via get_thread to find the messageId of the last message in the thread. Pass that messageId here to ensure proper threading.

 body

string

Optional. The plain text body content of the reply. Do NOT format this field with Markdown (such as headers #, bold **, bullet points *, or tables |). If formatted rich text is desired, use htmlBody instead. If htmlBody is also provided, this field is treated as the plain-text alternative. If htmlBody is not provided, then body is required.

 htmlBody

string

Optional. The HTML content of the reply. If provided, this will be used as the rich-text version of the email. Use this field (with valid HTML tags such as p, b, ul, li, h1) whenever rich text formatting is needed. If body is not provided, then htmlBody is required.

 replyAll

boolean

Optional. Whether to reply to all recipients. Defaults to false.

 to[]

string

Optional. The primary recipients of the email reply. If specified, overrides the default reply recipients. Each string MUST be a valid plain email address (e.g., "user@example.com").

 cc[]

string

Optional. The carbon copy recipients of the email reply. If specified, overrides the default CC recipients. Each string MUST be a valid plain email address (e.g., "user@example.com").

 bcc[]

string

Optional. The blind carbon copy recipients of the email reply. Each string MUST be a valid plain email address (e.g., "user@example.com").

 attachments[]

object (Attachment [/workspace/gmail/api/reference/mcp/tools_list/create_draft#Input.Schema.Attachment])

Optional. The attachments to include in the email reply. The combined size of attachments in the message cannot exceed 25MB. If you need to send files larger than 25MB, upload the file to Drive first and then insert the Drive link into body or htmlBody.

 includeSignature

boolean

Optional. Whether to append the user's configured Gmail web signature to the reply. Defaults to false.

Attachment

 JSON representation

{
 "id": string,
 "filename": string,
 "mimeType": string,
 "content": string,
 "inline": boolean
}

 Fields

 id

string

Output only. When present, contains the ID of an external attachment.

 filename

string

Optional. The name of the file to be attached, e.g. "invoice.pdf". Email clients show this name to recipients for both regular and inline attachments. If not provided, the attachment may be received with no name.

 mimeType

string

Optional. The field representing a content or media type must use IANA MIME type, https://www.iana.org/assignments/media-types/media-types.xhtml [https://www.iana.org/assignments/media-types/media-types.xhtml]. If not provided, defaults to "application/octet-stream".

 content

string (bytes [https://developers.google.com/discovery/v1/type-format] format)

Required. The base64-encoded content of the attachment.

A base64-encoded string.

 inline

boolean

Optional. If true, this attachment is handled as inline. An inline attachment is content, such as an image, that is displayed within the body of an HTML email instead of being listed as a separate file for download. To display an inline attachment, add an img element to htmlBody whose src is cid:attN, where N is the attachment's zero-based position in attachments, counting all attachments. For example, if attachments contains a PDF followed by an inline PNG, set src="cid:att1" on the PNG's img element. Don't reference inline attachments by filename. Other images in htmlBody are removed. If false or absent, defaults to false, and it's treated as a regular attachment.

The ids of the labels attached to the message. Includes ids of user labels and standard system labels limited to INBOX, TRASH, UNREAD, STARRED, IMPORTANT, SENT, DRAFT, CHAT, and the inbox category labels CATEGORY_PERSONAL (Primary tab), CATEGORY_SOCIAL, CATEGORY_PROMOTIONS, CATEGORY_UPDATES, CATEGORY_FORUMS.

 threadId

 historyId

string

Output only. The ID of the last history record that modified this message.

 internalDate

string

Output only. The internal message creation timestamp (epoch ms).

 sizeEstimate

integer

Output only. Estimated size in bytes of the message.

 viewUrl

string

Output only. Web URL to view the message in the Gmail Web UI.

 addressDisplayNames[]

object (AddressDisplayName [/workspace/gmail/api/reference/mcp/tools_list/send_message#Output.Schema.AddressDisplayName])

Output only. Contains display names from the From, To, Cc, and Bcc headers, with one entry for each address in sender, toRecipients, ccRecipients, or bccRecipients whose header includes a display name. Addresses whose header has no display name are omitted. Use these names verbatim when referring to people instead of inferring a name from an email address.

Union field _original_message_id.

_original_message_id can be only one of the following:

 originalMessageId

string

Optional. Output only. The unique identifier of the original message that was forwarded. Only populated for forwarded messages.

AttachmentMetadata

 JSON representation

{
 "id": string,
 "mimeType": string,
 "filename": string,
 "partId": string
}

 Fields

 id

string

Output only. The ID of the attachment.

 mimeType

string

The MIME type of the attachment.

 filename

string

The filename of the attachment.

 partId

string

Output only. The MIME part ID of the attachment (e.g., "1", "0.1").

This represents the 0-indexed hierarchical position of the part within the email MIME tree. The root message container is omitted, so direct top-level parts are indexed as "0", "1", etc. (they do not start with a "0." prefix). Nested multipart children append their sub-index (e.g., "0.1", "0.2").

AddressDisplayName

 JSON representation

{
 "emailAddress": string,
 "displayName": string
}

 Fields

 emailAddress

string

Output only. Specifies the email address, matching a value in sender, toRecipients, ccRecipients, or bccRecipients.

 displayName

string

Output only. Specifies the display name exactly as it appears in the header, for example Alice Smith.

Tool Annotations

 Tool annotations [https://modelcontextprotocol.io/specification/latest/schema#toolannotations] are sent to MCP clients to describe the basic risk of a given tool. Most clients treat these hints as untrusted, but they can be used to decide when a confirmation prompt might be sent to a user.

 Along with the title string, the following boolean hints are defined as follows:

readOnlyHint: If true, the tool doesn't modify its environment. Default: false.

destructiveHint: If true, then the tool can perform destructive actions. If false, then the tool can only perform additive actions. Default: true.

idempotentHint: If true, then calling the tool repeatedly with the same arguments will have no additional effect on its environment. Default: false.

openWorldHint: If true, then the tool can interact with an 'open world' of external entities. If false, then the tool can only interact with internal entities. For example, a web search tool would be open world, while a memory tool would not be open world.

Destructive Hint: ❌ | Idempotent Hint: ❌ | Read Only Hint: ❌ | Open World Hint: ✅
