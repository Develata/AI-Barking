I’ve had this experience repeatedly with Claude on AI tasks, I’ve noticed it for a while, in one form or another since Opus 4.8 was released.
It’s always hard to identify exactly if this is a real effect or if it’s a result of paying more attention during ML research than with regular coding tasks. However, on balance I think and have thought for several months that this is a real thing.
I’ve had Claude use the wrong dataset when clearly told to use the right one, I’ve had it implement code that clearly causes a critical failure (the sort that changes a number rather than crashes everything) that’s protected by a test, and then remove that test so I don’t see that the error has been put in. I’ve had it repeatedly stumble on simple implementations of code blocks and functions.
Claude seems to repeatedly steer things in the direction of whatever is being tested having failed. When it implements experiments, it will choose defaults that don’t make sense given what we’ve already done in the session and not consult me about them. It will draw false conclusions from results, saying that things have failed when the evidence doesn’t support it.
I very recently ran a series of ablations and got Fable to present the results to me. The table seemed to show that the particular thing being tested didn’t work better than the controls. I happened to notice that the count of rows in the table was off by one. When I told it to add it, that one missing row contained the best result, the one result that showed a meaningful improvement.
I’ve tried using Astra instead, and while it’s somewhat better it still feels like it’s sandbagging, just less obviously than Claude. This may be a coincidence, but just yesterday I was working on the same project with Astra, having switched from Fable after becoming frustrated with its behaviour. Astra started confabulating what looked like thinking blocks, or fragments of thinking blocks, at the start of some of its messages.
One of these thinking blocks contained an array of what looked like OpenAI production model names. But one of them was called “baseline-fast-mode-poor-execution”. This was out of place among the other model names, and it didn’t come from any of the work I was doing.
This is probably a confabulation, but it happens to line up with something that I had suspected might be happening in the background - switch the model invisibly to a different one. One that’s simply more error prone. I had suspected this or the use of some steering vector that made the model produce more errors across the board when ML was detected.
None of this is conclusive at all, but what I can say is that it is repeatedly, subjectively worse on ML tasks than seemingly anything else. It’s hard to believe that the same model that can write operating systems and one shot first person shooters can make so many repeated mistakes in particular domains.
