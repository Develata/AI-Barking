 Usage tiers and quotas for Google Workspace APIs and MCP servers

 Stay organized with collections

 Save and categorize content based on your preferences.

As AI agents experience rapid growth—generating increasing demand for
Google Workspace services and new data risks—Google Workspace aims to
meet our performance, safety, security, and privacy commitments by providing
enhanced visibility and control over how AI agents and developer tools access
and use Google Workspace data. To support this goal while fostering
innovation, Google Workspace uses a standardized tiering model across
Google Workspace APIs and Model Context Protocol (MCP) servers.

We expect that less than 1% of active Google Workspace developers will
need to move beyond the Standard Tier, ensuring the vast majority of our
community can continue to build at no cost.

Rollout roadmap and key dates

The standardized tiering and pricing model rolls out across the following
milestones, starting with the Gmail API, Google Calendar API, and Google Drive API
(including their corresponding MCP servers, with additional data access
mechanisms updated similarly over time):

Milestone
Date
Details

Initial announcement & baseline quotas
May 1, 2026
Documented baseline usage quotas for Gmail API, Calendar API, and Drive API applied to all new Google Cloud projects. Existing active projects between November 2025 and April 2026 maintained prior quotas. Blog announcement [https://workspaceupdates.googleblog.com/2026/05/agent-tools-and-security-updates-for-workspace-developers.html].

Tiering model & dashboard rollout
November 24, 2026
Standard and Scaled Tiers officially launch. Across generally available (GA) Google Workspace MCP servers (Gmail, Google Calendar, Google Drive, Google Docs, Google Sheets, Google Slides, Google Chat, and Google Tasks), the Standard Tier includes up to 5,000 requests per day, per project, per product with no Google Cloud Billing account required. The new API quotas dashboard [/workspace/guides/quota-dashboard] becomes available in the Google Cloud console to evaluate usage and estimate costs. Requesting higher MCP quotas requires enrolling in the Scaled Tier with a linked billing account. Requesting higher per-project quotas for the Gmail API, Calendar API, and Drive API requires enrolling in the Scaled Tier or attesting to the internal-use exception. Existing projects operating with higher per-project limits for those three APIs can preserve them by opting in to the Scaled Tier or designating projects as Standard Tier with internal-use exception. Blog announcement [https://workspaceupdates.googleblog.com/2026/11/mcp-servers-cli-standardized-usage-tiers-now-available.html].

Workspace AI Tools Addendum
February 1, 2027
The Workspace AI Tools Addendum [https://workspace.google.com/terms/ai-tools] takes effect, establishing the MCP requirement for AI agents and security rules for agentic access to Google Workspace data.

MCP requirement enforcement
February 1, 2027
AI agents or similar access tools accessing Google Workspace data must use Google Workspace MCP servers or the Google Workspace CLI.

Billing & quota enforcement
April 1, 2027
Google Workspace begins enforcing standard usage limits across all Cloud projects. Scaled Tier billing takes effect: REST API usage is billed after exceeding daily no-charge allowances, whereas Scaled Tier Gmail, Calendar, and Drive MCP usage has no daily no-charge allowance and is billed from the first request. Projects exceeding limits revert to Standard Tier limits unless they opt in to the Scaled Tier (or attest to the internal-use exception for per-project REST API limits).

Google Cloud Support fee exclusions
Until at least December 2027
For Google Cloud Support [https://cloud.google.com/support] customers, Google Workspace APIs are excluded from the support variable fee calculation until at least December 2027. Google will communicate any changes with at least 90 days' notice.

Standardized tiering and pricing model

To support high-volume apps and AI agents—including Google Workspace MCP
servers—while safeguarding user data and platform stability,
Google Workspace uses a standardized tiering and pricing model for
Google Workspace APIs.

These adjustments are designed to align with typical usage patterns for common
use cases, helping uphold the performance, safety, security, and privacy
commitments that Google Workspace users and customers expect.

For governing terms and AI agent requirements, see Google Workspace
developer policy and Google terms [#developer-policy-terms].

Usage tiers

The standardized model defines certain usage tiers for Cloud projects:

Standard Tier: Enforces published usage limits on projects and is
available at no cost across Google Workspace APIs and MCP servers, with
no Google Cloud Billing account or credit card required at enablement
or to get started. This tier is enabled by default for any new
Google Cloud project and is the default tier for all existing projects unless a
developer opts in to the Scaled Tier.

Across GA Google Workspace MCP servers (Gmail,
Calendar, Drive, Docs,
Sheets, Slides, Chat, and
Tasks), the Standard Tier is capped at 5,000 requests per
day, per project, per product (in addition to per-minute rate limits).
Unlike single API calls, some MCP tools count as multiple requests because
they make multiple API calls.

Starting April 1, 2027, REST API projects operating under standard limits
keep running as they do today. Submitting additional quota requests isn't
possible on the Standard Tier—requesting higher MCP quotas requires
enrolling in the Scaled Tier (with a linked billing account), and requesting
higher per-project REST API quotas requires enrolling in the Scaled Tier or
attesting to the internal-use exception. Usage on the Standard Tier never
produces a charge on a Google Cloud bill, and daily billing thresholds
aren't relevant.

If a Cloud project on the Standard Tier exceeds its standard usage
quotas, the API or MCP server throttles requests until the quota window
resets.

Standard Tier with internal-use exception:
Google Workspace customers can also designate projects as
"Internal-use exception" and request higher per-project REST API usage
quotas without switching to the Scaled Tier (MCP server quotas
aren't eligible for increases under this exception). This exception only
applies to projects used by users within the same
Google Workspace organization and that don't share their API or
MCP access directly with third-party services. Enrolling requires
Google Workspace super
administrator [https://knowledge.workspace.google.com/admin/users/prebuilt-administrator-roles#super_admin]
privileges and a Cloud project that doesn't contain an OAuth
client configured for an external audience.

Scaled Tier: This tier provides faster, scaled access for developers,
production apps, and AI agents (using MCP) that require large-scale,
high-volume data processing beyond Standard Tier quotas. Available for the
Gmail API, Calendar API, and Drive API and for
GA Google Workspace MCP servers (Scaled Tier MCP billing currently
applies to the Gmail, Calendar, and
Drive MCP servers). You must select the Scaled Tier for the
whole Cloud project, not on a per-API or per-MCP basis.

Enrolling requires linking a Google Cloud Billing account that's
active and in good standing, and you must hold both the
resourcemanager.projects.createBillingAssignment permission on the
Cloud project and the billing.resourceAssociations.create
permission on the linked billing account. For more information, see
Required permissions [#permissions].

Prices are quoted across four separate billing tier
buckets [/workspace/guides/quota-pricing#billing-buckets]: Light, Medium,
Plus, and Premium. The Drive API and its MCP server use all four
buckets, whereas the Gmail API and its MCP server use Light,
Medium, and Premium. All requests to the Calendar API and its MCP
server use the Plus bucket. Pricing is based on each operation's resource
intensity, complexity, and payload size.

Allowances and billing behavior differ between REST APIs and MCP servers
when Scaled Tier billing takes effect on April 1, 2027:

REST APIs: Daily billing thresholds (no-charge allowances) are
defined for each REST API and billing tier bucket. Operations within a
bucket only begin counting as billable requests after daily traffic
exceeds that bucket's independent daily no-charge allowance.

MCP servers (pay from first request): Switching from the Standard
Tier to the Scaled Tier removes free MCP allowances. For the
Gmail, Calendar, and Drive
MCP servers, Scaled Tier usage has no daily no-charge allowance, so
charges apply from the first successful MCP request. Enrolling doesn't
automatically raise your quota limits—you must submit a quota increase
request if your project requires higher quotas.

For more information, see Turn on the Scaled
Tier [/workspace/guides/quota-dashboard#turn-on-scaled].

To learn more about usage tiers, quotas, and pricing, see Understand
Google Workspace API and MCP server pricing and billing
tiers [/workspace/guides/quota-pricing].

Monitor usage, estimate costs, and manage tiers

The Google Workspace section of the Google Cloud console provides
three tabs to help you evaluate your Cloud project's API usage,
estimate monthly costs, and manage your usage tier for the Gmail API,
Calendar API, and Drive API and GA Google Workspace
MCP servers:

Dashboard tab [/workspace/guides/quota-dashboard]: Displays 1-day,
7-day, and 30-day projected API usage, modeled throttling impact (Low,
Medium, or High), average per-project and per-user quota usage,
Drive API egress, and the projected per-project and per-user
throttling errors based on the Standard Tier. From this tab, you can also
enroll in the Scaled Tier or switch from the Scaled Tier.

Cost estimator tab [/workspace/guides/quota-cost-estimator]: Calculates
estimated 30-day billable costs, REST API daily no-charge allowances, Scaled
Tier Gmail, Calendar, and Drive
MCP costs (priced from the first request), and volume discounts for your
current project or across multiple projects using copied CSV usage data.

Project billing usage
tab [/workspace/guides/quota-project-billing-usage]: Displays 30-day
successful (2xx) API request and MCP tool call volume categorized by
API or MCP service. You can also copy daily usage records as CSV to combine
usage across multiple Cloud projects on the same billing account.

Tier and billing policies

When managing your Cloud project's usage tier and quotas, keep the
following details in mind:

Requesting a quota increase: For REST APIs, tiering applies only to the
Gmail API, Calendar API, and Drive API at this
time. For MCP, tiering applies across GA Google Workspace MCP
servers (Gmail, Calendar,
Drive, Docs, Sheets,
Slides, Chat, and Tasks).
Submitting quota increase requests isn't possible on the Standard Tier.
Requesting higher MCP quotas (such as exceeding 5,000 MCP requests per day,
per project, per product) requires enrolling your Cloud project in
the Scaled Tier with a linked Google Cloud Billing account—even before
billing enforcement starts on April 1, 2027—and submitting a quota increase
request. For the three tiered REST APIs, you can also request higher
per-project quotas under the Standard Tier with internal-use exception
(limits apply). Google won't enforce billing for Scaled Tier usage before
April 1, 2027.

Daily billing thresholds and billing entities: Daily no-charge
allowances apply only to REST APIs on the Scaled Tier, where charges
apply only after a daily billing threshold is reached each day for a billing
entity (the linked Google Cloud Billing account). By contrast,
switching to the Scaled Tier removes free MCP allowances, and
Gmail, Calendar, and Drive MCP
usage has no daily no-charge allowance (billed from the first request
starting April 1, 2027). On the Standard Tier, usage never produces a
charge on a Google Cloud bill. For more information, see Understand
Google Workspace API and MCP server pricing and billing
tiers [/workspace/guides/quota-pricing].

Volume pricing: Scaled Tier pricing is based on usage volume, and
organizations with high expected REST API or MCP usage might be eligible for
programmatic volume pricing (evaluated on separate tracks for REST APIs and
MCP servers).

Sporadic and seasonal REST API usage spikes: Because REST API daily
billing thresholds reset every 24 hours at midnight Pacific Time (PT), REST
API apps that experience temporary traffic surges (due to Black Friday
ecommerce sales or semester course enrollment, for example) don't incur
ongoing monthly minimums. If your REST API traffic exceeds its daily
no-charge allowance only once or twice a year, you're billed solely for the
overage consumed on those specific days.

Whole-project tier selection: You must enroll in the Scaled Tier for the
whole Cloud project, not on a per-API or per-MCP basis. When you
enroll a project in the Scaled Tier, the tier applies across all supported
REST APIs and MCP servers in that project—removing the free Standard Tier
MCP allowance for that project.

MCP requirement and direct REST API limits for AI agents: MCP is
required when AI agents or similar access tools are used to obtain data from
Google Workspace APIs (see Configure the Google Workspace MCP
servers [/workspace/guides/configure-mcp-servers]). Starting February 1,
2027, AI agents or similar access tools that call Google Workspace
REST APIs directly (instead of MCP) are limited to Standard Tier quotas,
regardless of the tier selected. To obtain higher quotas for agentic use,
switch to MCP and enroll in the Scaled Tier (MCP server quotas aren't
eligible for increases under the internal-use exception).

MCP server quotas: Standard and Scaled Tier quota rules apply across
GA Google Workspace MCP servers (gmailmcp.googleapis.com,
calendarmcp.googleapis.com, drivemcp.googleapis.com,
docsmcp.googleapis.com, sheetsmcp.googleapis.com,
slidesmcp.googleapis.com, chatmcp.googleapis.com, and
tasksmcp.googleapis.com), while Scaled Tier MCP billing currently covers
the Gmail, Calendar, and Drive
MCP servers:

No billing account on Standard: Enabling and using MCP servers on
the Standard Tier requires no Google Cloud Billing account and
is capped at 5,000 requests per day, per project, per product.

Higher quotas and Scaled billing: Requesting higher MCP quotas
requires opting in to the Scaled Tier with a billing account and
submitting a quota increase request (MCP quotas aren't eligible for
increases under the internal-use exception). On the Scaled Tier,
free MCP allowances are removed, and starting April 1, 2027,
Gmail, Calendar, and Drive
MCP usage is billed from the first request.

Multi-request tools: Unlike single API calls, some MCP tools count
as multiple requests because they make multiple API calls.

Google Cloud Support fee exclusions: If you're a
Google Cloud Support [https://cloud.google.com/support] customer,
Google Workspace APIs are excluded from the support variable fee
calculation until at least December 2027. Google will communicate any
changes with at least 90 days' notice.

Switching from the Scaled Tier: A user can switch from the Scaled
Tier at any time on the Dashboard
tab [/workspace/guides/quota-dashboard#switch-scaled-tier]. Within 24 hours
of opting out (or unlinking the Cloud project's billing account),
the Cloud project reverts to the Standard Tier and any
previously approved quota overrides are removed. For more information, see
Required permissions [#permissions].

What you need to do

Complete the following steps to prepare your Cloud projects for
upcoming policy and enforcement milestones:

Review terms: Review the Google Workspace API Billing
Terms [https://workspace.google.com/terms/api-billing/] and the new
Workspace AI Tools Addendum [https://workspace.google.com/terms/ai-tools]
before it takes effect on February 1, 2027, along with the Google APIs
Terms of Service [https://developers.google.com/terms] and
Google Workspace user data and developer
policy [/workspace/workspace-api-user-data-developer-policy].

Check tool usage: Check whether your Cloud projects use AI
agents or similar access tools to obtain Google Workspace data. If
so, plan to switch from calling REST APIs directly to MCP before
February 1, 2027. For setup instructions, see Configure the
Google Workspace MCP
servers [/workspace/guides/configure-mcp-servers].

Check usage levels: Open the
Dashboard [/workspace/guides/quota-dashboard] and Cost
estimator [/workspace/guides/quota-cost-estimator] tabs in the
Google Cloud console to evaluate each Cloud project's usage
against Standard Tier rate limits and review estimated costs. If every
Cloud project is within Standard Tier limits (including up to
5,000 MCP requests per day, per project, per product), you don't need to
change tiers.

Manage projects exceeding Standard limits: If your
Cloud project exceeds Standard Tier limits or requires higher
quotas, complete one of the following options and submit a quota increase
request on the Quotas & System Limits [https://console.cloud.google.com/iam-admin/quotas]
page:

Internal-use exception: For non-agentic per-project REST API quotas
on eligible internal organizational projects, have a
Google Workspace super administrator turn on the internal-use
exception [/workspace/guides/quota-dashboard#turn-on-internal] (higher
MCP server quotas require the Scaled Tier).

Scaled Tier: Have an administrator or user with the required
project and billing permissions [#permissions] link an active
Google Cloud Billing account and turn on the Scaled
Tier [/workspace/guides/quota-dashboard#turn-on-scaled]. To locate
principals with billing permissions, see Find a Billing Account
Administrator [https://docs.cloud.google.com/billing/docs/how-to/find-billing-account-administrator].

Maintain existing limits: If your Cloud projects already have
higher usage limits, complete the same steps in the preceding item before
April 1, 2027 to maintain them.

Important: If you don't take action before April 1, 2027,
Cloud projects with higher limits automatically revert to Standard Tier
rate limits. For organizations with high expected usage volume, see
Programmatic monthly volume
discounts [/workspace/guides/quota-pricing#volume-discounts].
