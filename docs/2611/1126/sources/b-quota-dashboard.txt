 Monitor quota usage with the Google Workspace API dashboard

 Stay organized with collections

 Save and categorize content based on your preferences.

The Dashboard tab in the Google Workspace section of the Google Cloud console
displays projected API performance, quota utilization, and modeled throttling
impact for your Google Cloud project. It helps you determine whether your
Cloud project's usage fits within the no-cost Standard Tier (no
Google Cloud Billing account required, including up to 5,000 requests per day,
per project, per product across generally available (GA) Model Context Protocol
(MCP) servers) and if not, whether you need to reduce requests, turn on the
internal-use exception, or upgrade to the Scaled Tier to prevent
throttling.

The Usage and quota assessment table tracks the Gmail API,
Google Calendar API, and Google Drive API over up to the past 30 days (ending two days
before the current date) across 1-day, 7-day, or 30-day intervals. Tier changes
on the Dashboard tab apply to the whole Cloud project, covering the
three tracked REST APIs and all GA Google Workspace MCP servers.

From the Dashboard tab, you can also:

Turn on the internal-use exception [#turn-on-internal] or turn on the
Scaled Tier [#turn-on-scaled].

Switch from the internal-use exception [#switch-internal] or switch from
the Scaled Tier [#switch-scaled-tier] to the Standard Tier.

Open the Cost estimator [/workspace/guides/quota-cost-estimator].

View projected API usage and throttling impact

To view the Dashboard tab, you need the monitoring.timeSeries.list and
resourcemanager.projects.get permissions on the Cloud project (for
example, the Project Viewer role). For more information, see Required
permissions [/workspace/guides/quota-usage-tiers#permissions].

To review your Cloud project's quota utilization and to assess
potential throttling impacts using your project's recent API traffic, complete
these steps:

In the Google Cloud console, click Menu
menu
> the View all products tile
> Google Workspace
> Dashboard.

Go to Dashboard [https://console.cloud.google.com/workspace-api/dashboard] 

In the upper-right corner of the Dashboard tab, select a time range (1
day, 7 days, or 30 days).

In the Usage and quota assessment table, review the metrics for each
endpoint:

Endpoint: The service endpoint.

Modeled impact: The projected impact of exceeding documented
Standard Tier quotas, which can cause excess requests to be throttled:

Low: Less than 90% average utilization and 0 throttled
requests.

Medium: Greater than 90% average utilization or fewer than 10
throttled requests on any single day within the time period.

High: More than 10 throttled requests on any single day within
the time period.

Project quota usage: The average per-project usage compared to the
Standard Tier. For example, 100% usage means the project submitted
requests to this endpoint up to the per-minute per-project standard
limit, averaged over the time range.

User quota usage: The average per-user usage compared to the
Standard Tier. For example, 50% usage means the project submitted
requests to this endpoint at half the per-minute per-user standard
limit, averaged over the time range.

Drive egress: Average daily Google Drive data egress in bytes
compared to the Standard Tier daily egress system limit.

Project throttles: Number of throttling errors this endpoint would
have returned based on the Standard Tier quotas and egress system
limits.

User throttles: Number of throttling errors this endpoint would
have returned based on the Standard Tier quotas and egress system
limits.

Note: After you enroll a Cloud project in either the
internal-use exception or the Scaled Tier, the Modeled impact column
is hidden.

Determine whether you need to adjust your Cloud project setup:

If all endpoints show Low impact, and this level of performance is
adequate for your needs, you don't need to change your
Cloud project setup and can remain on the Standard Tier.

If any endpoint shows Medium or High impact, your project might
experience throttling or errors. Consider reducing your app's request
rate, turning on the internal-use exception [#turn-on-internal] (for
eligible internal apps), or upgrading to the Scaled
Tier [#turn-on-scaled].

(Optional) To estimate monthly costs across one or more
Google Cloud projects, click Open the cost estimator in the Need
higher usage quotas? section.

(Optional) If you don't have a Google Cloud Billing account linked to
your Cloud project, you can create one by clicking Create billing
account.

Increase your Google Workspace API quotas

Submitting additional quota requests isn't possible on the Standard Tier. If
your Cloud project requires higher quotas, select an option in the
Increase Google Workspace quotas section at the bottom of the Dashboard tab
based on your app's use case (note that higher MCP server quotas, such as
exceeding 5,000 MCP requests per day, per project, per product, require the
Scaled Tier):

Standard Tier with internal-use exception: Google Workspace
customers can designate projects as "Internal-use exception" and request
higher per-project REST API usage quotas without switching to the Scaled
Tier (MCP server quotas aren't eligible for increases under this exception).
This exception only applies to apps that process data strictly within your
Google Workspace organization, including migrating data into
Google Workspace using a third-party service. Projects must not
share their API or MCP access directly with third-party services. Usage on
this tier doesn't produce a charge on a Google Cloud bill.

Scaled Tier: For apps, AI agents (using MCP), and services that require
higher quotas and aren't eligible for the internal-use exception. Upgrades
apply to the whole Cloud project, not on a per-API or per-MCP
basis. Starting April 1, 2027, REST API charges apply after exceeding a
daily billing threshold for a billing entity, whereas switching to the
Scaled Tier removes free MCP allowances so Gmail,
Google Calendar, and Drive MCP server requests are billed
from the first request (with some MCP tools counting as multiple requests
because they make multiple API calls).

For more information, see Usage
tiers [/workspace/guides/quota-usage-tiers#usage-tiers].

For unit rates and allowance limits, see Understand Google Workspace API and
MCP server pricing and billing tiers [/workspace/guides/quota-pricing].

Turn on the internal-use exception

The Internal-use exception card is visible and accessible only to users with
Google Workspace super
administrator [https://knowledge.workspace.google.com/admin/users/prebuilt-administrator-roles#super_admin]
privileges for the organization that owns the project.

To qualify for the internal-use exception, your Cloud project must
meet the following constraints:

Google Workspace super administrator: Only
Google Workspace super administrators can complete the attestation
and opt in to mark a Cloud project as internal.

Google Cloud organization setup: A Google Cloud organization
resource is automatically created when a Google Workspace
organization is created. For more information, see Set up a
Google Cloud organization
resource [https://docs.cloud.google.com/resource-manager/docs/creating-managing-organization].

Organization resource migration for legacy projects: If you have a
legacy Cloud project that's not organized under your
Google Workspace organization's Google Cloud resource
hierarchy (for example, a project created under "No organization"), you must
migrate the project into your Google Cloud organization before you
can use the internal-use exception. For instructions, see Migrate
projects between organization
resources [https://docs.cloud.google.com/resource-manager/docs/project-migration].

Internal OAuth audience: Your Cloud project must not contain an
OAuth client configured for an external audience. It must use an internal
OAuth audience or service accounts only.

To turn on the internal-use exception:

On the Dashboard tab, go to the Increase Google Workspace quotas
section and locate the Internal-use exception card.

Select the checkbox to confirm that this project is for internal use only
and isn't used by a third party to access Google Workspace data, and
that you agree to the Google APIs Terms of
Service [https://developers.google.com/terms], Google Workspace
user data and developer
policy [/workspace/workspace-api-user-data-developer-policy], and Workspace
AI Tools Addendum [https://workspace.google.com/terms/ai-tools].

Click Agree and turn on.

The Current tier status changes to "Standard with internal-use
exception".

Turn on the Scaled Tier

To click Turn on the Scaled Tier and enroll a Cloud project,
you must hold both of the following permissions—even if a Google Cloud
Billing account is already linked to the Cloud project:

resourcemanager.projects.createBillingAssignment on the
Cloud project (for example, Project Billing Manager or
Project Owner)

billing.resourceAssociations.create on the Google Cloud Billing
account linked to the Cloud project (for example, Billing
Account
Administrator [https://docs.cloud.google.com/billing/docs/how-to/billing-access#overview-of-cloud-billing-roles-in-cloud-iam]
or Billing Account User)

Only when both permissions exist (along with permission to view the Dashboard
tab) is the Turn on the Scaled Tier button enabled. For a full list of
permissions by action, see Required
permissions [/workspace/guides/quota-usage-tiers#permissions].

Ensure that your Cloud project is linked to a Google Cloud
Billing account that's active and in good standing—that is, the billing
account isn't closed or suspended.

On the Dashboard tab, go to the Increase Google Workspace quotas
section and locate the Scaled Tier card.

Select the checkbox to confirm that you agree to enroll in the
Google Workspace Scaled Tier, pay for usage, and accept the
Google APIs Terms of Service [https://developers.google.com/terms],
Google Workspace user data and developer
policy [/workspace/workspace-api-user-data-developer-policy], and Workspace
AI Tools Addendum [https://workspace.google.com/terms/ai-tools].

Click Turn on the Scaled Tier.

The Current tier status changes to "Scaled, billed".

Important: Switching to the Scaled Tier removes free MCP allowances (billing
Gmail, Calendar, and Drive MCP
requests from the first request starting April 1, 2027) and doesn't
automatically raise your quota limits. Once enrolled, submit a quota increase
request on the Quotas & System Limits [https://console.cloud.google.com/iam-admin/quotas] page
if your Cloud project requires higher REST API or MCP quotas.

To locate administrators and other principals within your organization who have
Google Cloud Billing account permissions, see Find a Billing Account
Administrator [https://docs.cloud.google.com/billing/docs/how-to/find-billing-account-administrator].

Switch from the internal-use exception

To return a Cloud project from the internal-use exception to the
Standard Tier, you need Google Workspace super
administrator [https://knowledge.workspace.google.com/admin/users/prebuilt-administrator-roles#super_admin]
privileges for the project's organization. You also need permission to view the
Dashboard tab, as non-administrators can't see the Internal-use exception
card or opt out. For more information, see Required
permissions [/workspace/guides/quota-usage-tiers#permissions].

To initiate the switch:

On the Dashboard tab, click Opt out on the Internal-use
exception card.

In the confirmation dialog warning that switching returns your
Cloud project to the Standard Tier and changes its quotas,
click Switch.

The Current tier status changes to "Standard".

Within 24 hours of switching, your Cloud project reverts to the
Standard Tier and enforces standard rate limits, removing any previously
approved quota overrides. If your app's use case changes to serve external
users, you can also turn on the Scaled Tier [#turn-on-scaled] directly
from the Dashboard tab.

Switch from the Scaled Tier

If your Cloud project is enrolled in the Scaled Tier and you want
to return to the Standard Tier, you must be a user with either the
resourcemanager.projects.deleteBillingAssignment permission on the project or
the billing.resourceAssociations.delete permission on the linked billing
account. For more information, see Required
permissions [/workspace/guides/quota-usage-tiers#permissions] and Enable,
disable, or change billing for a
project [https://docs.cloud.google.com/billing/docs/how-to/modify-project].

Note: You cannot turn on the internal-use exception without first opting out of
the Scaled Tier.

To initiate the switch:

On the Dashboard tab, click Opt out on the Scaled Tier
card.

In the confirmation dialog warning that opting out returns your project
quotas to the Standard Tier and might limit your API request rate,
click Switch.

The Current tier status changes to "Standard".

Within 24 hours of switching (or unlinking your Cloud project's billing
account), your Cloud project reverts to the Standard Tier, any
previously approved quota overrides are removed, and standard rate limits apply.
