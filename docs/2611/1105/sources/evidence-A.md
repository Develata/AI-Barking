## 四、可能的吠点（线索 L6，进正文前须回一手来源）

1. 官方的说法有两处对不上：Changelog 说检查“asks before”，源码 README 说 `raises no prompt`、返回 `deny`；lydia 又说 `asks you … a web tool call`，而 README 明说 WebFetch、WebSearch 不检查（A6；Changelog：2026-11-03；README：2026-11-06）。
2. 这个模块是 `a courtesy, not a boundary`（README 原句），只匹配“邮箱 + User-Agent 字样”；变量、脚本、`$(git config user.email)`、URL、请求体、`From:` 头都放行（README 列出，A4）。
3. “把邮箱从上下文里拿走”还没发：Changelog 到 2.1.318 无此条，lydia 称下周初；稳定渠道（npm dist-tag `stable`）仍是没有该模块的 2.1.311（A5）。
4. 邮箱写进提示词的目的，官方人员自己的说法是为了让模型别瞎编 `@author` 标签（lydia 原话，A3a）；#81138 作者称 `Nothing uses it`，`userEmail` 在包里只有构造处与两个遥测事件（作者反编译，自述）。
5. 模型是在被告知“不要发给无关服务”的前提下仍写入的：Changelog 2.1.234 与 #101659 都写了这句指令（E1）。
6. 要邮箱的网站是真的存在：Wikimedia 政策要求脚本在 User-Agent 里带联系信息，但可以是邮箱、网站或 wiki 用户名，不必是邮箱（A9）；SEC 写 `Please declare your user agent`，样例含邮箱形式（E4），HN 上有人称实际放行非 curl UA（L6，varenc 自己的修正）。
7. 时间线：#81138 开立到本期取数 104 天（2026-07-25 → 2026-11-06），HN 与 GH 评论说“five months ago”不准确；更早还有 #55743（2026-05-03，被机器人按不活跃关闭，E3）、#101659（2026-10-13）、Reddit 帖（2026-10-28，A8）。mpoteat 说“a few days ago … on Reddit”，与最早 Reddit 帖相隔约 8 天，2.1.317 发布（11-03）在 Reddit 帖后 6 天。
8. 垃圾邮件与此事的因果没有证据，只是自述：#107757 全文无样本、无站点名；HN b112 称用一次性地址使用数月没收到垃圾邮件（item 50385693），hk1337 称遮罩邮箱只收到 Claude 的信（item 50386299），estetlinus 称这类邮件自 2005 年起就有（item 50389030）；mk89 称改用 Claude 后收到带姓名的垃圾邮件（item 50385589，25 条后代）。均为 L6。
9. 内置 WebFetch 的默认 User-Agent 不含邮箱：HN eightysixfour 称自己看到的是 `Claude-User (claude-code/2.1.318 (cli); +https://support.anthropic.com/)`（item 50385804，L6）。#107757 的“web searches”与此对照，泄漏发生在模型自己写的 curl 类命令里（lydia 同样说是 `when Claude wrote a command itself`）。
10. 模块在部分用户机器上“已加载却没拦住”（love540、KardKuro），或 /plugins 里看不到（francescor），按 README 的测试描述应拒绝；这与“最新 main 源码 = 发布包”是否一致无法从外部核（A7，只读源码，没跑）。
11. 官方源码公开晚于发布：poteat 在 2026-11-06 07:31 北京的评论还说 `I'll try to get that built-in mod source available`，PR 07:37 北京开、08:00 北京合并（A4）。
