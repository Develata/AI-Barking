48 个 AI Agent 找玛雅金字塔：72 小时的真与假

2026年11月12日·22 阅读·约 8 分钟读完

这几天 Hacker News 上最火的一条 AI 新闻，标题是这样的：「Google SWE points 48 AI agents at NASA Lidar, finds unmapped Maya pyramid in 72h」，562 分。

标题里三个数字都很刺激：48 个 agent、NASA 的 Lidar 数据、72 小时。但如果你去读原文，会发现原文里根本没有「Google SWE points」这个东西——没有评分、没有 SWE 基准、没有任何 Google SWE 的参与。这是社区转发时加上去的说法。

而比标题更值得看的是评论区：三位不同的读者独立指出，那座「未被测绘」的金字塔，其实在一篇已经发表的论文里就被测绘过。作者没有回应这一点。这篇文章讲清三件事：他到底做了什么、哪些是真的、以及这件事对用 agent 做研究的人意味着什么。

一句话结论

真实的部分：48 个 agent 把约 1,200 平方公里的公开 Lidar 条带转成图像，逐个筛查金字塔、平台、广场，过滤掉自然山丘、天坑和道路。作者收到墨西哥 INAH 的正式回复：「该位置没有已登记的考古遗址」。从起念到收到官方回复不到 72 小时。

被夸大的部分：标题里的「Google SWE points」不存在；「未被测绘」这一点被至少三位 HN 读者用同一篇已发表论文反驳；INAH 的回复只证明「没在登记册上」，不等于「没人发现过」。

真正值得学的一课：agent 很容易产出看起来很像发现的报告，但它不会主动去检索「这东西是不是早就有人做过」。HN 上一位做过同样尝试的实践者说，agent 的典型失败模式就是「先给结论，再在你逼它做文献检索时改口说 prior art 降低了新颖性」。

成本口径完全不同：这次没有花一分钱雇测绘队，用的是公开数据和通用模型。它不是「便宜版考古」，而是「外行用 agent 做了一次文献与影像的交叉筛查」。

1）72 小时时间线：从秘鲁的一次闲聊到 INAH 的回复

作者把整个过程写成了日记，时间线是全文最有意思的部分：

10 月 18 日：他在秘鲁旅行，用 Gemini 聊当地历史，了解到 Hiram Bingham「发现」马丘比丘的故事，起了念头。

10 月 19 日：早上起来看 agent 的报告，发现它们标出了一批「村子」和规整的方形结构。

10 月 20 日：他把报告改了几处（他承认「有几处是不对的」），翻译成西班牙语以提高回复概率，并把原始点云又查了一遍，确认那些形状在地面上、不是树造出来的。他不懂西班牙语，这一步只能信 agent。

10 月 21 日：INAH 回复——查了记录，该位置没有已登记的考古遗址。

技术方法本身很朴素，甚至有点「笨」：把 Lidar 条带转成图片，48 个 agent 挨个看，照着详细指南找金字塔、平台和广场。作者明确说「没有用任何特殊模型或分类器」——就是让模型肉眼审图。之后 agent 还去查了文献和档案，得出「有一个主要遗址似乎没有登记」的结论。

用到的模型：Gemini、ChatGPT、Claude、Grok 都出现在头脑风暴里，Gemini 还生成了那张示意图。原文没有提到任何 agent 编排框架。

示意：Lidar 的价值在于「把树剥掉」看地面。这次的关键素材是公开数据，不是新采集。

2）三个必须说清楚的边界

这篇文章之所以容易被误读，是因为它把三件不同的事混在一句话里：找到了形状、查了档案、拿到官方回复。三者强度完全不同。

第一，没有被实地验证。作者原话：「免责声明：我不是考古学家。」INAH 的回复只是查了登记册的记录，没有任何考古学家到过现场或独立确认。他自己也强调「这还不算官方认定」，并主动提出愿意配合 INAH 的实地核查——而在墨西哥，实地考察需要官方授权。

第二，解读部分是明确的推测。他把这座遗址解释为古典期（约公元 250–900 年）的市政中心，塔高估测 8–12 米，Lidar 回波来自 10–17 米深的林冠之下，3D 图的高度夸张了约 1.5 倍。关于神庙、统治者居所、水库和周边房屋的判断，他直接标注为 speculation——那个可能是水库的东西，「也可能只是个坑」。

第三，「不在登记册上」不等于「没人发现过」。这是最容易被推翻的一环，也是评论区真正吵起来的地方。

3）HN 上的反驳：AI Agent 的发现，论文里已经测绘过了

评论区有不止一位读者给出同一篇 ScienceDirect 上的已发表论文，说那座金字塔在论文第 13–14 页就有结构图，「你在图上就能看出是同一批结构」。还有人补了一句更尖锐的观察：那篇论文很可能本来就在模型的训练集里，agent 随时都能读到它。

这里要说明：我核对的是这些评论本身（可公开查验），以及原文作者的表述。原文里从来没有出现「prior art」这个词，他只写了「据所有人所知，之前没人把这座画到地图上」和「这不是官方认定」。两件事都对——但这恰恰是问题所在：「没人画到地图上」和「没人发现过」是两个命题，前者成立推不出后者。

最值得抄下来的是另一条评论。一位在计算物理问题上用过持久 agent 的实践者说，他的经历高度类似：

它（agent）能找到惊人的结果，真的让我吃惊，还能写出一份报告说服我这是真发现——直到我让它做文献检索、要求它一丝不苟。然后它回来告诉我「prior art 降低了这个发现的新颖性」，并且很轻松、很聪明地找到了解释这些发现的论文。

他还总结了一个更普遍的模式：agent 总是、反复地基于「它读过的约 80% 的现有研究」来断言新颖性。这在任何研究领域都是最危险的失败模式——因为剩下那 20% 恰恰是最难找、也最可能已经有人做过的部分。

示意：这次真正的工作量在「逐个审图 + 查文献 + 写报告」，而最容易漏掉的一步恰恰是「这东西是不是早有论文」。

4）但它仍然是一次有意义的能力演示

把批评说完，也要说清它对的地方。即使去掉「未被发现」这个标签，这件事仍然成立：

规模：1,200 平方公里、48 个 agent 逐个审图，这在人工成本上是不可能由一个人完成的。

方法正确：他没有直接相信 agent 的结论，而是回到原始点云去验证「形状在地面上还是树造成的」——这一步是整件事里最专业的一步。

流程完整：查文献、查档案、写报告、翻译、找到对口机构并发出、拿到回复。这条链路本身就是过去需要一个团队才能跑通的东西。

成本结构变了：作者考虑过雇一支测绘队，最后判断成本太高。他拿来跑的是公开数据加通用模型，没有付任何额外采集费用——原文没有给出具体的模型花销数字。

评论区里有一句话把这件事的分寸讲得很准：「你确实可以直接去做事，但也要把兴奋收一收。agent 很厉害，但最后那 10% 仍然很难，而且大多数事情需要领域专家。」

还有一条历史视角的评论值得提：有人做过英国（英格兰与威尔士）第一个在线 Lidar 地图，用它能找到许多此前未知的考古遗址。也就是说，「用公开 Lidar 找遗址」这条路本身不是新东西，AI 加进来改变的是「谁有时间逐个看」。

5）如果你要用 agent 做这类工作，该改什么

这件事对写代码的人没有直接关系，但对任何想用 agent 做「发现型」任务的人，它给出了一套很具体的检查清单：

把「查重」当成独立任务，而不是附属步骤。别让同一个 agent 在给出结论之后再顺手查一下——它已经有动机维护自己的结论。单独开一个 agent，任务是「找出反对这个结论的已发表工作」。

要求它引用具体页码。HN 上有人指出，连「论文在哪一页有结构图」都说不清楚的检索，等于没检索。

区分「没有记录」和「不存在」。INAH 说「登记册里没有」，这句话的信息量只到登记册为止。官方记录、公开论文、民间档案是三套独立的东西，缺一套不等于三套都缺。

原始数据要亲自回查。这次作者回查点云这一步，是整个流程里唯一一处主动对抗「模型幻觉」的动作，也是它值得被认真对待的原因。

别把「外行身份」当成优势来宣传。作者写过「天真的外行现在可能是一种超能力」，评论区对此分歧很大。能力是真的，但缺少领域知识恰恰是漏掉 prior art 的原因之一。

小结

这件事有两层价值，别混在一起。作为工程演示，它成立：48 个 agent、1,200 平方公里的公开 Lidar、72 小时内跑完从筛查到官方问询的全链路，这条链路以前一个人做不完。

作为科学发现，它已经被削弱了：标题里的「Google SWE points」根本不存在于原文，而「未被测绘」这一点至少被三位读者用已发表论文反驳。

最该带走的一句，是那位计算物理实践者的经验：agent 会先给你一个让你兴奋的结论，然后在你逼它认真做文献检索时，才发现它一直在用「读过的 80% 研究」来断言新颖性。想用 agent 做研究，第一件要设计的事不是「怎么让它找到更多」，而是「怎么让它诚实地告诉你，这东西早就有人做过」。
