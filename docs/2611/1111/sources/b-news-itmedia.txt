Amazon、AWSのAPIを手元で再現する「AWS Emulator」を無償公開　コードはすべてAIエージェントが記述

 公開
 2026年11月12日 09時56分

[ITmedia]

 印刷する [https://id.itmedia.co.jp/isentry/contents?sc=8c6c42f379f08f03b79653a3230abd5e8079999435030fd8ca703ae35fe9b37a&lc=025ca19d7b07d7f554fd7cd060b628e628d0f607afa3a6fde17c4488f35716d2&return_url=https://www.itmedia.co.jp/news/member/2611/12/2000003126/print&encoding=utf-8&ac=e8cb9106baa7e37eb9feb877b9f0a27ddaf48b95ba02da49cbb3a8247ee7fec4&cr=e9fd42802bc22856808963077023568339063544b05e5a8646e62c02a898e0fd]

Googleで優先するソースとして追加
 [https://www.google.com/preferences/source?q=https://www.itmedia.co.jp] 

　米Amazon傘下のAmazon Web Services（AWS）は11月11日（現地時間）、AWSのAPIを手元のPCなどで再現するツール「AWS Emulator」を公開した。開発者はクラウドのリソースを用意しなくても、AWSを使うアプリをローカル環境で構築したりテストしたりできる。AWSアカウントは不要で、追加料金も発生しない。AWSによると、すべてのコードは自律型AIエージェントが記述したという。

 [https://www.itmedia.co.jp/news/article/limage/2611/12/2000003126/10011939]

　AWS Emulatorは、AWS APIのエンドポイントとして動くローカルのプログラムで、GUIはない。AWS CLIやAWS SDKの接続先を環境変数でエミュレータに指定すれば、コードを書き換えずに使える。AWSのAPIモデル438件を基に作られ、数百のサービスのインタフェースに対応する。ただし、どこまで実装できているかはサービスや操作によって異なる。AWSとどれだけ同じように動くかを示す“忠実度”のスコアはリリースごとにGitHubで公開しており、検証に使うテスト群も別のリポジトリ「aws-emulator-evaluation-suite」で公開した。

　想定する用途は、ローカルでのテストや、AWSアカウントもリソースも使わずにCI/CDパイプラインで統合テストを回すこと、AIコーディングエージェントを使ったAWS向けアプリの試作など。AIコーディングエージェント向けには、エミュレータのインストールから起動、接続までを担う「aws-emulator」スキルも用意した。

　Linuxでは、x86_64版とaarch64版のRPMパッケージまたはDebianパッケージからインストールする。macOSとWindowsでは、プロジェクトのDockerfileでイメージをビルドしてDockerで動かす。ソースコードはGitHub [https://github.com/aws/aws-emulator]でCC0ライセンスで公開している。

 [https://www.itmedia.co.jp/news/article/limage/2611/12/2000003126/10011940]
修正をまとめて再検証し、すべてのチェックを通ったコードだけをリリースする。配布用のバイナリを作り、GitHubでも公開する（画像：AWS）

　本番環境で使うことは想定していない。IAMポリシーやリソースベースのポリシーはAWSと同じようには評価されないので、セキュリティのテストには使わないよう呼び掛けている。リソースはすべてメモリ上に置かれ、エミュレータを止めると消える。

　開発を率いたAWSのシニアプリンシパルエンジニア、マシュー・ゴールドバーグ氏によると、AWS Emulatorは週末の実験として始まった。きっかけは、米Anthropicの研究者が今年、AIエージェントだけでCコンパイラを作ってみせた [https://www.anthropic.com/research/building-c-compiler]ことだったという。同氏はAWSのAI開発環境「Kiro」 [https://www.itmedia.co.jp/news/article/2507/16/1250716110/]に、AWS CLIを基にテストを書く、実際のAWS環境で成功するまでテストを修正する、そのテストにパスするインメモリ実装を作成する、という3段階の作業を指示した。最初の「Amazon SQS」は約15分で完成したという。

　現在は、APIモデルからテストを作って実際のAWSで検証するチーム、そのテストをエミュレータで実行して不具合を報告するチーム、報告された不具合を直すチームという3種類のエージェントチームが並行して開発している。数百のエージェントが同時に動き、1日に数千件の問題を修正しているという。人間の開発チームはコードを一切書いておらず、レビューもしていない。エミュレータは1日に何度も更新されている。

 [https://www.itmedia.co.jp/news/article/limage/2611/12/2000003126/10011941]
AWS Emulatorを開発する3つのエージェントチーム。テストの作成、不具合の発見、修正を分担する（画像：AWS）
