我们正式推出 GPT‑6.2 Astra 和 GPT‑6.2 Sol：前者是应对最棘手项目的全新前沿模型，后者则是面向日常工作的高效多面手。两款模型都能以更少的输出 Token，在高难度任务中取得更好的结果，让你在用量限制内完成更多工作。对企业和开发者而言，这意味着能以适合大规模应用的成本，获得前沿性能。

GPT‑6.2 Astra 为 AI 处理复杂专业工作的质量树立了新标杆。它生成的幻灯片、电子表格和文档更少带有 AI 写作痕迹，也更贴合你提供的模板和所在领域的惯例。它编写的代码更简洁，构建的前端在视觉和功能上都更出色，尤其适用于网站、游戏和 3D 设计。

在测试多步骤专业工作的 Agents’ Last Exam 中，GPT‑6.2 Astra 创下新高：得分比 GPT‑6 Astra 高 5.2 分，成本却不到其三分之一；比 Claude Fable 5.2 高 5.5 分，成本仅为其 5%。

Agents’ Last Exam 评估模型处理长程专业工作流的能力。排行榜中 Fable 5.2 的结果不包含使用了备用模型的九项任务。

我们认为，GPT-6.2 Astra 是全球最适合科学家使用的模型。它在 Terminal-Bench-Science 0.1 上创下新高，该基准测试评估模型在终端中开展科学工作的能力。GPT-6.2 Astra 的得分比 GPT-6 Astra 高 9 个百分点，成本却不到其三分之一。它还在 Vals Science Index 上创下新高，该评估要求模型解读真实生物数据，并通过实验推断模拟系统的运行方式。

GPT-6.2 Sol：我们日常工作的首选模型

相比 GPT‑6.1 Sol，GPT‑6.2 Sol 更智能、更高效，让你在同一付费套餐下完成更多任务。它能高效完成多步骤智能体工作流，文笔清晰自然，协作起来也得心应手。OpenAI 的许多员工都将它作为处理技术和非技术任务的默认模型。

在 Cognition 的 FrontierCode 2.0 中，GPT‑6.2 Sol 与 GPT‑6.2 Astra 的得分相差不到 0.5 分，成本约为其五分之一（两者均设为 Max）。

FrontierCode 2.0 评估对真实代码库的修改是否符合维护者的合并标准。

凭借速度和智能表现，它也非常适合处理工作之外人们寻求 AI 帮助的重要事务。在我们最近发布、用于衡量高难度日常任务表现的 LifeVal⁠ [https://openai.com/index/lifeval/] 评估中，GPT‑6.2 Sol 的得分高于 GPT‑6 Astra，成本约为其七分之一。

LifeVal 测试模型根据个人需求处理日常任务的能力，例如搬家后筛选幼儿园、寻找符合家庭预算和通勤需求的住房，或为刚被诊断出疾病、正在适应的父母规划膳食。

符合行业标准的专业成果

我们训练 GPT‑6.2 Astra，使其能够制作更清晰、设计更精良的幻灯片、电子表格和文档，更贴合法律、销售、金融和会计等领域专业人士的工作惯例。它的文字更直接、更具体，泛泛而谈的结论和冗余内容更少。

Harvey LAB‑AA v1.1 通过法律任务，测试模型能否从源文档中找到相关事实，按照详细的任务要求加以运用，并生成准确且满足所有要求的交付成果。GPT‑6.2 Astra 创下了新的最佳水平，通过率超过 Claude Fable 5.2 的两倍，成本约为其六分之一。我们面向律师定制的 GPT-6.2 Astra 配置——OpenAI 法律解决方案⁠ [https://openai.com/index/astra-law-6-2]——在这一基准测试中的得分更高。

Harvey LAB‑AA 测试合同条款审查等法律工作。其主要评分指标仅在交付成果满足全部评分标准且不含实质性幻觉时才予以计分。

我们的内部基准测试 GDPval v2 是 GDPval⁠ [https://openai.com/index/gdpval/] 的新一代版本，用于评估咨询、金融和设计等领域真实项目中复杂、长流程的工作流。GPT‑6.2 Astra 在我们测试的模型中表现领先，得分比 GPT‑6 Astra 高出 6.2 个百分点，同时输出 Token 用量减少了 22%。GPT‑6.2 Sol 的得分比 GPT‑6.1 Sol 提高了 5.3 分。

GDPval v2 包含来自金融、数据科学、生物技术和市场营销等领域真实项目的长流程知识工作任务。

网络安全能力

GPT‑6.2 Astra 和 GPT-6.2 Sol 的网络安全能力再次实现显著跃升。它们能更有效地发现和利用漏洞，编写更安全的代码，生成更好的补丁，并在多项评估中大幅提升 Token 使用效率。与 GPT‑6 Astra⁠ [https://openai.com/index/gpt-6-astra/] 一样，6.2 Astra 和 Sol 均达到我们准备框架⁠ [https://openai.com/index/updating-our-preparedness-framework/]中网络安全能力的“严重”级别阈值。

鉴于 GPT‑6.2 Astra 和 Sol 的能力有所提升，我们在推出这两个模型时，针对风险较高的网络安全辅助任务采取了更严格的安全防护措施。这些防护措施降低了滥用风险，但也限制了部分合法的漏洞研究和安全测试工作流。目前，通过 OpenAI Daybreak⁠ [https://openai.com/daybreak/]，网络防御人员除了可以使用 GPT-6 Astra 的 Alpha 版本，还可以在 Daybreak Blue 上使用对网络安全请求拒绝更少的 GPT‑6 Sol，并在 Daybreak Red 上使用 GPT‑6 Cyber⁠ [https://openai.com/index/introducing-gpt-6-cyber/] 进行高级、经授权的安全测试。我们将努力把 GPT‑6.2 模型引入 Daybreak。

下面重点展示关键基准测试结果，测试采用内部配置，并关闭了网络安全防护措施和分类器。完整结果和方法详见配套系统卡⁠（在新窗口中打开） [https://deploymentsafety.openai.com/gpt-6-2-astra-sol]。

安全与对齐

我们采用迄今最强的安全防护措施来部署 GPT-6.2 Astra 和 Sol。我们收紧了限制，并强化了用于监测模型⁠ [https://openai.com/index/how-we-detect-frontier-model-misalignment/]和在必要时进行干预⁠ [https://openai.com/index/control-room/]的系统。

与 GPT-6 Astra 一样，GPT-6.2 Astra 和 Sol 除了达到网络安全能力的“严重”级别阈值，也都达到我们准备框架⁠ [https://openai.com/index/updating-our-preparedness-framework/]中生物和化学能力的“高”级别阈值。我们已实施防护措施来缓解相关风险，并加强了对一系列潜在两用性生物和网络安全请求的限制。

关于安全防护措施和测试的更多详情，请参阅 GPT-6.2 系统卡⁠（在新窗口中打开） [https://deploymentsafety.openai.com/gpt-6-2-astra-sol]。

AI 研究能力与安全防护措施

GPT-6.2 Astra 是我们首个对外发布、达到“AI 自我改进”高阈值的模型，该指标衡量模型加速 AI 研究的能力。“高”级别代表我们的评估认为：相较于 2024 年的基线，该模型带来的影响相当于为每位 OpenAI 研究人员额外配备一名能力出色的研究工程师作为助手。我们跟踪这项能力，是因为能够帮助开发未来 AI 系统的模型也可能引入新的安全风险，例如推动进展的速度快于安全防护措施或人类监督的适应速度。

为应对这些风险，我们在模型训练和部署流程中加入了更多监督与控制措施。在扩大 GPT-6.2 Astra 的内部访问范围之前，我们评估了其对齐情况，并确认各个阶段所需的安全防护措施均已到位。我们加强了研究环境中的隔离防护⁠ [https://openai.com/index/securing-our-frontier-model-training-environment/]，并使用能力最强的模型测试这些措施。我们还构建了 Control Room⁠ [https://openai.com/index/control-room/]，该系统可跟踪研究工作负载，并在需要干预时阻止模型继续输出。我们扩展后的监测机制⁠ [https://openai.com/index/how-we-detect-frontier-model-misalignment/]会检查模型在内部工作负载和受支持的外部部署中的推理与行动。它可以自动标记未经授权的行为，并在支持的情况下暂停工作负载或对话。

对齐

两款模型在大多数对齐评估中的表现与 GPT-6 Astra 相近，并在模拟职场任务中采取了更少的不当行动。不过，在两项测试中，它们更容易漏报阻碍工作的问题，例如文件缺失或搜索工具不可用。我们在 Codex 中添加了指令，大幅减少了此类遗漏，并将继续研究这一行为。

定价与可用性

即日起，所有 Plus、Pro、Enterprise 和 Edu 用户都可在 ChatGPT 工作和 Codex 中使用 GPT-6.2 Astra 和 Sol。Pro 500 订阅用户可为这两款模型启用超高速模式。我们还首次向 Pro 200 订阅用户开放超高速模式，率先支持 GPT-6.2 Sol。符合条件的 Enterprise 和 Edu 用户，在工作空间管理员启用后，也可获得相同访问权限。开发者也可通过 OpenAI API 使用 gpt-6.2-astra 和 gpt-6.2-sol，两款模型在发布时均支持超高速模式。

得益于更高的 Token 使用效率、输入和输出 Token 价格降低 20%，以及缓存输入 Token 价格进一步降低 60%，GPT‑6.2 Astra 的单项任务成本显著低于 GPT‑6 Astra。标准 API 定价按每百万 Token 计：输入 8 美元，缓存输入 0.40 美元，输出 40 美元。GPT‑6.2 Sol 沿用 GPT‑6.1 Sol 的定价，每百万 Token 的输入价格为 2 美元，缓存输入为 0.10 美元，输出为 10 美元。

使用 GPT-6.2 Astra 和 Sol 时，为提高缓存复用率、帮助降低成本和延迟，并跨轮次保留推理，我们建议保持提示词前缀不变，并在对话中追加新指令⁠（在新窗口中打开） [https://developers.openai.com/api/docs/guides/preserved-reasoning]。
