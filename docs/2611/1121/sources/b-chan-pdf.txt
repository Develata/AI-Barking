                                                                                                Abstract
                                                   Recently, a truly subquadratic algorithm for the 3SUM problem and a truly subcubic algorithm for the
                                               all-pairs shortest paths (APSP) problem were found by Anthropic, as reported by Alman and Vassilevska
                                               Williams (2026). These algorithms relied on a new subroutine for rectangular matrix multiplication with
                                               selected output entries, which was obtained by modifying known matrix multiplication techniques of
                                               Schönhage (1981) and Coppersmith (1982).
                                                  1. We present a different truly subquadratic randomized algorithm for 3SUM for integer inputs. It
                                                     completely avoids the use of matrix multiplication but instead modifies known dynamic program-
                                                     ming algorithms for subset convolution and the zeta transform, which rely only on simple subtrac-
                                                     tion tricks via inclusion–exclusion (and does not even require fast Fourier transform), and so is
                                                     conceptually easier to understand (the whole solution is about 5 pages long).
                                                  2. Following a similar approach, we obtain a randomized algorithm for k-SUM for integer inputs for
                                                     odd constant k in O(n⌈k/2⌉−εk ) time for some constant εk > 0, disproving the k-SUM Hypothesis
                                                     for all odd k.
                                                  3. Existing reductions from 3SUM and APSP to selected-entries rectangular matrix multiplication
                                                     were randomized in the case of real-valued input. We present new deterministic reductions, yield-
                                                     ing a truly subquadratic deterministic algorithm for Real 3SUM and a truly subcubic deterministic
                                                     algorithm for Real APSP.

                                         Recently, Anthropic found the first truly subcubic algorithm for the all-pairs shortest paths (APSP) problem
                                         and the first truly subquadratic algorithm for the 3SUM problem, as announced and presented by Alman
                                         and Vassilevska Williams [AW26]. The key to the breakthrough lies in a faster algorithm for the following

     The new subroutine was obtained by modifying known matrix multiplication techniques of Schön-
hage [Sch81] and Coppersmith [Cop82] to achieve output-sensitivity. This is surprising, since matrix mul-
tiplication is usually used as a black box in algorithmic applications, and there were not many successful
prior examples when modifying matrix multiplication algorithms helped.
     Once this matrix problem has been solved, faster algorithms for both APSP and 3SUM—and, more
strongly, the Exact Triangle problem—follow more or less immediately, by using or adapting existing re-
ductions from APSP/3SUM/Exact Triangle to AE Sparse Triangle [Păt10, KPP16, VX20, CVX22, CX24,
FKP24]. There are multiple options, and some of these reductions already hold in the lopsided setting. In
the integer input case, deterministic reductions were known [CX24, FKP24]; however, in the real case, only
randomized reductions were known [CVX22]. (See also [SY26] for a more recent reduction from APSP to
selected-entries matrix multiplication in the integer case.)
     Several improvements have been found just days after the initial announcement of the breakthrough2
but in this new era, conceptual understanding and better exposition are perhaps more important than small
incremental improvements. In this manuscript, we address two themes: 1. simplifying these algorithms, to
make the ideas more broadly accessible, and 2. derandomizing the algorithms in the real input case.

3SUM simplified. Shortly after the announcement of the breakthrough, Karingula and Lovett [KL26]
have already presented a simplification (found with the help of swarms of agents) of the main subroutine for
selected-entries rectangular matrix multiplication (with slightly worse exponents). The original explanation
of the subroutine [AW26], requiring about 18 pages, has now been cut down to 7 pages (not counting the
remaining reduction from 3SUM/APSP to lopsided AE Sparse Triangle, which would require at least 2 more
pages).
    While the usage of matrix multiplication tools for APSP is inevitable as APSP is equivalent to
(min, +)-matrix multiplication, an interesting question is whether further simplifications are possible for
3SUM (to the general public, 3SUM seems to attract even more attention than APSP). Our intuition is
this: 3SUM and the easier (min, +)-convolution problem are about sequences of numbers, whereas Ex-
act Triangle and (min, +)-matrix multiplication are their matrix counterparts (see Figure 1). Sequence
problems are more often solved using convolutions or fast Fourier transform (FFT) instead of matrix
multiplication. For example, known algorithms for the bounded monotone (min, +)-convolution prob-
lem [CL15, CDXZ22] mostly used FFT, whereas known algorithms for bounded monotone (min, +)-matrix
multiplication [BGSV19, CDXZ22] used fast matrix multiplication.
    A natural thought is to try to modify existing algorithms for standard convolution such as FFT, Karat-
suba’s, and Toom and Cook’s, which if doable might be easier than modifying matrix multiplication algo-
rithms such as Schönhage’s and Coppersmith’s, to those who are not experts in matrix multiplication ma-
chineries. Even if possible, it still seems to require effort to achieve output-sensitivity: for all these recursive
algorithms, it is nontrivial to analyze which nodes of the recursion tree are necessary for the selected output
entries (see all the figures needed in the descriptions by both Alman and Vassilevska Williams [AW26] and
Karingula and Lovett [KL26]).

    We find a simpler way to obtain a truly subquadratic, Monte-Carlo randomized algorithm for 3SUM for
polynomially bounded integer inputs. The key idea is to switch to a different but related problem, subset
convolution (see Problem 2.1). Standard algorithms for subset convolution are based on the so-called zeta
(or Möbius) transform, which is solved by simple dynamic programming (DP), using just subtraction or
inclusion–exclusion tricks, and are simpler than FFT. Adapting these subset convolution algorithms to the
selected-entries setting turns out to be easy, due to the simple DAG or lattice structure of the DP (no messy
analysis of dependency patterns of “input encoding/preparation” and “output decoding/reconstruction” in
recursion trees [AW26, KL26]). In fact, this observation was noted explicitly before by Björklund, Husfeldt,
Kaski, and Koivisto [BHKK10] (for a different application, concerning exponential-time algorithms for
certain problems in bounded-degree graphs).3 For completeness, we include a description of the selected-
entries subset convolution algorithm in Section 2.1, which takes just one and a half page. We believe this is
the simplest way to introduce to a broader audience the possibility of output-sensitivity for selected-entries
versions of algebraic problems.4
    While this greatly simplifies the algebraic part of the solution, a bit more work is now required in the
remaining part, to reduce 3SUM to subset convolution, since subset convolution is farther away from 3SUM
than standard convolution. Nevertheless, this part is in more familiar territory to algorithm designers in fine-
grained complexity, and indeed can be solved in under 3 pages using hashing techniques (see Section 2.2).
Hashing is commonly used in prior work about convolutions and 3SUM-related reductions (e.g., see [CH02,
BDP08, Păt10, CH20, BFN21, BFN22]), but this reduction requires some nontrivial technical ideas, and
does not seem to follow directly from any existing work.5
    The solution here raises some new interesting questions concerning whether the 3SUM algorithm here
might be considered combinatorial, and more generally what is the meaning of “combinatorial algorithms”.
See Section 2.3 for discussion. (Spoiler: we, the authors, do not have a definitive answer, and will leave the
question to the readers to decide for themselves.)
    By known simple reductions [CMWW19], we also immediately obtain a simpler truly subquadratic
randomized algorithm for (min, +)-convolution for polynomially bounded integer inputs, which in turn has
many applications, e.g., see [CMWW19, KPS17, BN21, Bri24, Jin24].

k-SUM Hypothesis refuted for all odd k. As an unintended byproduct of this simpler approach, we ob-
tain an O(n⌈k/2⌉−εk )-time randomized algorithm for the k-SUM problem for polynomially bounded integer
inputs, for every odd constant k ≥ 5, for some constant εk > 0. This thus refutes the k-SUM Hypothe-
sis for all odd k (at least for the integer setting, with randomization); see [Eri99, AL13, ABBK17, KN22]
for conditional lower bounds based on this hypothesis. Alman and Vassilevska Williams [AW26] explicitly
listed the k-SUM Hypothesis for larger k as one of the remaining open questions, as their approach based on
selected-entries rectangular matrix multiplication does not seem to generalize. This demonstrates another
advantage of working with convolution-based approaches instead of matrix multiplication.
     As is easy to see, k-SUM for odd k reduces to an unbalanced instance of 3SUM, where the first set
has n⌊k/2⌋ elements, the second set has n elements, and the third (“query”) set has n⌊k/2⌋ elements. As the
number of queries is large, we need to refine the 3SUM algorithm to achieve lower cost per query. To this
end, the extra idea is to use convolution where elements are vectors in [r]d instead of subsets (bit vectors),
for a larger constant base r. This extended problem with selected entries can still be solved by adapting
standard algorithms for subset convolution. The remaining hashing part proceeds similar to before, and the
analysis is only slightly more involved. (See Section 3.)

Real 3SUM and APSP derandomized. In the second half of the paper (Sections 4–5, which can be
read independently of Sections 2–3), we turn to the question of derandomization in the real input case
(the recent algorithms in the integer input case are already deterministic). The subroutine for selected-
entries rectangular matrix multiplication or lopsided AE Sparse Triangle was already deterministic [AW26].
The issue lies in the reduction of APSP/3SUM to AE Sparse Triangle. In the real case, the only known
reduction was the one by Chan, Vassilevska Williams, and Xu [CVX22], which crucially relied on random
sampling. (Fischer, Polak, and Schmidt [FPS26] recently gave a reduction from Real 3SUM to Integer
3SUM, but it was complicated and also used randomization.) In contrast, the previous best slightly subcubic
real APSP algorithm [Wil18] before the recent breakthrough was successfully derandomized [CW21], while
the previous best slightly subquadratic real 3SUM algorithm [Cha20] was already deterministic.
    We describe deterministic reductions from both Real 3SUM and Real APSP to #AE Sparse Triangle.
The new reductions build on Chan, Vassilevska Williams, and Xu’s approach [CVX22]; the main new
idea is clever but simple, especially for Real APSP (the details are a bit trickier for Real 3SUM). These
deterministic reductions lead to the first truly subquadratic and subcubic-time deterministic algorithms for
Real 3SUM and Real APSP respectively.

2.2    Reducing 3SUM to Subset Convolution
Now we solve integer 3SUM using the new subroutine for selected-entries subset convolution. This uses
hashing techniques. We first apply linear hashing (taking “mod p” for a prime p) to reduce the size of
the input numbers and then view the numbers as bit vectors using their binary representations, which then
correspond to subsets of indices. If the subsets corresponding to two numbers happen to be disjoint, then
their union corresponds precisely to the sum, and so subset convolution gives us exactly what we want!
However, usually we do not have disjointness. The idea is to further randomly scramble the input numbers
(using a family of linear hash functions that achieve 3-wise independence), and with enough repetitions, the
disjointness property can be shown to hold in at least one of the trials with good probability.
     The final algorithm for the reduction is still relatively simple, but the analysis requires some technical
effort. One issue is collision of the hash of sums of pairs (which is why hashing alone does not solve integer
3SUM very efficiently in prior work, except in shaving logs [BDP08]), but in our case, subset convolution
filters out pairs that do not satisfy the disjointness property, and this helps to bound the target universe size p.
The precise details are given below (we state the result more generally when the input sets A and B may not

2.3     Discussion
The algorithm here raises some interesting philosophical questions:

Could the breakthrough have been found earlier? To some researchers, the solution reported by Alman
and Vassilevska Williams [AW26] felt like something that humans could have eventually discovered, or
could have been discovered earlier had we been luckier. It might be that not many researchers in fine-
grained complexity are comfortable enough to open up the matrix multiplication black box to seriously try
solving the selected-entries matrix multiplication problem faster. The approach here completely lowers the
barrier of entry on the algebraic side (subset convolution is only about inclusion–exclusion formulas), so
in hindsight, there is even less excuse for researchers to have missed the breakthrough! Experts in subset
convolution [BHKK10] already knew the idea in Section 2.1, while experts in hashing might be able to
figure out the details in Section 2.2 on their own, with some effort. However, without the more complicated
solution in [AW26], we would not have seriously attacked the 3SUM problem via selected-entries subset
convolution in the first place.

Is the 3SUM algorithm here combinatorial? The answer to this question is subjective, as there is no
formal definition of “combinatorial algorithms”.
      • If “combinatorial” means avoiding fast matrix multiplication but allowing FFT, the answer is yes.
        The motivation for this informal definition is that fast matrix multiplication algorithms are not very
        practical, but FFT is.
      • If “combinatorial” means avoiding both fast matrix multiplication and FFT, the answer is still yes.
        We use the fast zeta transform, which is just dynamic programming with inclusion–exclusion for-
        mulas. Zeta transforms and inclusion–exclusion have been used before not just in exponential-time
        algorithms (e.g., [Kar82, BHKK07, BHK09]) but also for some counting problems in fine-grained
        complexity (e.g., [VW13]). In algorithm design, we often use subtraction tricks without referring
        to them as non-combinatorial. (In fact, the word “combinatorial” literally refers to counting, and
        inclusion–exclusion is a standard trick in combinatorics.) However, one could debate why we allow
        inclusion–exclusion but not, say, Strassen’s matrix multiplication algorithm (or even Schönhage’s),
        which is also based on “just” subtractions and clever cancellations.
      • If “combinatorial” means avoiding completely all algebraic techniques, the answer is no. However,
        one could say that hashing techniques, commonly used in algorithm design (including the reduction
        in Section 2.2), are also algebraic. Then many algorithms that were considered combinatorial before
        might not be. It is not clear where one would draw the line. . .
    If the algorithm here were considered to be combinatorial, then this would also imply a new combi-
natorial, truly subquadratic algorithm for Boolean convolution of two n-bit vectors, since the latter is a
special case of All-Numbers 3SUM; but this algorithm would be more complicated (and slower) than, say,
Karatsuba’s algorithm.
    If the ultimate goal is just to exclude non-practical algorithms, then the current consensus of combi-
natorial algorithms does not seem too appropriate: some of the known “combinatorial” algorithms such
as [AFK+ 24] for Boolean matrix multiplication are far more complicated and probably less practical than
Strassen’s, for example, and some of the known algorithms for shaving logs [Cha15, Yu18] have large hid-
den constant factors and would not be competitive in practice. The 3SUM algorithm here in its present form
may not be too practical either.

                                                      10
    If the defining characteristic of combinatorial matrix multiplication algorithms is generalizability to
(min, +)-matrix multiplication (which would successfully exclude Strassen’s but include some log-shaving
algorithms [Cha19]), then the recent breakthrough on APSP/(min, +)-matrix multiplication has turned the
question upside-down.
    Here is another alternative, informal, and imprecise way to characterize combinatorial algorithms: in-
termediate values maintained by the algorithm should be describable “naturally”. For example, Strassen’s
matrix multiplication algorithm and Karatsuba’s convolution algorithm do not seem to fulfill this require-
ment, since intermediate values arising during recursion seem “magical” and do not have clear “meanings”.
On the other hand, the 3SUM algorithm here arguably satisfies this criterion: the intermediate values main-
tained by the DP are the zeta transforms and the covering products of subsets, which have relatively simple
definitions.


3     More on 3SUM, and k-SUM for Odd k
The 3SUM algorithm in the previous section has query cost O(n0.965 ), which cannot be lowered to below
n2/3 even if we allow larger preprocessing. In this section, we describe a variant of the algorithm, which
can make the query cost an arbitrarily small polynomial, while still supporting the unbalanced case when
the sets A and B have different sizes. As a consequence, this leads to a faster algorithm for k-SUM for any
constant odd k for integer input.

3.1   Selected-Entries Convolution in [r]d for Small r
The main additional idea is to use a larger base r > 2. This requires a generalization of the subset con-
volution problem where elements are vectors in [r]d . The r = 2 or bit-vector case corresponds precisely
to subset convolution. This is essentially standard d-dimensional convolution with coordinate values in [r],
which is known to be reducible to standard one-dimensional convolution over [O(r)d ] when d is a constant
and r is a variable. However, we need the opposite regime when r is a constant and d is a variable, and we
need the version with selected entries.

4    Real APSP Derandomized
In this section, we present a truly subcubic-time deterministic algorithm for APSP for real input.
    It is well known (by repeated squaring) that the real APSP problem reduces to computing the (min, +)-
product of two n × n real matrices, which in turn reduces to n/d instances of (min, +)-product of n × d
and d × n matrices:
Problem 4.1 (Rectangular (min, +) matrix multiplication). Given an n × d real matrix A and a d × n
matrix B, compute C[i, j] = mink∈[d] (A[i, k] + B[k, j]) for each i, j ∈ [n].
    For simplicity of presentation, we assume that there are no degeneracies (no two pairs of input numbers
have equal sum); degenerate cases can be addressed by perturbation or by straightforward modifications.
    Chan, Vassilevska Williams, and Xu’s previous approach [CVX22] considered an intermediate “verifi-
cation” problem:

                                                         14
Problem 4.2 (Verification). We are given an n × d real matrix A and a d × n matrix B and indices pij ∈ [d]
for each i, j ∈ [n]. For each i, j ∈ [n], we want to decide whether there exists an index p′ij ∈ [d] satisfying

                                       A[i, p′ij ] + A[p′ij , j] < A[i, pij ] + A[pij , j],

and if yes, report one such p′ij .
     If the answer is no, then pij is indeed the correct index for the (min, +)-product entry C[i, j].
     Chan, Vassilevska Williams, and Xu showed that this verification problem can be reduced to Lopsided
AE Sparse Triangle (and thus to selected-entries rectangular matrix multiplication), by adapting simple
ideas found in previous slightly subcubic APSP algorithms such as [Fre76, Cha08, Cha10, Wil18] (notably,
“Fredman’s trick”).
     To reduce the original problem to this verification problem, they applied a well-known random sampling
approach: take a random subset R ⊆ [d] of a certain size r, compute arg mink∈R (A[i, k] + B[k, j]) for each
i, j (by brute force or by recursion). This gives us good candidates pij for verification, since for each i, j,
the number of p′ with a smaller A[i, p′ ] + B[p′ , j] is expected to be around d/r.
     Unfortunately, we do not see a good way to derandomize this sampling approach. (Essentially, we want
a small hitting set R for a certain set system which we cannot afford to generate explicitly.) We have un-
successfully tried various sophisticated ideas, such as the method of conditional probabilities, or limited
