Universal XSS found in uBlock Origin's element picker

Original: Universal XSS in uBlock Origin from website-driven element picker

 Listen

Why This Matters

Browser extension UXSS bugs grant cross-origin JS access, bypassing web's core security boundary.

 PithWire Take
 An AI found the bug, another AI wrote the PoC. The human mostly supervised.

Researcher Smitty van Bodegom disclosed a one-click universal XSS in uBlock Origin's MV2 Firefox build, letting malicious sites inject arbitrary JS into any page via trusted filter injection. Fixed Nov 2026.

Security researcher Smitty van Bodegom (loops) found a universal XSS vulnerability in uBlock Origin's MV2 Firefox extension, with a related lesser issue also affecting uBO Lite (MV3). The attack chain starts by leaking the extension's random internal UUID — extractable by hooking XMLHttpRequest calls triggered by a default uBO filter rule that proxies ad-server fetches through the extension. With the UUID in hand, an attacker embeds an invisible, zero-opacity iframe pointing to the extension's element picker UI (epicker-ui.html), then drives it programmatically via postMessage and a MessageChannel. By sending a crafted showDialog message followed by a resultsetDetails message, the attacker bypasses the picker's normal filter restrictions and injects a trusted filter — one capable of running arbitrary JavaScript on any site. The invisible iframe is then positioned to overlay a legitimate-looking button, tricking the user into clicking the hidden "Create" button that commits the malicious filter. Notably, the core vulnerability was identified by GPT-5.6 Sol after van Bodegom suspected filter injection could lead to UXSS; the researcher verified the issue and wrote the disclosure, while Claude generated most of the proof-of-concept code. The issue is now patched; a GitHub advisory has further technical details.
