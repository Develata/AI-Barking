Compare models

If you’re unsure which model to use, start with Claude Opus 5.5 [/docs/en/models/opus-5-5/overview] for most workloads. Use Claude Fable 5.2 [/docs/en/models/fable-5-2/overview] for demanding reasoning and long-horizon agentic work, or when your evals on Claude Opus 5.5 at higher effort still fall short. All current models support text and image input, text output, multilingual capabilities, vision, and tool use. Each model’s page lists the platforms it’s available on.

Using the Models API

You can query model capabilities and token limits programmatically with the Models API [/docs/en/api/models/list]Preview with links to the API reference available — press Tab until focus enters the card, Escape to return.. The response includes max_input_tokens [/docs/en/api/models#model_info.max_input_tokens]Preview with links to the API reference available — press Tab until focus enters the card, Escape to return., max_tokens [/docs/en/api/models#model_info.max_tokens]Preview with links to the API reference available — press Tab until focus enters the card, Escape to return., and a capabilities [/docs/en/api/models#model_info.capabilities]Preview with links to the API reference available — press Tab until focus enters the card, Escape to return. object for every available model.

Each model in the response also has a line [/docs/en/api/models#model_info.line]Preview with links to the API reference available — press Tab until focus enters the card, Escape to return. field, which names the model line it belongs to. Claude Opus 4.5 and Claude Opus 4.6 both report opus. Use line to group models, for example, in a model picker. line is null when a model belongs to no line. Read line instead of inferring it from the model’s id. Anthropic might add more lines, so don’t treat the set of values as fixed.

Each model’s capabilities object includes thinking.types.disabled [/docs/en/api/models#thinking_types.disabled]Preview with links to the API reference available — press Tab until focus enters the card, Escape to return., which reports whether the model accepts thinking: {type: "disabled"}, the setting that turns thinking off [/docs/en/build-with-claude/thinking#turning-thinking-off]. supported is false when the model rejects "disabled" with a 400 error, and true on a model that doesn’t support thinking. Even when supported is true, the API can still reject a "disabled" request for another reason. One such reason is an effort [/docs/en/build-with-claude/effort] level that the model doesn’t allow with thinking off.

Each model’s capabilities object also includes thinking.types.between_tools [/docs/en/api/models#thinking_types.between_tools]Preview with links to the API reference available — press Tab until focus enters the card, Escape to return., which reports whether the model accepts thinking: {type: "between_tools"}, the setting that turns off up-front thinking [/docs/en/build-with-claude/thinking#turning-thinking-off]. supported is false when the model rejects "between_tools" with a 400 error. Even when supported is true, the API can still reject a "between_tools" request for another reason, such as an effort [/docs/en/build-with-claude/effort] level that the model doesn’t allow with "between_tools". For Claude Sonnet 5.5, for example, the Models API reports thinking.types.between_tools.supported as true and thinking.types.disabled.supported as false.

Each model’s capabilities object also includes server_tools [/docs/en/api/models#model_capabilities.server_tools]Preview with links to the API reference available — press Tab until focus enters the card, Escape to return., which reports whether the model accepts the web search [/docs/en/agents-and-tools/tool-use/web-search-tool] and code execution [/docs/en/agents-and-tools/tool-use/code-execution-tool] tools. It doesn’t cover other server tools, such as web fetch. server_tools.web_search.supported and server_tools.code_execution.supported are true when the model accepts at least one version of that tool, not necessarily every version. server_tools.supported is true when the model accepts at least one of the two tools. Even when a tool is supported, your organization’s settings can still cause a request that uses it to fail. For example, an administrator can disable web search [/docs/en/agents-and-tools/tool-use/web-search-tool#how-to-use-web-search].

The top-level code_execution [/docs/en/api/models#model_capabilities.code_execution]Preview with links to the API reference available — press Tab until focus enters the card, Escape to return. capability is a different check. It reports whether code that Claude runs in the code execution tool can call the request’s other tools, as in programmatic tool calling [/docs/en/agents-and-tools/tool-use/programmatic-tool-calling]. For Claude Haiku 4.5, for example, the Models API reports server_tools.code_execution.supported as true and code_execution.supported as false.

Prompt and output performance

Current Claude models excel in:

Performance: Top-tier results in reasoning, coding, multilingual tasks, long-context handling, honesty, and image processing. See Prompting best practices [/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices] for general and model-specific prompting guidance.

Engaging responses: Claude models are ideal for applications that require rich, human-like interactions. If you prefer more concise responses, adjust your prompts to guide the model toward the output length you want. Refer to the prompt engineering guides [/docs/en/build-with-claude/prompt-engineering] for details.

Output quality: When migrating from a previous model generation, you might notice larger improvements in overall performance. If you’re on Claude Opus 5 or earlier, see the Claude Opus 5.5 migration guide [/docs/en/models/opus-5-5/migration-guide].
