Measurement conditions · constrained budget and memory residency

The 16 GiB VRAM + 20 GiB RAM rows are the same RTX 5090 D 24 GB, not a different card. VRAM is capped with --vram-reserve-mib 8192. System RAM is capped by a cgroup (MemoryMax=20G, no swap). With residency on, the same card holds Q3_K (40.81 GiB of weights)
as 23.14 GiB VRAM + 31.28 GiB RAM, and NVFP4 (47.79 GiB) as 23.25 GiB VRAM + 38.27 GiB RAM — disjoint expert sets,
nothing counted twice.

See Usage & troubleshooting [#usage-help] for memory-saving options.

Architecture

Architecture details · diagram, configuration and expert routing

 [https://huggingface.co/Edge0/Edge0-145B-NVFP4/resolve/main/assets/arch.svg]

Edge0-145B

Total parameters
145B · 10.12 B active per token

Layers
48 · hybrid attention, full every 4 layers + sparse indexer

Experts
512 per layer, 10 routed + 1 shared active per token, SwiGLU width 640

Expert pool
84.6 B parameters at latent width ℓ = 1792

PLE
51.2 B n-gram embedding table, fp8, memory-mapped

MTP head
1.26 B draft model, 512 experts, for speculative decode

Context
256K · KV int8 with 32K resident

Builds
Q3_K 40.81 GiB · NVFP4 47.79 GiB

Left: the stack the model actually runs — token embedding, 48 hybrid-attention layers, final norm, lm_head.
Right: one layer opened up. Attention reads and writes the full 2560 width. D then projects the token down to
ℓ per routing group, the router picks 10 of 512 experts, each expert runs ℓ → 640 → ℓ, a shared expert runs
alongside, and U projects the combined result back to 2560.

Everything outside the expert pool stays at 2560: D and U are shared, one copy per layer. Only the 512 experts work at
ℓ. That is why an expert is a fixed 1,630,720 B record — the engine keeps a few thousand of them on the card and streams
the rest from host memory, at a cost that tracks how many experts are resident and not how big the model is.

Quick start

Each model folder (Q3_K or NVFP4, Edge0-145B or Edge0-120B) runs on Edge0 [https://github.com/Edge0-AI/Edge0]
through edge0-infer, from the command line or from the Edge0 Chat desktop app. Keep the folder as it is:
edge0-infer identifies the model by model_name in its model.json.

Platform & documentation notes

The build instructions target NVIDIA GPUs with CUDA 13 on Linux or Windows (x64 or ARM64). The Apple M2 Ultra measurements use Metal; they do not establish macOS release availability.

Build & command-line instructions

1. Build. Clone the repository, then build two parts:

git clone https://github.com/Edge0-AI/Edge0.git edge0

edge0-strata, the engine: follow "Build (Linux, NVIDIA)" or "Build (Windows, NVIDIA)" in edge0-strata/EDGE0.md [https://github.com/Edge0-AI/Edge0/blob/main/edge0-strata/EDGE0.md].

edge0-infer: follow "Build" (Linux) or "Windows" in edge0-infer/docs/getting-started.md [https://github.com/Edge0-AI/Edge0/blob/main/edge0-infer/docs/getting-started.md].

2. Run from the command line. Pass one model folder, such as Edge0-145B-NVFP4, not the folder that holds several of
them. On Windows the program is build\windows\bin\edge0-infer.exe.

build/cpu/bin/edge0-infer serve --model /path/to/Edge0-145B-NVFP4

It prints Listening: http://127.0.0.1:8000 model=<name> once the weights are loaded, where <name> is edge0_145b,
and then serves OpenAI- and Anthropic-compatible endpoints:

curl localhost:8000/v1/chat/completions -H 'content-type: application/json' -d '{"model":"edge0_145b","messages":[{"role":"user","content":"hi"}],"max_tokens":64}'

edge0-infer chat --model /path/to/Edge0-145B-NVFP4 opens an interactive session instead. More options:
edge0-infer/docs/edge0-145b.md [https://github.com/Edge0-AI/Edge0/blob/main/edge0-infer/docs/edge0-145b.md].

Desktop app · Windows

⬇️ Download: GitHub Releases [https://github.com/Edge0-AI/Edge0/releases]

Usage & troubleshooting

145B / 120B · Memory options

Low RAM · SSD offload

SSD mode: --mmap-experts — read uncached experts from SSD on demand.

Low-memory arguments:

--resident-budget-gib 20 --expert-profile expert-profile.bin

Up to 20 GiB of host RAM for the expert cache; uncached experts are read from SSD on demand. Includes --mmap-experts and disjoint GPU/RAM caches automatically.

Required: a static expert profile. Replace expert-profile.bin with your profile path.

RAM budget · what 20 GiB covers

Expert cache: --resident-budget-gib 20 caps host-RAM expert caching at 20 GiB, lowered further to fit available memory.

Total RAM: expert cache + other runtime allocations. This flag does not set a total-process RAM limit.

Benchmark limit: the 20 GiB total RAM test budget is a separate measurement condition.

GPU / RAM · avoid duplicate experts

Enable: --resident-experts or --resident-budget-gib N, with a static --expert-profile.

Effect: experts cached in VRAM need no duplicate RAM copy. Compatible with SSD loading.

Default: off, prioritizing speed.

Automatically enabled: --mmap-experts, --resident-cpu-experts, --resident-pin.

 [#capacity-controls-·-vram-and-host-ram]

 Capacity controls · VRAM and host RAM

All of these live in the pack's model.json, not on a command line: flags go in args, environment
variables in env, with paths relative to the pack directory. That is the same file the Edge0 Chat app
and edge0-infer read, so a change there applies to every launch.

"args": ["--expert-cache", "auto", "--kv-resident", "32768", "--vram-reserve-mib", "1024"],
"env": {"STRATA_LATENT_DENSE": "./latent_dense_q8.bin", "STRATA_LATENT_DENSE_FMT": "8",
 "STRATA_LAT_FUSED_Q3K": "0"}

 [#vram]

 VRAM

Flag
Meaning
Default

--vram-reserve-mib N
VRAM left free for the desktop, the driver and other processes; the engine sizes its caches from what remains. It means "leave this much free", not "give the engine this much", so the same number means different things on cards with different totals. Accepted but not listed by --help.
700

--expert-cache N|auto
Expert slots kept in VRAM. auto derives the count from the free VRAM after the fixed footprint (skeleton projections ≈ 2.9 GiB, MTP draft ≈ 0.8 GiB, verify and draft-head buffers ≈ 0.45 GiB, plus the D/U device buffers).
0 (none)

--expert-cache-device1..3 N|auto
Use the second and third GPU as further expert-cache tiers.
off

--kv-resident N
Keep N KV cells per QSA layer in VRAM and stream the K/V from pinned host RAM, which frees VRAM for experts.
0 (all in VRAM)

--mtp-q4 all|proj|head
4-bit copies of the draft layer's projections and/or head, about 0.3–0.5 GiB less VRAM.
off

--prefill CHUNK
Prompt chunk size; bigger chunks need bigger device buffers. auto uses the largest chunk whose buffers the expert cache can lend.
auto

--spec N
The MTP drafter's verify window: how many tokens it proposes per check. A bigger window needs bigger verify buffers (about 180 MiB at 4) and pays off when every window has a fixed per-layer cost. The shipped packs use 4; the macOS setup picks 2, or 3 when the experts stream from SSD. Without an MTP layer there is no speculation.
4

 [#host-ram]

 Host RAM

Flag
Meaning
Default

--memory-limit-mib N
The RAM this engine's container or cgroup may use, for when the container cannot see its own limit.
0 (detect)

--resident-budget-gib N
Cap on the host-RAM expert cache. It holds only the experts the VRAM cache does not hold, so the two sets are disjoint, and the value is clamped to the RAM actually available minus headroom. Requires a static --expert-profile.
0 (off)

--resident-experts
The same with the whole complement as the budget.
off

--mmap-experts
Read experts through the pack file on demand instead of pinning them, so nothing is resident in RAM.
off

--conversation-cache-mib N
Conversation cache. 0 turns it off.
adaptive

--ple-io direct|mmap|ram
The PLE table on its SSD: direct reads it unbuffered and it never enters memory; ram locks the whole table in RAM.
direct

--kv-resident N
The streamed K/V lives in pinned host RAM (1.55 GiB at 32768 cells).
—
