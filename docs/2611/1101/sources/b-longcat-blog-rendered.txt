评测

今天，我们正式发布 LongCat-2.5这是一个面向长程智能体任务的原生多模态模型。模型总参数量为 1.6 万亿，每个 token 激活约 480 亿参数，在 LongCat-2.0 的基础上进一步强化了原生视觉理解与智能体编程能力。

LongCat-2.5 在长程智能体任务中有明显效果提升，这源于我们在长序列训练中加入了更多长程轨迹数据，并通过大规模长程强化学习，提升模型在复杂代码库开发、完整项目构建等任务中的端到端工程能力。围绕数据合成、环境构建与跨 Harness 混合训练，我们持续扩展这条训练链路。此外，我们也将真实 Agent 的失败轨迹转化为可复现、可验证的训练任务，针对模型能力短板持续补充训练数据。

与此同时，LongCat-2.5 在 Visual Coding 上表现出色，并支持创意设计和 3D 等任务。它具备原生视觉理解能力，可将视觉信号表示为多层级离散 token，使主干模型以统一的 token 形式处理视觉与文本输入。

这些升级背后，是持续演进的基础设施：我们优化了国产算力上的长上下文训练与 W4A4 推理，并通过训推数值一致性和长上下文 rollout 优化，支撑大规模长程 RL 的高效运行。

视觉表征建模

LongCat-2.5 将视觉信号表示为多层级离散 token，使主干模型以统一的 token 形式处理视觉与文本输入。这一设计融合了原生分辨率视觉离散化、离线视觉预处理，以及与主干模型联合学习的视觉 embedding，既能支持原生多模态融合，也简化了训练中的视觉计算与负载管理。

离散原生分辨率视觉 Transformer：为了让视觉基本单元的建模具备类似语言建模的 token 级抽象能力，LongCat-2.5 将视觉信号表示为多层级词表 token。沿用 LongCat-Next 的方法，模型对语义对齐编码器（Semantic-and-Aligned Encoder，SAE）产生的原生分辨率特征应用残差向量量化（Residual Vector Quantization，RVQ），以缓解视觉离散化的信息瓶颈。

图 1：原生分辨率视觉离散化：将不同分辨率的图像编码为离散 token 序列，并通过视觉解码器重建图像。

离线视觉 token 预处理：为减少在线视觉计算量、降低工作负载的异构性，固定的 tokenizer 允许模型离线预计算并缓存视觉 token ID。这样，主干模型可以直接处理预先分词的序列，简化长序列打包与切分，并改善分布式训练的负载均衡。

原生视觉表示：视觉码本 embedding 与主干模型联合学习。在平均激活参数约为 3B 的较小规模 MoE 模型上，初步验证显示，视觉与文本 embedding 在 t-SNE 可视化中呈交织分布，说明二者已在共享语义空间中实现融合。

图 2：视觉与文本 embedding 的 t-SNE 对比。右图为平均激活参数约 3B 的 MoE 模型上的验证结果。
大规模智能体强化学习

强化学习扩展（RL scaling）是提升模型智能的关键环节。我们为 LongCat-2.5 搭建了全面的 Agentic RL 训练链路，从数据、环境、算法和 Harness 等方面对长程任务进行大规模扩展。

图 3：面向长程任务的 Agentic RL 训练链路，涵盖数据与环境、异步训练、奖励设计和混合训练。

大规模数据合成与环境构建：我们构建了一条可扩展的数据合成流水线，自动生成训练任务、可交互环境和可验证的测试用例，数据来源涵盖 GitHub 公开仓库和内部真实场景的代码任务。筛选出 PR 和关联 issue 后，Agent 会自动打标签、搭好可交互环境，并进行 fail-to-pass（F2P）和 pass-to-pass（P2P）测试。在 RL 训练过程中，模型实际 rollout 产生的轨迹和通过率会反过来帮助二次打标和筛选数据。同时我们还会分析假阴性、假阳性等误判，持续修正和扩充 F2P 测试用例，让测试覆盖更多任务功能，也让验证信号更加准确。

异步强化学习与稳定性优化：我们采用部分采样（partial rollout）的异步训练策略，解决长尾任务拖慢整体效率的问题：每个 RL step 会多采样一些任务，凑够一批后先中断，并且把没跑完的轨迹存下来，在下一轮接着跑。具体多采样多少，会根据任务通过率进行动态调整；全对或全错的零梯度样本组会被过滤掉，以保证有效梯度。在 partial rollout 中，同一轨迹的 token 可能来自不同历史 checkpoint，从而带来样本陈旧性。为保障训练稳定性，我们裁剪采样阶段与当前训练阶段的 logprob 差异，并基于历史累计差异调整每个 token 的梯度贡献，以限制陈旧性带来的梯度偏差；此外，我们也从 infra 视角提供了训推一致性的优化方案。

Reward hacking 与输出行为优化：为了防止模型"钻空子"拿奖励，我们在任务环境中断网、清除 git 历史和文件缓存，并引入 LLM judge 监督轨迹。在输出行为上，我们对重复思考和重复工具调用施加额外惩罚；对过度思考和长度增长过快的问题，则通过重新分配正样本中的奖励加以抑制。

混合训练与泛化：模型可在 RL 过程中自主学习并适配相近任务和 Harness。冷启动阶段仅需覆盖少量适配 scaffold 的用例，到了 RL 阶段，通过跨多任务、跨 scaffold 的混合训练可显著提高模型泛化能力，并促进不同任务上的效果提升。

多专家在线教学

为让主线模型同时具备各领域能力，我们沿用 LongCat-2.0 的专家组机制，分别优化 Agent 能力、推理能力和交互体验，涵盖多轮任务执行、单轮推理、细粒度指令遵循，以及不牺牲有用性的安全防御。在 MOPD 中，学生模型在各领域任务中在线采样，领域专家通过采样结果上的全词表 KL 散度训练学生。也就是说，学生先按自己的方式答题，专家再纠正它在整个词表上的概率分布。

样本既要反映学生的实际任务行为，也要让教师给出可信的学习信号。为减少分布偏移，先前工作将教师在 SFT 或 RL 阶段见过的轨迹拆为 per-turn prefix，作为学生采样的上下文。我们进一步将每轮教师回复按固定长度拆为 per-cut prefix，并将学生自采样的最大长度限制为该值，以处理单轮长回复中的分布偏移。

图 4：用于学生在线采样的 per-cut prefix。

为控制计算与存储成本，我们将同一教师轨迹的 prefix 归为一组，送至同一个推理引擎，共享 prefill 计算与 KV cache。训练时，以教师轨迹为树干、学生采样为分支构建树，结合 Tree Attention，通过单次前传与反传就完成同组所有样本的 OPD 训练，避免教师轨迹上的冗余计算与存储。

国产算力上的长上下文训练

LongCat-2.5 在中训练和监督微调阶段均采用长序列训练。国产算力单卡显存不足 80 GB，因此训练系统重点压低显存开销，并围绕超节点架构设计并行策略。

面向超节点的并行策略

LongCat-2.5 根据超节点拓扑配置并行组，FSDP 和 EP 并行度都与单个超节点的卡数一致，CP 并行度不超过这个卡数。这样，参数 AllGather、专家 token AllToAll 和 KV AllGather 都能在超节点内的高带宽互联域中完成，减少跨节点通信开销。

混合词表并行在 DP 和 CP 联合并行域内，对基础词嵌入层、LM head 和 N-gram 嵌入层进行分片，进一步降低显存占用。

大规模专家并行容易出现负载不均衡问题。为此，LongCat-2.5 基于 MoonEP 引入阈值触发的动态专家复制机制：只有当 EP 负载不均衡程度达到预设阈值时才启用复制，避免额外通信开销超过负载均衡带来的收益；同时防止路由 token 导致接收端显存溢出，或通信操作导致发送端显存溢出。

提前生成图像 token 后，训练计算图不再包含视觉编码器，并行实现更简单。由于图像 token 数量已知，系统可以在数据打包和打散时预估各模态的负载比例，使各数据并行 rank 上的模态占比尽量接近。

FSDP 与系统优化

LongCat-2.5 引入双重分片 FSDP，模型参数在超节点内的 FSDP 域中分片，FP32 主权重和优化器状态则通过 HSDP 副本进一步跨 FSDP 域分片。这样既保持参数通信效率，又降低常驻显存。

参数、梯度和优化器状态统一组织为连续的扁平化缓冲区，支持非均匀分片和 Muon 优化器分片。同时，系统直接写入权重梯度、复用临时缓冲区，减少中间拷贝，从而降低峰值显存占用。

系统采用零拷贝 AllGather/ReduceScatter，消除默认通信算法引入的中间拷贝。EP 将 token 与路由概率打包传输，并采用基于 AIV 的通信实现，缓解 AICPU 任务展开瓶颈。参数预取使 AllGather 与计算重叠执行，同时控制与 CP 的资源竞争；ScMoE 则使 EP 通信与稠密分支计算重叠执行。

此外，系统通过批量执行梯度操作、合并指标归约、CPU 绑核和 NUMA 感知调度，降低主机侧开销。

综合上述优化，该 FSDP 配置在长序列 SFT 任务中的单卡吞吐量较 DDP 基线提升 86%。

训推精度一致性

训练和推理算出来的数值如果不一致，模型表现就可能"飘"。基于 IsoExec、GLM-5 和 XoRL 的工作，我们构建了生产级训推一致性方案，使训练、Prefill 和 Decode 可以各自独立选择并行配置，在性能接近无损的同时，保持逐 token logprob 的 bitwise 一致。具体做法是：训推两端统一采用高效的 batch-invariant 算子，并对齐框架计算逻辑，同时补齐 backward 支持。该方案已在实验和生产任务中默认启用，为算子与框架迭代提供统一的数值回归基准。不过，不同并行方式本身就可能导致训推无法对齐，我们在社区方案的基础上，进一步扩展了 TP 和 DCP 的训推一致性支持。

TP：以完整 K 维计算替代分段求和，性能接近无损。传统 TP 会把 K 维切分到多张卡上，各自算一部分，再做 Reduce-Scatter 求和。问题是，跨卡求和的顺序和训练时不一样，数值就容易对不上。为解决这一问题，我们在训练侧保留权重分片，通过权重 All-Gather 和输入 AlltoAll，让每张卡独立完成完整 K 维 GEMM，不再对局部结果进行 Reduce-Scatter 求和。Prefill 沿用同一方案；Decode 阶段则将 o_proj/fc2 改为 column-parallel，通过输入 All-Gather、完整 K 维 GEMM 和输出 AlltoAll 完成计算，既避免每一步聚合完整权重，也避免跨卡数值求和。

DCP：在训练与 Prefill 中复现 Decode 的累加路径。Decode 阶段会按特定配置对 KV 做分块计算，再按固定顺序归约。训练和 Prefill 如果累加顺序不同，精度就会产生差异。为此，我们在训练 forward 和推理 Prefill 中接入配套的 sparse attention 算子，复现指定 DCP 配置下 Decode 的 KV 分块与归约顺序，从而把训练、Prefill、Decode 三者的计算精度对齐。

长上下文 rollout 优化

针对负载可控的长上下文多轮 rollout，我们采用 PD 分离，也就是把 Prefill 和 Decode 拆开，分别选择合适的并行策略，并从缓存存储、跨层卸载和请求调度三个方面协同优化：

扩大有效缓存容量：Prefill 阶段采用 QCP 按 token 分配计算、KVP 按页分散存储，避免 MLA 下 TP 切分带来的 KV 冗余。HiCache 在 KV 回迁显存后，会释放主存里没有其他读取引用的副本，减少显存和主存这两级缓存的重复占用；同时，我们基于 Mooncake 重构了权重管理与 Actor offload 方案，为 HiCache 释放更多内存。

通过跨层预取隐藏搬运开销：利用 LSA 奇数层复用前一偶数层 top-k 索引的特点，我们将奇数层完整 KV 卸载至主存，显存里只保留小容量工作缓存。等偶数层产生索引后，提前加载下一奇数层所需 KV，并让它与当前层后续计算重叠执行，在 TPOT 无损的情况下，Decode 阶段的 KV 缓存容量接近翻倍。

通过容量感知调度避免重算雪崩：多条长轨迹交替推进时，缓存不够可能导致互相淘汰对方的前缀，引发大规模重算。为此，Router 会根据 L1+L2 缓存容量和请求 token 总量控制请求放行，并优先推进完成度较高的 Group，尽早凑齐训练批次、释放缓存，避免反复淘汰和重算。

图 6：所测长上下文负载的 Prefill/Decode 配置；在该场景下，P/D 实例配比 3:2 性能最优。
W4A4 高效推理

针对 1.6T 级 MoE 模型，我们结合模型结构与国产 AI 加速器的硬件特性，围绕量化精度、底层算子与推理流水开展协同优化，构建 W4A4 高效推理方案。

该方案将专家权重与激活同时量化至 4 bit，并通过原生 INT4 矩阵乘法单元执行相应的矩阵计算。

在精度方面，我们以 FlatQuant 的可学习等价变换为基础，进一步优化 MoE 模型的量化精度，在已评测的各项下游任务上，量化后的模型表现与量化前保持相当。

在算子与数据路径方面，我们通过专家共享的输入变换，在 token 复制与分发前完成量化，让同一份 INT4 表示贯穿专家通信与计算。同时，我们把变换、尺度计算、量化和打包融合到专用算子，并结合权重布局与转置访问优化，减少数据搬运和转换开销。

在系统层面，prefill 与 decode 的执行特点不同，前者更偏重批量计算，后者更偏重逐 token 推进和通信。我们依据模型的数据依赖和硬件资源约束，分别优化计算与通信的流水重叠，尽量减少互相等待。
