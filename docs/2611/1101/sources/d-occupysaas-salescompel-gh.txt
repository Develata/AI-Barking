SalesCompel
 [#salescompel]

An open-source, free-to-use Salesforce replacement project, with an initial tenant-isolated Go/PostgreSQL candidate and Vue record workflow.

See the compatibility roadmap [/occupysaas/salescompel/blob/main/docs/plans/2026-10-14-salesforce-compatibility-roadmap.md] for the proposed architecture, migration strategy, and milestones.

UI prototype
 [#ui-prototype]

 [/occupysaas/salescompel/blob/main/docs/pics/ui-prototype.png]

The early Vue prototype lets people explore Account/Contact lists, details and
create/edit flows using synthetic data. It includes light/dark themes, Pinia,
Vue Router, localization and RTL support. Unimplemented destinations are disabled
and marked Planned. Preview edits stay in memory and do not call the backend.
See the prototype walkthrough [/occupysaas/salescompel/blob/main/docs/compat/ui/preview-walkthrough.md] to run it
locally and understand its scope.

Roadmap and progress
 [#roadmap-and-progress]

As of October 20, 2026, completed work packages include the compatibility
laboratory, the Go/PostgreSQL candidate walking slice, an accepted eleven-scenario
reference baseline, bounded metadata/catalog improvements, external-ID body
validation and the early UI prototype. These are subsystem deliveries; no full
program milestone has a recorded exit-gate pass yet.

The draft budget is roughly 185–350 additional plan equivalents through M9,
including discovery and rework reserve. This is a rough scope estimate, not a
delivery-date forecast; M10 needs separately bounded inventories. An early UI
track runs alongside foundation work so feedback can shape the product sooner.

Next priorities are closing foundation evidence gaps, resolving external-ID
equality and migration behavior, completing the target inventory, and testing
Apex/Flow/custom-UI feasibility early. See the
progress roadmap and estimate assumptions [/occupysaas/salescompel/blob/main/docs/plans/2026-10-20-progress-and-remaining-roadmap.md]
and the full architecture and milestone gates [/occupysaas/salescompel/blob/main/docs/plans/2026-10-14-salesforce-compatibility-roadmap.md].

Compatibility laboratory
 [#compatibility-laboratory]

Plan 1 [/occupysaas/salescompel/blob/main/docs/plans/2026-10-15-plan-1-compatibility-laboratory.md] is implemented as an offline specification and test laboratory. See setup, live-test prerequisites, and recovery [/occupysaas/salescompel/blob/main/docs/compat/README.md].

npm ci --prefix compat/clients/node --ignore-scripts
npm --prefix compat/clients/node run check

The OpenAPI 3.2 REST contract [/occupysaas/salescompel/blob/main/api/openapi.yaml] is a proposed broader subset; the Plan 2 implementation guide [/occupysaas/salescompel/blob/main/docs/compat/plan-2-implementation.md] lists the routes served by the candidate. Official Salesforce schema fixtures retain their own licenses; see provenance [/occupysaas/salescompel/blob/main/compat/fixtures/openapi/salesforce/provenance.json]. The Plan 4 pilot baseline [/occupysaas/salescompel/blob/main/docs/compat/plan-4-reference-baseline.md] records two repeatable live reference captures; no candidate Salesforce compatibility certification has been performed.

Platform walking slice
 [#platform-walking-slice]

Plan 2 [/occupysaas/salescompel/blob/main/docs/superpowers/plans/2026-10-15-plan-2-platform-walking-slice.md] implements persistent Account/Contact CRUD, describe, limited queries, external-ID upsert, provisioned bearer authentication and a localized Vue editor. See the setup and verification guide [/occupysaas/salescompel/blob/main/docs/compat/plan-2-implementation.md]. The roadmap also tracks M1R release-history review [/occupysaas/salescompel/blob/main/docs/plans/2026-10-14-salesforce-compatibility-roadmap.md#m1r--salesforce-release-notes-and-changelog-review].

The Plan 16 local candidate acceptance [/occupysaas/salescompel/blob/main/docs/compat/plan-16-cli-query-column-metadata.md] records two complete sequential passing runs across database, real clients, restart and browser gates.

The candidate is not production-ready or certified Salesforce-compatible. The eleven-scenario reference baseline is recorded; broader M1 obligations and the wider protocol/security/migration surfaces remain pending.

Catalog upgrades
 [#catalog-upgrades]

The candidate now uses catalog version 2 with 80-character bounds for both synthetic
Account custom fields. Existing databases upgrade transactionally at startup;
oversized values block the upgrade without changing data. Stop old instances and
back up before upgrading. See the Plan 8 upgrade and rollback guide [/occupysaas/salescompel/blob/main/docs/compat/plan-8-active-field-metadata.md].
