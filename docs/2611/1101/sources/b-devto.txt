Attributed compile + one small offline run on my box

Primary source: Introducing LongCat-2.5 — Native Multimodality for Agentic Tasks [https://longcat.ai/blog/longcat-2.5/] by Meituan / LongCat team, published 2026-11-1.

Pricing / billing: LongCat-2.5 pricing [https://longcat.ai/platform/docs/pricing/longcat-2.5] and API Pay-As-You-Go [https://longcat.ai/platform/docs/api-pay-as-you-go] (limited-time discounted rates; platform billing authoritative).

API: Chat Completions [https://longcat.ai/platform/docs/api/chat] + Platform Quick Start [https://longcat.ai/platform/docs/] — OpenAI-compat https://api.longcat.chat/openai, Anthropic-compat https://api.longcat.chat/anthropic, model id LongCat-2.5.

Secondary CN press: 美团发布LongCat-2.5大模型，“国模国芯”实现新突破 [https://www.meituan.com/news/NN261102280001343] (Meituan / 经济观察报 framing, 2026-11-02) for the “scores between Claude-Opus-4.8 and Claude-Opus-5” claim and product/API availability.

Benchmarks and prices below are vendor-reported unless I say otherwise. This box did not call chat completions. Offline preflight = public HTTP scrapes + list-price arithmetic only.

Meituan shipped LongCat-2.5 on 2026-11-1 (blog) with wide coverage on 2026-11-2: a 1.6T-parameter MoE (~48B activated per token) pitched as a native multimodal model for long-horizon agentic work. For builders, the useful story is not “another 万亿 MoE.” It is four concrete checks: (1) OpenAI- and Anthropic-compatible endpoints with a single model string, (2) a thinking object that forces temperature (1.0 on / 0.7 off), (3) limited-time list price $0.30 / $0.006 cached / $1.20 per 1M tokens, and (4) vendor benches that Meituan’s own CN framing places between Claude Opus 4.8 and Opus 5 — which is a reason to run your golden eval, not a reason to merge their table into your prod decision.

Try-it surface is longcat.ai; developers get a prepaid Pay-As-You-Go API the same week. That is enough to A/B against a current default without waiting for open weights — and also enough to over-trust a vendor dashboard if you skip your own tickets.

 [#what-it-is-short]
 What it is (short)

LongCat-2.5 builds on LongCat-2.0 with stronger native visual understanding and agentic coding (vendor). Visual signals are represented as multi-level discrete tokens (RVQ over a Semantic-and-Aligned Encoder / SAE-style path), so vision and text share a unified token stream. Training emphasis is long-horizon RL: more long trajectories in long-sequence training, failure trajectories turned into verifiable tasks, mixed training across harnesses. Infra notes (for context only): long-context training and W4A4 inference on domestic AI accelerators; vendor online stress vs W8A8 INT8 cites prefill +43.3%, decode +42.77%, TTFT −15.91%, TPOT −19.72%, GMM kernel ~1.73×. That is serving math, not permission to skip quality gates.

Site / docs language also says the model works across Claude Code, Codex, and Hermes harnesses. Treat that as compatibility marketing until you wire one harness and measure your own tasks. Blog eval footnotes themselves show different harnesses per bench (Claude Code on several coding rows, Codex on SkillsBench, custom browse harness on BrowseComp) — another reminder that “works across” is not “one config wins every leaderboard.”

Skip the deep train–inference / supernode digression for day-one integration. Remember only: long context (1M) is a first-class claim, multimodal is native (not a bolted vision sidecar in the marketing story), and agentic RL is the capability bet.

 [#how-to-call-it-dual-endpoints-the-temperature-lock]
 How to call it: dual endpoints + the temperature lock

Platform docs advertise two bases:

Model id: LongCat-2.5. Context window: 1M tokens; max output: 128K. Default top_p on chat docs: 0.95.

Thinking is an object, not a free-form string:

"thinking": { "type": "enabled" }

or { "type": "disabled" }.

Trap: chat docs say temperature is fixed at 1.0 with thinking enabled and 0.7 with thinking disabled; other values are overridden. If your client still sends temperature: 0 from an older Anthropic/OpenAI template, you are not getting determinism — you are getting the forced default for the thinking mode you picked. Eval note on the blog: LongCat-2.5 rows use enable_thinking=on, temperature=1.0, top_p=0.95 unless specified; other models marked * are public reports.

OpenAI SDK shape is the usual base_url="https://api.longcat.chat/openai" + Bearer key. Anthropic SDK path uses https://api.longcat.chat/anthropic with the docs’ header pattern (Authorization: Bearer … plus Anthropic-style body). Pick one client stack for the A/B; do not flip formats mid-eval or you will confuse tool-schema bugs with model bugs.

Builder rule: set thinking explicitly per route, assume temperature will be clamped, and pin the base URL + model string in config — do not guess. If you need lower temperature for classification, you likely want thinking disabled (and you still get 0.7, not 0.0). Document that in the route table so the next engineer does not “fix” sampling with a dead knob.

Meituan’s 2026-11-02 CN press frames results as sitting between Claude-Opus-4.8 and Claude-Opus-5 on several mainstream benches (and exceeding Opus-5 on some). That is a vendor / press claim next to their own charts — useful as a map of where they want you to look, useless as a substitute for your golden set. Same caution as this series always uses: do not paste “between Opus 4.8 and 5” into a slide that implies an independent Artificial Analysis or third-party harness unless that harness is cited.

Jump vs 2.0 on Terminal Bench v4.0 (3.0 → 38.5) and DeepSWE (9.7 → 64.6) is the internal “agentic coding moved” signal. Still: those are their runs with their thinking/temp settings. Replicate on your repos before you retire the incumbent model string.

Cache is the swing factor on long agent loops. Thinking-on also tends to inflate reasoning / output tokens relative to thinking-off — price the knob and the rate card together, and remember temperature will not save you from that inflation. For a rough sanity check: at these list rates, 1M in + 1M out is $1.50 before cache; an 80k/20k turn with fat prefix reuse lands closer to ~$0.03 if the 80% cache assumption holds. Measure real cached vs uncached fields on usage before you put the middle rows in a forecast.

CNY list (¥2 / ¥0.04 / ¥8) is on the same docs pages — use it if you bill in RMB; this post’s arithmetic sticks to USD for series consistency.

 [#checklist-before-you-swap]
 Checklist before you swap

Freeze a golden eval on your agent failures (repo patches, terminal tasks, browse/tool traces, visual coding if that is your product). Vendor TB / BrowseComp / Vision2Web are someone else’s harness.

Pin base URL + model id — LongCat-2.5 on either api.longcat.chat/openai or …/anthropic. Confirm which SDK headers your client needs (Anthropic path wants the usual Anthropic-shaped request).

Set thinking explicitly. Assume temperature is overridden (1.0 on / 0.7 off). Do not rely on a silent temperature: 0 from old templates.

Price both columns: list $0.30/$1.20/$0.006 and expected output tokens with thinking on. Re-run the arithmetic with your real prompt sizes. Treat rates as limited-time.

Harness claim ≠ drop-in. If you use Claude Code / Codex / Hermes, prove one path with your tools and auth before you rewrite defaults.

Multimodal only if you need it. Discrete visual tokens are the product story; your golden set should include the visual tasks you actually ship.

Billing hygiene: prepaid balance; only HTTP 200 billed; do not forecast from failed 429 storms.

Do not conflate Meituan vendor rows, CN “between Opus 4.8 and 5” framing, and any third-party index you have not opened yourself.

 [#when-longcat25-might-become-a-default]
 When LongCat-2.5 might become a default

Only after a callable path and a golden eval win on your tickets:

Long-horizon coding / agent loops where your current default fails and an OpenAI- or Anthropic-shaped client is already in the stack.

You have chosen thinking on/off per route, knowing temperature is locked.

Cost model survives realistic cache and thinking-on output inflation at $0.30/$1.20.

You verified the harness you actually run (not only the brochure list).

You can roll back without rewriting orchestration.

If you are already deep in Anthropic- or OpenAI-shaped agent code, LongCat-2.5 is a same-week candidate for a side-by-side — not because the Opus framing is gospel, but because the integration surface is familiar and the list price is easy to model. If you need open weights, local GPUs, or a third-party index row before you trial anything, this drop is the wrong trigger; wait for a surface that matches that constraint.

LongCat-2.5’s builder-relevant release is the dual-compat API, the thinking/temperature lock, the $0.30/$1.20 limited-time card, and vendor benches framed near Opus 4.8–5. Treat those as labeled inputs, run your own eval, and only then change the production model string.
