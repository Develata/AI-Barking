Nginx曝出NGINX2Root漏洞链：攻击者无需认证即可远程执行命令

IT之家 11 月 19 日消息，安全研究团队 Xint Security Research 于当地时间 11 月 18 日公开披露了一串名为 NGINX2Root 的漏洞攻击链，涉及 5 个 Nginx 远程代码执行（RCE）漏洞，以及 1 个 Linux 内核 SCTP 子系统权限提升漏洞。

攻击者无需身份认证，即可利用特定配置下的 Nginx 漏洞执行任意命令；如果进一步结合 Linux 内核漏洞，还可能实现 Docker 容器逃逸并获取宿主机 root 权限。

据 Xint 技术报告，5 个 Nginx 漏洞分别对应不同的功能和配置场景，涉及 HTTP/2、HTTP/3、反向代理及邮件代理等模块，并非所有漏洞都需要同时利用。

IT之家注意到，其中影响范围较广的是 CVE-2026-123007，该漏洞源于 HTTP/2 流量控制中的整数溢出问题，可导致堆内存越界写入。只要 Nginx 监听端口启用了 HTTP/2，就可能受到影响。

另外 4 个漏洞分别为 CVE-2026-123634、CVE-2026-123633、CVE-2026-121810 和 CVE-2026-113425，涉及特定反向代理配置、HTTP/2 上游连接、HTTP/3 上游请求以及邮件代理功能。攻击者成功利用后，可以在处理请求的 Nginx Worker 进程权限下执行命令。

Xint 研究人员还演示了完整攻击链：首先利用 Nginx 远程代码执行漏洞，在 Docker 容器内部以 Nginx Worker 权限执行命令，随后利用 Linux 内核 SCTP 子系统中的另一处漏洞提升权限，最终突破容器隔离，取得底层宿主机的 root 权限。研究团队表示，相关测试还覆盖了 AWS、谷歌云和微软 Azure 等云环境。

根据欧洲网络安全机构 CERT-EU 同日发布的安全公告，F5 已公开处理这 5 个 Nginx 漏洞，但截至公告发布时，尚未发现这些漏洞已在野外遭到实际利用的报告。CERT-EU 建议优先检查面向互联网开放的 Nginx 服务。

在修复方面，Xint 建议升级至 Nginx 1.31.9。Sophos 发布的安全公告则确认，Nginx Open Source 1.30.7 和 1.31.9 已包含相关漏洞修复，Nginx Plus 也已发布对应修复版本。

暂时无法升级的管理员，可以通过关闭 HTTP/2 缓解其中 CVE-2026-123007 和 CVE-2026-123633 两个漏洞的风险，但这一措施无法覆盖其余漏洞。
