Notes & limitations
Data may be delayed. Figures combine Censys scans, updated hourly, with a daily Censys snapshot. Each service's status comes from its most recent scan, which can be up to 9 days old.
Numbers can change as detection improves. As Censys refines how it identifies nginx and reads its version, and as we refine how HTTP/2 is detected, services can be added or reclassified, so totals may shift without any change on the internet.
This tracks one of the nginx2root bugs: CVE-2026-123007, memory corruption in HTTP/2 flow control, the one that only needs HTTP/2 on. The other four (resolver, HTTP/2 and HTTP/3 connection draining, mail proxy) depend on configuration that cannot be seen from the Internet and are not counted.
Exposed needs two things on the same endpoint: an nginx Server header with a version from 1.9.5 to 1.31.8, and HTTP/2 among the protocols the endpoint answered in our scans.
Most nginx servers hide their version (Server: nginx). Those that show HTTP/2 (103,799,113 services) cannot be judged and are left out of the exposed count; turn on Include unknown versions at the top to see them in grey. The real number of exposed services is higher than the exposed count.
Affected versions without an HTTP/2 sign are not shown (61,149,520 services). Not seeing HTTP/2 is not proof that it is off: scans do not test every protocol on every endpoint, so the exposed count can be low. HTTP/2 seen without TLS (cleartext) counts too. HTTP/2 seen through a load balancer or CDN in front of nginx is counted, even though the front end may be the one speaking HTTP/2.
Services that stopped showing HTTP/2 before the bug was disclosed on 2026-11-18 (1,627,014) are not counted as exposed or fixed.
Distro builds are shown separately where nginx says so. Ubuntu's nginx labels itself in the Server header (nginx/1.24.0 (Ubuntu)), and Ubuntu ships fixes without changing the version number, so those services may already be fixed. Debian and the Red Hat family patch the same way but do not label nginx's header, so their servers count as exposed; an operating system detected from anything else (another header, a default page) is not used. nginx Plus reports the open-source version it is based on and is counted the same way.
"Fixed" means an exposed service later showed 1.30.7+ or 1.31.9+ (patched), or showed no HTTP/2 sign for 7 days from disclosure on (mitigated). Services already on a fixed release when we first saw them (709,117) are not counted as fixed. A service seen exposed again stops counting as fixed. A configuration reload does not replace the running binary: nginx must be restarted or upgraded.
Only nginx reachable through HTTP/2 is counted. Services on versions older than 1.9.5 (536,919) are tracked but not shown. A service that was exposed stays on the page once fixed, as patched or mitigated.
Never-released versions are excluded (1,670 services). Other decoys may still be counted.
Counts are services, not organizations or machines. A service is an IP address or hostname plus port; one server can host many websites.
This is an estimate for situational awareness, not a source of truth. It is not an authoritative inventory or a vulnerability assessment of any specific system. Check your own systems directly.
Sources: Censys advisory: nginx2root, nginx security advisories, Xint: nginx2root.
