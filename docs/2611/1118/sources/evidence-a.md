## 二、可能的吠点（线索摘要没提或说反的条件与限制）

1. 说法 vs 证据（“五队撞车”）：Wiz 的话是“Wiz Research, Ikotas Labs, Metnir, Rapid7, and Xint independently uncovered two critical remote code execution vulnerabilities”。F5 公告逐个 CVE 列出的人：123007 为 Rapid7、Wiz、Xint、Ikotas 四方；123633 为 Metnir、Wiz、Xint、Palo Alto Networks Unit 42（memN0ps）四方。没有任何一个 CVE 是 Wiz 所列的五队，且 Unit 42 不在 Wiz 名单里（F5 K000163926 / K000163928）。
2. 说法 vs 证据（“AI 找到的”）：Wiz 称 Atlas “discover both”；Metnir（pipeline + 公开模型）、Ikotas（“using GPT-6 Astra”，F5 公告）、Xint 的另外四个（“fully automated … scan”）是 AI；但 Xint 的 123007 是“a Xint researcher found”（准备 ZeroDay Cloud 时），Rapid7 的 123007 写“discovered by Stephen Fewer”，全文未提 AI（Rapid7 博客；Xint 博客）。
3. 说法 vs 证据（“2.25 亿网站”）：Wiz 写 “powers more than 225 million websites”（Netcraft 九月调查，nginx 站点数 225,366,509，占其 1,470,435,351 sites 的 15.3%）。这是使用量；Censys 看板数“受影响版本 + 开 HTTP/2”的 services 为 8,817,296（21:07 数据，口径是端点），另有 103,799,113 个 services 隐藏版本但显示 HTTP/2，因此“受影响”只能给出下限与未知，Censys 自己说 “The real number of exposed services is higher than the exposed count”；Censys 的 74,183,698 web properties 只按版本号筛、未过滤 HTTP/2。三个数口径互不相同，不要并列成比例。
4. 说法 vs 证据（评级）：Wiz、F5、Censys 写 “Critical”、CVSS 4.0 为 9.2；同一份 F5 公告里 CVSS 3.1 是 8.1（High），两版向量的攻击复杂度都是 AC:H；nginx.org 自己的评级 123007 为 major、123633 为 medium；nginx 变更日志只写 “cause a segmentation fault in a worker process, or might have potential other impact”（123007）。CERT-EU 的数是 8.1。
5. 说法 vs 证据（“远程代码执行”）：F5 对两个 CVE 都写 “attackers can execute code on systems with ASLR disabled or when the attacker can bypass ASLR”；Wiz 写 “ASLR do not protect against these issues”。Metnir 对 123633：开 ASLR 的利用“took about ten minutes, nearly all of it spent on defeating memory layout randomization”。
6. 说法 vs 证据（“要不要管”的前提）：123007 只需开 HTTP/2（CERT-EU：“The only precondition is HTTP/2 enabled on a listening port”），但 Rapid7 的 RCE 需约 128 GB HTTP/2 流量，“a network slower than approximately 300 Mbit/s … will not be able to succeed”，“should an HTTP/2 connection be proxied … likely not … satisfies exploiting the vulnerability”，依赖特定 CPU（avx512f/avx512vl）与 glibc 路径，仅验证了 Docker 镜像 1.31.8；Wiz 的演示是 64 位、HTTPS、响应在内存；123633 需 HTTP/2 + 转发到上游 + worker 连接槽位紧张（nginx.org 与 F5：“if this process is running low on worker_connections”）。Wiz：“CDNs and WAFs that terminate HTTP/2 may mitigate parts of the exploit … This depends on implementation.”
7. 说法 vs 证据（“root”）：CVE 本身只到 worker 进程权限（CERT-EU：“with the privileges of the NGINX worker process”）。拿 root 需串一个另外的 Linux 内核 SCTP 漏洞，Xint 与 Censys 都写该内核漏洞暂无补丁、无 CVE；Censys 未验证这条链（“Censys has not verified the kernel flaw or that exploit chain”）；Xint 提到“SCTP module is installed by default”的发行版很多，但“Whether SCTP is reachable on a given host still depends on the kernel, the available modules, and the container's restrictions.”
8. 具体缺口：缓解建议不统一。F5 两篇公告 Mitigation 栏写 “None”；Wiz、CERT-EU、Xint、Censys 都说关 HTTP/2；Censys 与 Xint 强调只挡 123007 与 123633（“Disabling HTTP/2 blocks CVE-2026-123007 and CVE-2026-123633 only”），其余三个（resolver、HTTP/3、mail proxy）要各自缓解；代价：“services that require HTTP/2, such as native gRPC, will be affected”（Xint）。
9. 具体缺口：“已经修了”不等于“版本号变了”。Xint：“A backport can fix a vulnerability without changing the version reported by nginx -v”（Ubuntu 22.04 的 1.18.0-6ubuntu14.22、14.23 都显示 1.18.0）；“A configuration reload alone does not replace the running executable.” Censys：1.31.8 受影响、1.30.7 不受影响，尽管数字更小。
10. 具体缺口：没有证据显示已被利用（CERT-EU、Censys、F5 发言人转述、CISA ADP SSVC “Exploitation none”，KEV 目录版本 2026.11.18 未收录）；但 Rapid7 PoC 已公开（只针对 123007），Censys 另公开了自测 PoC（只复现到流控状态出错，无崩溃）。
11. 次要：另有一个常被忽略的时间事实：修复提交在 GitHub 上 2026-11-11 已公开（commit 信息含 “Reported by Xint.io.”），发布日 11-18。HN 评论者提出这一点，已核实提交日期。

## 三、夸大说法实例

见 A6 表。最贴近“2.25亿网站待修”的是团子技术日报；CSO、The Register、Security Affairs 标题把“AI 找到”概括成全部；奇安信 CERT 通告写“EXP状态 已公开”与各研究团队“不放 exploit”不符。未找到逐字写成“黑客可直接拿 root”的标题。

## 四、扫描说法勘误

1. “CVSS 均写 8.1”（扫描/CERT-EU）：CERT-EU 确实只写 8.1；F5 官方是 v3.1 8.1（High）+ v4.0 9.2（Critical）两个数。Wiz 只写 9.2。
2. “Rapid7 已公开 PoC，Censys 称 doesn’t look like a plug-and-play exploit（后半句被截断）”：原文全句已读全：“Rapid7 says it needs roughly 128 GB of HTTP/2 traffic and was built against a single test setup.”
3. “页面有 NGINX 主机数统计（Claude 未读到）”：页内图为 “All 19,671,971” 主机（hosts，IP 级）；文字里 “331,242,037 web properties” 与 “74,183,698 web properties”；看板另给 8,817,296 等，见 A4。
4. “Xint 站 nginx2root.com 只得 600 字节”：该站是壳页，指向 Xint 博客；博客全文 `a-xint.*` 已存档。
5. “F5 官方公告另有 K 文章编号（未核）”：已核。K000163926（CVE-2026-123007）、K000163928（CVE-2026-123633）、K000164058（总索引），均为公开页。
6. “Wiz 引用的使用量统计，不是受影响数”：核实为 Netcraft 九月调查中 nginx 站点数 225,366,509。
7. “Wiz 逐字：Wiz Atlas ‘discover’、两大模型 ‘validate’”：核实无误。
8. “nginx.org 123007 major / 123633 medium”：核实无误；同批 major 另有 118899、113425；nginx.org 的一条编号笔误 “CVE-CVE-2026-121810”（HTTP/3 那条）。
9. Wiz 表格 Plus 起点写 “R33”，F5 公告写 “Rx R34 - R36 None”（F5 对 R33 未给 versions known to be vulnerable，因 R33 已过技术支持期，F5 脚注：“F5 evaluates only software versions that have not yet reached the End of Technical Support (EoTS)”）。
10. 扫描标 “1.31.8 is affected while 1.30.7 is not”：核实为 Censys 原话，且与 nginx.org “Not vulnerable: 1.31.9+, 1.30.7+” 一致。
11. Wiz 的“五队”：见吠点 1，逐 CVE 为四方，且名单不同。
12. Wiz 博客页面含一段可能被误读的 “Exploitable in default configurations with HTTP/2 enabled” 只针对 123007；123633 为 “Exploitable configured with HTTP/2 as a proxy server”。

## 五、对读者（已核实事实，每条注出处；没有的写“无”）

- 怎么查自己的版本：运行 `nginx -v 2>&1`，1.9.5 到 1.31.8 的官方版本含漏洞代码；1.9.4 或更早“Released before HTTP/2 support and thus not affected”；发行版或设备版本号“Do not rely on the version string alone”。查有没有编译 HTTP/2 模块：`nginx -V 2>&1 | grep -q -- '--with-http_v2_module'`；查配置是否开 HTTP/2：`sudo nginx -T 2>&1 | sed 's/#.*//' | grep -nE 'listen[[:space:]].*http2|^[[:space:]]*http2[[:space:]]+on[[:space:]]*;'`（出处：Xint 博客 2.3）。从外部查是否协商 h2：`openssl s_client -connect {HOST}:443 -servername {HOST} -alpn h2`（同上；若前面有 CDN，则只测到 CDN）。
- 哪些版本已修：nginx 开源版 stable 1.30.7、mainline 1.31.9 及以后；“1.31.8 is affected while 1.30.7 is not”（Censys 公告）；Plus 37.0.8.1 / 37.3.0.1（123007），37.0.7.1 / 37.2.0.1（123633）；R34–R36 无修复；Instance Manager 2.25.0、Gateway Fabric 2.9.0、Ingress Controller 2026-lts-r11 / 5.8.0（出处：F5 K000163926 / K000163928；nginx.org 公告页与首页）。BIG-IP 全模块、F5OS：“Not vulnerable”（F5 K000163926）。
- 关 HTTP/2 的官方缓解原句：Wiz：“If upgrading is not immediately possible, temporarily disable HTTP/2.”“Set http2 off; in affected server blocks on NGINX 1.25.1 or later, and remove the http2 parameter from any listen directives.”；CERT-EU：“disabling HTTP/2 on exposed listeners (by removing the http2 from the listen directives, or set http2 off;) mitigates the vulnerabilities CVE-2026-123007 and CVE-2026-123633”。注意 F5 公告的 Mitigation 栏写 “None”；关 HTTP/2 只挡这两个（Xint：“disabling HTTP/2 addresses only two of the five nginx vulnerabilities”）；代价：“services that require HTTP/2, such as native gRPC, will be affected”（Xint 博客 3.3.1）。
- 升级后要重启：“A configuration reload alone does not replace the running executable.”（Xint 3.1）；Metnir：Restart NGINX after installing the patched executable，容器要重建（Metnir 博客）。
- 发行版是否已推更新：Ubuntu 已发 USN-9159-1（2026-11-19）：24.04 LTS → nginx 1.24.0-2ubuntu7.20，22.04 LTS → 1.18.0-6ubuntu14.23，26.04/26.10 另有版本；20.04、18.04、16.04 的修复在 Ubuntu Pro（ESM）：“Fix available with Ubuntu Pro”（`a-usn.*`）。Debian 安全追踪页（取于 2026-11-19 21:33）：bookworm、trixie 与 security 通道均标 “vulnerable”，只有 sid 的 1.30.6-4 标 “fixed”（`a-deb-tracker.*`，页面会变）。云厂商（AWS、GCP、Azure 等）是否已推更新：**未查到一手公告**；Xint 称 AWS/GCP/Azure 上有演示环境（nginx2root.com），不等于云厂商公告。
- 哪些人不受影响（或不受其中一项）：没有开 HTTP/2 的 nginx 不受 123007、123633 影响（CERT-EU、Xint）；官方构建里没有 `--with-http_v2_module` 的不受影响（Xint 2.3.2）；CDN 或 WAF 在前面终止 HTTP/2 时可能挡掉部分利用，“This depends on implementation”（Wiz）；经代理转发的 HTTP/2 帧“will likely not be retransmitted in a way that satisfies exploiting the vulnerability”（Rapid7，只针对 123007 的 RCE 路径）。
- 当前威胁状态：CERT-EU、Censys 均写未见在野利用；CISA KEV 查询未收录（见 A3）；Rapid7 PoC 已公开但需约 128 GB 流量（A5）。
- 不是 nginx 的人：BIG-IP 不受这些 CVE 影响（F5）。读者用 nginx 的情形（自己的服务器、云主机、Docker 镜像里的 nginx、Kubernetes ingress 控制器）：社区版 ingress-nginx 已于 2026-03 停止安全修复，Metnir 称其默认开 HTTP/2，应迁移到有维护的控制器（Metnir 博客脚注）。
