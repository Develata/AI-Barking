 [#1-general-information]

 1. General Information

DaisyRose-27B is RadixArk's first model: a multimodal reasoning model built on Qwen3.8-27B with reinforcement learning only, without any supervised fine-tuning or distillation. It was trained on about 1,200 curated long-horizon agent tasks, with sessions of up to 1M tokens, for 18 days on 144 H200 GPUs. Terminal Bench 4.1 pass@1 rises from 5.6 to 12.0, and the model also improves on most of the other coding, reasoning and instruction-following benchmarks below.

DaisyRose-27B keeps the base model's architecture, tokenizer and chat template, along with its image understanding and 256K-token context, so it is a drop-in replacement for Qwen3.8-27B in existing inference and post-training stacks. Weights are released under Apache-2.0 in BF16, FP8, and NVFP4.

How we evaluated

Terminal Bench 4.1: Averaged over 8 repetitions per task, internal mini-swe-agent harness with summarization enabled.
Terminal Bench 2.1: Averaged over 5 repetitions per task, Terminus 2 harness.
DeepSWE v1.1: Averaged over 8 repetitions per task, mini-swe-agent harness.
SWE Bench Pro v2: Averaged over 5 repetitions per task, mini-swe-agent harness. Qwen3.8-27B score from Table 3 of the SWE Bench Pro v2 paper [https://arxiv.org/html/2611.16289#S4.T3] (full 642-task set, mini-swe-agent).
HLE (text only): Averaged over 5 repetitions per problem, GPT-6 Luna grader, no tools.
IFBench: Averaged over 4 repetitions per prompt (300 prompts), official allenai/IFBench scorer, prompt-level loose accuracy on the final response (thinking excluded).
GPQA Diamond: Averaged over 8 repetitions per question (198 questions), simple-evals multiple-choice template and answer extraction, answer order reshuffled each repetition.

All DaisyRose-27B runs use the base model's recommended thinking-mode settings: temperature 1.0, top_p 0.95, top_k 20, min_p 0, reasoning effort xhigh (the template default), no max_tokens cap within the 256K context. DaisyRose-27B scores are the higher of our BF16 and FP8 runs, which differ by less than one point on every benchmark where we ran both. Other models' numbers are as reported by their developers: see the sources below.

 [#3-getting-started]

 3. Getting Started

 [#serving-with-sglang]

 Serving with SGLang

We strongly recommend serving DaisyRose-27B with SGLang and DSpark speculative decoding, using the official lmsysorg/sglang:latest Docker image (DSpark is included).

The SGLang cookbook for DaisyRose-27B [https://docs.sglang.io/cookbook/autoregressive/RadixArk/DaisyRose-27B] generates the launch command for each GPU and precision. BF16 on a 4-GPU node, one replica per GPU:

docker run --gpus all --ipc=host --shm-size 32g -p 30000:30000 \
 -v ~/.cache/huggingface:/root/.cache/huggingface \
 lmsysorg/sglang:latest \
 python3 -m sglang.launch_server \
 --model-path RadixArk/DaisyRose-27B \
 --served-model-name DaisyRose-27B \
 --tp-size 1 --dp-size 4 \
 --context-length 262144 \
 --reasoning-parser qwen3 \
 --tool-call-parser qwen3_coder \
 --trust-remote-code \
 --mem-fraction-static 0.85 \
 --kv-cache-dtype fp8_e4m3 \
 --chunked-prefill-size 2048 \
 --mamba-full-memory-ratio 11.01 \
 --mamba-radix-cache-strategy extra_buffer_lazy \
 --mamba-ssm-dtype float32 \
 --speculative-algorithm DSPARK \
 --speculative-draft-model-path RadixArk/Qwen3.8-27B-DSpark \
 --speculative-draft-attention-backend flashinfer \
 --host 0.0.0.0 --port 30000

 [#supported-hardware]

 Supported hardware

DaisyRose-27B runs on a single GPU, from data-center cards (H200, B200, GB300) to local hardware such as RTX PRO 6000, RTX 5090 and DGX Spark. The weights take about 52 GB in BF16, 29 GB in FP8 and 23 GB in NVFP4; NVFP4 needs a Blackwell GPU. See the SGLang cookbook for DaisyRose-27B [https://docs.sglang.io/cookbook/autoregressive/RadixArk/DaisyRose-27B] for per-GPU launch settings.

 [#quickstart]

 Quickstart

The example uses the openai Python client against the server above. The model thinks before answering by default; the thinking comes back in reasoning_content and the answer in content.

from openai import OpenAI

client = OpenAI(base_url="http://localhost:30000/v1", api_key="none")
SAMPLING = dict(temperature=1.0, top_p=0.95, extra_body={"top_k": 20, "min_p": 0.0})

resp = client.chat.completions.create(
 model="DaisyRose-27B",
 messages=[{"role": "user", "content": "How many positive divisors does 360 have?"}],
 **SAMPLING,
)
print(resp.choices[0].message.reasoning_content) # thinking
print(resp.choices[0].message.content) # final answer

Use temperature 1.0, top_p 0.95, top_k 20, min_p 0 in thinking mode.

Leave max_tokens unset for hard problems; long thinking runs to tens of thousands of tokens.

In multi-turn chats, send earlier turns back with their reasoning_content; the chat template keeps it by default.

Multimodal causal language model with a vision encoder; thinking model

Qwen3.8-27B (Qwen3_5ForConditionalGeneration): 64 decoder layers in a 3:1 pattern of linear-attention (Gated DeltaNet) and full-attention layers, hidden size 5,120, a 27-layer vision encoder, and one multi-token-prediction layer

Output modalities
Text

 [#5-training]

 5. Training

DaisyRose-27B is trained from Qwen3.8-27B with reinforcement learning only. The vision encoder and the multi-token-prediction head are the base model's, unchanged.

Training data. We built the tasks with Eigent AI [https://www.eigent.ai], starting from its large pool of tasks in machine learning, software engineering, science and other fields. About 1,200 made it into the final training set. Each task targets a mistake the base model makes and is tuned until its solve rate is neither too easy nor too hard to learn from. Each is a long job of several interdependent problems: an attempt gets up to 1.5 hours in a sandbox, with more than 100 tool calls and more than 256K output tokens. We reviewed every task together with the model's attempts, and fixed or removed any that could be passed without really solving it.

Training infrastructure. Training ran fully asynchronously with Miles [https://github.com/radixark/miles], our open-source reinforcement-learning framework, on RadixArk's internal training backend. 128 H200s ran the agent on its tasks, served by SGLang [https://github.com/sgl-project/sglang], while 16 more trained on the finished trajectories; after every step the updated weights went back to the 128. Each step learns from a handful of very long sessions, some as long as 1M tokens. The run took 18 days on 144 H200s, about 63,000 GPU-hours. Every attempt ran in a sandbox on our own sandbox service, built on AgentENV [https://github.com/kvcache-ai/AgentENV].
