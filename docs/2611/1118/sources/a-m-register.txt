Hot on the heels of serious vulnerabilities in seemingly every other widely used software powering the entire internet, F5 today released emergency patches for 10 bugs in open source NGINX. 

These include critical remote code execution flaws that let attackers hijack NGINX servers with HTTP/2 enabled, as well as the millions of websites running NGINX, to steal sensitive data and disrupt services.

“At this time, we have found no evidence of active exploitation of any of these vulnerabilities in the wild,” and F5 spokesperson told The Register. “We continue to monitor closely and will share updates via myF5 as we learn more.”

 REG AD

As with all of the other recently disclosed vulnerabilities in foundational technologies like PHP, Apache, and Java, these critical NGINX bugs were uncovered by researchers using AI. One of them has been hiding in the code for at least 10 years.

 REG AD

Tomer Schwartz, Wiz’s chief technology officer of exposure management and AppSec, helped find the bug, along with researchers from Ikotas Labs, Metnir, Rapid7, and Xint working independently. 

Schwartz told The Register that this wave of AI-discovered flaws “point to a new reality.”

“We need to treat every internet-connected system as potentially vulnerable,” Schwartz said. “AI has changed not only which vulnerabilities can be found, but how quickly longstanding risks can become real threats.” 

NGINX is the world’s most widely used [https://w3techs.com/technologies/overview/web_server] open source web server, handling HTTPS requests and routing incoming traffic to the right application or API. It powers about a third of all websites [https://technologychecker.io/technology/nginx] (around 225 million [https://www.netcraft.com/blog/september-2026-web-server-survey]), and F5 maintains the open source version.

On Wednesday, F5 published [https://my.f5.com/manage/s/article/K000164058] an out-of-band security notification that addressed 10 CVEs in open source NGINIX. If you run NGINX, update to 1.31.9 [https://github.com/nginx/nginx/releases#release-release-1.31.9] as soon as possible.

CVE-2026-123633 and CVE-2026-123007

Two of the vulns are especially serious as they allow a remote attacker to execute code on the NGINX server without authentication. These two, tracked as CVE-2026-123633 [https://my.f5.com/manage/s/article/K000163928] and CVE-2026-123007 [https://my.f5.com/manage/s/article/K000163926], both received a critical, 9.2 CVSS rating, and CVE-2026-123007 affects versions dating back to NGINX 1.9.5 in 2015. Both vulnerabilities require HTTP/2 to be enabled on the affected NGINX server. 

All of the security shops listed earlier independently found at least one of these two CVEs - most, if not all, with an AI assist - and reported them to F5.

 REG AD

“Both vulnerabilities are memory-safety issues in how NGINX handles HTTP/2 traffic,” Schwartz and fellow Wiz kid Nir Ohfeld said [https://www.wiz.io/blog/nginx-http2-rce-vulnerabilities#mitigation-and-detection-26] in a Wednesday blog about the two bugs. “In CVE-2026-123633, a connection's memory is freed while a request still needs it, creating a use-after-free. In CVE-2026-123007, incorrect flow-control accounting leads to an invalid memory copy.”

Rapid7’s team also published a proof-of-concep [https://github.com/sfewer-r7/CVE-2026-123007]t [https://github.com/sfewer-r7/CVE-2026-123007] to demonstrate leveraging CVE-2026-123007 for unauthenticated remote code execution against a vulnerable linux/amd64 Docker image running nginx version 1.31.8.

Xint found three other NGINX flaws, plus a separate vulnerability in the Linux kernel that can be chained with any of the five NGINX vulnerabilities to gain root privileges on the host. The research team dubbed the six bugs “nginx2root [https://xint.io/blog/nginx2root-remote-code-execution].” 

The AI-powered offensive security firm also published videos demonstrating attacks [http://nginx2root.com/?__hstc=249718425.a1079c6e67748a740a96a201e1df7767.1791987327891.1793023659126.1795022967674.3&__hssc=249718425.1.1795022967674&__hsfp=077a14059406525d5fd8646185169540] using CVE-2026-123007 to execute commands as the NGINX worker inside a container, and then using the kernel vulnerability to escalate to root on the host. These attacks work on AWS, Microsoft Azure, Google Cloud Platform, and bare-metal servers.

AI-powered bug hunting for the win?

"While preparing for ZeroDay Cloud 2026, a Xint researcher found CVE-2026-123007," the company said in a Wednesday blog. "A few days later, a fully automated Xint scan found the other four without human guidance."

All of these newly-disclosed CVEs point to a larger security issue - especially in light of Tuesday’s Java4Shell [https://www.theregister.com/security/2026/11/18/oracle-reveals-fix-this-asap-grade-java4shell-bug-that-allows-attacks-on-many-third-party-apps/5310661], found by AI-bug-hunting-outfit Calif, PHP2Shell [https://www.theregister.com/security/2026/10/22/php-blames-supply-chain-security-biz-chainguard-for-putting-huge-chunks-of-the-web-at-risk/5304611] (Calif was one of the firms that also used AI to find and weaponize these critical vulns in PHP), and a critical Apache flaw under active exploitation [https://lists.apache.org/thread/lnz4s26tv6hdo03wngtdbpfj4hg4gtds] .

“AI is also accelerating vulnerability discovery faster than existing infrastructure was designed to absorb,” Schwartz told us. “Even after a vendor ships a fix, security teams still face heavy manual work in terms of locating vulnerable versions and configurations, testing patches, deploying interim mitigations (such as disabling HTTP/2), and coordinating all of these rollouts.”

 REG AD

There is light at the end of the tunnel, he believes. “In the long run, AI-powered vulnerability research will harden foundational software.”

But in the meantime, it’s a nightmare for security teams, vulnerability managers, and system administrators, who are drowning in the near-daily deluge of CVEs to patch [https://www.theregister.com/security/2026/11/13/this-years-bug-count-just-passed-100k/5309882] before attackers find and exploit these vulnerabilities. 

“Continued collaboration between security researchers, maintainers, and defenders is crucial to absorb the speed and scale of these disclosures,” Schwartz said.®
