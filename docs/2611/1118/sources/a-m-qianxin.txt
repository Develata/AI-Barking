危害描述：攻击者无需认证即可通过公网 TLS/HTTP/2 端口触发漏洞，读取进程内存（绕过 ASLR）并改写堆上对象，最终以 nginx worker 权限执行任意命令；结合内核 SCTP 提权漏洞可逃逸容器并在宿主机取得 root。成功利用后的典型影响包括：Web 业务被植入后门或篡改、配置文件与证书私钥被窃取、横向移动到后端 upstream 与内网、宿主机被完全控制。由于 nginx 通常位于业务入口，且 CVE-2026-123007 自 2015 年起存在于所有官方版本，受影响面覆盖绝大多数未升级的对外服务。

01

漏洞详情

>>>>

影响组件

nginx 是全球部署最广泛的 Web 服务器与反向代理之一，承担 HTTP/HTTPS、反向代理、负载均衡、HTTP/2、HTTP/3（QUIC）以及邮件代理等职能。本次披露的 5 个漏洞均为内存破坏类缺陷（1 个整数下溢导致的堆越界读写、4 个释放后使用），每一条都可独立造成远程代码执行，但触发所需的配置不同，不构成互相依赖的利用链。

>>>>

漏洞描述

近日，奇安信CERT监测到官方修复nginx2root nginx 多个远程代码执行漏洞，5个 nginx 远程代码执行漏洞（统称 nginx2root）。其中影响面最大的 CVE-2026-123007 是 HTTP/2 流控整数下溢导致的堆越界读写：客户端通过 WINDOW_UPDATE 与流清理逻辑让连接级发送窗口被重复归还额度，使 size_t 类型的发送窗口越过 2^31-1 上限；后续剩余额度校验发生无符号回绕，窗口可被推高到接近 2^64，在转换为有符号 off_t 后变成负长度，最终进入 TLS 输出路径的超大memcpy，形成有界堆越界读与越界写。攻击者据此泄露堆、nginx 镜像与 libc 地址（绕过 ASLR），覆盖 cleanup 回调函数指针，在 nginx worker 权限下执行任意命令。目前该漏洞PoC和技术细节已公开。鉴于该漏洞影响范围较大，建议客户尽快做好自查及防护。

>>>>

利用条件

五个漏洞均无需认证、无需用户交互，攻击者只要能直连 nginx 监听端口即可发起攻击。区别在于各漏洞的前置配置：

CVE-2026-123007 要求 HTTP/2 已启用（配置了 http2 on;，或使用 listen ... http2），且该端口暴露在不可信网络；攻击者需自行构造 HTTP/2 帧，组合 WINDOW_UPDATE、RST_STREAM 和 SETTINGS 把发送窗口推高，不需要后端、第三方模块或特殊 location，是五条路径中唯一在基础配置下即可利用的一条（稳定崩溃只需重复触发，完整 RCE 还依赖堆布局与地址泄露条件）；

CVE-2026-123634 要求配置了 resolver，proxy_pass 的目标由请求变量决定（如 http://$host），且存在 mirror 或 SSI 等子请求，与主请求解析同名 upstream；

CVE-2026-123633 要求以 HTTP/2 接收请求并反向代理到后端，同时 worker 连接数接近 worker_connections 上限；

CVE-2026-121810 要求启用 HTTP/3（listen ... quic / http3 on;），并反向代理到后端；

CVE-2026-113425 要求 mail 代理开启 proxy on 并配置 auth_http，在登录阶段触发；

成功利用后，代码均以 nginx worker 权限执行，要提权到宿主机 root 还需串联 Xint 未公开细节、暂无 CVE 的 Linux 内核 SCTP UAF。

临时缓解措施：

1、按自身配置选择对应项；关闭 HTTP/2 只能阻断 2 个漏洞。

原生 gRPC 等强制 HTTP/2 的业务会受影响。需检查同一监听地址端口上的 所有 server 块。

2、移除请求期 DNS 解析（CVE-2026-123634）

适用于 proxy_pass 含变量（如 proxy_pass http://$host;）且使用 mirror 的场景。改为固定 upstream；如需保留 mirror，主请求与 mirror 均须指向固定 upstream。mirror_request_body on 可阻断已测试的利用路径，但并未修复 resolver 缺陷，不可单独依赖。

3、关闭 HTTP/3（QUIC）（CVE-2026-121810）

4、限制 mail 代理访问（CVE-2026-113425）

使用 proxy on + auth_http 时，将 IMAP/POP3/SMTP 监听改为仅回环或仅可信 IP。

5、切断已有连接

reload 只对新连接生效，旧 worker（nginx: worker process is shutting down）仍沿用旧配置。确认无残留后执行 systemctl restart nginx，可能导致业务短时间中断。
