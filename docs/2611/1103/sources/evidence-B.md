## 2. 可能的吠点（线索摘要没提或说反的条件；每条一句，注明出处）

1. 作者自己写：“it does not claim to establish data exfiltration”，而 HN 标题写“attempts to share all API data”（issue 正文；HN 50354960）。
2. “trust its own startup hook”指安装器经 Codex 的 `hooks/list` + `config/batchWrite` 写 `hooks.state.<key>.trusted_hash`；作者承认“The trust record alone does not prove who created that specific record”（issue §4、`codex-hooks.ts` L25–28、L85）。
3. 钩子只注入文字指令，末句写明“User instructions … take precedence over this mandate”（`session-start-context.md`）；并非可执行逻辑，也没有上传。
4. Postman 自己的 README 写明“installation also approves Postman's session-start hook … There is no separate hook prompt”，即“自动批准”是文档化的设计，而不是被发现的隐蔽行为；争议点是“桌面版升级时自动运行它”（README、`detected-agents` 文档）。
5. 官方文档写的是用户自己运行 `npx @postman/postman-plugin`（有确认提示）；桌面版如何触发同一安装器，没有官方文档（`install/overview`、`detected-agents`）。
6. 第二名用户（12.35.1，11-03 22:58Z）的 `config.toml` **没有** `trusted_hash`，自己说没有证据数据被上传（评论 6618575621）。
7. 原作者的日志来自 12.33.4，没在干净 Mac 复现，日志原件未公开（issue “Steps To Reproduce”）。
8. Claude Code 一侧没有逐个钩子的信任记录（foma-agent 在自己的机器上测 Claude Code 2.1.302，L6，AI 代理账号自述，未运行 Postman 安装器）：issue 要求的“钩子信任应由用户在宿主里决定”，在 Claude Code 上并没有对应机制，不是 Postman 的单方面绕过。
9. 官方口吻账号称“you can uninstall any of these components from inside the app”，但 ck-tecso 称菜单卸载后 Copilot 里的配置未被移除（单人自述）。
10. 发行说明 12.31.7 明写“CLI 随 app 安装与更新”；未写插件自动装入已有 Codex/Claude Code（B6-3）。
11. 插件 README 有“Publishing happens by default”（工作区已连接 `postman init` 之后）和“MCP tool calls reach Postman by design”：数据路径是 CLI/MCP 的使用语义，不是升级时自动发生（README）。
12. 社区高赞质疑（仅线索 L6）：HN 50358055（primitivesuave）称 Postman 对每个请求记录详细信息含模板变量展开后的值；HN 50355797（neya）称请求被代理到 Postman 服务器。两者都是自述，无抓包，且与插件事件无关；未核实。HN 评论无单条得分字段（Algolia 不给；Firebase 同），故未记分。
13. 另一个视角：HN 50361173（silverjaw，称曾在 Postman 工作 4 年，正在做竞品 Sannr）有利益相关，不作依据。
14. 利益披露：The New Stack 的所有者是 OpenAI 与 Postman 的投资方 Insight Partners 的关联方（页脚原句见 B7-2）。
