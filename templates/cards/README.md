# 省流卡、速览聚合图、吠点卡与批注截图

规则见 `EDITORIAL.md`“省流卡与批注截图”与“速览”，命名见 `AGENTS.md`。2026-10-04 起每期加速览聚合图（`roundup.html`，与省流卡同一套纸白配色，主帖条目一行、标“详见前页”）；没有主帖的速览专帖另由 `cover.html` 渲染两张模板封面。版式 2026-10-02 经 Develata 认可；2026-10-03 起省流卡只列事实，批注图只有原文批注与译注；2026-10-28 起每个主帖加一张吠点卡（`bark.html`，`images/00-bark-N.png`），吠点在图上只出现这一次，公众号不插。批注图的“原文截图”标签与译注框用低饱和墨蓝（`annot.html` 顶部的 `--accent: #3a5f8f`，底 `#e8eef5`）；荧光笔四色只用于高亮与编号，编号圆点已调柔，与蓝框明度相近。省流卡不用墨蓝（整张蓝框太闷）：纸白卡片，左侧彩条与标签取荧光笔四色（金、赭橙、鼠尾草绿、紫），按条目顺序循环，与批注图的编号同一套颜色。2026-10-03 配色：原先的亮宝蓝 #1f4fd1 与橙、黄、绿高亮近乎互补，同框时刺眼，故降饱和度。

| 文件 | 作用 |
|---|---|
| `tldr.html`、`roundup.html`、`bark.html`、`annot.html` | 省流卡、速览聚合图、吠点卡、批注图的版式模板，`barking card` 填充；改版式只改这里 |
| `cover.html` | 速览专帖（`kind = "roundup"`）的模板封面，3:4 与 2.35:1 共用，看板娘取 `common_images/profile_picture.png` |
| `example.toml` | `images/cards.toml` 样例（0926 期），字段说明在注释里 |
| `visual-review.md` | 视觉复核提示词 |

工具：Chrome 无头模式渲染（荧光笔依赖 CSS 正片叠底；Typst 0.15 尚无混合模式，见 typst/typst#8815），Tesseract 定位关键句，ffmpeg 放大底图。安装：`scoop install tesseract tesseract-languages`（ffmpeg、Chrome 已有）。找不到 Chrome 时用环境变量 `BARKING_CHROME` 指定。Scoop 安装语言包时设置了用户环境变量 `TESSDATA_PREFIX`，安装前已打开的终端要重开才生效。

## 步骤

1. 每张要批注的截图另存一份底图 `images/NN-name-raw.png`（原始裁切，像素不改；从取证截图裁切或上下拼接用 `barking shot <期次目录> <组前缀> cropbox|stack`，动作自动记入 `sources/<组前缀>-shots-log.jsonl`）。底图宽度尽量窄（页面 CSS 宽约 700 px 以内），否则缩进 1080 宽的卡片后英文太小；高度则放宽：2026-10-03 起图上不再占地方放吠点，底图在两三条译注时可截到约 600 CSS px 高（版面自动按高度缩放，被压得过小会报错）。除关键段落外，把标题、前后文、图表的标题与图例、卡片边框、页面配色等背景留全，让读者看出这是哪一页、哪一块，不要只掐一两行。取证按 2 倍像素比截图，读者放大后仍清晰。
2. 复制 `example.toml` 为 `images/cards.toml`，填写省流卡、速览、吠点卡与各批注图。吠点卡 `[[bark]]` 每个主帖一张，`tag` 与省流卡一一对应、同序；小标题自动取速览里同 tag 的主帖条目；`points` 照抄正文该主帖吠点段的全部条目（逐字、完整、同序，不写①②）。速览的主帖条目从正文逐字摘短标题；其余条目的句子先写进 `sources/fact-check.md` 的“速览”一节，再原样抄到 `text`。省流卡的 `fact` 从正文逐字摘取（可加句末标点；不相邻的几段用“；”拼接，每段各自核对；不要断章丢掉同句里改变含义的限定）；`quote` 写英文原句，`gloss` 照 `fact-check.md` 的译法。
3. 渲染：

   ```bash
   cargo run --release --manifest-path tools/barking/Cargo.toml -- card docs/<YYMM>/<MMDD>
   ```

   只渲染改过的卡片：工具对每张图的全部输入（它在 cards.toml 里的条目、`date` 等共用字段、批注底图或看板娘的字节、模板、批注图所用的 Tesseract 版本与语言模型（`tesseract --list-langs` 报告的目录里那份 `.traineddata` 的内容哈希；OCR 时用 `--tessdata-dir` 显式指定同一目录，认不出版本或模型时这些批注图不记缓存、每次重渲），以及 barking 程序本身，重新编译即算改动）算哈希，与上次成功渲染时的比对，相同且成图还在就跳过，并列出跳过了哪几张；被跳过的成图只更新修改时间，`barking lint` 的“早于 cards.toml”提醒仍然有效。成图本身不参与比对（发布时 oxipng 会重压缩它）；Chrome 版本与系统字体也不参与比对。手工替换过成图、升级了 Chrome、装卸或更新了系统字体后，用 `--all` 全部重渲，或在期次目录后跟文件名（如 `00-tldr.png`）强制重渲这几张（两者不能同时用）。缓存文件不存在就全部重渲；存在却读不了或已损坏，则报错停下，不渲染（按提示删掉即可）。哈希缓存在系统临时目录 `barking-card/cache/`，按 images 目录的绝对路径分文件（主检出与各 worktree 互不影响），条目按小写输出名记（Windows 文件名不分大小写），不放在 `images/`：那里被 Git 忽略的文件都会被 `barking offsite` 登记上传；缓存丢了只是下次全部重渲。每张卡片先截图到临时目录，成功后才替换成图；替换前先从缓存删去这张的记录，渲染中途被打断只会导致下次重渲，不会把旧图或半截图当成最新。同一期同时只能跑一个 `barking card`：缓存目录里有同名 `.lock` 锁文件（内容是进程号），第二个进程会报错退出；上次运行被强行中断（如 Ctrl+C）留下的锁，按报错提示删掉即可。

   渲染前先把不需要 Chrome 与 OCR 的检查对整个 cards.toml 跑完、一次列出全部问题（停用的吠点字段、速览条数与字数、tag 对应（含吠点卡）、吠点卡的空条目与自写编号、输出名重复、缺 `date`、note 条数、`quote` 与 `rects` 二选一、`rects` 越界、`underline` 配 `rects`、`emph` 不在 `gloss` 中、底图缺失；点名渲染时只查点名卡片的底图，因为底图不入库、新检出里可能没有），有问题就一张都不渲染。之后各张卡片独立渲染：某张失败（找不到原句、版面溢出）不影响其余各张，最后汇总列出失败的卡片与原因；同一张批注图里每条 note 的定位问题也一次列全。失败的卡片不记缓存，下次照常重试。

   工具用 OCR 找到每条 `quote` 并逐行加高亮。比对只看字母和数字：空格、标点、直引号与弯引号（' ‘ ’ “ ” 等）、撇号、连字符与破折号（- – —）都不参与比对，OCR 在引文内部把词拆开或连上也不影响（`Google’s` 能对上 OCR 的 `Google's`、`Googles`，`“hard-won lessons”` 能对上 `“hard-won lessons",`），连字（ﬁ、ﬂ）按普通字母算。唯一的字形容错：引文里单独成词的字母 `I`，OCR 常读成 `|`、`l` 或 `1`（或与下一个词粘成 `|do`），视为相同；其他字母和数字一律严格比对（引文的 `l` 不会对上 OCR 的 `1`，引文的 `1` 也不会对上 `I`）。引文范围内 OCR 读出的 `|` 不会被跳过（它可能是引文漏写的 `I`），对不上就报错。匹配到的词在图上必须连成一片，否则报错并提示改用 `rects`，因为可能把不相连的文字拼成一句（Tesseract 按单一文本块读图时，会把并排的两栏读进同一行）。规则：OCR 一行里相邻两个词（`|` 也算词，只有 `.,;:'"` 这类纯标点不算）之间的空白超过 2.5h 就是“栏缝”，h 为该行最高的词框；唯一的例外是行首的列表编号（`a.`、`a)`、`(iv)`、`[3]`、`12.`，括号须成对）后面，允许到 4h。单行引文：从引文前一个词到引文后一个词之间不能有栏缝。**跨行引文：涉及的每一行都不能有栏缝，所以分栏或表格版式里的跨行引文一律拒绝，请改用 `rects`**；此外除最后一行外每行都要读到行尾，续行都从行首开始，各行在 OCR 中相邻、逐行向下，上下间距不超过两行中较矮者的 1.5 倍。不能跨 Tesseract 文本块。OCR 把编号读走样（如把 `l.` 读成 `I,`）时不算编号，按 2.5h 判。以下情况直接报错，不会猜位置：找不到原句、出现不止一次、起止落在一个词中间（如 state-of-the-art 只引半截）、识别置信度低于 60（单个字母也不例外：低置信度说明框的位置可疑，而行首行尾的框决定高亮边界）、`underline` 不在本条原句内。OCR 认不准的图（拼接图、低清图）删去 `quote`，改写 `rects`（底图像素 `[x, y, w, h]`，每行一个；此时不能用 `underline`）。版面放不下（省流卡或速览条目超出、吠点卡字号缩到 36px 仍超出、速览的主帖条目折成两行、模板封面的标签放不下、批注图底图被压到铺满宽度的 75% 以下、标题或页脚过长）也报错，按提示删减。中间 HTML 在系统临时目录 `barking-card/<进程号>/`，报错信息里会给出路径。
4. 自查：逐张打开成图；高亮处再裁出来放大看（例：`ffmpeg -i out.png -vf "crop=1080:420:0:600" zoom.png`）。确认高亮没有扫进邻句、下划线落在目标限定词下方、引号与换行正常、页脚不压内容。
5. 视觉复核（必做，跨模型）：

   ```bash
   cargo run --release --manifest-path tools/barking/Cargo.toml -- review docs/<YYMM>/<MMDD> --visual
   ```

   它按 `visual-review.md` 填好提示词（附图清单 = 省流卡、速览图、吠点卡、封面、每张批注图及其 `-raw` 底图，末尾附 `EDITORIAL.md` 的“省流卡与批注截图”“速览”两节），写进临时目录，并打印交给 WSL 中 Codex（`gpt-6-astra`，effort `medium`，只读）的完整命令；加 `--run` 则直接执行（Codex 慢，放后台运行，等完成通知后读报告）。等价的手工命令，每张图一个 `--image=` 参数，路径用 `wsl -d Debian -e wslpath -a` 转换：

   ```bash
   MSYS_NO_PATHCONV=1 wsl -d Debian -e bash -lc 'cd "$1" && exec timeout 1200 "$0" exec -m gpt-6-astra -c "model_reasoning_effort=\"medium\"" -s read-only --skip-git-repo-check --ephemeral -C "$1" -o "$2" --image=images/00-tldr.png --image=images/01-x.png --image=images/01-x-raw.png - < "$3"' /home/deve/.bun/bin/codex "<期次目录的 WSL 路径>" "<报告的 WSL 路径>" "<提示词的 WSL 路径>"
   ```

   Codex 不可用或超时时，改派 Sonnet 子代理按同一提示词看图复核，并在记录中注明复核方。Claude 逐条核实意见再改，结论记入 `sources/fact-check.md`。
6. `barking lint`：省流卡与速览主帖条目的文字须在正文同一行中逐字出现，速览其余条目须逐字列在事实清单“速览”一节且级别与措辞相符，第 N 张吠点卡须与正文第 N 段“吠点：”逐条逐字一致、一条不缺（1027 期起缺吠点卡也报错；均为 error）；吠点卡没列进正式配图、没按主帖顺序、所在行没注明公众号不插，cards.toml 改过而图未重渲、省流卡不在正式配图第一行、`fact-check.md` 没有“视觉复核”记录，均给 warn。
7. `images/README.md` 的正式配图里，省流卡列第 1 行、速览聚合图第 2 行（速览专帖只有速览图，列第 1 行），其后按主帖顺序，每个主帖先列吠点卡（该行注明“公众号不插”），再列它的批注图；批注图替代原截图；`-raw` 底图列入备用图（用途写“批注底图”）。1002 期起，包括卡片在内的全部图片都不入 Git，发布后由 `barking offsite --upload` 存 OpenList（路径与 SHA-256 见 `sources/offsite.tsv`）；日后重渲，先从 OpenList 同一路径取回底图。
